# QQBot 跨模块联动与 Capability

QQBot 模块通过 Suite 的 Capability 体系和 EventBus 与其他模块深度联动，同时提供完整的数据存储层支持跨服同步。

## Capability 注册

QQBot 模块在启动时注册以下 Capability，供其他模块查询和调用：

### QQBotBroadcastable

向 QQ 群发送消息的能力，供其他模块推送通知到群。

| 方法 | 说明 |
|---|---|
| `sendToGroup(long groupId, String message)` | 向指定群发送消息 |
| `sendToAllGroups(String message)` | 向所有已配置群发送消息 |

**使用示例**（其他模块通过 `getCapability` 获取）：

```java
QQBotBroadcastable broadcaster = getCapability(QQBotBroadcastable.class);
if (broadcaster != null) {
    broadcaster.sendToAllGroups("[系统] 服务器即将维护，请做好准备");
}
```

### QQBotNotifiable

反向通知能力，允许其他模块监听 QQ 群消息事件。

| 方法 | 说明 |
|---|---|
| `registerListener(QQGroupEventListener listener)` | 注册群消息事件监听器 |
| `unregisterListener(QQGroupEventListener listener)` | 注销群消息事件监听器 |

**QQGroupEventListener 接口**：

```java
@FunctionalInterface
public interface QQGroupEventListener {
    void onGroupMessage(long groupId, long userId, String nick, String message);
}
```

### QqBindCapable

QQ 绑定状态查询与确认能力，供 loginview 等模块集成登录门控。

| 方法 | 返回值 | 说明 |
|---|---|---|
| `isBound(UUID playerUuid)` | boolean | 查询玩家是否已绑定 QQ |
| `getBoundQqId(UUID playerUuid)` | Long | 获取玩家绑定的 QQ 号（未绑定返回 null） |
| `confirmBind(Player player, String code)` | BindResult | 确认绑定（含自动加白名单逻辑） |

**BindResult 记录**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | boolean | 是否绑定成功 |
| `qqId` | Long | 绑定的 QQ 号（成功时） |
| `message` | String | 结果消息 |

> `confirmBind` 成功时会自动执行白名单添加命令（若 `whitelist.auto-add-on-bind` 启用），保持与 `/qqbot bind` 行为一致。

### 数据清理与迁移

- `/axs purge` 支持按 UUID 或全量清理玩家绑定数据（积分、签到等按 QQ 号关联的数据不在清理范围）
- `/axs migrate` 支持跨源数据迁移

## EventBus 事件订阅

QQBot 模块订阅以下 EventBus 事件：

### axs.market.auction_purchased

订阅 Market 模块的拍卖成交事件（通配符 `axs.market.*`），当成交价 >= `market-broadcast.threshold` 时推送到所有群。

| 事件字段 | 说明 |
|---|---|
| `price` | 成交价格 |
| `formatted_price` | 格式化后的价格 |
| `buyer` | 购买者名称（结算时买家通常已离线，`event.player()` 为 null，以此字段为准） |
| `buyer_uuid` / `seller_uuid` | 买家/卖家 UUID |
| `currency` / `tax` | 货币 ID / 税费 |
| `listing_id` / `item` | 挂单 ID / 物品标识 |

**推送格式**：`[交易] <玩家名> 以 <价格> 购买了拍卖行物品`

**配置项**：

| 配置 | 默认值 | 说明 |
|---|---|---|
| `market-broadcast.enabled` | `true` | 是否启用大额交易播报 |
| `market-broadcast.threshold` | `1000.0` | 大额交易阈值 |

### axs.mail.* （预留）

预留邮件相关事件订阅，当前未实现具体逻辑。

## 跨服同步

### 共享存储模式

当 `storage.shared: true` 时，QQBot 使用本体统一数据源（`plugins/ArcartX-Suite/config.yml` 的 `storage` 节）。多服环境下，所有服务器共享同一数据库，实现绑定数据、积分、签到记录的跨服同步。

| 数据 | 跨服同步 | 说明 |
|---|---|---|
| QQ-游戏绑定 | ✅ | 所有服共享绑定关系 |
| 积分余额 | ✅ | 积分跨服通用 |
| 签到记录 | ✅ | 每日签到全局生效 |
| 兑换流水 | ✅ | 每日限购跨服计算 |
| 黑名单 | ✅ | 动态黑名单跨服生效 |
| 红包 | ✅ | 红包跨服可抢 |
| 群活跃度 | ✅ | 活跃度跨服统计 |

### 自建存储模式

当 `storage.shared: false` 时，模块使用独立数据库连接。此模式下各服数据独立，不跨服同步。

## 数据存储

QQBot 模块将绑定关系、积分、签到记录、兑换流水、黑名单、红包与群活跃度存储在数据库中（SQLite 或 MySQL）。

## 与其他模块联动

### Mail 模块（邮件系统）

QQBot 通过 `MailDispatchable` Capability 与 Mail 模块联动：

| 联动场景 | 说明 |
|---|---|
| 积分兑换奖品 | 兑换成功后通过邮件预设发放奖品给绑定玩家 |
| 群内发邮件 | 管理员通过 `#发邮件 <玩家名> <预设ID>` 发送邮件预设 |
| 失败退款 | 邮件发放失败时自动退还积分 |

**配置要求**：

- 奖品的 `mail.presets` 须对应 Mail 模块中配置的邮件预设 ID
- Mail 模块需已安装并正常运行

### Market 模块（交易行）

QQBot 通过 EventBus 订阅 Market 模块的拍卖成交事件：

| 联动场景 | 说明 |
|---|---|
| 大额交易播报 | 拍卖成交价 ``>`=` 阈值时推送到所有群 |

**配置要求**：

- `market-broadcast.enabled: true`
- `market-broadcast.threshold` 设置合理阈值

### Essentials 模块（基础功能）

QQBot 通过 `EssentialsQueryable` Capability 获取玩家状态：

| 联动场景 | 说明 |
|---|---|
| 查在线指令 | 在线列表中显示 AFK / 隐身 / 无敌状态标签 |

### LoginView 模块（登录面板）

QQBot 通过 `QqBindCapable` Capability 向 LoginView 模块暴露绑定状态：

| 联动场景 | 说明 |
|---|---|
| 登录门控 | LoginView 在登录面板中查询 QQ 绑定状态，引导玩家完成绑定 |
| 绑定确认 | LoginView 可调用 `confirmBind` 完成绑定流程 |

> QQBot 自身仅记录玩家账号类型与绑定状态的审计日志，不拦截登录。实际登录门控由 LoginView 模块统一管控。

### Chat 模块（聊天系统）

QQBot 软依赖 `chat` 模块：

| 联动场景 | 说明 |
|---|---|
| 消息同步 | 监听 `AsyncPlayerChatEvent` 将游戏内聊天转发到 QQ 群 |
| 进退服通知 | 监听 `PlayerJoinEvent` / `PlayerQuitEvent` 推送通知到群 |

## 游戏内事件同步

以下游戏内行为可推送到 QQ 群（由配置开关控制）：

| 事件 | 说明 |
|---|---|
| 玩家聊天 | 游戏聊天 → QQ 群同步 |
| 玩家进服/退服 | QQ 群通知 |
| 击杀/死亡 | 播报（支持 Boss/PvP 过滤） |

## OneBot 协议

QQBot 通过 OneBot 11 WebSocket 协议与实现端（SnowLuma 等）交互，支持发送群消息、@消息、撤回、禁言等操作，并处理群消息、入群、禁言等事件。

## SnowLuma 进程管理

QQBot 内置 SnowLuma 进程管理器，支持两种运行模式：

### Native 模式

| 特性 | 说明 |
|---|---|
| 运行方式 | 本地 Node.js 子进程（直接以 `node index.mjs` 启动，优先使用安装包内置运行时） |
| 环境要求 | 完整版自带 Node 运行时，零依赖；lite 版需系统 Node.js 22.13+ / 23.4+ |
| 安装方式 | `/axs qqbot snowluma install`（从 GitHub 下载，优先完整版，实时进度显示） |
| 进程管理 | 自动启动/停止/清理残留进程 |
| 端口清理 | 按配置的 WS 端口清理残留进程 |
| WebUI 密码 | 首次启动的临时密码自动捕获并保存至 `snowluma/webui-password.txt`，可随时用 `/axs qqbot snowluma password` 查看 |
| JVM 钩子 | 注册 ShutdownHook 确保异常退出时清理进程 |

### Docker 模式

| 特性 | 说明 |
|---|---|
| 运行方式 | Docker 容器 |
| 环境要求 | Docker 已安装 |
| 安装方式 | `/axs qqbot snowluma install`（docker pull + docker run，支持 `auto-install` 自动部署） |
| 端口映射 | WebUI / WS / HTTP / noVNC 端口可配置 |
| 数据持久化 | 自动挂载 3 个 volume（data / qq-config / qq-data） |
| 日志查看 | `/axs qqbot snowluma logs` |
| WebUI 密码 | `/axs qqbot snowluma password` 自动从容器日志提取临时密码；`password reset` 可重置 |

## 配置版本迁移

模块支持配置文件自动迁移，启动时自动检测 `config-version` 并升级到当前版本（含 `storage.mode` → `storage.shared` 等结构调整），无需人工干预。
