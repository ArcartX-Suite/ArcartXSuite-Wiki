配置位于 plugins/ArcartX-Suite/data/qqbot/config.yml。片段用于修改对应小节，保留其他内容；保存后 /axs reload qqbot。首次接入见[安装教程](/docs/qqbot)。

## 连接

| onebot 字段 | 默认 | 作用 |
| --- | --- | --- |
| ws-url | ws://127.0.0.1:3001 | 正向 Universal WS 完整地址，含路径 |
| access-token | 空 | 对应账号和适配器的 token；SnowLuma 默认自动生成 |
| reconnect-interval-seconds | 10 | 断线重连间隔秒数 |
| heartbeat-interval-seconds | 30 | WebSocket ping/pong 存活检测超时，限制 10–300 秒；区别于实现端 OneBot 业务心跳 |

## 托管

以下字段位于 onebot.snowluma。

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| mode | external | external 仅连接；native/docker 启用托管 |
| dir | snowluma | 服务端下独立子目录，保存安装或归属标记 |
| auto-start | false | 模块启动、重载后自动启动已安装托管服务 |
| webui-password | 空 | 首次初始化密码，不覆盖已设置的密码 |
| accept-agreements | false | 阅读并同意发行包协议后可启用协议确认变量 |

完整包按实际系统和架构选择，不回退到其他架构或 Lite。Node 按包内 engines.node 检查，缺省要求 ^24.22.1 或 >=26.12.1；推荐内置运行时。

Docker 字段位于 onebot.snowluma.docker：

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| container-name | snowluma | 同名外部容器不接管 |
| image | motricseven7/snowluma:latest | install 拉取的镜像，可固定 tag |
| bind-address | 127.0.0.1 | 宿主发布地址，仅接受 IPv4/IPv6 字面量；默认回环 |
| webui-port / ws-port / http-port / novnc-port | 5099 / 3001 / 3000 / 6081 | 绑定到 bind-address 的宿主端口 |
| vnc-password | 空 | 空时由镜像生成，在 logs 中查询 |
| auto-install | false | 模块启动时，托管容器不存在才自动安装；更新用 install 命令 |

修改 ws-port 时同步修改 onebot.ws-url。修改发布地址或端口后，执行 install 重建已验证归属的托管容器。默认回环访问时使用 SSH 转发；显式非回环绑定（例如 0.0.0.0 或宿主 IP）必须配置非空 vnc-password，否则安装、启动和密码重置重启会被拒绝。非回环访问还需自己配置防火墙、访问范围及 OneBot token。bind-address 不接受 hostname、带 zone 的 IPv6、空白或命令文本。

容器通过本地标记和标签双重验证；更新保留 /app/data 及 QQ 命名卷。external 下安装、启动、停止、密码命令只返回说明。不要删除 .axs-qqbot-owner 或数据卷。

## 群与发送

groups 默认 []。每个元素含 group-id、sync-mode、game-to-qq、qq-to-game、commands-enabled、join-message、quit-message。同步方向可填 both、game-to-qq、qq-to-game、none。进退服文本留空关闭。

| 模板 | 可用变量 |
| --- | --- |
| game-to-qq | `{player}`、`{display_name}`、`{message}`、`{server}` |
| qq-to-game | `{nick}`、`{qq}`、`{message}`、`{group}` |
| join-message / quit-message | `{player}`、`{online}`、`{max}` |

普通玩家发群只到允许 game-to-qq 的配置群；管理员可显式选择配置内任意群。

| delivery 字段 | 默认 | 作用 |
| --- | --- | --- |
| max-message-length | 300 | 玩家输入长度上限 |
| player-cooldown-seconds | 3 | 普通发送冷却 |
| group-messages-per-minute | 30 | 所有出口共享每群预算 |
| require-binding | false | 发送前必须绑定 QQ |
| vanilla-chat-fallback | false | 无 Chat 时明确启用原版聊天转发 |

## 绑定、白名单和管理

binding.enabled 控制入口；bind-prefix、unbind-prefix、query-prefix 默认 #绑定、#解绑、#查绑。宿主认证固定验证码 300 秒、Realm 内一对一；旧 method、code-expire-seconds、max-bindings-per-qq 不再可调。

whitelist.enabled、add-command、remove-command、add-prefix、remove-prefix、list-prefix 控制独立 Minecraft 白名单。绑定不自动添加，解绑不自动移除。准入要求在[宿主认证](/docs/loginview/configuration)设置。

admin.qq-list 是明确受信任的管理 QQ 名单，默认 []。admin.enabled 是总开关，默认 false；只有总开关为 true 且命中名单，才可使用已开启的白名单增删查、踢/封、发邮件、公告、黑名单及自定义 server-command。普通QQ群管/群主不会自动获得游戏服务器权限。

admin.remote-console-enabled 默认 false，单独控制 #cmd。需要具体群管理时，设置 admin.enabled:true 并填入可信 QQ，仍保持 remote-console-enabled:false；#cmd 只有两个开关均为 true 才开放。command-prefix 默认 #cmd，allowed-commands 限制远程控制台命令名。只把你明确授权的人加入名单。

custom-commands 为命令名到定义的映射，command-prefix 默认 #，help-prefix 默认 #帮助。

| 自定义字段 | 作用 |
| --- | --- |
| permission | builtin/papi-query 的 0 为普通群员；>0 及所有 server-command 均要求 admin.enabled:true 且命中可信名单 |
| type | builtin / papi-query / server-command |
| builtin-id | online-list / server-status / points-leaderboard |
| command | 固定业务命令模板；不要提供任意 `{args}` 执行入口 |
| placeholders / format | PAPI 查询项及结果模板 |
| usage | 用法提示 |

## 其他功能

下表中的路径相对于对应小节。默认值以新生成的 config.yml 为准；列表元素的默认值说明添加条目但省略字段时的取值。监控、定时及业务通知也受每群发送预算约束，目标群号必须已在 groups 中声明。

### 签到与奖品

signin 的积分计算、全部指令前缀，以及 prizes 的逐字段说明、完整邮件预设示例和兑换复核流程见[签到积分与兑换](/docs/qqbot/signin-points)。prizes 默认 []，配置真实 Mail 预设并验证成功后再添加奖品。

### 服务器监控 monitor

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | false | 是否检测并推送 TPS、内存告警 |
| tps-threshold | double | 15.0 | 1 分钟 TPS 低于该值时告警 |
| memory-threshold-percent | integer | 90 | 已用 JVM 堆内存占最大堆比例达到该百分比时告警；不是整台主机内存 |
| check-interval-seconds | integer | 60 | 检测间隔，单位秒 |
| cooldown-seconds | integer | 300 | 同类告警的最短间隔，TPS 与内存分别计时 |
| alarm-groups | list&lt;long&gt; | [] | 接收告警的已配置群；空列表表示所有配置群 |
| tps-alarm-format | string | ⚠ 服务器告警\nTPS 过低: `{tps}`（阈值 `{threshold}`） | 支持 `{tps}`、`{threshold}` |
| memory-alarm-format | string | ⚠ 服务器告警\n内存占用过高: `{used}`MB/`{max}`MB (`{percent}`%) | 支持 `{used}`、`{max}`、`{percent}`，容量单位为 MiB 量级 |

例如只给运维群推送，避免向全部玩家群发送告警：

~~~yaml
monitor:
  enabled: true
  tps-threshold: 15.0
  memory-threshold-percent: 90
  check-interval-seconds: 60
  cooldown-seconds: 300
  alarm-groups: [123456789]
  tps-alarm-format: "⚠ TPS {tps}，低于阈值 {threshold}"
  memory-alarm-format: "⚠ JVM内存 {used}/{max}MB（{percent}%）"
~~~

把示例群号换成 groups 中真实的运维群号。持续高负载时，最多每个冷却周期推送一次同类告警。

### 定时消息 scheduled-messages

整个小节默认 []，没有条目就不发送。每个条目支持：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| id | string | 必填 | 条目唯一标识；使用不同且稳定的 ID，空 ID 不加载 |
| mode | string | interval | interval 固定间隔；daily 每日指定时间 |
| interval-seconds | integer | 0 | interval 的间隔秒数，必须大于 0；0 不触发 |
| daily-time | string | 12:00 | daily 的触发时间，使用 24 小时制 HH:mm，例如 09:30 |
| message | string | 空字符串 | 消息内容；空内容不发送，支持 `{online}`、`{max}`、`{tps}` |
| target-groups | list&lt;long&gt; | [] | 目标配置群；[] 表示所有配置群，填写群号则只发这些群 |

推送全部群使用 target-groups: []，指定群使用群号列表；YAML 统一使用 target-groups 这个字段名。每日时间使用服务器系统时区；interval 在启动后等待一个完整间隔才首次发送。daily 不补发停服期间错过的历史消息。

下面同时配置每 6 小时在线播报，以及每天中午的签到提醒：

~~~yaml
scheduled-messages:
  - id: "online-report"
    mode: "interval"
    interval-seconds: 21600
    message: "在线 {online}/{max}，TPS {tps}"
    target-groups: [123456789]
  - id: "signin-noon"
    mode: "daily"
    daily-time: "12:00"
    message: "今天别忘了 #签到。"
    target-groups: []
~~~

要停止某条定时消息，移除该条目后重载；要全部关闭，改回 scheduled-messages: []。

### 击杀与死亡播报 broadcast

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| kill.enabled | boolean | false | 玩家击杀实体后向配置群播报；没有玩家击杀者时不播报 |
| kill.format | string | 🗡 `{killer}` 击杀了 `{victim}` | `{killer}` 为击杀玩家，`{victim}` 优先使用被击杀实体的自定义名称 |
| kill.boss-only | boolean | true | 仅播报名称匹配 boss-keywords 的非玩家实体 |
| kill.player-kill-only | boolean | false | 仅播报玩家击杀玩家；启用时优先于 boss-only |
| kill.boss-keywords | list&lt;string&gt; | [Boss, 首领, 魔王] | 名称包含任一关键词即视为 Boss；不是 Boss 插件的实体 ID |
| death.enabled | boolean | false | 玩家死亡时向配置群播报 |
| death.format | string | ☠ `{player}` 死亡了 | `{player}` 为死亡玩家名 |

只播报 PvP 时设 kill.player-kill-only:true；希望播报所有有玩家击杀者的实体时，将两个 only 开关均设 false。播报属于业务通知，不受各群聊天同步方向控制。

### 大额交易播报 market-broadcast

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | false | 是否推送 Market 拍卖成交消息，需要 Market 模块正常运行 |
| threshold | double | 1000.0 | 拍卖实际成交价大于或等于该值时播报 |

该功能针对拍卖成交，不代表商店、回收等所有交易都会推送。金额单位沿用 Market 对应交易币种，先用测试成交确认阈值符合你的经济配置。

### 入群欢迎 welcome

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | false | 新成员进入已配置群时，提及该成员并发送欢迎内容 |
| message | string | 欢迎新成员加入！\n发送 #绑定 &lt;游戏名&gt; 关联你的游戏账号\n发送 #帮助 查看可用指令 | 支持 `{qq}`、`{group}`；无需手写 CQ 提及码 |

欢迎模板中的换行使用 YAML 双引号内的 \n。游戏账号需要先创建，再按绑定步骤验证身份。

### 关键词自动回复 auto-reply

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | false | 是否处理关键词回复 |
| cooldown-seconds | integer | 30 | 同一群连续两次自动回复的最短间隔秒数 |
| rules | list&lt;object&gt; | 下方两条示例规则 | 按顺序匹配，命中第一条后回复 |
| rules[].keywords | list&lt;string&gt; | 每条规则分别填写 | 任一关键词匹配即可；空关键词列表的条目不加载 |
| rules[].response | string | 每条规则分别填写 | 命中后发送的普通文本，不是服务器命令 |
| rules[].exact-match | boolean | false | true 要求整条消息等于关键词；false 包含即匹配；匹配忽略大小写 |

默认附带的两条规则如下，首次启用前先替换服务器地址：

~~~yaml
auto-reply:
  enabled: false
  cooldown-seconds: 30
  rules:
    - keywords: ["怎么进服", "服务器地址", "ip"]
      response: "服务器地址: play.example.com\n首次进入请先在群内 #绑定 <游戏名>"
      exact-match: false
    - keywords: ["怎么绑定", "如何绑定"]
      response: "在群里发送: #绑定 <你的游戏名>\n然后按提示在游戏内输入验证码即可"
      exact-match: false
~~~

像 ip 这样的短关键词容易误匹配普通聊天；需要精确触发时设 exact-match:true，或换成较完整的词组。

### 群公告 announce

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | false | 是否启用群内公告指令 |
| prefix | string | #公告 | 群指令前缀，后面填写公告内容 |
| game-format | string | &e&l[群公告] &f`{content}` | 游戏聊天栏格式，`{content}` 为公告正文 |
| qq-receipt | string | ✓ 公告已发布到游戏内 | 发布后给群的回执 |
| title-enabled | boolean | true | 是否同时显示游戏标题 |
| title-text | string | &e群公告 | 游戏主标题 |

### 踢人、封禁和自动审核 moderation

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | false | 启用手动踢出、封禁群指令 |
| kick-prefix | string | #踢 | 用法：#踢 玩家名 原因 |
| ban-prefix | string | #封禁 | 用法：#封禁 玩家名 原因 |
| kick-command | string | kick `{name}` `{reason}` | 控制台命令模板，`{name}` 为目标游戏玩家，`{reason}` 为原因 |
| ban-command | string | ban `{name}` `{reason}` | 封禁命令模板；使用其他封禁插件时换成其真实命令 |

手动管理指令只允许已开启管理总开关的可信 QQ。下面两个子功能使用各自 enabled，不把 moderation.enabled 当作它们的总开关。

QQ 禁言同步的字段位于 moderation.sync-ban：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | false | 收到 QQ 群禁言事件时，对被禁言 QQ 绑定的游戏账号执行命令 |
| command | string | tempban `{name}` `{duration}` `{reason}` | 需服务器提供 tempban 命令或替换为实际封禁插件命令 |
| use-duration | boolean | true | 是否把 QQ 禁言时长带入 `{duration}`；按分钟向上取整，最少 1m |
| reason | string | QQ群禁言同步 | 填入 `{reason}` 的固定原因 |

只有绑定账号能解析到游戏目标。解除 QQ 禁言不会自动解除游戏封禁。设 use-duration:false 时 `{duration}` 为空，请同时把 command 改成不需要时长的有效命令，例如 ban `{name}` `{reason}`。

广告自动审核字段位于 moderation.auto-moderation：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | false | 命中关键词时过滤该消息，并请求 QQ 撤回和禁言 |
| keywords | list&lt;string&gt; | [http://, https://, www., 点击, 加群] | 消息包含任一词即命中，忽略大小写 |
| ban-duration-seconds | integer | 600 | QQ 禁言秒数，0 表示解除禁言；最大按 OneBot 允许范围限制为 2592000 秒 |
| cooldown-seconds | integer | 300 | 同一群两次撤回/禁言动作的最短间隔；冷却期间仍过滤命中的消息 |

先在测试群验证，机器人 QQ 需要具有撤回、禁言对应成员的权限。下面只对链接关键词做审核，不把“点击”等常见词列入：

~~~yaml
moderation:
  enabled: false
  auto-moderation:
    enabled: true
    keywords: ["http://", "https://", "www."]
    ban-duration-seconds: 600
    cooldown-seconds: 300
~~~

这个示例只开启自动审核，未开启手动踢人/封禁或 QQ 禁言到游戏封禁同步。需要允许成员分享链接时保留 enabled:false，或按自己的群规则修改关键词。

### 黑名单 blacklist

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | false | 启用配置静态黑名单与对应群管理指令 |
| qq-list | list&lt;long&gt; | [] | 配置内禁止使用机器人功能的 QQ 号 |
| add-prefix | string | #黑名单添加 | 可信 QQ 添加动态黑名单，用法后接 QQ 号或可解析的玩家名 |
| remove-prefix | string | #黑名单移除 | 可信 QQ 移除动态黑名单 |
| list-prefix | string | #黑名单列表 | 可信 QQ 查询配置及动态黑名单 |

黑名单会拦截该 QQ 的群指令、聊天同步、签到及相关群事件。通过管理命令添加的动态名单单独保存；关闭配置 enabled 不等于移除已有动态记录。需要解除时使用 /axs qqbot blacklist remove QQ号，并同步从配置 qq-list 删除静态条目。

### 群提及提示 at-to-game

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| enabled | boolean | true | 群消息提及某 QQ 时，若其绑定的游戏玩家在线且已准入，向该玩家发送标题和聊天提示 |

该设置是“QQ群提及 → 游戏提示”，与游戏内 /qqbot at 的发送权限和冷却分别控制。

messages 节集中提供各场景文字模板；可保留默认文本，仅按需要修改对应项及已有占位符。换行用双引号字符串中的 \n。不要把真实 token、密码或服务器命令执行入口写入群回复模板。常用的消息格式例子见[消息同步与群通知](/docs/qqbot/message-sync)。

## 存储

storage.shared 默认 true，沿用本体存储。积分、红包和兑换属于 QQBot 数据；绑定属于宿主认证。改 QQBot 数据库不能迁移认证绑定。

自建 SQLite：

~~~yaml
storage:
  shared: false
  mode: "sqlite"
  sqlite:
    file: "qqbot.db"
  pool-size: 1
~~~

自建 MySQL：

~~~yaml
storage:
  shared: false
  mode: "mysql"
  pool-size: 4
  mysql:
    host: "127.0.0.1"
    port: 3306
    database: "arcartxsuite"
    username: "axs"
    password: "替换成数据库密码"
    table-prefix: "axs_qqbot_"
~~~

切换前备份、迁移并验证数据，再改连接；改配置不会自动搬迁积分。诊断提案应保留独立 mode/mysql/sqlite 参数，应用前核对目标。

## 界面和文案

ui.bind-ui-id、notify-ui-id、admin-ui-id 默认 AXS:qqbot_bind、AXS:qqbot_notify、AXS:qqbot_admin。register-ui-on-enable 控制注册，overwrite-ui-files 默认 false，notify-enabled 控制 HUD。

新版界面导出到模块数据目录的 ui/qqbot_v2/，三个文件为 qqbot_bind.yml、qqbot_admin.yml、qqbot_notify.yml。旧 ui/ 下的自定义文件保留；新版定制需编辑 ui/qqbot_v2/ 中实际加载的文件，编辑前备份。运行时 UI ID 保持不变。

messages 节设置群业务文案，messages.yml 设置游戏命令文案。settings.debug 排错，settings.server-id 标识来源。真实 token、密码及归属标记不要放进公开示例或截图。
