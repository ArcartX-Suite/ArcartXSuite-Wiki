# OneBot 连接与 SnowLuma 管理

QQBot 模块通过 **OneBot 11 正向 WebSocket 协议** 与 QQ 机器人实现端建立长连接，实现双向事件推送与指令调用。模块内置 SnowLuma 进程管理器，支持 native（本地子进程）和 docker（容器）两种模式自动拉起 OneBot 实现端。

## OneBot 11 协议概述

OneBot 11 是 QQ 机器人领域的标准通信协议，QQBot 模块作为 **WebSocket 客户端** 连接到 OneBot 实现端（服务端）。实现端负责对接 QQ 客户端，将 QQ 群事件推送给模块，同时接收模块发出的 Action 请求（如发送群消息、禁言等）。

### 支持的实现端

| 实现端 | 说明 |
|---|---|
| SnowLuma | 模块内置进程管理，推荐使用 |
| NapCat | 第三方 OneBot 实现，需手动启动 |
| Lagrange | 第三方 OneBot 实现，需手动启动 |

> 模块不限定实现端，只要兼容 OneBot 11 正向 WebSocket 协议即可连接。使用非 SnowLuma 实现端时，将 `onebot.snowluma.auto-start` 设为 `false`，手动启动实现端后模块会自动连接。

## OneBotClient 连接机制

`OneBotClient` 是模块的 WebSocket 客户端封装，负责连接管理、事件接收和 Action 调用。

### 连接流程

```
模块启动 (startService)
  │
  ├─ SnowLumaProcessManager.init()     ← 异步线程
  │    ├─ native: auto-start 时拉起子进程（优先内置 node 运行时）
  │    └─ docker: auto-install 时自动 pull + run 容器，auto-start 时启动已有容器
  │
  ├─ SnowLuma 已运行 → waitForPort(wsUrl, 8000ms) 等待 WS 端口就绪
  │
  ├─ SnowLuma 未运行 → 本机 ws 且端口无服务 → 打印部署引导
  │                    （未安装提示 install / 已安装提示 start；端口已有
  │                      NapCat 等服务或 ws 指向远程则不打扰）
  │
  └─ OneBotClient.start()              ← 始终启动，实现端就绪后自动重连
       ├─ probePort()                  ← TCP 端口探测（1秒超时）
       │    ├─ 端口不通 → 触发 onClose → scheduleReconnect
       │    └─ 端口可连 → WebSocketClient.connect()
       │
       └─ onOpen 回调
            ├─ 标记 connected = true
            ├─ 调用 onBotConnected()
            └─ 心跳由服务端推送，客户端无需主动发送
```

### 端口探测机制

模块在发起 WebSocket 连接前，先用独立 Socket 做一次 TCP connect（超时 1 秒）探测端口是否监听：

- **端口不通**：直接触发 `onClose` 回调进入重连调度，不调用 `super.run()`，避免 java-websocket 库内部 slf4j 打印 `ConnectException` 堆栈刷屏
- **端口可连**：正常进入 WebSocket 握手流程
- **URL 无法解析**：跳过探测，交由后续 connect 正常处理

> 端口探测与 WebSocket 连接在同一线程内执行，竞态窗口极小。

### 自动重连

连接断开后，模块按 `reconnect-interval-seconds`（默认 10 秒）间隔自动重连。重连日志采用分级抑制策略，避免刷屏：

| 阶段 | 日志行为 |
|---|---|
| 首次断开 | 打印完整告警（含 wsUrl、重连间隔） |
| 首次后 | 每隔 6 次重连失败打印一次摘要（含累计失败次数、已耗时秒数） |
| 连接成功 | 清零失败计数，重置告警标志 |

### 断开原因识别

`OneBotClient` 根据远端标志和最近异常信息推断断开原因：

| 原因常量 | 触发条件 |
|---|---|
| `远端关闭连接` | `remote = true`（服务端主动关闭） |
| `连接被拒绝（OneBot 服务未启动或地址端口错误）` | 异常信息包含 `Connection refused` |
| `连接超时` | 异常信息包含 `timeout` 或 `timed out` |
| `连接断开: <详情>` | 其他异常 |

## OneBot 事件处理

收到 WebSocket 消息后，`OneBotClient` 将 JSON 解析为 `OneBotEvent` 对象，回调给 `QQBotService.handleOneBotEvent()` 处理。

### OneBotEvent 支持的事件类型

| 事件类型 | 子类型 | 说明 |
|---|---|---|
| `message` | `group` | 群消息（指令处理、消息同步、自动回复） |
| `notice` | `group_increase` | 群成员增加（入群欢迎） |
| `notice` | `group_decrease` | 群成员减少 |
| `notice` | `group_ban` | 群禁言事件（禁言同步封禁） |
| `meta_event` | `heartbeat` | 心跳保活 |
| `meta_event` | `lifecycle` | 生命周期事件 |

### 消息段解析

OneBot 群消息可能以消息段数组形式发送，`OneBotEvent` 自动提取纯文本：

| 消息段类型 | 提取结果 |
|---|---|
| `text` | 提取 `data.text` 原文 |
| `at` | 提取为 `@<QQ号>` |
| `face` | 替换为 `[表情]` |
| `image` | 替换为 `[图片]` |
| `reply` | 忽略（回复引用） |
| 其他 | 替换为 `[<类型>]` |

`atQQs()` 方法可从消息段数组中提取被 @ 的 QQ 号列表，用于 @ 提示功能。

### 发送者信息

| 方法 | 说明 |
|---|---|
| `senderNickname()` | 发送者昵称 |
| `senderCard()` | 群名片（优先于昵称） |
| `senderRole()` | 群角色（`member` / `admin` / `owner`） |
| `isSenderAdmin()` | 是否为群管理或群主 |

## OneBot Action 调用

模块通过 WebSocket 发送 JSON 格式的 Action 请求到实现端：

| Action | 方法 | 说明 |
|---|---|---|
| `send_group_msg` | `sendGroupMessage(groupId, message)` | 发送纯文本群消息 |
| `send_group_msg`（消息段） | `sendGroupMessageAt(groupId, qqId, message)` | 发送 @ + 文本消息 |
| `delete_msg` | `deleteMessage(messageId)` | 撤回消息 |
| `set_group_ban` | `setGroupBan(groupId, qqId, durationSec)` | 禁言群成员 |

> 所有 Action 在未连接时静默忽略，不抛异常。`sendGroupMessageAt` 使用消息段数组形式发送，包含 `at` 段和可选的 `text` 段。

## SnowLuma 进程管理

`SnowLumaProcessManager` 负责管理 SnowLuma OneBot 实现端的生命周期，支持 native 和 docker 两种模式。

### Native 模式

本地 Node.js 子进程模式，适用于 Windows / Linux / macOS。

| 特性 | 说明 |
|---|---|
| 环境要求 | 完整版自带 Node 运行时，**零依赖解压即用**；lite 版需系统 Node.js 22.13+ / 23.4+ |
| 安装方式 | `/axs qqbot snowluma install`（从 GitHub 下载，优先完整版，实时推送下载进度） |
| 进程管理 | 自动启动 / 停止 / 清理残留进程 |
| 输出监控 | 独立守护线程读取 stdout，检测端口冲突等致命错误，并捕获 WebUI 初始密码 |
| JVM 钩子 | 注册 ShutdownHook 确保异常退出时清理进程 |

#### 启动流程

1. 检测 Node.js 环境（优先使用安装目录内置 `node`/`node.exe`；无内置运行时则检查 PATH `node --version`，要求 22.13+ / 23.4+）
2. 检查安装目录是否存在入口文件
3. 清理端口残留进程（WebUI 5099 + 配置的 WS 端口）
4. 构建 `ProcessBuilder` 直接以 `node index.mjs` 启动子进程（不经 launcher 脚本，避免批处理回显干扰与 pause 挂起）
5. 守护线程监控输出：词边界匹配告警/错误行转发到控制台，识别 `initial credentials`/`临时密码` 行并捕获保存
6. 等待 3 秒确认进程存活
7. 标记状态为 `RUNNING`；进程意外退出时自动降级为 `STOPPED` 并告警

#### WebUI 初始密码

SnowLuma 的 WebUI（默认 `http://127.0.0.1:5099`）首次启动时会在 stdout 打印一次 `admin` 账号的随机临时密码：

- **模块自动捕获**：识别密码行后打印到控制台，并保存到 `<安装目录>/webui-password.txt`
- **随时查询**：`/axs qqbot snowluma password`（docker 模式自动从 `docker logs` 提取）
- **注意**：临时密码未修改的情况下，SnowLuma 下次启动会重新生成新密码（捕获随之更新）；首次登录后请立即改密
- **固定密码**：可在 `onebot.snowluma.webui-password` 预设初始密码（仅首次初始化生效）
- **忘记密码**：停止 SnowLuma，删除 `<安装目录>/config/webui.json` 后重启将生成新临时密码

#### 残留进程清理

启动前和停止时，按端口查找并清理残留的 SnowLuma / Node 进程：

| 端口 | 来源 |
|---|---|
| 5099 | WebUI 固定端口 |
| 配置的 WS 端口 | 从 `onebot.ws-url` 解析得到 |

清理逻辑：
- Windows：`netstat -ano | findstr LISTENING` 查找 PID → `taskkill /F /T /PID` 终止进程树
- Linux：`lsof -ti:<port>` 查找 PID → `kill -TERM` → `kill -KILL` 兜底
- 仅清理命令行包含 `snowluma` / `node` / `index.js` 的进程，避免误伤

### Docker 模式

Docker 容器模式，推荐 Linux VPS 使用。

| 特性 | 说明 |
|---|---|
| 环境要求 | Docker 已安装 |
| 安装方式 | `docker pull` + `docker run`（自动挂载 3 个 volume，拉取进度实时推送） |
| 自动部署 | `docker.auto-install: true` 时模块启动发现容器不存在会自动 pull + run |
| 端口映射 | WebUI / WS / HTTP / noVNC 端口可配置 |
| 数据持久化 | 自动挂载 `data` / `qq-config` / `qq-data` 三个 volume |
| 日志查看 | `/axs qqbot snowluma logs`（`docker logs --tail 50`） |

#### Docker 容器创建参数

```yaml
docker run -d
  --name <container-name>
  --restart unless-stopped
  --shm-size=1g
  --cap-add=SYS_PTRACE
  --security-opt seccomp=unconfined
  -p <webui-port>:5099
  -p <http-port>:3000
  -p <ws-port>:3001
  -p <novnc-port>:6081        # 浏览器远程操作内嵌 QQ 客户端登录
  -e VNC_PASSWD=<vnc-password>                    # 仅在配置 vnc-password 时注入
  -e SNOWLUMA_WEBUI_BOOTSTRAP_PASSWORD=<webui-password>  # 仅在配置时注入
  -e SNOWLUMA_ACCEPT_EULA=1 -e SNOWLUMA_ACCEPT_PRIVACY=1 # 仅在 accept-agreements: true 时注入
  -v <container-name>-data:/app/data
  -v <container-name>-qq-config:/app/.config
  -v <container-name>-qq-data:/app/.local/share
  <image>
```

| `RUNNING` | 运行中 |

### SnowLuma 管理命令

通过 `/axs qqbot snowluma <子命令>` 管理：

| 子命令 | 说明 |
|---|---|
| `start` | 启动 SnowLuma（成功提示 WebUI 地址与密码获取方式） |
| `stop` | 停止 SnowLuma |
| `status` | 查看状态报告（容器名 / 镜像 / 版本 / Node / 运行状态 / WebUI / 安装进度） |
| `install` | 下载安装（异步执行，实时推送下载/拉取进度） |
| `logs` | 查看最近日志（仅 Docker 模式） |

### 实现端缺失提醒

模块启动时若检测到 **ws-url 指向本机且端口无服务监听**，会在控制台打印部署引导（区分「未安装」与「已安装未运行」两种情形），避免用户不知道需要安装 SnowLuma：

- 未安装 → 提示 `/axs qqbot snowluma install` + `start` + WebUI/密码查询步骤
- 已安装未运行 → 提示 `/axs qqbot snowluma start`
- ws-url 指向远程地址或本机端口已有服务（NapCat 等）→ 不打扰，直接走连接/重连流程

OneBot 断开告警也会根据实际情况附加 SnowLuma 状态提示（未安装 / 未运行的指引命令）。

## 异步启动设计

SnowLuma 启动和 WebSocket 连接在 **异步线程** 中执行，避免阻塞主线程触发 Paper 看门狗：

```
runTaskAsynchronously(plugin, () -> {
    if (closed) return;                    // 模块已关闭则跳过
    slm.init();                            // 初始化 SnowLuma（auto-start 拉起 / docker auto-install 部署）
    if (closed) {                          // 启动期间模块被关闭
        slm.shutdown();                    // 立即回收，避免孤儿进程
        obc.shutdown();
        return;
    }
    if (running) {                         // SnowLuma 已运行
        waitForPort(wsUrl, 8000);          // 等待端口就绪
        if (closed) { slm.shutdown(); obc.shutdown(); return; }
        obc.start();                       // 连接 OneBot
        return;
    }
    // SnowLuma 未运行：本机 ws 且端口无服务 → 打印部署引导；
    // 其他实现端在跑 / 远程 ws → 不打扰
    if (localWs && !probePort(wsUrl, 800)) logOneBotSetupGuide(slm);
    obc.start();                           // 始终启动客户端，实现端就绪后自动重连
});
```

> `closed` 标志位防止异步启动期间模块被关闭导致孤儿进程。若启动期间模块被关闭，立即回收 SnowLuma 进程和 WebSocket 客户端。

## 配置参考

```yaml
onebot:
  # OneBot 正向 WebSocket 地址
  ws-url: "ws://127.0.0.1:3001"
  # 鉴权 token（留空表示不鉴权）
  access-token: ""
  # 断线重连间隔（秒）
  reconnect-interval-seconds: 10
  # 心跳间隔（秒，服务端主动推送，此参数保留兼容）
  heartbeat-interval-seconds: 30
  snowluma:
    # 运行模式: native / docker
    mode: "native"
    # 安装目录（相对于服务端根目录，仅 native 模式）
    dir: "snowluma"
    # 模块启动时自动启动 SnowLuma
    auto-start: false
    # WebUI 初始密码（可选，仅首次初始化生效；留空则随机生成临时密码）
    webui-password: ""
    # 自动同意 SnowLuma EULA 与隐私协议
    accept-agreements: false
    docker:
      container-name: "snowluma"
      image: "motricseven7/snowluma:latest"
      webui-port: 5099
      ws-port: 3001
      http-port: 3000
      # noVNC 网页远程桌面端口（浏览器操作内嵌 QQ 客户端登录用）
      novnc-port: 6081
      # VNC/noVNC 访问密码（可选）
      vnc-password: ""
      auto-install: false
```

### 配置字段说明

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `ws-url` | string | `"ws://127.0.0.1:3001"` | OneBot WebSocket 地址 |
| `access-token` | string | `""` | 鉴权 token（通过 `Authorization: Bearer` 头发送） |
| `reconnect-interval-seconds` | int | `10` | 重连间隔（秒） |
| `heartbeat-interval-seconds` | int | `30` | 心跳间隔（保留兼容，实际由服务端推送） |
| `snowluma.mode` | string | `"native"` | `native` 或 `docker` |
| `snowluma.auto-start` | boolean | `false` | 模块启动时自动拉起 SnowLuma |
| `snowluma.webui-password` | string | `""` | WebUI 初始密码（仅首次初始化生效，留空随机生成） |
| `snowluma.accept-agreements` | boolean | `false` | 自动同意 EULA 与隐私协议 |

> WS 端口从 `ws-url` 自动解析，用于 SnowLuma 残留进程清理。修改端口时清理逻辑会跟随配置，而非写死 3001。

## 故障排查

| 现象 | 可能原因 | 解决方案 |
|---|---|---|
| 连接被拒绝 | OneBot 实现端未启动 | 启动实现端后执行 `/axs reload qqbot` |
| 连接超时 | 防火墙拦截或地址错误 | 检查 `ws-url` 和防火墙规则 |
| SnowLuma 启动失败 | Node.js 缺失或版本过低 | 执行 `/axs qqbot snowluma install` 安装完整版（自带运行时），或安装 Node.js 22.13+ 后 `/axs reload qqbot` |
| 不知道 WebUI 密码 | 临时密码只在首次启动打印一次 | 执行 `/axs qqbot snowluma password` 查看；忘记密码可删除 `snowluma/config/webui.json` 后重启生成新密码 |
| WebUI 显示协议确认页 | 首次启动需同意 EULA/隐私协议 | 在 WebUI 页面点击同意，或设 `snowluma.accept-agreements: true` |
| 端口冲突 | 其他进程占用 5099/3001 | 模块会自动清理残留，或手动终止占用进程 |
| 频繁断开重连 | 实现端不稳定 | 检查实现端日志，适当增大 `reconnect-interval-seconds` |

> 开启 `settings.debug: true` 可查看 OneBot 事件和 WebSocket 异常详情（堆栈降级为 FINE 调试级）。
