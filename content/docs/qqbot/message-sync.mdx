## 同步方向

| sync-mode | 游戏到QQ | QQ到游戏 |
| --- | --- | --- |
| both | 是 | 是 |
| game-to-qq | 是 | 否 |
| qq-to-game | 否 | 是 |
| none | 否 | 否 |

none 可保留群指令和通知。普通玩家的面板、send、at 仅发往允许游戏到 QQ 的配置群。管理员明确发送可选择其他配置群。

## 游戏消息

有 Chat 模块时，QQBot 接收经过 Chat 校验的公开全服消息。私聊、管理频道、范围频道以及限制接收者的消息不会外发。不要用 QQ 同步替代频道访问控制。

无 Chat 时默认不监听原版聊天。需要时设置：

~~~yaml
delivery:
  max-message-length: 300
  player-cooldown-seconds: 3
  group-messages-per-minute: 30
  require-binding: false
  vanilla-chat-fallback: true
~~~

原版 fallback 只接受未取消的聊天事件，仍检查准入、发送权限、方向及限流。安装 Chat 后使用公开频道接入，不会同时重复转发。

玩家也可 /qqbot send 消息，或打开 /qqbot 的消息中心，输入文本后发送。中心展示最近 10 条群消息和自己的发送结果。@ 使用 /qqbot at QQ号 消息，默认 OP 权限、10 秒冷却。

## 回执与预算

所有出口共用每群发送预算，包括玩家、管理员、群回复、定时消息和业务广播。超出预算、无可发送群、长度过长或连接断开都会返回明确结果。

“已发送”依据实现端动作成功回执；它不证明每个群成员已经阅读。超时或断线时可能结果未知：先查看 QQ 群和实现端日志，不自动重发、不连续点击。多群发送可以部分成功，应按每群结果处理。

## 群消息到游戏

机器人账号需加入配置群，OneBot 适配器需为 Universal。普通文字按 qq-to-game 模板展示，CQ/非文字段不会当作 Minecraft 指令执行。黑名单及功能开关影响处理。

~~~yaml
groups:
  - group-id: 123456789
    sync-mode: "both"
    game-to-qq: "[{server}] {player}: {message}"
    qq-to-game: "&7[QQ] &f{nick}: &7{message}"
    commands-enabled: true
    join-message: ""
    quit-message: ""
~~~

进退服文本空时关闭，非空可使用 `{player}`、`{online}`、`{max}`。模板变量不等于 PlaceholderAPI，按对应字段支持范围填写。

## 通知示例

关键词回复适合服务器地址、绑定方式等常见问题：

~~~yaml
auto-reply:
  enabled: true
  cooldown-seconds: 30
  rules:
    - keywords: ["服务器地址", "怎么进服"]
      exact-match: false
      response: "地址: play.example.com\n首次使用请先创建游戏账号，再发送 #绑定 <游戏名>"
welcome:
  enabled: true
  message: "欢迎加入！发送 #帮助 查看指令。"
~~~

定时消息默认空列表，明确配置后才发送。daily-time 使用服务器系统时区：

~~~yaml
scheduled-messages:
  - id: "signin-reminder"
    mode: "daily"
    daily-time: "12:00"
    target-groups: [123456789]
    message: "今天别忘了 #签到。在线 {online}/{max}"
~~~

monitor 可按 TPS/内存阈值告警，设置 check-interval-seconds 和 cooldown-seconds。broadcast.kill/death、market-broadcast 需要按场景明确开启。

公告、踢人、封禁、群禁言同步和自动审核均属于管理功能。先在测试群验证命令模板及账号权限，再启用；机器人在 QQ 中没有管理权限时，撤回或禁言动作会失败，应检查动作回执。
