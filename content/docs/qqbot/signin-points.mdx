每个 QQ 对应一个积分账户。签到、积分转账和红包使用 QQBot 存储，日期按服务端系统时区计算。

积分、红包和兑换审计按 QQ 归属。删除游戏角色不会清除 QQ 资产；解绑或更换游戏角色也不会自动清空这些记录。

## 签到

~~~yaml
signin:
  enabled: true
  base-points: 10
  streak-bonus: 2
  max-streak-bonus: 50
  sign-prefix: "#签到"
  aliases: ["#打卡"]
  shop-prefix: "#商店"
  redeem-prefix: "#兑换"
  points-query-prefix: "#积分"
  transfer-prefix: "#转账"
  red-packet-prefix: "#红包"
  grab-red-packet-prefix: "#抢红包"
  activity-prefix: "#活跃排行"
~~~

每日积分 = base-points + min((连续天数 - 1) × streak-bonus, max-streak-bonus)。上例首日 10 分、第二天 12 分；昨天未签到则重置连续天数。当天重复请求不会再次发分。

#积分 查询余额及累计收支；#积分榜 查询当前余额 Top10。周日 23:59 播报的是当前余额榜，不清空积分，也不是本周赚取积分排行。重启不会补发错过的历史周榜。

## 兑换奖品

默认 prizes 为空。先安装 Mail，创建并验证预设，例如 qqbot_diamond，确认它确实能向测试玩家发送 10 颗钻石，再添加：

~~~yaml
prizes:
  - id: "diamond"
    name: "钻石礼包"
    cost: 100
    description: "10 颗钻石"
    mail:
      presets: ["qqbot_diamond"]
    require-bind: true
    limit-per-day: 1
    discount-rate: 1.0
    discount-until: 0
~~~

| 字段 | 作用 |
| --- | --- |
| id | 稳定唯一 ID，忽略大小写；修改显示名不应换 ID |
| name / description | 商店展示 |
| cost | 原价积分 |
| mail.presets | 1–100 个真实 Mail 预设 ID，逐项跟踪发放 |
| limit-per-day | 当日每 QQ 限购；0 不限 |
| discount-rate | 折扣比例，0.8 为八折 |
| discount-until | 折扣截止 Unix 毫秒时间戳，0 不折扣 |

当前兑换始终要求宿主绑定；旧 require-bind:false 不能跳过，因为邮件需要确定的游戏收件账号。有效折扣价为 max(1, ceil(cost × discount-rate))。

玩家 #商店 查看、#兑换 diamond 下单。系统先原子扣款并占限购，再发邮件。每笔订单记录逐项状态；同一奖品存在未结案订单时不能重复下单。

## 发送异常的处理

| 结果 | 积分与限购 | 操作 |
| --- | --- | --- |
| 所有邮件明确成功 | 保留扣款和限购，结案 | 到游戏查邮件 |
| 所有邮件明确失败 | 自动退款并释放限购 | 修好预设后再兑换 |
| 部分成功、结果未知、处理中断 | 保留扣款与额度，待复核 | 管理员查订单及 Mail 记录 |

超时不是明确失败，不能据此自动重发或全额退款。发放节点使用心跳租约，其他健康节点的在途订单不会被重启节点抢占。当前节点关闭时冻结遗留订单；异常崩溃时在租约过期后冻结，通常最多约 70 秒。仍在发放的订单不能人工处理，冻结后再独立核对，不自动重发。管理员使用：

~~~text
/axs qqbot redemptions list 20
/axs qqbot redemptions get 兑换ID
/axs qqbot redemptions resolve 兑换ID delivered confirm 已核对并补齐全部邮件
/axs qqbot redemptions resolve 兑换ID not-delivered confirm 已独立核实所有预设均未发送
~~~

delivered 在核对并补齐发放后保留扣款结案。not-delivered 仅在全部未发送时退款；任何项已确认 SENT 时拒绝整单退款。备注需 4–500 字，保留核对依据。

## 转账与红包

#转账 QQ号 积分 在两个账户间转移积分。#红包 总积分 份数 先扣款并创建拼手气红包，#抢红包 红包ID 领取；总积分和份数必须大于零，份数不能大于积分。

每个 QQ 对同一红包只能领取一次。红包创建 24 小时后过期，模块定期把未领完部分退给发送者。重复检查不会重复退款。关闭签到功能时不再处理这些签到积分指令。

## 首次验证

1. 测试 QQ #签到，记录余额，再重复签到，余额不应再次增加。
2. 使用真实奖品兑换一次，核对订单、扣款和游戏邮件。
3. 达到每日限购后再次兑换，应拒绝。
4. 用测试预设模拟明确失败，确认全部失败才退款。
5. 对未知/中断订单按复核流程核对，勿反复下单或重发。
