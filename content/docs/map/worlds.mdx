# 世界与地图渲染

## 概述

Map 模块的世界配置与地图画面完全解耦：**地图地形由 Arcart-Suite-Map 客户端 mod 扫描客户端区块实时渲染**，服务端不需要、也不再支持地图纹理图片配置（`texture`/`image-width`/`pixel-offset-x` 等旧字段已废弃）。

服务端只负责：

- 告诉 mod 当前要渲染哪个世界（`worldId`）以及它对应的 MC 维度 key
- 下发已点亮区域（战争迷雾数据）
- 下发标点列表（锚点/路径点/标记点/第三方插件注册路径点）与详情数据

mod 侧负责：区块地形扫描、地图纹理生成、缩放/平移/形状交互、标点与玩家箭头绘制、探索缓存落盘。

| 场景 | UI | 说明 |
|---|---|---|
| 全屏大地图 | `map_menu.yml` | 世界切换、滚轮缩放、拖拽平移、单击放置标记点 |
| 小地图 HUD | `map_hud.yml` | 右上角常驻，圆形/方形切换，实时显示玩家位置与朝向 |

> mod 未安装时渲染区保持空白，UI 的列表、详情面板、解锁、传送、分享等功能不受影响。

## 世界配置

### 目录结构

每个世界一个独立文件，放在 `data/map/worlds/` 目录下（目录名由 `worlds-directory` 配置，默认 `worlds`），**文件名即世界 ID**（对应 Bukkit world name，大小写不敏感）：

```
data/map/
  ArcartXMap.yml
  worlds/
    world.yml            ← 世界 ID = world
    bskyblock_world.yml  ← 世界 ID = bskyblock_world
```

模块启动时按文件名字母顺序加载目录下所有 `.yml` 文件。目录不存在时自动创建并导出示例文件 `worlds/world.yml`。

### 字段说明

```yaml
# worlds/world.yml — 文件名即世界 ID
enabled: true
display-name: ""

anchors:
  spawn:
    enabled: true
    display-name: "出生点"
    x: 0
    y: 64
    z: 0
    description: "默认出生点锚点。"
    permission: ""
    sort-order: 0
    unlock:
      default: true
      on-permission: false
    unlock-currencies: []
    teleport-currencies: []
    unlock-items: []
    # light-region:
    #   points: [[-50, -50], [50, -50], [50, 50], [-50, 50]]
    # light-radius: 100
```

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enabled` | `boolean` | `true` | 是否在地图菜单中显示此世界 |
| `display-name` | `String` | `""` | 显示名称；留空时运行时从 Multiverse-Core colourless alias 自动补 |
| `anchors` | `Map` | — | 该世界的锚点列表（见 [锚点系统](./anchors)） |

<Callout type="info">
维度（dimension）完全自动按 Bukkit `world.getKey()` 解析下发给客户端 mod，无需配置。旧版本的 `texture`、`image-width/height`、`pixel-offset-x/z`、`default-zoom`、`hud-zoom`、`hud-size` 字段已全部废弃——缩放与偏移由玩家在客户端用鼠标滚轮/拖拽实时控制。
</Callout>

### 世界选择逻辑

当玩家打开地图或 HUD 时，服务端按以下优先级确定初始世界：

| 优先级 | 条件 | 说明 |
|---|---|---|
| 1 | 玩家请求指定世界 ID | 若该世界已配置则使用，否则返回空 |
| 2 | 玩家视图状态中已选中的世界 | `MapPlayerViewState.selectedWorldId` 非空且已配置 |
| 3 | 玩家当前所在的世界 | `player.getWorld().getName()` 对应的世界 ID 已配置 |
| 4 | 配置中的第一个世界 | `worlds` 映射的第一个条目 |

> 若以上条件均不满足，地图菜单返回「当前世界未配置地图，且没有可用的默认地图」，HUD 返回「当前没有可显示的小地图世界」。

### 旧格式兼容

若 `worlds/` 目录为空或不存在世界文件，模块回退读取 `ArcartXMap.yml` 中的内联 `worlds` 节（仅取 `enabled`/`display-name`，纹理字段被忽略）：

```yaml
# ArcartXMap.yml — 旧格式降级，不推荐
worlds:
  world:
    enabled: true
    display-name: "主世界"
```

> 内联 `worlds` 节不含 `anchors`——锚点必须写在 `worlds/<worldId>.yml` 的 `anchors` 节中。

## 点亮区域（战争迷雾）

锚点可配置点亮区域：玩家解锁该锚点后，小地图上对应区域从迷雾中亮起。未点亮的区域由 mod 渲染遮罩。

每个锚点支持两种写法（可同时配置，任一生效即可）：

| 字段 | 格式 | 说明 |
|---|---|---|
| `light-region.points` | `[[x,z], ...]` | 多边形顶点列表（至少 3 点），世界坐标 |
| `light-radius` | 数值 | 以锚点为中心的圆形点亮半径（方块数） |

```yaml
anchors:
  spawn:
    # ...
    light-region:
      points: [[-50, -50], [50, -50], [50, 50], [-50, 50]]
    light-radius: 100
```

服务端把已解锁锚点的点亮区域并集通过 HUD 快照的 `litRegions` 字段下发；UI 调用 `mapRenderer.setLitRegions(worldId, regions)` 传给 mod。不配置任何点亮字段 = 该锚点不参与点亮。

## 渲染流程

### 全屏地图渲染

```
MapService.syncMenu()
  └→ MapSnapshotBuilder.build()
       └→ 菜单快照（世界列表 + 锚点/路径点/标记点/第三方插件注册路径点 + 点亮区域 + 详情）
  └→ PacketBridgeAPI.sendPacket(menuUiId, "init"/"update", payload)
       └→ 客户端 UI packetHandler 接收数据
            └→ axsmap.getMapRenderer() 获取 MapRenderer（懒加载缓存）
            └→ setWorldId(worldId) / setWorldDimension(worldId, dimension)
            └→ setLitRegions(worldId, litRegions)
            └→ tick 每帧 setRegion(x, y, w, h, scale) 传地图渲染区屏幕坐标
            └→ syncMarkers() → clearMarkers() + addMarker(...) 同步标点
```

### 小地图 HUD 渲染

```
MapService.syncHud()
  └→ HudSnapshot（visible + worldId + dimension + litRegions + playerYaw + trackingText）
  └→ PacketBridgeAPI.sendPacket(hudUiId, "init"/"update", payload)
       └→ 客户端 UI packetHandler 接收数据
            └→ axsmap.getMapRenderer() 获取 MapRenderer
            └→ setWorldId / setWorldDimension / setLitRegions
            └→ tick 每帧 setHudAnchor(anchorX, anchorY, scale) 传右上角锚点
                 └→ mod 按内部 hudSize 状态计算渲染区域，绘制圆形/方形小地图
```

### mod 渲染细节

| 环节 | 说明 |
|---|---|
| 地形扫描 | mod 监听客户端区块加载（`ClientChunkEvents.CHUNK_LOAD`），把区块列标记为待扫描，避免已探索区域显示黑色空洞 |
| 缓存落盘 | 断开连接时把各维度扫描结果写入 `arcartsuitemap/<维度>.dat`，下次进服跨世界查看大地图可直接显示已探索地形 |
| 圆形遮罩 | 小地图圆形遮罩在 mod CPU 端生成视图纹理时应用，含 1px 抗锯齿与圆形描边 |
| 世界名/坐标 | 由 `map_hud.yml` 的 Text 控件渲染：世界名走 `Placeholder.parse("%multiverse-core_alias%")`，坐标用 `Player.getPosX/Y/Z` 本地实时取 |
| 看门狗 | HUD 停止调用 `setHudAnchor` 超过约 150ms 时 mod 自动停用渲染；UI `close` 时也主动调 `closeHud()` |

### 小地图客户端按键

小地图形状与大小由玩家在客户端用按键调整（mod 的 `MapInputHandler` 处理）：

| 按键 | 作用 |
|---|---|
| `[` | 切换圆形 / 方形小地图 |
| `+` / `-` | 调整小地图尺寸 |
| `,` / `.` | 调整小地图缩放 |

### 大地图交互

`MapInputHandler` 处理全屏地图的鼠标交互：滚轮缩放、拖拽平移、单击放置标记点（Pin）。

## 标点同步

地图菜单的锚点、路径点、标记点和第三方插件注册路径点通过 `syncMarkers()` 同步到客户端 mod：

```
packetHandler init/update
  └→ syncMarkers()
       └→ MapRenderer.clearMarkers()
       └→ 遍历 anchorRows        → addMarker(id, 'anchor',   displayName, x, z, selected, tracked, unlocked)
       └→ 遍历 waypointRows      → addMarker(id, 'waypoint', name,        x, z, selected, tracked, true)
       └→ 遍历 externalTargetRows→ addMarker(id, 'external', name,        x, z, selected, tracked, true)
       └→ 遍历 pinRows           → addMarker(id, 'pin',      name,        x, z, selected, false,   true)
```

`addMarker()` 参数：`id` / `type`（`anchor`/`waypoint`/`external`/`pin`）/ `name` / 世界坐标 `x,z` / `selected` / `tracked` / `unlocked`（仅锚点有意义）。

> 标点使用世界坐标，mod 根据当前缩放和视野中心自行计算标点在屏幕上的位置。

## 多世界切换

1. 玩家在地图菜单点击世界列表项，UI 发送 `open_world` Packet
2. `MapService.openWorld()` 验证世界是否已配置
3. 更新 `MapPlayerViewState.selectedWorldId`，同时清除锚点/路径点/标记点/第三方插件注册路径点的选中状态
4. 调用 `sync()` 重新构建快照并推送 `update` Packet
5. UI 调用 `setWorldId()` + `setWorldDimension()` 通知 mod 切换到对应维度渲染

### 世界列表排序

世界列表按 `worlds/` 目录文件名加载顺序排列（文件名字母序）。菜单 UI 使用水平滚动列表展示世界项，每项显示世界名称和选中状态。
