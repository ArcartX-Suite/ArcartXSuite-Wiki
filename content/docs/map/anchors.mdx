# 锚点系统

## 概述

锚点是 Map 模块的核心功能之一，表示地图上可解锁、可传送的标记点。每个锚点绑定一个世界坐标，玩家可通过消耗货币和物品解锁锚点，解锁后可消耗货币传送到锚点位置。

锚点功能涉及以下组件：

| 组件 | 类 | 职责 |
|---|---|---|
| 锚点定义 | `AnchorDefinition` | 配置层，描述锚点的坐标、费用、权限等 |
| 锚点存储 | `JdbcMapRepository` | 持久化锚点解锁记录到 `AXS_map_unlocks` 表 |
| 解锁逻辑 | `MapService.unlockAnchorInternal()` | 费用检查、原子插入、回滚机制 |
| 传送逻辑 | `MapService.teleportAnchorInternal()` | 权限校验、货币消耗、Bukkit 传送 |
| 费用格式化 | `MapService.formatUnlockCostText()` | 生成 UI 显示的费用文本 |

> 锚点定义存储在 `data/map/anchors/` 目录下的 YAML 文件中，`anchors` 节在 `configSpec()` 中声明为 `dynamicSection`，用户可自由增删锚点条目。

## 锚点定义

### 文件结构

锚点定义文件位于 `data/map/anchors/` 目录，每个 `*.yml` 文件可包含多个锚点，根键即为锚点 ID。模块启动时按文件名字母顺序加载目录下所有 `.yml` 文件。

```yaml
# data/map/anchors/default.yml
spawn:
  enabled: true
  display-name: "新手村"
  world: "world"
  x: 0
  y: 80
  z: 0
  description: "所有玩家默认可见的主城锚点。"
  permission: ""
  sort-order: 0
  unlock-currencies: []
  teleport-currencies:
    - currency: "money"
      amount: 10
  unlock-items: []

mine:
  enabled: true
  display-name: "矿洞入口"
  world: "world"
  x: 128
  y: 64
  z: -42
  description: "示例锁定锚点，演示货币 + 物品解锁。"
  permission: ""
  sort-order: 10
  unlock-currencies:
    - currency: "money"
      amount: 200
    - currency: "points"
      amount: 5
  teleport-currencies:
    - currency: "money"
      amount: 30
  unlock-items:
    - amount: 2
      matcher:
        material-ids:
          - "ender_pearl"
```

### 字段说明

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enabled` | `boolean` | `true` | 是否启用此锚点 |
| `display-name` | `String` | 锚点 ID | 在地图上显示的名称 |
| `world` | `String` | `""` | 所在世界名（对应 Bukkit world name，不区分大小写） |
| `x` / `y` / `z` | `double` | `0` | 锚点在世界中的坐标 |
| `description` | `String` | `""` | 锚点描述文本，显示在详情面板 |
| `permission` | `String` | `""` | 使用此锚点所需权限（留空 = 无限制） |
| `sort-order` | `int` | 当前锚点数 | 排序权重（越小越靠前） |
| `unlock-currencies` | `List` | `[]` | 解锁需消耗的货币列表 |
| `teleport-currencies` | `List` | `[]` | 传送需消耗的货币列表 |
| `unlock-items` | `List` | `[]` | 解锁需消耗的物品列表 |

> 锚点 ID 不区分大小写，内部统一转换为小写存储。同一个锚点 ID 在不同文件中定义时，后加载的文件会覆盖先加载的。

### 锚点目录

锚点目录路径通过 `ArcartXMap.yml` 的 `anchors-directory` 配置项指定（默认 `anchors`），相对模块数据目录 `data/map/`。

模块启动时检查目录是否存在，不存在则自动创建并导出默认锚点文件 `default.yml`。若目录下已有 `.yml` 或 `.yaml` 文件，则不再导出默认文件。

## 解锁机制

### 解锁流程

```
玩家点击「解锁」按钮
  └→ UI 发送 unlock_anchor Packet（含 action_token）
       └→ MapUiPacketHandler.beginActionToken() 校验 token
       └→ MapService.unlockAnchorInternal()
            1. 验证锚点存在且未已解锁
            2. 验证权限与世界配置
            3. 预检物品消耗（prepareItemConsumption）
            4. 原子插入解锁记录（tryUnlockAnchor）
            5. 扣除货币（chargeCurrencies）
            6. 扣除物品（applyItemConsumption）
            7. 若任一步骤失败，按序回滚
            8. 刷新 UI
```

### 解锁条件检查

| 检查项 | 失败消息 | 说明 |
|---|---|---|
| 锚点是否存在 | `未找到锚点: {0}` | 锚点 ID 在配置中不存在 |
| 是否已解锁 | `该锚点已解锁。` | 玩家已解锁过此锚点 |
| 权限检查 | `你没有使用该锚点的权限。` | `permission` 字段非空且玩家无权限 |
| 世界配置 | `锚点所在世界未配置地图: {0}` | 锚点的 `world` 不在 `worlds` 配置中 |
| 物品预检 | `缺少解锁所需物品。` | 背包中匹配物品不足 |
| 货币余额 | `余额不足: {0}` | 货币余额低于解锁费用 |
| 货币桥接 | `货币桥接不可用: {0}` | 货币系统未安装或不可用 |
| 数据库写入 | `写入锚点解锁数据失败。` | 解锁记录写入数据库失败 |

### 原子性与回滚

解锁操作采用「先记录后扣费」策略，确保数据一致性：

| 步骤 | 操作 | 失败时回滚 |
|---|---|---|
| 1 | 预检物品消耗 | 无需回滚（仅检查未实际扣除） |
| 2 | 原子插入解锁记录 | `tryUnlockAnchor` 使用 `INSERT OR IGNORE` / `INSERT IGNORE`，已解锁时返回 `false` |
| 3 | 扣除货币 | 回滚步骤 2：`removeUnlock` 删除解锁记录 |
| 4 | 扣除物品 | 回滚步骤 3：`rollbackCurrencies` 退还货币；回滚步骤 2：`removeUnlock` |

> 物品消耗使用「快照 + 差量」机制：先克隆背包内容，计算各槽位扣除量，最后一次性更新背包。失败时恢复原始背包快照。

### 解锁费用文本

UI 详情面板显示的解锁费用文本由 `formatUnlockCostText()` 生成：

| 费用类型 | 格式 | 示例 |
|---|---|---|
| 仅货币 | `货币名 x数量` | `金币 x200` |
| 多货币 | `货币名1 x数量 + 货币名2 x数量` | `金币 x200 + 点券 x5` |
| 仅物品 | `物品条件 x数量` | `物品条件 x2` |
| 货币 + 物品 | `货币名 x数量 + 物品条件 x数量` | `金币 x200 + 物品条件 x2` |
| 无费用 | `免费解锁` | — |

> 货币显示名来自 `CurrencyBridge.definition().displayName()`。货币金额使用 `BigDecimal.setScale(2, RoundingMode.DOWN)` 保留两位小数并去除尾随零。

## 传送机制

### 传送流程

```
玩家点击「传送」按钮
  └→ UI 发送 teleport_anchor Packet（含 action_token）
       └→ MapUiPacketHandler.beginActionToken() 校验 token
       └→ MapService.teleportAnchorInternal()
            1. 验证锚点存在且已解锁
            2. 验证权限与世界配置
            3. 检查目标世界是否已加载
            4. 扣除传送货币
            5. 执行 Bukkit 传送
            6. 若传送失败，回滚货币
            7. 刷新 UI
```

### 传送条件检查

| 检查项 | 失败消息 | 说明 |
|---|---|---|
| 锚点是否存在 | `未找到锚点: {0}` | 锚点 ID 在配置中不存在 |
| 是否已解锁 | `该锚点尚未解锁。` | 玩家未解锁此锚点 |
| 权限检查 | `你没有使用该锚点的权限。` | `permission` 字段非空且玩家无权限 |
| 世界配置 | `锚点所在世界未配置地图: {0}` | 锚点的 `world` 不在 `worlds` 配置中 |
| 世界加载 | `目标世界当前未加载: {0}` | `Bukkit.getWorld()` 返回 `null` |
| 货币余额 | `余额不足: {0}` | 货币余额低于传送费用 |
| 传送执行 | `传送失败，请稍后重试。` | `Player.teleport()` 返回 `false` |

### 传送坐标

传送目标坐标为锚点定义的 `x` / `y` / `z`，保留玩家当前的 `yaw` 和 `pitch`：

```java
new Location(world, anchor.x(), anchor.y(), anchor.z(),
    player.getLocation().getYaw(), player.getLocation().getPitch())
```

### 传送费用文本

传送费用文本由 `formatTeleportCostText()` 生成，格式与解锁费用相同但仅包含货币（传送不支持物品消耗）：

| 费用类型 | 格式 | 示例 |
|---|---|---|
| 有货币 | `货币名 x数量` | `金币 x10` |
| 多货币 | `货币名1 x数量 + 货币名2 x数量` | `金币 x10 + 点券 x1` |
| 无费用 | `免费传送` | — |

## 货币消耗

### 货币配置

```yaml
unlock-currencies:
  - currency: "money"
    amount: 200
  - currency: "points"
    amount: 5
```

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `currency` | `String` | 非空，小写 | 货币 ID（通过 `CurrencyBridgeAPI` 解析） |
| `amount` | `BigDecimal` | 必须 `> 0` | 消耗金额 |

> 货币 ID 不区分大小写，内部统一转换为小写。`amount` 为 0 或负数的条目会被忽略。

### 扣费流程

1. **余额检查**：遍历所有货币费用，检查对应 `CurrencyBridge` 是否可用且余额充足
2. **逐笔扣除**：按顺序调用 `bridge.withdraw(player, amount)` 扣除每笔货币
3. **失败回滚**：任一笔扣除失败时，已成功扣除的货币通过 `bridge.deposit()` 退还

| 失败场景 | 消息 | 回滚 |
|---|---|---|
| 桥接不可用 | `货币桥接不可用: {0}` | 已扣除的货币退还 |
| 余额不足 | `余额不足: {0}` | 未开始扣除 |
| 扣费失败 | `扣费失败: {0}` 或桥接返回的消息 | 已扣除的货币退还 |

> 货币系统通过 `CurrencyBridgeAPI` 桥接，支持 Vault、PlayerPoints 等。参考 /docs/guide/conditions 了解货币条件配置。

## 物品消耗

### 物品配置

```yaml
unlock-items:
  - amount: 2
    matcher:
      material-ids:
        - "ender_pearl"
```

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `amount` | `int` | 最小 1 | 消耗数量 |
| `matcher` | `ItemMatcher` | 非空匹配器 | 物品匹配器配置 |

> 物品匹配器配置参考 /docs/guide/item-sources 中的物品匹配器语法。空匹配器（`emptyMatcher() == true`）的条目会被忽略。

### 物品消耗机制

物品消耗采用「预检 + 快照 + 差量」三步机制：

| 阶段 | 操作 | 说明 |
|---|---|---|
| 预检 | `prepareItemConsumption()` | 克隆背包，遍历所有匹配器计算各槽位扣除量，不足时返回失败 |
| 扣除 | `applyItemConsumption()` | 根据差量数组更新背包，`setStorageContents()` 一次性写入 |
| 回滚 | `rollbackItemConsumption()` | 恢复预检阶段保存的原始背包快照 |

> 物品匹配通过 `ItemMatcherAPI.matches()` 完成，支持 `material-ids`、`name-contains`、`lore-contains` 等匹配条件。

## 权限控制

### 锚点权限

每个锚点可通过 `permission` 字段设置使用权限：

| 配置 | 效果 |
|---|---|
| `permission: ""` | 无权限限制，所有玩家可使用 |
| `permission: "arcartxsuite.map.vip"` | 仅拥有该权限的玩家可解锁和传送 |

权限检查在解锁和传送操作中均会执行。无权限时提示「你没有使用该锚点的权限」。

### 路径点上限权限

路径点数量上限通过 `waypoints.limits` 按权限区分：

```yaml
waypoints:
  default-max-count: 5
  limits:
    - permission: "ArcartXSuite.map.admin"
      max-count: 20
```

最终上限取 `default-max-count` 与所有匹配权限的 `limits` 中的最大值。

| 权限节点 | 默认 | 说明 |
|---|---|---|
| `arcartxsuite.map.use` | 所有玩家 | 使用 `/map` 玩家命令的权限 |
| `arcartxsuite.map.admin` | 管理员 | 路径点上限提升权限 |

## 默认解锁

### 配置

拥有指定权限的玩家在进服时自动解锁对应锚点：

```yaml
default-unlocks:
  - permission: "ArcartXSuite.map.use"
    anchors:
      - "spawn"
  - permission: "ArcartXSuite.map.vip"
    anchors:
      - "spawn"
      - "vip_hall"
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `permission` | `String` | 所需权限节点（非空时生效） |
| `anchors` | `List<String>` | 自动解锁的锚点 ID 列表 |

### 触发时机

默认解锁在客户端初始化完成时触发（`ClientInitializedHandler`）：

1. 玩家客户端初始化完成
2. `MapService.handleClientInitialized()` 调用 `ensureDefaultUnlocks()`
3. 遍历 `default-unlocks` 规则，检查玩家权限
4. 对匹配规则的锚点，检查是否已解锁，未解锁则调用 `repository.unlockAnchor()` 写入记录
5. 若有新解锁的锚点，刷新玩家数据缓存

> 默认解锁使用 `defaultUnlocksEnsured` 集合确保每个玩家在一次会话中只执行一次。玩家退出重进后会重新执行。

### 默认解锁示例

| 配置 | 效果 |
|---|---|
| `permission: "ArcartXSuite.map.use"` + `anchors: ["spawn"]` | 所有拥有基础使用权限的玩家进服自动解锁 `spawn` 锚点 |
| `permission: "ArcartXSuite.map.vip"` + `anchors: ["spawn", "vip_hall"]` | VIP 玩家进服自动解锁 `spawn` 和 `vip_hall` 锚点 |

> 默认解锁不扣除任何费用。若锚点已解锁，重复执行不会产生重复记录（`tryUnlockAnchor` 使用 `INSERT OR IGNORE`）。

## 锚点排序

### 排序规则

锚点在地图菜单中的排序由 `sort-order` 字段控制，排序逻辑在 `MapSnapshotBuilder.build()` 中实现：

1. 先按 `sortOrder` 升序排列
2. 相同 `sortOrder` 的锚点按 `displayName` 字母顺序排列（不区分大小写）

```java
visibleAnchors.stream()
    .sorted(Comparator
        .comparingInt(AnchorView::sortOrder)
        .thenComparing(AnchorView::displayName, String.CASE_INSENSITIVE_ORDER))
    .toList()
```

### 排序示例

| 锚点 | sort-order | display-name | 排序结果 |
|---|---|---|---|
| spawn | 0 | 新手村 | 1 |
| market | 0 | 交易中心 | 2 |
| mine | 10 | 矿洞入口 | 3 |
| nether_hub | 0 | 下界中枢 | 4（不同世界，不参与同世界排序） |

> 锚点仅在当前选中世界中显示。排序仅对同一世界内的锚点生效。

## 数据持久化

### 解锁记录表

锚点解锁记录存储在 `AXS_map_unlocks` 表中：

| 列 | SQLite 类型 | MySQL 类型 | 说明 |
|---|---|---|---|
| `uuid` | `TEXT NOT NULL` | `VARCHAR(36) NOT NULL` | 玩家 UUID |
| `anchor_id` | `TEXT NOT NULL` | `VARCHAR(128) NOT NULL` | 锚点 ID |
| `unlock_time` | `INTEGER NOT NULL` | `BIGINT NOT NULL` | 解锁时间戳（毫秒） |
| **主键** | `(uuid, anchor_id)` | `(uuid, anchor_id)` | 联合主键 |

### 解锁记录操作

| 操作 | 方法 | SQL 语法 |
|---|---|---|
| 原子插入 | `tryUnlockAnchor()` | SQLite: `INSERT OR IGNORE`；MySQL: `INSERT IGNORE` |
| 移除记录 | `removeUnlock()` | `DELETE FROM AXS_map_unlocks WHERE uuid = ? AND anchor_id = ?` |
| 加载已解锁 | `loadUnlockedAnchors()` | `SELECT anchor_id FROM AXS_map_unlocks WHERE uuid = ? ORDER BY unlock_time ASC, anchor_id ASC` |

> 解锁记录使用联合主键 `(uuid, anchor_id)` 确保同一玩家对同一锚点只记录一次。`tryUnlockAnchor` 返回 `false` 表示已存在记录。

### 数据缓存

为减少数据库查询，`MapService` 使用 `CachedPlayerMapData` 缓存玩家的解锁记录和路径点：

| 缓存操作 | 触发时机 |
|---|---|
| 加载缓存 | 首次访问玩家数据时从数据库加载 |
| 刷新缓存 | 解锁锚点、创建/删除路径点后调用 `invalidatePlayerDataCache()` |
| 清除缓存 | 玩家退出服务器时移除 |

> 缓存为进程内 `ConcurrentHashMap`，非持久化。服务器重启后缓存重建。

## 玩家数据清除

Map 模块注册 `PlayerDataPurgeable` Capability，支持 `/axs purge` 统一清理玩家地图数据：

| 方法 | 说明 |
|---|---|
| `purgePlayerData(UUID)` | 删除指定玩家的解锁记录和路径点，返回删除行数 |
| `purgeAllPlayerData()` | 删除所有玩家的解锁记录和路径点，返回删除行数 |

> 清除操作在事务中执行，同时删除 `AXS_map_unlocks` 和 `AXS_map_waypoints` 两表中的玩家数据。失败时返回 `-1`。参考 /docs/guide/conditions 了解数据清除条件配置。
