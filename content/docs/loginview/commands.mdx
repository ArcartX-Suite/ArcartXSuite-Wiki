## 常用命令

| 命令 | 用途 |
| --- | --- |
| `/axs loginview status` | 显示模块与宿主认证的职责提示 |
| `/axs loginview open <玩家>` | 为在线玩家尝试打开登录或账号界面 |
| `/axs reload loginview` | 重载 LoginView 界面和打开延迟配置 |
| `/axs unload loginview` | 卸载 LoginView，解除该模块的操作限制 |

以上管理操作需要 `arcartxsuite.admin`。认证后端、入口和登录策略在 `authentication.yml` 中配置，改动后重启游戏服。中心的账号策略改动后重启中心。

`status` 用于确认模块命令已注册。中心连通性和认证入口状态需要结合启动日志及实际登录结果验证。

## 账号管理界面

已用本地密码登录的玩家，由管理员执行 `/axs loginview open 玩家名` 打开账号界面，可在其中修改密码。

中心同时开启了游戏内密码和外部授权时，近期用密码登录的玩家还可点击“关联官网账号”，再完成官网授权和游戏核对。[官网关联步骤](/docs/loginview/external-authorization#现有账号关联)

## 故障排查

| 故障现象 | 检查项 | 处理方法 |
| --- | --- | --- |
| 完全没有登录界面 | 模块加载结果、ArcartX 客户端、`modules.loginview.enabled` | 确认模块已安装并启用，再用 open 命令测试 |
| 改了认证方式却没生效 | 是否只执行了 reload | 重启游戏服，中心策略有变时也重启中心 |
| 提示中心密码入口未启用 | 中心的 `gamePasswordEnabled` 和 `external` | 启用中心密码认证或配置外部授权，确保至少提供一种登录入口 |
| 中心提示缺少节点密钥 | 启动中心及游戏服的环境变量 | 两个进程都设置同名、同值的节点密钥 |
| 节点请求被拒绝 | `realm-id`、`node-id`、audience、密钥和机器时钟 | 按中心教程的对照表逐项核对 |
| 单服混合提示需要在线模式 | 游戏服的 `server.properties` | 单服混合认证使用 `online-mode=true` |
| 密码入口提示需要直连在线模式 | `ingress.type` 与 `server.properties` | 单服密码使用 `password`、`online-mode=true`，改完后重启游戏服。代理子服按 `signed-proxy` 配置 |
| 混合入口提示握手回执不存在或过期 | 实际启动脚本、网关地址和端口 | 使用生成的混合脚本重启，然后重新连接 |
| Velocity 子服一直等待验证 | 代理注册名称、转发设置、公钥、Realm 和目标标识 | 按代理转发配置的字段对应表核对 |
| 官网登录成功但游戏仍等待 | 玩家是否刷新并核对确认码 | 回原游戏连接刷新，再确认本次授权 |
| 已验证身份但仍不能操作 | 条款或 QQ 绑定步骤 | 完成界面列出的要求 |
| 只有别的登录插件在限制玩家 | 对应插件的状态 | 按该插件的命令完成登录，LoginView 缺席时由对应插件管理限制 |

## 认证状态查询

安装 PlaceholderAPI 且 LoginView 已加载时，可用以下命令查询自己的准入状态。

```text
/papi parse me %axsauth_admitted%
```

| 占位符 | 用途与返回内容 |
| --- | --- |
| `%axsauth_admitted%` | 是否已完成全部要求并放行，返回 true 或 false |
| `%axsauth_verified%` | 是否已证明身份，返回 true 或 false |
| `%axsauth_stage%` | 当前步骤，例如 awaiting_identity、awaiting_requirements、admitted |
| `%axsauth_provider%` | 验证方式，例如 local-password、microsoft、littleskin、oidc |
| `%axsauth_registered%` | 账号登记状态，返回 registered、unregistered 或 unknown |

已验证身份仍可能在等待条款或绑定。业务条件通常使用 `%axsauth_admitted%` 判断玩家是否可以参与游戏。
