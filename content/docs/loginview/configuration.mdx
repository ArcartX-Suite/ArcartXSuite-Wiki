---
title: "单服密码认证"
description: "配置游戏内账号注册、密码验证、服务器条款和 QQ 绑定要求。"
---

本模式由游戏服管理账号并验证密码。玩家首次连接时注册账号，后续连接使用已登记的密码登录。

## 模块启用

安装 LoginView 后，在宿主 `config.yml` 的 `modules` 配置中启用该模块。以下为相关配置项，编辑时保留其他模块设置。

```yaml
modules:
  loginview:
    enabled: true
```

单服密码认证要求玩家直连启用了 Minecraft 在线验证的游戏服。将游戏服根目录的 `server.properties` 设为以下值。

```properties
online-mode=true
```

玩家先通过 Minecraft 在线验证，再输入本服密码。使用代理的子服按[代理转发认证](/docs/loginview/mixed-login#velocity-代理认证)配置。`online-mode=false` 的游戏服会拒绝加载本页的密码入口。

## 认证配置

将以下完整配置保存到 `plugins/ArcartX-Suite/authentication.yml`。样例启用服务器条款，关闭 QQ 绑定，适合验证基础密码流程。

```yaml
schema-version: 1
backend: standalone
realm-id: local
timezone: Asia/Shanghai
login-timeout-seconds: 300
ingress:
  type: password
password:
  min-length: 8
  max-length: 128
  max-attempts: 5
  cooldown-seconds: 300
requirements:
  terms: true
  qq-binding: false
terms:
  version: '1'
  lines:
    - '请遵守服务器规则，保护账号凭据。'
performance:
  workers: 2
  queue-capacity: 128
```

| 字段 | 用途 | 配置说明 |
| --- | --- | --- |
| `realm-id` | 区分本服的账号范围 | 单服可使用 `local`，投入使用后保持该值稳定 |
| `login-timeout-seconds` | 玩家最多等待多久完成登录 | 默认 300 秒，范围 30 至 1800 秒 |
| `password.min-length` | 新密码的最短长度 | 样例为 8 个字符 |
| `password.max-length` | 密码最长长度 | 最多 128 个字符，且不能小于最短长度 |
| `password.max-attempts` | 进入冷却前的失败次数 | 样例为 5 次，范围 1 至 20 |
| `password.cooldown-seconds` | 失败后的冷却时间 | 样例为 300 秒 |
| `requirements.terms` | 是否要求同意服务器条款 | 使用条款时填写 `true` |
| `requirements.qq-binding` | 是否要求绑定 QQ 后才放行 | 完成 QQBot 接入与绑定验证后再启用 |
| `terms.version` | 当前条款版本 | 使用字符串值，修改条款正文时同步更新版本 |
| `terms.lines` | 界面显示的条款 | 最多 3 行，每行不超过 60 个字符 |
| `performance` | 登录请求处理容量 | 初次使用保留样例值 |

账号使用宿主配置的 SQLite 或 MySQL 存储。普通单服可以先沿用宿主现有的存储设置。

## 界面配置

界面的实际配置文件为 `plugins/ArcartX-Suite/data/loginview/config.yml`，内容如下。

```yaml
config-version: 1
open-delay-ticks: 20
```

`open-delay-ticks` 控制进服后尝试打开界面的延迟，范围为 0 至 600 tick。样例值 20 约为 1 秒，认证要求由 `authentication.yml` 控制。

## 启动与验证

在测试服用匹配的 ArcartX 客户端和一名未登记的普通玩家验收。

1. 重启游戏服，控制台执行 `axs status`，确认 `loginview` 已启用。若出现「游戏内密码认证要求直连」或 LoginView 加载失败，先修正启动配置再放行玩家。
2. 首次连接后应打开注册界面。提交两次不同的密码，应提示不一致。未完成认证时尝试走动和使用方块，两项都应受限。
3. 用两次相同的合规密码注册并确认条款。界面应关闭，玩家可以移动和使用方块。
4. 重新连接后应打开登录界面。输错一次密码，确认仍在登录界面且无法操作。随后输入正确密码，确认界面关闭、玩家可正常操作。
5. 安装了 PlaceholderAPI 时，成功放行后用 `/papi parse me %axsauth_admitted%` 核对结果应为 `true`。模块加载状态和未登录时的实际限制也应分别验收。

界面外观或打开延迟改变后，可以用 `/axs reload loginview` 重载。修改认证后端、密码策略、条款或入口后，重启游戏服。

## QQ 绑定要求

完成 QQBot 的连接和群内绑定验证后，将 `requirements.qq-binding` 设为 `true` 并重启。玩家通过密码认证后，须在群内申请验证码并回到登录界面确认，完成绑定后才允许操作。[QQ 绑定流程](/docs/qqbot/binding-whitelist)

## 界面加载排查

界面未显示时，检查 LoginView 的加载结果和客户端 ArcartX 环境。管理员可执行 `/axs loginview open 玩家名` 测试界面。已通过认证的连接通常不会再次自动打开登录页。[管理与排错](/docs/loginview/commands)
