---
title: "认证与界面配置"
description: "分别配置宿主认证策略和 LoginView 界面。"
---

宿主从插件数据目录读取 `authentication.yml`。LoginView 模块从其模块配置目录读取 `LoginView.yml`。修改认证后端、可信入口、密码或条款策略后重启宿主。

宿主仅在启用 LoginView 时读取并执行认证策略。卸载 LoginView 会停止对应运行时并恢复普通进服状态。

## 界面加载配置

```yaml
config-version: 1
open-delay-ticks: 20
```

`open-delay-ticks` 范围为 0 至 600 tick。认证界面 ID 为 `AXS:auth_v1`，模块 UI 文件为 `ui/auth_v1.yml`。

## 单服认证配置

```yaml
schema-version: 1
backend: standalone
realm-id: local
timezone: Asia/Shanghai
login-timeout-seconds: 300
ingress:
  type: password
  gateway-url: http://127.0.0.1:25599
  audience: local-node
  trusted-proxies: []
password:
  min-length: 8
  max-length: 128
  max-attempts: 5
  cooldown-seconds: 300
requirements:
  terms: true
  qq-binding: false
terms:
  version: '1'
  lines:
    - '请遵守服务器规则，保护账号凭据。'
performance:
  workers: 2
  queue-capacity: 128
```

账号和绑定使用宿主配置的 SQLite 或 MySQL 存储。修改条款正文时更新 `terms.version`，玩家确认的是界面实际展示的版本。

| `ingress.type` | 部署要求 |
| --- | --- |
| `password` | 游戏内密码入口 |
| `local-mixed` | 同机直连、`online-mode=true`，认证宿主实际通过 Java Agent 接入同一个本机网关 |
| `signed-proxy` | 可信代理转发玩家身份，目标服校验签名、签发者、Realm、audience 和当前连接挑战 |

混合入口默认关闭密码登录，明确需要同时提供密码时设置 `ingress.password-login: true`。代理信任项使用 `issuer`、`public-key` 和 `providers`。签名转发当前采用 Velocity，部署前验证真实握手与转发。资料查询、同名及 UUID 形态不作为身份验证依据。

使用 `backend: center` 时采用独立的节点配置结构，密码、条款及 QQ 绑定要求由中心下发。[独立认证中心](/docs/loginview/center)
