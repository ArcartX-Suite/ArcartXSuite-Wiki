# 认证模式与 AuthMe 迁移

LoginView 支持两种认证模式，通过 `auth.mode` 配置项切换。`standalone` 模式使用 AXS 自有账户库，`authme` 模式将认证操作委托给 AuthMe 插件。`standalone` 模式还支持从 AuthMe 数据库迁移历史账户，实现平滑过渡。

## 认证模式总览

| 模式 | 配置值 | 账户存储 | AuthMe 依赖 | Session 持久化 | reset-password 命令 |
|---|---|---|---|---|---|
| 独立模式 | `standalone` | AXS 账户表 | 不需要 | 支持 | 可用 |
| 兼容模式 | `authme` | AuthMe 数据库 | 必需 | 由 AuthMe 管理 | 不可用 |

<Callout type="warn">
`auth.mode=authme` 时必须安装 AuthMe 插件且插件已启用，否则 LoginView 模块不加载。`standalone` 模式完全独立运行，不需要 AuthMe。
</Callout>

## standalone 独立模式

玩家注册、登录、改密均由 LoginView 自行处理，密码加盐哈希存储，支持登录尝试限制与 Session 持久化（见[安全策略与会话管理](/docs/loginview/security)）。

从 AuthMe 迁移导入的账户可继续使用原密码登录；首次登录成功后，可自动转换为新存储格式（见下文重哈希配置）。

## authme 兼容模式

`authme` 模式下，登录验证、注册、改密、登录状态全部转发给 AuthMe 插件处理，LoginView 仅提供 UI 界面。AuthMe 未安装或不可用时相关操作安全降级，不会导致服务器崩溃。

<Callout type="info">
`authme` 模式下密码存储、Session 管理均由 AuthMe 负责。`reset-password` 命令在此模式下不可用，需使用 AuthMe 自带命令。
</Callout>

## AuthMe 数据迁移

`standalone` 模式下，LoginView 可从 AuthMe 数据库导入历史账户。迁移只复制密码哈希，不保存明文密码。

支持迁移的 AuthMe 哈希格式：BCRYPT、BCRYPT2Y、SHA256。若 AuthMe 使用了其他算法，迁移的账户无法用原密码验证，请让玩家通过 `reset-password` 重置。

### 迁移配置

迁移配置位于 `config.yml` 的 `authme-migration` 节：

```yaml
authme-migration:
  source:
    # SQLite 示例
    jdbc-url: jdbc:sqlite:plugins/AuthMe/AuthMe.db
    # MySQL 示例
    # jdbc-url: jdbc:mysql://127.0.0.1:3306/authme?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai
    username: ''
    password: ''
    table: authme
  columns:
    name: username
    real-name: realname
    password: password
    salt: salt
    last-ip: ip
    last-login: lastlogin
    registration-date: regdate
    registration-ip: regip
    email: email
  imported-hash-algorithm: AUTHME_BCRYPT
  batch-size: 200
```

### 列映射

通过列映射将 AuthMe 表字段对应到 AXS 账户字段：

| 配置字段 | 默认值 | 说明 |
|---|---|---|
| `columns.name` | `username` | 玩家名 |
| `columns.real-name` | `realname` | 原始用户名（保留大小写） |
| `columns.password` | `password` | 密码哈希值 |
| `columns.salt` | `salt` | 盐字段（部分算法需要） |
| `columns.email` | `email` | 邮箱 |
| `columns.registration-ip` | `regip` | 注册 IP |
| `columns.last-ip` | `ip` | 最后登录 IP |
| `columns.registration-date` | `regdate` | 注册时间戳 |
| `columns.last-login` | `lastlogin` | 最后登录时间戳 |

<Callout type="info">
若 AuthMe 使用了非默认列名，需在配置中修改对应映射。
</Callout>

### 迁移命令

```bash
# 预览模式（只扫描不导入）
/axs loginview migrate-authme dry-run

# 执行迁移
/axs loginview migrate-authme
```

迁移结果输出格式：

```
AuthMe 迁移完成: 扫描 256，可导入 240，跳过 16
```

| 结果字段 | 说明 |
|---|---|
| 扫描数 | AuthMe 源表中的总记录数 |
| 导入数 | 成功导入或可导入的记录数（含空名/空哈希跳过后的有效记录） |
| 跳过数 | 因玩家名或密码哈希为空而跳过的记录数 |

同名账户会被新数据覆盖更新。迁移过程中每 `batch-size` 条记录会向命令发送者上报进度。

### 迁移后安全操作

执行 `/axs loginview migration-commands` 查看迁移后的安全操作提示：

```
1. 先执行 /axs loginview migrate-authme dry-run 预览数量
2. 确认无误后执行 /axs loginview migrate-authme
3. 玩家首次用旧密码登录成功后，可自动转换为新存储格式
4. 完成验证后再停用 AuthMe，避免玩家无法登录
```

## 迁移后重哈希

迁移导入的账户首次用旧密码登录成功后，自动转换为新存储格式，此后不再依赖 AuthMe 的哈希验证。

| 配置 | 说明 |
|---|---|
| `rehash-migrated-password-on-login: true` | 迁移账户首次登录后自动转换（推荐，默认） |
| `rehash-migrated-password-on-login: false` | 迁移账户保持原格式验证 |

<Callout type="info">
推荐保持 `rehash-migrated-password-on-login: true`，迁移完成后可安全停用 AuthMe。
</Callout>

## 模式选择建议

| 场景 | 推荐模式 | 原因 |
|---|---|---|
| 全新服务器，无 AuthMe 历史 | `standalone` | 无需额外依赖 |
| 已有 AuthMe，希望逐步迁移 | `standalone` + 迁移 | 导入历史数据后逐步转换，最终停用 AuthMe |
| 已有 AuthMe，不想迁移数据 | `authme` | 保留现有认证体系，仅升级 UI 体验 |
| 需要密码重置功能 | `standalone` | `reset-password` 命令仅 standalone 可用 |
| 需要跨服 Session | `standalone` | Session 持久化仅 standalone 模式支持 |
