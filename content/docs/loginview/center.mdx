---
title: "独立认证中心"
description: "部署认证中心与游戏节点，集中管理账号、密码策略和游戏准入要求。"
---

独立认证中心负责账号存储与登录策略，游戏服根据中心的验证结果放行玩家。本页采用中心密码认证，玩家在游戏界面注册和输入密码。官网及启动器授权见[外部身份接入](/docs/loginview/external-authorization)。

## 部署条件

| 准备项 | 要求 |
| --- | --- |
| 认证中心发行包 | 解压后包含 `bin` 启动脚本和 `lib` 依赖目录，使用 Java 17 或以上 |
| 游戏服 | Suite 与 LoginView 已安装，玩家直连，`server.properties` 中 `online-mode=true` |
| 节点密钥 | 中心与对应游戏服使用相同的值，通过各自进程环境变量传入 |

以下示例将中心与游戏服部署在同一台 Windows 机器上。中心目录为 `D:/AXSAuth/`，配置文件为 `D:/AXSAuth/center.json`。部署前应准备包含启动脚本和依赖目录的独立中心发行包。

## 生成节点密钥

在 PowerShell 7 执行以下命令生成随机密钥，并妥善保存。中心与对应游戏服的进程环境变量使用相同的密钥值。

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

每增加一台游戏服，生成一份新的密钥，并在中心 `nodes` 数组中增加对应登记项。

## 中心配置

将以下完整 JSON 保存为 `D:/AXSAuth/center.json`。样例设置 `gamePasswordEnabled: true`，启用游戏内密码认证。

```json
{
  "schemaVersion": 1,
  "port": 25600,
  "database": "data/auth-center.sqlite",
  "external": null,
  "realms": [
    {
      "id": "network",
      "gamePasswordEnabled": true,
      "minLength": 8,
      "maxLength": 128,
      "requireTerms": true,
      "termsVersion": "1",
      "termsLines": [
        "请遵守服务器规则，保护账号凭据。"
      ],
      "requireBinding": false,
      "timezone": "Asia/Shanghai",
      "loginTimeoutSeconds": 300
    }
  ],
  "nodes": [
    {
      "id": "lobby",
      "realm": "network",
      "audience": "lobby-node",
      "keyEnvironment": "AXS_AUTH_LOBBY_KEY",
      "scopes": [
        "auth"
      ]
    }
  ]
}
```

| 字段 | 用途 | 配置说明 |
| --- | --- | --- |
| `port` | 中心的节点连接端口 | `25600`，要与游戏服 URL 中的端口一致 |
| `database` | 中心的 SQLite 文件 | 相对于本配置文件目录，应用会创建 `data` 目录 |
| `external` | 官网和启动器授权入口 | 本方案填写 `null` |
| `realms[0].id` | 一组账号的范围名 | `network`，与游戏服的 `realm-id` 一致 |
| `gamePasswordEnabled` | 是否允许游戏内注册与密码认证 | 本方案必须为 `true` |
| `requireTerms`、`termsVersion`、`termsLines` | 条款开关、版本和正文 | 由中心统一控制 |
| `requireBinding` | 是否必须绑定 QQ | 先保持 `false`，基础登录通过后再启用 |
| `nodes[0].id` | 当前游戏服的中心登记名 | `lobby`，与游戏服的 `node-id` 一致 |
| `nodes[0].audience` | 当前节点的目标标识 | `lobby-node`，与游戏服的 `ingress.audience` 一致 |
| `nodes[0].keyEnvironment` | 读取节点密钥的环境变量名 | `AXS_AUTH_LOBBY_KEY`，此字段填变量名 |

数据目录的访问权限应仅授予中心运行账号。新部署时可由应用创建 `data` 目录，使用已有目录时须核对访问权限。

## 启动认证中心

在运行中心的 PowerShell 窗口中设置环境变量，再执行发行包的启动脚本。命令中的密钥占位文字须替换为已生成的密钥值。

```powershell
$env:AXS_AUTH_LOBBY_KEY = '粘贴第一步生成的完整密钥'
& 'D:\AXSAuth\bin\auth-center.bat' 'D:\AXSAuth\center.json'
```

中心启动后，确认监听地址为 `127.0.0.1:25600` 并保持进程运行。环境变量仅对当前窗口及其子进程生效，使用服务或面板启动时，需要在对应启动环境中设置。

## 游戏节点配置

将以下完整节点配置保存到游戏服的 `plugins/ArcartX-Suite/authentication.yml`。

```yaml
schema-version: 1
backend: center
realm-id: network
ingress:
  type: password
  audience: lobby-node
performance:
  workers: 2
  queue-capacity: 128
center:
  url: http://127.0.0.1:25600
  node-id: lobby
  key-environment: AXS_AUTH_LOBBY_KEY
```

中心模式的节点字段固定填写 `ingress.type: password`。玩家实际上是否需要输入密码，由中心的 `gamePasswordEnabled` 决定。

节点配置须与中心登记项逐项匹配。

| 游戏服字段 | 中心字段 | 本例值 |
| --- | --- | --- |
| `realm-id` | `realms[].id` 和 `nodes[].realm` | `network` |
| `center.node-id` | `nodes[].id` | `lobby` |
| `ingress.audience` | `nodes[].audience` | `lobby-node` |
| `center.key-environment` | `nodes[].keyEnvironment` | `AXS_AUTH_LOBBY_KEY` |

在游戏服的启动环境中设置 `AXS_AUTH_LOBBY_KEY`，使用与中心对应节点相同的密钥值。启动游戏服后，确认 LoginView 加载成功。

## 验证密码认证

使用测试账号首次连接时，应显示注册界面。完成注册与条款确认后，玩家可正常操作。重新连接时，应使用已登记的密码登录。

中心至少需要启用一种登录入口。`gamePasswordEnabled: false` 与 `external: null` 同时存在时，玩家无法完成认证。出现“未启用游戏内密码登录”提示时，检查这两个字段的组合。

完成基础登录验证后，测试中心暂时不可用时的操作限制，以及中心恢复后的重新认证。游戏服通过短期授权持续确认连接的准入状态。

## 跨主机部署

在中心机器上配置 HTTPS 反向代理，将节点请求转发至本机 `http://127.0.0.1:25600/v1/node/rpc`。游戏服的 `center.url` 使用 HTTPS 服务根地址，例如 `https://auth.example.net`。

游戏服访问异机中心必须使用 HTTPS，节点密钥仍通过两边的环境变量传入。保持机器时钟同步。

## QQ 绑定策略

在中心 Realm 设置 `requireBinding: true`。为负责 QQBot 的游戏节点增加 `binding-read`、`binding-write` 权限，再配置 QQBot 并验证群内申请、游戏内确认流程。

中心配置变更后重启中心。游戏服的 `authentication.yml` 变更后重启游戏服。界面样式与打开延迟仍在游戏服的 LoginView 配置中调整。[界面文件位置](/docs/loginview/configuration#界面配置)
