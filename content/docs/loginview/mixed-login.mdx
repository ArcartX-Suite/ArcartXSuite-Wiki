---
title: "混合账号认证"
description: "配置微软与 LittleSkin 账号认证，分别支持单服直连和 Velocity 代理转发。"
---

混合账号认证接收微软和 LittleSkin 身份。验证完成后，玩家继续执行条款确认和已启用的 QQ 绑定要求。以下两种部署方式均由游戏服保存账号记录。

| 连接拓扑 | 认证入口 | 网关部署位置 |
| --- | --- | --- |
| 玩家直接连接游戏服 | 单服混合认证，`local-mixed` | 与游戏服同一台机器 |
| 玩家通过 Velocity 进入子服 | 代理转发认证，`signed-proxy` | 与 Velocity 同一台机器 |

微软与 LittleSkin 账号通过在线身份验证后免输本服密码。需要在同一台在线模式游戏服再验证本服密码时，按[单服密码认证](/docs/loginview/configuration)设置对应入口。

## 单服混合认证

### 生成启动脚本

游戏服需要安装 Suite 和 LoginView。在宿主 `config.yml` 中设置以下 `auth` 配置，保留文件里的其他设置。

```yaml
auth:
  enabled: true
  auto-check-version: false
  yggdrasil-source: "https://littleskin.cn/api/yggdrasil?mixed"
  mixed-proxy-port: 25599
  mixed-proxy-host: "127.0.0.1"
  mixed-proxy-token: ""
```

设置 `auth.enabled: true` 后重启游戏服，在控制台执行 `axs auth setup`。游戏内执行 `/axs auth setup` 同时需要 `arcartxsuite.admin` 和 `arcartxsuite.auth.admin`。

确认服务器根目录生成 `start-mixed-auth.bat` 和 `start-mixed-auth.sh`，然后停服。脚本会先启动本机网关，再带着所需的认证参数启动游戏服。

### 配置游戏服入口

在 `server.properties` 中设置 `online-mode=true`。

将以下完整内容保存到游戏服的 `plugins/ArcartX-Suite/authentication.yml`。

```yaml
schema-version: 1
backend: standalone
realm-id: local
timezone: Asia/Shanghai
login-timeout-seconds: 300
ingress:
  type: local-mixed
  gateway-url: http://127.0.0.1:25599
  password-login: false
requirements:
  terms: true
  qq-binding: false
terms:
  version: '1'
  lines:
    - '请遵守服务器规则，保护账号凭据。'
performance:
  workers: 2
  queue-capacity: 128
```

`gateway-url` 的端口必须与上一步的 `mixed-proxy-port` 一致，地址使用本机 `127.0.0.1`。

### 启动游戏服

Windows 使用 `start-mixed-auth.bat`，Linux 使用 `start-mixed-auth.sh`。主机面板需要实际执行对应脚本，或完整保留脚本里的启动顺序和 Java 启动参数。

认证入口同时检查网关和实际 Java 启动参数，游戏服须通过生成的混合启动脚本启动。

### 验证身份与准入

用微软账号和 LittleSkin 账号各测试一次。验证通过后，界面应进入条款步骤或直接关闭，玩家可以操作游戏。若提示握手回执过期，先重新连接，再检查脚本、网关端口和实际启动参数。

## Velocity 代理认证

Velocity 负责验证玩家身份，子服校验代理传入的认证结果。该转发入口使用 Velocity 对应适配。

### 配置玩家信息转发

在 Velocity 的 `servers` 中登记子服，确认玩家能够通过代理连接。下文使用子服名称 `lobby`。

对于 Paper 子服，按 Velocity 的现代转发步骤设置 `player-info-forwarding-mode=modern`、子服 `online-mode=false`，并匹配 Paper 的 Velocity 转发开关和共享值。限制玩家绕过代理直连子服。具体文件位置以所用 Paper 版本为准。[Velocity 官方转发教程](https://docs.papermc.io/velocity/player-information-forwarding/)

### 生成代理启动脚本

在 Velocity 安装 Suite 的代理端插件。编辑代理插件实际生成的 `proxy-config.yml`，先配置以下内容。

```yaml
deny-offline: true
auth-forwarding:
  enabled: false
auth:
  enabled: true
  auto-check-version: false
  yggdrasil-source: "https://littleskin.cn/api/yggdrasil?mixed"
  mixed-proxy-port: 25599
  mixed-proxy-bind-host: "127.0.0.1"
  mixed-proxy-token: ""
  mixed-proxy-allow-ips: []
```

启动一次代理，在代理控制台执行 `axsproxy auth setup`。生成脚本后停止代理。后续使用代理目录里的 `start-mixed-auth` 脚本启动，Velocity 保持 `online-mode=true`。

### 启用认证转发

将代理 `proxy-config.yml` 中的 `auth-forwarding` 整段替换为以下内容，再用新脚本启动代理。

```yaml
auth-forwarding:
  enabled: true
  issuer: proxy-main
  gateway-url: http://127.0.0.1:25599
  targets:
    lobby:
      realm: network
      audience: lobby-node
```

在代理启动日志中找到以 `[AuthForwarding]` 开头、包含 `public-key=` 的一行。复制其中完整的公钥值，下一步填到子服。代理生成的私钥文件留在代理端。

### 配置子服信任项

子服安装 Suite 和 LoginView。将下面完整配置保存到子服的 `plugins/ArcartX-Suite/authentication.yml`，把公钥占位符换成刚复制的值。

```yaml
schema-version: 1
backend: standalone
realm-id: network
timezone: Asia/Shanghai
login-timeout-seconds: 300
ingress:
  type: signed-proxy
  audience: lobby-node
  password-login: false
  trusted-proxies:
    - issuer: proxy-main
      public-key: "替换为代理日志中的完整公钥"
      providers: [microsoft, littleskin]
requirements:
  terms: true
  qq-binding: false
terms:
  version: '1'
  lines:
    - '请遵守服务器规则，保护账号凭据。'
performance:
  workers: 2
  queue-capacity: 128
```

子服的宿主 `config.yml` 中 `auth.enabled` 保持 `false`，混合网关由代理启动。开启子服的 LoginView，然后重启子服。

| 代理上的字段 | 子服上要对应的字段 | 本例 |
| --- | --- | --- |
| `targets` 下的子服名称 | Velocity 的子服注册名称 | `lobby` |
| `targets.lobby.realm` | `realm-id` | `network` |
| `targets.lobby.audience` | `ingress.audience` | `lobby-node` |
| `issuer` | `trusted-proxies` 中的 `issuer` | `proxy-main` |
| 启动日志的 `public-key` | `trusted-proxies` 中的 `public-key` | 复制完整公钥 |

### 验证代理入口

玩家必须通过 Velocity 的地址进入。分别用微软和 LittleSkin 账号测试，子服应接受验证结果并继续条款步骤。

若一直等待可信验证，先核对上表五项，再检查实际连接是否来自已配置的 `lobby` 子服及其转发设置。

## 部署约束

| 配置情况 | 处理要求 |
| --- | --- |
| 子服配置了 `local-mixed`，玩家却从 Velocity 进入 | 使用代理转发认证的 `signed-proxy`，网关部署在代理端 |
| 单服提示需要在线模式 | 单服混合认证的游戏服必须设置 `online-mode=true` |
| 在中心模式中使用混合入口 | 中心节点按独立中心教程配置，当前中心入口要求直连 |
| 服务器需要允许普通离线账号 | 由适合离线部署的其他登录插件管理。Suite 的单服密码入口要求在线模式直连 |

游戏内注册与密码登录的部署步骤见[单服密码认证](/docs/loginview/configuration)。
