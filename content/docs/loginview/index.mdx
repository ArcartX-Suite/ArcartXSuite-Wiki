title: "登录认证"

LoginView 提供游戏内登录、条款确认、QQ 绑定和外部授权界面。服务器可在本服管理账号，也可将账号和策略交由独立认证中心管理。

## 登录模式

| 模式 | 身份验证方式 | 部署条件 | 配置文档 |
| --- | --- | --- | --- |
| 单服密码认证 | 玩家通过 Minecraft 在线验证后，在游戏界面注册或输入本服密码 | 玩家直连，游戏服 `online-mode=true` | [单服密码认证](/docs/loginview/configuration) |
| 单服混合认证 | 验证微软或 LittleSkin 账号，通过后免输本服密码 | 玩家直连游戏服，同机运行混合登录网关 | [单服混合认证](/docs/loginview/mixed-login#单服混合认证) |
| 代理转发认证 | Velocity 验证账号，子服校验代理传入的结果 | Velocity 代理、对应插件与已配置转发的子服 | [Velocity 代理认证](/docs/loginview/mixed-login#velocity-代理认证) |
| 中心密码认证 | 玩家在游戏界面注册、输入密码，由中心验证 | 独立认证中心，玩家直连在线模式游戏服 | [独立认证中心](/docs/loginview/center) |
| 外部授权认证 | 玩家通过官网或启动器授权，再在原游戏连接确认 | 独立认证中心与可接入的 OIDC 身份系统 | [外部身份接入](/docs/loginview/external-authorization) |

### 配置项对应关系

`backend` 指定账号管理位置，`ingress.type` 指定游戏服的认证入口。

| 模式 | 游戏服 backend | 游戏服 ingress.type | 其他关键设置 |
| --- | --- | --- | --- |
| 单服密码认证 | `standalone` | `password` | 游戏服保持 `online-mode=true`，在本服设置密码、条款和绑定要求 |
| 单服混合认证 | `standalone` | `local-mixed` | 游戏服启用在线模式并使用混合启动脚本 |
| 代理转发认证 | `standalone` | `signed-proxy` | 子服配置可信代理及对应公钥 |
| 中心密码认证 | `center` | `password` | 中心设置 `gamePasswordEnabled: true` |
| 外部授权认证 | `center` | `password` | 中心配置 `external`，密码入口按需启用 |

中心节点要求玩家直连，且 `online-mode=true`。Velocity 代理转发采用 `standalone` 与 `signed-proxy` 的组合。普通离线账号的密码认证请使用适合该部署方式的登录插件。

## 与其他登录插件配合

使用 AuthMe 等其他登录插件时，在 Suite 的 `config.yml` 中设置 `modules.loginview.enabled: false`，或卸载 LoginView，然后按对应插件的文档配置认证。

LoginView 的玩家操作限制随模块启停。模块缺席、关闭、卸载，以及加载或重载失败时，Suite 恢复普通进服状态。其他登录插件继续管理各自的认证要求和玩家限制。

## 部署流程

1. 根据身份来源和服务器拓扑选择登录模式。
2. 准备 ArcartX 客户端、服务端环境及 LoginView 模块，确认模块可正常加载。
3. 按对应教程设置认证配置，重启相关进程。
4. 使用测试账号验证身份、条款及绑定流程，再开放玩家连接。

以下路径以 `plugins/ArcartX-Suite/` 为宿主数据目录。实际目录名以服务器生成结果为准。

| 配置文件 | 用途 |
| --- | --- |
| `plugins/ArcartX-Suite/config.yml` | 通过 modules.loginview.enabled 控制模块启用状态 |
| `plugins/ArcartX-Suite/authentication.yml` | 配置账号后端与游戏服认证入口 |
| `plugins/ArcartX-Suite/data/loginview/config.yml` | 配置登录界面的打开延迟 |
| `plugins/ArcartX-Suite/ui/auth_v1.yml` | 配置界面外观 |
| 中心配置文件，例如 `D:/AXSAuth/center.json` | 配置中心账号策略、外部身份系统及游戏节点 |

## 配置验证

先在控制台执行 `axs status` 核对 LoginView 已启用，再按所选模式使用测试账号验证。等待密码或端外确认时，移动和方块交互应受限。使用混合或代理免密入口时，验证正确账号通过在线握手，错误身份在进入游戏前被拒绝。开启条款或 QQ 绑定时，还要逐项核对完成前后的操作权限。

安装 PlaceholderAPI 后，可通过 `/papi parse me %axsauth_admitted%` 查询准入结果。完成全部要求后应返回 `true`。
