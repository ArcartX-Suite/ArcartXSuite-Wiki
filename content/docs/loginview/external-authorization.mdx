---
title: "外部身份接入"
description: "通过 OIDC 接入官网身份，配置启动器授权与原游戏连接确认。"
---

玩家在已有官网或启动器完成授权，回到游戏核对并确认后进入服务器。LoginView 提供认证接口与游戏界面，官网和启动器可以使用接入方已有的产品。

部署前完成中心发行包、节点密钥和游戏服环境准备。本页在中心节点配置的基础上启用外部授权，并增加 HTTPS 入口。游戏服继续使用相同的中心模式 `authentication.yml`。[独立认证中心](/docs/loginview/center)

## 身份系统要求

| 现有条件 | 接入要求 |
| --- | --- |
| 官网支持 OIDC | 按本页登记中心回调，并索取下表参数 |
| 已有启动器，也有可用的 OIDC 身份系统 | 同时在中心登记启动器，再按接口参考接入 |
| 官网只有自定义“验证登录”URL 或密码查询接口 | 先由接入方提供 OIDC 适配，再使用本页配置 |
| 使用游戏内注册和密码登录 | 采用中心密码认证 |

OIDC 是网站向其他应用提供身份认证的标准协议。本配置需要提供方的授权端点与换码端点，配置前应确认身份系统具备相应能力。

由身份系统管理员或开发者提供以下接入参数。

| 参数 | 中文含义 | 填到哪里 |
| --- | --- | --- |
| Issuer | 身份系统的唯一标识，必须逐字一致 | `providers[].issuer` |
| Authorization endpoint | 浏览器登录授权地址 | `providers[].authorize` |
| Token endpoint | 中心交换授权结果的地址 | `providers[].token` |
| Client ID | 网站为认证中心分配的应用 ID | `providers[].clientId` |
| Client secret | 网站为认证中心分配的应用密钥 | 中心进程的 `AXS_WEBSITE_OIDC_SECRET` 环境变量 |
| Key ID | 当前签名公钥的编号 | `providers[].keyId` |
| RSA 公钥 | X.509 SubjectPublicKeyInfo DER 格式的 Base64 公钥 | `providers[].rsaPublicKey` |

提供方需支持授权码流程、S256、`client_secret_basic`、`RS256`，并在身份结果中提供 `nonce` 和 `auth_time`。这些由提供方和接入开发者确认。

## 授权域名与回调登记

本例中心的公开域名为 `https://auth.example.net`。在网站身份系统中登记中心应用 `axs-center`，回调地址必须填写以下完整地址。

```text
https://auth.example.net/v1/external/callback
```

提供方分配的应用 ID 和密钥配置在中心。游戏节点的 `lobby` 标识与节点密钥沿用中心节点配置。

## 外部授权配置

将以下完整配置保存为中心的 `center.json`，并替换域名、提供方地址、应用 ID、公钥编号和公钥值。

样例启用外部授权并关闭游戏内密码认证。需要同时提供密码认证时，将 `gamePasswordEnabled` 设为 `true`。

```json
{
  "schemaVersion": 1,
  "port": 25600,
  "database": "data/auth-center.sqlite",
  "external": {
    "port": 25601,
    "origin": "https://auth.example.net",
    "providers": [
      {
        "realm": "network",
        "issuer": "https://id.example.net",
        "authorize": "https://id.example.net/authorize",
        "token": "https://id.example.net/token",
        "clientId": "axs-center",
        "secretEnvironment": "AXS_WEBSITE_OIDC_SECRET",
        "keyId": "替换为网站提供的公钥编号",
        "rsaPublicKey": "替换为网站提供的公钥Base64"
      }
    ],
    "launchers": [
      {
        "id": "example-launcher",
        "realm": "network",
        "redirect": "http://127.0.0.1:43981/callback"
      }
    ]
  },
  "realms": [
    {
      "id": "network",
      "gamePasswordEnabled": false,
      "minLength": 8,
      "maxLength": 128,
      "requireTerms": true,
      "termsVersion": "1",
      "termsLines": [
        "请遵守服务器规则，保护账号凭据。"
      ],
      "requireBinding": false,
      "timezone": "Asia/Shanghai",
      "loginTimeoutSeconds": 300
    }
  ],
  "nodes": [
    {
      "id": "lobby",
      "realm": "network",
      "audience": "lobby-node",
      "keyEnvironment": "AXS_AUTH_LOBBY_KEY",
      "scopes": [
        "auth"
      ]
    }
  ]
}
```

`external.launchers` 用于登记启动器。仅接入官网时，使用空数组 `[]`。登记启动器时，由接入方提供应用 `id` 及实际监听的本机回调地址。

## HTTPS 转发配置

在认证中心所在机器上配置反向代理，使用你在 `origin` 中填写的 HTTPS 域名。转发时保持原请求路径。

| 对外地址 | 转发到中心本机 | 用途 |
| --- | --- | --- |
| `https://auth.example.net/v1/external/...` | `http://127.0.0.1:25601/v1/external/...` | 浏览器和启动器授权 |
| `https://auth.example.net/v1/node/rpc` | `http://127.0.0.1:25600/v1/node/rpc` | 异机游戏节点访问中心，同机节点可以继续走本机地址 |

外部授权转发应保留 Origin 和 Cookie，并对请求来源限流。授权路径应关闭包含查询串、请求正文和 Cookie 的访问日志。

`origin` 填服务根地址，不带末尾斜线和接口路径。例如填写 `https://auth.example.net`。

## 环境变量与启动

中心进程需要游戏节点密钥，以及身份提供方分配的应用密钥。在启动中心的 PowerShell 窗口中设置以下环境变量。

```powershell
$env:AXS_AUTH_LOBBY_KEY = '与游戏服相同的节点密钥'
$env:AXS_WEBSITE_OIDC_SECRET = '网站为 axs-center 分配的应用密钥'
& 'D:\AXSAuth\bin\auth-center.bat' 'D:\AXSAuth\center.json'
```

游戏服只需要 `AXS_AUTH_LOBBY_KEY`。网站应用密钥配置在中心进程。

中心启动失败时，根据日志核对环境变量、公钥格式和身份提供方的 HTTPS 端点。配置前替换样例中的全部占位参数。

## 官网授权验证

1. 玩家进入游戏，LoginView 应显示授权地址和游戏授权码。
2. 在浏览器打开该地址，输入游戏里的授权码，再前往官网登录。
3. 登录后确认页面显示的玩家名和目标服。确认授权，记下网页显示的核对码。
4. 回到游戏点击“刷新状态”。游戏应显示相同的核对码，核对后点击“确认授权”。
5. 如果启用了条款或 QQ 绑定，继续完成这些要求，随后才能操作游戏。

游戏授权码用于定位当前连接，核对码用于确认该连接收到的授权结果。玩家退出后，原连接的授权结果失效。

## 启动器接入

启动器有两条可选流程。

| 流程 | 玩家操作 | 开发者需要实现什么 |
| --- | --- | --- |
| 系统浏览器授权 | 从启动器打开浏览器，完成官网授权后返回启动器 | 创建 S256 参数、接收登记的本机回调、核对 state 并交换授权码 |
| 设备授权 | 启动器展示用户码，玩家在浏览器输入并授权 | 私有设备码轮询、等待或降速、处理拒绝和取消 |

启动器取得短期启动凭据后，启动游戏。玩家将游戏显示的授权码交给启动器，启动器调用配对接口并展示核对码。玩家在原游戏连接刷新和确认后继续登录。[启动器接口参考](/docs/loginview/external-api)

接入前可使用通用 HTTP 客户端验证设备授权接口及异常处理，再将调用流程集成到已有启动器。

## 现有账号关联

关联前在中心启用游戏内密码认证，玩家使用原账号密码登录。管理员执行 `/axs loginview open 玩家名` 打开账号管理界面后，玩家点击“关联官网账号”，完成官网授权和游戏核对。

账号关联要求近期密码验证。验证超时后需要重新登录，再发起关联。官网账号与游戏账号名称相同，也需要完成双方身份验证。
