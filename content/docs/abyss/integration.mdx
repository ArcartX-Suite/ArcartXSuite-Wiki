# 集成与兼容性

## 外部插件集成

| 插件 | 必需性 | 集成的功能 |
|---|---|---|
| PlaceholderAPI | **硬依赖** | 条件占位符解析（`requirements.conditions`/`submit-conditions`/`check`）+ 注册 `%axsabyss_*%` 扩展 |
| MythicMobs | 软依赖 | `monsters.yml` 中无前缀/`mythic:` 怪物经 MM 生成；`cast_skill`/`play_model_animation` 脚本动作 |
| WorldEdit / FAWE | 软依赖 | `world.template` 为 schematic 时的粘贴；`void`/世界文件夹来源不需要 |
| Adyeshach | 软依赖 | NPC 渲染（`npcs.yml` 的 PLAYER 型皮肤 NPC）；未装时 NPC 退化为原版实体 |
| Vault | 间接 | 货币消耗/奖励经宿主 `currencyManager` → Vault 等货币源 |
| ArcartX MOD | 客户端 | 全部 UI/HUD 展示；无客户端副本仍可正常玩（命令进本、宝箱直接发放） |

### MythicMobs 怪物路由

`monsters.yml` 的 `mob-id` 按前缀路由：

```
vanilla:ZOMBIE       → 原版 ZOMBIE
SkeletalKnight       → MythicMobs SkeletalKnight（失败回退原版 SKELETON 同类）
mythic:SkeletalKnight→ 同上，显式前缀
```

MM 不可用时全部 mob-id 按原版实体名解析，副本不会因此崩溃。

### 物品来源

`rewards.yml`/`required-items` 中的物品描述经宿主 `ItemSourceRegistry` 统一生成，支持 `material:`（原版）及 MythicMobs/NeigeItems/Overture/MMOItems 等外源前缀（见宿主物品来源配置）。

## 跨模块能力

模块注册 `AbyssQueryable` Capability（`axs-api`，`@Stable`）供其他模块查询玩家地牢状态：

```java
AbyssQueryable abyss = getCapability(AbyssQueryable.class);
if (abyss != null && abyss.isInDungeon(player.getUniqueId())) {
    String dungeon = abyss.currentDungeonId(player.getUniqueId());
}
```

| 方法 | 说明 |
|---|---|
| `isInDungeon(uuid)` | 是否在副本中 |
| `currentDungeonId(uuid)` | 当前地牢 ID（不在副本为 null） |
| `currentRunningSeconds(uuid)` | 当前副本已运行秒数 |
| `cooldownRemaining(uuid, dungeonId)` | 剩余冷却 |
| `stamina(uuid)` | 体力（体力系统关闭返回 -1） |
| `completions(uuid, dungeonId)` | 通关次数 |
| `bestTime(uuid, dungeonId)` | 最佳通关秒数 |
| `dungeonIds()` | 全部地牢模板 ID |

### EventBus 事件主题

abyss 向 EventBus 发布以下主题（`axs.abyss.*`），battlepass 任务等订阅方按 `event-topic` 消费。**玩家级**主题的 `event.player()` 为对应玩家（驱动战令任务必须用这个级别）；实例级主题 `player` 为 null 或首名玩家：

| 主题 | 级别 | 触发 | 主要 payload |
|---|---|---|---|
| `axs.abyss.enter` | 实例 | 队伍进本 | `dungeon` `instance` `players` `plan`（有方案时） |
| `axs.abyss.player_enter` | 玩家 | 每名队员进本 | `dungeon` `instance` `party-size` `plan`（有方案时） |
| `axs.abyss.start` | 实例 | 副本正式开始 | `dungeon` `instance` `players` |
| `axs.abyss.complete` | 实例 | 通关 | `dungeon` `instance` `time_seconds` |
| `axs.abyss.player_complete` | 玩家 | 每名队员通关 | `dungeon` `instance` `time_seconds` `party-size` |
| `axs.abyss.fail` | 实例 | 失败 | `dungeon` `instance` `reason` |
| `axs.abyss.player_fail` | 玩家 | 每名队员失败 | `dungeon` `instance` `reason` |
| `axs.abyss.leave` | 玩家 | 离开副本 | `dungeon` `instance` `reason` |
| `axs.abyss.player_death` | 玩家 | 副本内死亡 | `dungeon` `instance` `deaths` |
| `axs.abyss.mob_kill` | 玩家 | 击杀副本怪 | `dungeon` `instance` `mob`（实体UUID） |
| `axs.abyss.mob_group_start` / `mob_group_complete` | 实例 | 怪物组开始/完成 | `dungeon` `instance` `group` |
| `axs.abyss.party_created` | 玩家(队长) | 建队 | `party` `mode` `max_size` |
| `axs.abyss.party_member_join` | 玩家(新成员) | 加入队伍 | `party` `mode` `size` |
| `axs.abyss.party_member_leave` | 玩家(离线为null) | 离开/被踢/移除 | `party` `mode` `reason`(quit/kick/removed) |
| `axs.abyss.party_disbanded` | null | 队伍解散 | `party` `mode` |
| `axs.abyss.party_leader_change` | 玩家(新队长) | 队长变更/移交 | `party` `mode` |
| `axs.abyss.global_change` | null | 全服计数每次变更 | `key` `value` `delta` `dungeon` `instance` `player` |
| `axs.abyss.global_threshold` | null | 全服计数首次跨越 `global-thresholds` 阈值 | `key` `value` `threshold` `dungeon` `instance` `player` |
| `axs.abyss.puzzle_step` | 玩家(触发者) | 机关每步正确推进 | `dungeon` `instance` `puzzle` `step` `steps` |
| `axs.abyss.puzzle_complete` | 玩家(触发者) | 机关完成 | `dungeon` `instance` `puzzle` |
| `axs.abyss.puzzle_fail` | 玩家(触发者) | 机关错误/锁定 | `dungeon` `instance` `puzzle` `reason`（miss_sequence/miss_input/locked） |
| `axs.abyss.guide_arrive` | 玩家 | 到达 `guide_point` 导航目标 | `dungeon` `instance` `nav` |
| `axs.abyss.buff_offer` | 玩家(触发者) | 增益池发起选择 | `dungeon` `instance` `pool` |
| `axs.abyss.buff_pick` | 玩家 | 增益生效（面板选择/hud 直发/超时兜底均发） | `dungeon` `instance` `pool` `option` |

> **职责边界**：`global_*` 系列只提供「持久化计数 + 事件出口」。阈值命中后的全服事件玩法（防守战/阵营混战/全服 Boss 等）由 eventpacket 规则、regions 区域规则或外部玩法模块订阅实现——abyss 不承载副本实例之外的世界状态。

战令任务示例（`battlepass` 任务配置）：

```yaml
event-topic: axs.abyss.player_complete
conditions:
  - "{dungeon} == skeleton_throne"
```

### abyss 消费的能力

脚本动作与 `links` 声明式联动按需解析以下 capability（见 [脚本系统·跨模块联动](/docs/abyss/scripting#跨模块联动) 与 [地牢模板·links](/docs/abyss/dungeons#links-跨模块联动)）：

| capability | 来源模块 | 用途 |
|---|---|---|
| `SignalDispatchable` | eventpacket | `signal` 动作 → 规则引擎 |
| `AnnouncerBroadcastable` | announcer | `announce_global` / `links.announce-clear` |
| `QQBotBroadcastable` | qqbot | `qq_group` / `links.qq-notify-clear` |
| `SubtitlePlayable` | subtitle | `subtitle` 动作 |
| `ChatCardSendable` | chat | `chat_card` 动作 |
| `CombatEffectTriggerable` | combateffect | `combat_effect` 动作 |
| `BattlePassAccess` | battlepass | `bp_task` 动作 |
| `MapNavigable` | map | `links.entrance` 地图入口标记+内置导航 |
| `EssentialsQueryable` | essentials | `recovery` 的 `teleport`（裸写=送回 spawn）/`afk-kick-minutes` |
| 属性桥 `AttributeBridgeRegistry` | 宿主 | `apply_attribute`/`remove_attribute` + 属性伤害/治疗计入战斗统计 |

### 队伍系统开放能力 `AbyssPartyAccess`

外部插件/其他模块可复用 abyss 的队伍数据结构与组队 UI（战区摸金、公会团本等场景）：

```java
AbyssPartyAccess parties = getCapability(AbyssPartyAccess.class);
if (parties != null) {
    // 建队：guild 模式、10 人上限（覆盖全局 party.max-members）
    var party = parties.createParty(leader, "公会一团", "guild", 10);
    // 同公会校验：注册后该模式队伍的任何加入路径（邀请/大厅/审批/直加）都会回调
    parties.registerJoinValidator("guild", (p, applicant) ->
        guildApi.sameGuild(p.leader(), applicant) ? null : "仅同公会成员可加入");
    // 直加成员（跳过邀请流程，仍过校验钩子）
    parties.addMember(party.id(), memberUuid);
}
```

| 能力 | 说明 |
|---|---|
| `partyOf` / `isInParty` / `isLeader` / `getParty` / `publicParties` | 队伍查询（返回 `PartySnapshot` 不可变视图：id/name/mode/leader/members/maxSize/dungeonId） |
| `createParty` | 编程式建队：`mode`（"free"自由/"guild"公会/自定义）+ 每队 `maxSize` 覆盖 |
| `addMember` / `removeMember` / `transferLeader` / `disband` | 成员管理（全部发 EventBus 事件） |
| `registerJoinValidator(mode, v)` | 按模式注册加入校验——同公会检查等由你的插件实现 |

副本侧配合：地牢模板 `requirements.party-mode: "guild"` 可限制该副本仅接受公会模式队伍进入（自由组队/无队伍被拒）；`party-required` 控制是否强制组队。

## 服务端兼容性

| 平台 | 状态 |
|---|---|
| Spigot / Paper 1.20.1+ | 完全支持（`api-version` 声明） |
| Mohist | 兼容：虚空世界用 `NORMAL + VoidGenerator` 生成（规避 Mohist 上 `WorldType.FLAT` 空 layers 配置报错）；玩家命令 `abyss`/`party` 在宿主 `plugin.yml` 静态声明，不依赖运行时 CommandMap 注册 |

> `abyss.nms-fast-load` 默认开启快速世界加载通道，在不支持的服务端上自动回退纯 Bukkit API，不会产生错误。

## 数据持久化

| 数据 | 存储 |
|---|---|
| 体力/冷却/通关记录/最佳时间 | SQLite（`data/abyss/abyss.db`）或 MySQL（`storage.mode`） |
| 排行榜 | 同上，按地牢独立榜单 |
| 副本实例/变量/会话态 | 纯内存，实例结束销毁 |

玩家掉线：副本内玩家退出时恢复并移出实例；HUD/宝箱 token 清理在 `handleQuit` 中无条件执行，不留会话态。

## 故障排查

| 现象 | 排查方向 |
|---|---|
| `/abyss` 未知命令 | 宿主 jar 未更新到含 `abyss`/`party` 声明的版本——这两个命令走 `plugin.yml` 静态声明，模块热更新不生效；更新宿主后重启 |
| `/abyss` 执行无响应 | UI 未注册：模块版本过旧（UI 注册在 `1b40ae61` 加入）或 `ui.register-on-enable: false`；检查服务端日志 `Abyss UI 注册` 相关行 |
| 进本后聊天栏疯狂重复消息 | 旧版本 `InteractManager` 防抖失效 + failMessage 无节流，已修复；升级模块 |
| `No key layers in MapLike[{}]` | Mohist + `WorldType.FLAT` 已知问题，已改 `VoidGenerator`，升级模块 |
| `[Script] JavaScript ScriptEngine 不可用` | 服务端无 Nashorn/GraalJS，`js:` 动作被跳过——避免用 `js:` 前缀（示例地牢未用） |
| `MythicBukkit 未安装` 警告 | `external-softdepends` 同时声明 MythicMobs/MythicBukkit 的正常提示，MM 接入不受影响 |
| MythicMobs 怪物没刷出/变成原版怪 | MM 加载失败自动回退原版，检查服务端日志 `MythicMobs` 接入行与怪物 ID 拼写 |
| 宝箱二次打开残留旧图标 | 旧版本 `seticon` 未显式触发，已修复（属性声明 + init 显式 `seticon()`） |
| 离线队员踢不掉 | 旧版本按名字查找，已改为 UUID 优先 |
| 世界实例残留不删 | `instance-cleanup-timeout` 过长或实例未正常结束；`/axs abyss status` 看实例，`/axs abyss cancel <地牢>` 强制清 |

## 已知限制

- `js:` 内联脚本需服务端装 Nashorn/GraalJS，默认 Java 17 不含 JS 引擎（Aria 脚本 `aria:` 不受影响）
- 排行榜/统计 UI 需 ArcartX 客户端，无客户端时数据仍落库但不可视化
- schematic 世界来源需 WorldEdit/FAWE，未装时该类型模板无法加载（`void`/文件夹来源不受影响）
