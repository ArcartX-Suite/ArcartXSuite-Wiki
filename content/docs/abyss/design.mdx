设计模式用于编辑地牢草稿。它会打开可编辑的设计世界，关卡玩法暂停。下面沿用[按钮开战示例](/docs/abyss/walkthrough)的 ID，让面板字段与文件对应。

## 进入前准备

先用 `/abyss list` 确认地牢已加载。用 `/axs abyss design <地牢ID>` 进入设计会话，用 `/axs abyss design ui` 重开面板。

选择已有对象再改值。新增引用前先创建目标对象，例如先建 `guards` 怪组，再把它选作阶段的刷怪目标。中文显示名与对象 ID 分别填写。

## 面板中改什么

| 面板区域 | 修改内容 | 对应文件 |
| --- | --- | --- |
| 楼层路线 | 选择本层引用的房间、入口与终点 | `floors.yml`、`rooms.yml` |
| 流程阶段 | 入口阶段、完成条件、超时与后继分支 | `stages.yml` |
| 生命周期与流程段 | 开局、完成、失败和自定义动作段 | `scripts.yml` |
| 怪组和交互对象 | 生成点、触发方式、操作条件及事件动作 | `monsters.yml`、`interacts.yml` 等 |
| 结算设置 | 通关与失败的退出方式、倒计时及显示 | 模板 `config.yml/settlement` |
| 试跑追踪 | 阅读当前草稿执行记录 | 用于验证本轮草稿 |

### 文字、数字、开关与坐标

文字或数字输入后确认提交，再检查字段是否显示新值。循环选择项通过按钮切换。坐标和区域字段使用「重新标记」在设计世界内选位置。取点前确认当前对象使用的是世界坐标、房间相对坐标还是随机构件锚点。

脚本行可上移、下移。添加后检查它位于正确事件，怪组生成时与完成时的动作分别配置。

## 第一步：配置开战阶段

在「流程阶段」中建立 `prepare` 和 `wave`。

1. 把 `prepare` 设为入口，显示名填“等待开战”。
2. 完成条件选「手动推进」，让它等待按钮。
3. 动作选「提示」，执行对象选 `@all`，内容填“请按入口按钮”，添加到进入时动作。
4. 后继分支选择 `wave`，条件选「无条件」，确认追加。

设为入口会使其他阶段失去入口标记。查看别的阶段时，不必重新设置入口。

## 第二步：给战斗阶段添加动作

选择 `wave`，完成条件选「怪组清空」，引用 `guards`。

动作选「刷怪」，目标从草稿选 `guards`，追加到进入时。`guards` 自身设为 `MANUAL`，由阶段统一生成。要在清完时给提示，切换动作时机到完成，再添加「提示」。

| 动作表单 | 参数 | 使用场景 | 可替换示例 |
| --- | --- | --- | --- |
| 提示、动作栏 | 执行对象、文字 | 通知当前目标 | `message @all &e前往入口` |
| 刷怪、清除怪组 | 已有怪组 ID | 生成本波或显式跳过本波 | `spawn_group guards` |
| 设置变量、增减变量 | 变量名、数值或文本 | 保存机关选择、累计次数 | `setvar bonus 1` |
| 调用流程段 | 已有自定义流程段 | 复用多处相同动作 | `run_script warning` |
| 延时调用流程段 | 秒数、已有自定义流程段 | 稍后触发预告或增援，当前动作继续 | `delay 3 run_script warning` |
| 等待 | 秒数 | 暂停当前动作列表，之后继续下一行 | `wait 3` |
| 发奖励、开奖励箱 | 执行对象、奖励集或宝箱 ID | 发放或主动领取 | `grant_reward @all clear_pack` |
| 跳到阶段 | 已有阶段 ID | 切换流程并结束当前分支 | `flow_jump finish` |

标题的淡入、停留、淡出用 tick。音效填写 ID、音量和音调。导航点填写 ID、`x,y,z`、到达半径和文字。添加后检查动作行，精确写法见[脚本动作参考](/docs/abyss/scripting#动作清单)。

## 第三步：添加路线条件

阶段完成条件控制“什么时候完成”，分支条件控制“完成后去哪里”。先建立 `extra` 和 `finish`，再给 `wave` 添加后继。

1. 第一分支指向 `extra`，按变量或目标选择条件。
2. 第二分支指向 `finish`，条件选「无条件」作为兜底。
3. 检查顺序。无条件分支位于前面时，后面的分支不会命中。

「变量成立」适合布尔标记。需要 `var:bonus == 1` 这样的比较式时，按[阶段字段](/docs/abyss/stages)在 YAML 填写精确条件，保存并重开设计会话核对。

## 第四步：复用流程段

在「生命周期与流程段」建立 `warning`，添加面向全员的提示。到调用事件选择「延时调用流程段」，填 `3` 秒并选择 `warning`，确认后应看到 `delay 3 run_script warning`。

固定生命周期段可以清空动作。自定义段改名后，同步检查所有调用方。造地形放 `world-init`，开战提示放 `start`，完成奖励放 `complete`，避免多个机关发同一份奖励。

## 第五步：注入事件并读追踪

从当前草稿开始一轮试跑，选择对象的「试跑事件」注入，再看「试跑追踪」。本轮使用开始时的草稿快照。改配置后开始新一轮，避免用旧快照判断新修改。

| 操作 | 预期记录 |
| --- | --- |
| 开始试跑 | 初始化、开始动作，以及进入 `prepare` |
| 注入入口按钮脚本事件 | 变量守卫生效，进入 `wave` |
| 注入 `guards` 的 `on-end` | 清怪条件成立，命中普通或额外分支 |
| 若有额外战斗，注入 `elite` 的 `on-end` | 进入 `finish` 并通关 |
| 另开一轮，等待阶段超时 | 执行超时动作并失败 |

即使怪组的完成动作列表为空，也可注入其完成事件。试跑的变量操作、等待、流程段调用和阶段跳转会参与判断，世界修改、奖励和外部动作只记录。需要实时玩家或脚本引擎环境的条件可能显示为跳过，需进真实测试本确认。

动作正在等待时，先等它结束再注入。出现“该事件不在试跑快照中”时重启本轮。动作预算耗尽时，检查无条件阶段循环和相互调用的流程段。

## 保存和正式验证

`/axs abyss design save` 回写配置并重载模板。若修改了要带回模板的世界方块，使用 `/axs abyss design save world`。`/axs abyss design exit` 会丢弃未保存修改。

随机构件的锚点要标在构件内部。保存更新共享构件定义，同名构件都会采用它。

重新进入真实副本，确认按钮只生效一次、怪物实际生成、门能开关、奖励到账和退出倒计时。先验证单人，再验证队伍成员先后操作同一个机关的情况。
