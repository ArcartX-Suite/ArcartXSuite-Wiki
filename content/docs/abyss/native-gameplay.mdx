Abyss 自带本局战术面板。玩家通过 `/abyss run` 或队伍面板的“本局战术”打开，
无需安装 XC。公开接口与原生玩法共用额度、发奖记录和撤离回执。

## 玩家操作

| 入口 | 操作 |
| --- | --- |
| `/abyss run`、`/abyss rescue` | 打开自救与队友救援列表 |
| `/abyss loot` | 查看当前局或最近一局已登记的战利品 |
| 队伍面板“本局战术” | 打开战术面板 |
| 结算面板“战利品” | 打开本局战利品页 |
| 战术面板“离开副本”、`/abyss leave` | 使用持久化撤离流程 |

阵亡后面板会自动打开。点击“自救”或阵亡队友的条目开始读条，面板关闭后
在行动栏显示剩余时间。保持原位，移动超过半格、受伤、离场、断线或目标状态变化会中断救援。
中断发生在提交前会释放额度。开始确认结果后以服务端回执为准。

每次成功救援消耗**被救成员**的一次本局额度。自救与被队友救起共用该额度，
例如每人两次时，自救一次后还可被队友救起一次。队友救援要求救援者存活。
多人同时救同一目标只会有一次成功预留。界面关闭、重复点击或重新打开不会生成新的成功扣减。

全队阵亡后进入配置的自救窗口。窗口内有人成功恢复，当前团灭倒计时取消。
再次团灭会重新计算窗口。窗口到期仍无人恢复，才执行 `all-death` 流程并判负。
关闭自救或原生救援时，继续采用原有团灭策略。

## 服主配置

在流程工作台的结算设置中配置额度、启用原生救援、允许自救、读条时长、
队友距离和团灭自救窗口。通关和失败两个表单同步显示同一组救援设置。

也可在副本 `config.yml` 使用以下配置。

```yaml
requirements:
  revive-limit: 2
  native-rescue:
    enabled: true
    allow-self: true
    channel-seconds: 5
    range: 0
    wipe-window-seconds: 15
```

| 字段 | 范围与含义 |
| --- | --- |
| `revive-limit` | 每人每局 0～1000 次，0 为关闭 |
| `enabled` | 原生救援开关，旧副本缺省为 false |
| `allow-self` | 允许阵亡者自救，缺省为 true |
| `channel-seconds` | 1～20 秒，缺省 5 秒 |
| `range` | 0～128 格，0 表示同世界内不限距，大于 0 按玩家当前位置限制 |
| `wipe-window-seconds` | 1～120 秒，启用自救时须比读条至少长 2 秒 |

原生玩法不需要配置 `external-control-owner`。第三方接入仍按
[救援公开接口](/docs/api/AbyssReviveAccess)验证外部 owner。
已有的自动复活脚本需要与原生救援协调，避免读条前先被脚本复活。

`example` 与 `procgen` 自带示例均配置两次额度、五秒读条和十五秒自救窗口。
`example` 原有八秒自动复活已改为原生救援提示。保留了原通关奖励、翻牌、转盘和三选一入口。
已有服务器的示例文件按资源导出策略保留，需通过工作台开启或同步新版配置。

## 战利品和撤离

战利品页按玩家权限过滤，支持翻页、刷新及局结束后的回看。最近一局索引在本功能启用后
新建正式副本时保存，断线重进后仍可查询。读取失败、无权限和记录变化会显示明确提示。

当前展示命名奖励、标准宝箱和已选中的奖励玩法条目，区分待发放、宿主已接收和已发放。
地面物品仍需在副本内拾取。实际领取沿用宝箱、结算奖励按钮或 `/abyss rewards`。
战利品行保持只读。

撤离只处理点击者，执行副本原有离场清理。重复点击会补查原操作，
返回传送未完成时可继续重试。旧面板不会撤离刚进入的另一个副本。
团灭和正常结算仍遵循配置的退出策略。

救援结果未知时保留原操作编号并显示待核账，重新打开或刷新战术面板会补查，
不通过重新生成操作编号来补做一次复活。
