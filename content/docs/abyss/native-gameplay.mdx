title: "自救、救援与本局战术"
description: "使用 Abyss 自带面板配置并体验救援、战利品回顾和撤离。"
---

执行 `/abyss run`，或点击队伍面板的“本局战术”，即可打开战术面板。玩家可在这里自救、救援队友、查看战利品或离开副本。

## 玩家操作

| 入口 | 操作 |
| --- | --- |
| `/abyss run`、`/abyss rescue` | 打开自救与队友救援列表 |
| `/abyss loot` | 查看当前局或最近一局已登记的战利品 |
| 队伍面板“本局战术” | 打开战术面板 |
| 结算面板“战利品” | 打开本局战利品页 |
| 战术面板“离开副本”、`/abyss leave` | 离开副本并返回安全位置 |

阵亡后面板会自动打开。若游戏仍显示原版死亡界面，先完成重生，再选择自救。点击“自救”或阵亡队友的条目开始读条，面板关闭后
在行动栏显示剩余时间。保持原位，移动超过半格、受伤、离场、断线或目标状态变化会中断救援。
中断发生在提交前会释放额度。开始确认结果后以服务端回执为准。

每次成功救援消耗**被救成员**的一次本局额度。自救与被队友救起共用该额度，
例如每人两次时，自救一次后还可被队友救起一次。队友救援要求救援者存活。
多人同时救同一目标只会有一次成功预留。界面关闭、重复点击或重新打开不会生成新的成功扣减。

全队阵亡后进入配置的自救窗口。窗口内有人成功恢复，当前团灭倒计时取消。
再次团灭会重新计算窗口。窗口到期仍无人恢复，才执行 `all-death` 流程并判负。
关闭自救或原生救援时，团灭后直接按副本的团灭设置处理。

## 服主配置

在流程工作台的结算设置中配置额度、启用原生救援、允许自救、读条时长、
队友距离和团灭自救窗口。通关和失败两个表单同步显示同一组救援设置。

也可在副本 `config.yml` 使用以下配置。

```yaml
requirements:
  revive-limit: 2
  native-rescue:
    enabled: true
    allow-self: true
    channel-seconds: 5
    range: 0
    wipe-window-seconds: 15
```

| 字段 | 范围与含义 |
| --- | --- |
| `revive-limit` | 每人每局 0～1000 次，0 为关闭 |
| `native-rescue.enabled` | 启用救援，默认 `false` |
| `native-rescue.allow-self` | 允许阵亡者自救，默认 `true` |
| `native-rescue.channel-seconds` | 读条时长为 1～20 秒，默认 5 秒 |
| `native-rescue.range` | 救援距离为 0～128 格。默认 0，表示同世界内不限距离 |
| `native-rescue.wipe-window-seconds` | 团灭自救窗口为 1～120 秒，默认 15 秒。启用自救时须比读条至少长 2 秒 |

如果副本配置了自动复活脚本，请检查其触发时机，避免脚本在玩家完成救援读条前复活目标。

`example` 与 `procgen` 示例均配置每人每局两次额度、五秒读条和十五秒自救窗口。以服务器实际加载的副本配置为准。

## 战利品和撤离

战利品页按成员身份显示可查看的奖励。支持翻页、刷新及结束后查看最近一局。读取失败、无权限或记录发生变化时，界面会提示原因。

当前展示命名奖励、标准宝箱和已选中的奖励玩法条目。内置奖励可显示待发放或宿主已接收，实际到账请查看对应的背包、仓库、邮件或余额。
地面物品仍需在副本内拾取。实际领取沿用宝箱、结算奖励按钮或 `/abyss rewards`。
战利品行保持只读。

撤离操作只处理发起者。重复点击时会查询原操作。界面提示返回传送未完成时，可以再次尝试。等待撤离结果期间，该成员不能发起或接受救援。
团灭和正常结算仍遵循配置的退出策略。

救援结果未知时保留原操作编号并显示待核账，重新打开或刷新战术面板会补查，
不通过重新生成操作编号来补做一次复活。
