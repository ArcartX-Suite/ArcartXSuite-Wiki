# 地牢模板编写

每个地牢是 `plugins/ArcartX-Suite/data/abyss/abysses/<地牢ID>/` 下的一个目录，目录名即地牢 ID（建议小写英文+下划线）。模块首次启动会自动导出 `abysses/example/` 示例地牢——直接复制改配置即可得到新副本。

## 目录结构

```
abysses/<地牢ID>/
├── config.yml       ← 地牢基本信息（必需）
├── monsters.yml     ← 怪物组/波次
├── scripts.yml      ← 生命周期脚本
├── tasks.yml        ← 副本内定时/事件任务
├── interacts.yml    ← 交互点
├── obstacles.yml    ← 障碍物
├── npcs.yml         ← 副本 NPC
├── quests.yml       ← 副本任务
├── rewards.yml      ← 奖励集/宝箱
├── floors.yml       ← 楼层定义（mode: floors 多层房间地牢）
├── rooms.yml        ← 房间模板池（floors 模式）
└── world/           ← 世界文件夹（可选，含 level.dat）
```

> 除 `config.yml` 外所有文件均可省略，缺失时使用空配置。

## config.yml — 地牢主配置

```yaml
name: "&6虚空试炼场"           # 显示名（支持 & 颜色码）
icon: "END_STONE"            # 浏览器卡片图标（Material 名）
difficulty: "简单"            # 难度标签（显示用）
description:                  # 描述（列表，逐行显示在详情面板）
  - "&7在虚空平台上击退两波怪物"

world:
  template: "void"           # 世界来源，见下表
  spawn: "0,80,0,90,0"       # 出生点 x,y,z,yaw,pitch（副本世界坐标）
  # 世界治理（可选）：gamerule 覆盖 / 自然刷怪控制 / 副本级命令控制
  gamerules:                 # Bukkit GameRule 名 → 值（布尔或整数），叠加在模块默认规则之上
    keepInventory: true
    mobGriefing: false
  disable-natural-spawn: true        # 禁环境驱动刷怪（脚本刷怪走 CUSTOM 不受影响）
  disabled-spawn-reasons: []         # 额外禁用的 SpawnReason 名（可含 CUSTOM）
  command-control:                   # 副本级命令控制（覆盖全局 restrictions.command-mode）
    mode: "inherit"                  # inherit=沿用全局 / blacklist / whitelist
    commands: []                     # mode 非 inherit 时的黑/白名单（按主命令匹配）

time-limit: 600              # 限时（秒），超时触发 timeout-action
timeout-action: "FAIL"       # FAIL=判负 / KICK=踢出
max-instances: 0             # 该地牢最大并行实例数，0=不限

requirements:
  min-players: 1             # 最小进本人数
  max-players: 4             # 最大进本人数
  party-required: false      # 是否必须组队
  party-mode: ""             # 要求队伍模式（空=不限；"guild"=仅公会模式队伍，自由组队被拒）
  min-level: 0               # 最低玩家等级（0=不限）
  max-level: 0               # 最高等级（0=不限）
  cooldown: 300              # 通关冷却（秒），按玩家+地牢独立计时
  money-cost: 0              # 货币消耗
  currency-id: "money"       # 货币 ID（宿主 currencies 定义）
  stamina-cost: 10           # 体力消耗
  required-items: []         # 进本消耗物品列表
  required-permissions: []   # 需要的权限节点
  conditions: []             # PAPI 条件表达式（如 "%player_level% >= 10"）
  require-all-players: true  # false=物品/货币/权限/条件只校验队长（队长买单全队进）
  leader-conditions: []      # 仅队长需要满足的额外条件（PAPI 表达式）
  disabled-commands: [spawn] # 本副本额外禁用命令（绝对黑名单，叠加于命令控制之上）
  disabled-items: []         # 本副本额外禁用物品

links:                       # 跨模块联动（全部可选，模块缺席自动跳过）
  entrance: "world;100,64,-50"          # 地牢入口地图标记 "世界;x,y,z"（map 模块紫色外部目标+内置导航）
  announce-clear: "&6{party} 通关 {dungeon}&6，用时 &f{time}&6！"  # 通关全服播报（announcer 模块）
  announce-forward: false               # 播报是否跨服转发
  qq-notify-clear: false                # 通关推 QQ 群（qqbot 模块）
  qq-group: 0                           # 指定群号，<=0=全部已配置群

# 作战方案：进本前选择，影响本局怪组/脚本分支（详见「plans 作战方案」节）
plans:
  strong:
    name: "&c强攻·正面突破"
    lore: ["怪群密集，需火力压制", "掉落倾向：弹药/武器件"]
  sneak:
    name: "&b潜入·暗杀优先"
    lore: ["敌人分散警觉，需潜行", "掉落倾向：稀有材料/情报"]

# 世界入口点：主世界/场景里的物理入口，右键触发进本（详见「entrances 世界入口点」节）
entrances:
  - world: world                 # 入口所在世界（非副本世界）
    location: "100,64,-50"       # 方块坐标（与 region 二选一，可都填）
    name: "正门"
  - world: world
    region: "90,60,-60;95,70,-55"  # 立方区域（区域内任意方块右键都触发）
    plan: strong                 # 固定方案（可选；不配且 plans>1 → 弹方案选择菜单）
    name: "侧墙裂缝"
```

### links 跨模块联动

声明式联动——不写脚本即可接其他模块。`announce-clear` 支持占位 `{party}`（队伍名）、`{dungeon}`（地牢显示名）、`{time}`（用时）。如需更细粒度（首通播报、成员名单、自定义条件），在 `scripts.yml` 生命周期脚本里用 `signal`/`announce_global`/`qq_group`/`bp_task` 等联动动作（见 [脚本系统](/docs/abyss/scripting#跨模块联动)）。

`entrance` 推送为地图紫色外部目标，玩家可在地图面板点"导航"，由地图内置导航栈寻路（不占玩家路径点上限）；入口指向主城等固定世界坐标，不要指向副本世界内部。

> **地图标记 vs 物理入口**：`links.entrance` 只是地图上的导航标记（指路用）；真正右键进本要配下面的 `entrances` 世界入口点。两者通常指向同一位置。

### plans 作战方案

进本前选择的作战方案（如"强攻/潜入/破局"），影响本局怪组与脚本分支，**不影响剧情走向**。

- **定义**：`plans` 节每个 key 是方案 id，`name` 显示名（支持 `&`）、`lore` 描述行（菜单展示用）
- **选择入口**（三处都生效）：
  - 命令：`/abyss enter <地牢> <方案id>`
  - 入口点 `plan:` 字段固定方案（适合"不同物理入口=不同打法"）
  - 入口点不配 `plan` 且方案多于一个时，点击者收到**可点击的方案选择菜单**（聊天栏，点击自动执行进本命令）
- **不选方案**：模板定义了 plans 但没指定时，默认取第一个方案
- **实例变量**：进本后 `{plan}`=方案 id、`{plan_name}`=显示名，可在脚本/消息文本中引用
- **事件**：`axs.abyss.enter` / `axs.abyss.player_enter` 的 payload 附带 `plan`

**方案怎么影响玩法**（两条路，可混用）：

1. **怪组过滤**——`monsters.yml` 和 `rooms.yml` 的怪物组加 `plans: [方案id]` 字段后，只有该方案进本才注册此组。不同方案刷完全不同的怪群：
   ```yaml
   wave_assault:              # 只在"强攻"方案出现
     plans: [strong]
     spawn-timing: AUTO_START
     monsters: [...]
   ```
2. **脚本分支**——`{plan}` 变量配合 `check` 动作分流奖励/机制：
   ```yaml
   on-end:
     - "check @trigger var:plan == strong"      # 仅强攻方案继续往下走
     - "grant_reward @trigger ammo_cache"        # 强攻掉弹药箱
   ```

### entrances 世界入口点

主世界/场景里的**物理进本点**——玩家右键登记的方块（或区域内任意方块）触发进本，命中后交互事件自动取消（门/箱子不会真的打开）。

- `world`：入口所在世界名（主世界场景，**不是**副本世界——副本世界名带 `axs_abyss_` 前缀且是实例世界）
- `location`：单点 `"x,y,z"`；`region`：立方区域 `"x1,y1,z1;x2,y2,z2"`——两者可都填，同一入口多点命中
- `plan`：可选，固定方案 id（对应 `plans` 键名）；不配且模板多方案 → 弹方案菜单
- `name`：可选显示名
- **队伍带入**：点击者是队长且有队员 → 自动带全队进本（沿用进本条件校验：体力/冷却/道具按 `require-all-players` 规则判定）
- 进本失败（条件不满足/冷却中/实例满等）会给点击者发失败原因
- 与 `links.entrance` 地图标记独立，建议配合使用：地图指路 + 到点右键进本

### world.template（世界来源）

| 值 | 说明 |
|---|---|
| `void` | 生成虚空世界（全空气），用 `init` 脚本现场搭场景。零依赖最简方案 |
| 目录名 | `abysses/<地牢ID>/world/` 下的完整世界存档文件夹（需含 `level.dat`），逐实例复制 |
| `maps/<名>` 或 `.schem` | WorldEdit/FAWE schematic，粘贴到虚空世界。需安装 WorldEdit 或 FAWE |

### world 世界治理

- `gamerules`：按副本覆盖游戏规则（如 `keepInventory`、`randomTickSpeed`），未知规则名自动跳过；模块默认已内置一套副本规则（关日夜/天气/火焰蔓延/自然刷怪、keepInventory=true 等）
- `disable-natural-spawn`：拦截自然/刷怪笼/巡逻/袭击等环境驱动生成；副本脚本刷怪走 `CUSTOM` 来源不受影响
- `disabled-spawn-reasons`：按 `CreatureSpawnEvent.SpawnReason` 名精确禁用（含 `CUSTOM`，可彻底锁死生成）
- `command-control`：副本级命令黑/白名单，`mode: inherit` 时沿用全局 `restrictions.command-mode`；`whitelist` 适合 PVP/硬核副本「只许用这几个命令」

## monsters.yml — 怪物组/波次

顶层每个 key 是一个怪物组 ID，组内 `monsters` 为刷怪点列表：

```yaml
wave_1:
  spawn-timing: AUTO_START            # 触发方式，见下表
  monsters:
    - mob-id: "vanilla:ZOMBIE"        # vanilla: 强制原版 / 无前缀走 MythicMobs
      location: "3,80,3"              # x,y,z
      amount: 3
  complete-when-alive-below: 0        # 存活数低于此值时组完成
  plans: []                           # 限定作战方案 id 列表（空=所有方案都刷；见 plans 作战方案）
  on-start:                           # 组开始时执行的脚本动作
    - "message @all &e第一波来袭！"
  on-end:                             # 组完成时执行
    - "spawn_group wave_2"
```

| spawn-timing | 触发时机 |
|---|---|
| `AUTO_START` | 副本 start 脚本后自动刷 |
| `DELAYED` | 延迟触发（配合 `trigger-after` 或脚本） |
| `TRIGGERED` | 由其他组的 `on-end` 中 `spawn_group <组>` 触发 |
| `MANUAL` / `SCRIPTED` | 仅脚本动作 `spawn_group` 触发 |

`mob-id` 路由规则：`vanilla:` 前缀强制原版；其余尝试 MythicMobs，加载失败自动回退原版同类型实体。

## tasks.yml — 副本内任务

```yaml
tips:
  type: TIMED                        # 指定秒数触发
  times: [60, 300, 540]
  timed-scripts:
    60: ["message @all &7已进行 1 分钟"]
    300: ["message @all &e时间过半！"]

supply:
  type: INTERVAL                     # 循环任务
  interval: 120                      # 每 120 秒
  script:
    - "message @all &7补给已投放"

on_kill:
  type: EVENT                        # 事件任务
  event: monster_kill                # 怪物被击杀
  script:
    - "setvar last_killer {killer}"
```

| type | 触发方式 |
|---|---|
| `TIMED` | 副本进行到 `times` 列出的秒数时执行对应 `timed-scripts` |
| `INTERVAL` | 每 `interval` 秒循环执行 `script` |
| `EVENT` | 指定事件发生时执行（如 `monster_kill`，上下文含 `{killer}`） |

## interacts.yml — 交互点

```yaml
trial_chest:
  type: RIGHT_CLICK_BLOCK            # 见下表
  location: "5,80,5"                 # 方块坐标（方块型用）
  region: ["0,60,0", "20,80,20"]     # 区域对角（区域型用）
  entity-name: "宝箱守卫"             # 实体名（RIGHT_CLICK_ENTITY 用）
  required-block: "GOLD_BLOCK"       # 要求的目标方块
  once: true                         # 一次性触发
  conditions: []                     # PAPI 条件
  fail-message: "&c条件不满足"        # 条件失败提示（独立 5 秒节流）
  script:                            # 触发时执行
    - "open_chest_ui @trigger trial_chest"
```

| type | 说明 |
|---|---|
| `RIGHT_CLICK_BLOCK` / `LEFT_CLICK_BLOCK` | 右键/左键 `location` 处指定方块 |
| `BREAK_BLOCK` / `PLACE_BLOCK` | 破坏/放置 `location` 处方块 |
| `STEP_ON` | 站上 `location` 处方块 |
| `ENTER_REGION` | 进入 `region` 区域（边沿触发，离开后再进可重触发） |
| `RIGHT_CLICK_ENTITY` | 右键名为 `entity-name` 的实体 |

> 防抖：同一玩家对同一交互点 500ms 内不重复触发；条件失败的提示消息独立节流 5 秒。

## puzzles.yml — 机关解谜

每个地牢目录可放 `puzzles.yml` 定义实例级机关——状态随副本创建/销毁，不占主世界。两种类型：

- `sequence` — 按顺序触发一组 interact 点名（压力阀/符文顺序/接线板）
- `input` — 弹 ArcartX 输入面板，玩家键盘输入密码/口令（电梯通行码）

```yaml
# 序列型：按 4-2-1-3 顺序点阀门
valve_sequence:
  name: "冷却阀序列"
  type: sequence
  steps: [valve_4, valve_2, valve_1, valve_3]   # interacts.yml 中的点名（可重复）
  reset-on-miss: true          # 点错顺序→清空进度重来；false=错序只惩罚不回退
  miss-limit: 5                # 累计错序上限（0=不限）；超限→on-fail 并锁定
  on-step:                     # 每步正确执行
    - "sound @trigger ui.button.click 1 1.6"
    - "title @trigger &a阀门 {var:puzzle.valve_sequence}/4 已开启"
  on-miss:                     # 错序惩罚
    - "subtitle @all &c阀门顺序错误"
    - "spawn_group noise_lure"
  on-complete:
    - "delete_obstacle pump_door"
  on-fail:
    - "broadcast &c控制台已锁定"

# 输入型：加密电梯四位码
elevator_code:
  name: "加密电梯终端"
  type: input
  answer: "4312"               # 正确答案（仅服务端比对，永不下发客户端）
  case-sensitive: false        # 大小写敏感
  length: 4                    # 输入框最大长度（0=不限）
  input-pattern: "^[0-9]*$"    # 客户端字符过滤正则（可删）
  title: "加密电梯终端"         # 面板标题（空用 name）
  hint: "输入四位通行码"        # 输入框空提示
  masked: true                 # 掩码显示（*）
  max-attempts: 3              # 允许错误次数（0=不限；超限→on-fail+锁定）
  per-player: false            # true=每人独立计次；false=全队共享额度
  on-miss: ["title @trigger &c通行码错误"]
  on-complete: ["delete_obstacle elevator_gate"]
  on-fail: ["broadcast &c终端已锁定"]
```

### 联动方式

- **步骤点名** = `interacts.yml` 键名。interact 触发成功即上报谜题系统——步骤点可以不挂 `script`（纯机关点），也可以同时挂脚本做额外反馈
- **input 面板入口**：interact/NPC 脚本里用 `puzzle_prompt <机关id>` 打开；指定玩家用 `puzzle_prompt_player <玩家|@all> <机关id>`
- **实例变量**：`{var:puzzle.<id>}`=进度（sequence=步数/input=尝试次数）、`{var:puzzle.<id>.done}`="1"、`{var:puzzle.<id>.locked}`="1"
- **事件**：`axs.abyss.puzzle_step` / `axs.abyss.puzzle_complete` / `axs.abyss.puzzle_fail`（`reason`: `miss_sequence`/`miss_input`/`locked`）
- **管理/脚本动作**：`puzzle_reset` / `puzzle_solve` / `puzzle_state <id> <变量>` —— 跳关、动态重置、状态读取
- **安全模型**：答案只在服务端比对；UI 提交需 action_token + 玩家实例校验，伪造包/跨实例提交无效

### 管理员局内操作

```
/axs abyss puzzle                  # 列出当前实例全部机关状态
/axs abyss puzzle <id>             # 单机关详情（类型/进度/步数）
/axs abyss puzzle <id> reset       # 重置进度+解锁
/axs abyss puzzle <id> solve       # 直接判定完成（触发 on-complete）
/axs abyss puzzle <id> fail        # 强制锁定（触发 on-fail）
/axs abyss puzzle <id> prompt [玩家]  # 给玩家打开输入面板（测试用）
```

所有操作**只改当前实例内存状态**，不写回 `puzzles.yml`——局内调试完不影响下个副本实例。

## buffs.yml — 增益选择池

roguelike 式"祝福"系统：清房/层间/神龛交互等时机，给玩家弹**三选一增益卡片**（或静默按权重直接生效）。触发不写在本文件——在任何生命周期段 / interact / 机关脚本里用 `buff_offer <池id>` 动作发起，时机完全由编排决定。

```yaml
pools:
  room_blessing:
    name: "房间肃清祝福"          # 面板标题
    pick: 1                     # 每玩家选一个
    candidates: 3               # 候选数（<=0=全显；按 weight 加权抽取，不重复）
    presentation: panel         # panel=AX 卡片面板 / hud=不弹窗直接生效
    timeout: 20                 # 选择限时秒（0=不限）
    timeout-auto: random        # 超时兜底：first|random|none
    once-per-instance: false    # true=本池每实例只能 offer 一次
    options:
      - id: sharp_edge
        name: "&c利刃"
        icon: IRON_SWORD        # 物品材质名 → 卡片图标（可空）
        rarity: rare            # common|rare|epic|legendary → 描边色
        weight: 10              # 抽中权重
        desc: ["攻击伤害 +15%"]  # 面板最多显示前 3 行
        effects:                # 脚本行（全动作可用，@trigger=选择者）
          - "apply_attribute @trigger attack_damage 15 percent"
          - "message @trigger &d✦ &c利刃 &7已生效"
```

### 效果三通道

`effects` 是完整脚本行列表，落地路径全走现有机制：

- **药水**：`apply_potion @trigger SPEED 1 9999`
- **属性加成**：`apply_attribute @trigger <属性> <值> [percent]`（Symphony/AttributePlus/MythicLib/Crane 统一属性桥，装了哪个走哪个）
- **变量驱动**：`setvar buff_ember_mark 1` —— 伤害加成/特殊机制在怪物组/武器脚本里 `check` 变量分支实现，策划自由度最大

### 触发方式（脚本动作）

```yaml
# rooms.yml 清房后
on-clear:
  - "buff_offer room_blessing"

# floors.yml 层进入 / interact 神龛点击 / 机关完成同理
on-enter:

```

`buff_grant <池id> <选择器> [optionId]` 直接赋予不弹窗（剧情强制增益/调试）；`buff_clear <池id>` 撤下未完成的待选面板。

### 联动

- **实例变量**：`{var:buff.<poolId>}`=最近所选 option id、`{var:buff.<poolId>.count}`=已发放人次
- **事件**：`axs.abyss.buff_offer` / `axs.abyss.buff_pick`（payload 含 `pool`/`option`）
- **超时**：`timeout` 到时按 `timeout-auto` 兜底，客户端面板自动关闭

## obstacles.yml — 障碍物

障碍物是副本开始时自动放置的方块组，可用于封路/边界/装饰：

```yaml
edge_wall:
  blocks:
    - "-7,79,-7,BEDROCK"             # x,y,z,Material
    - "-7,79,7,BEDROCK"
  auto-create: true                  # 副本开始时自动放置
  trigger-mode: NONE                 # NONE / ENTER / LEAVE / PERSIST
  on-delete: []                      # 障碍移除时执行的脚本
```

| trigger-mode | 说明 |
|---|---|
| `NONE` | 纯方块组，无触发 |
| `ENTER` / `LEAVE` | 玩家进入/离开障碍区域时触发脚本 |
| `PERSIST` | 玩家在区域内持续期间按周期触发 |

脚本可用 `create_obstacle <名>` / `delete_obstacle <名>` 动态控制。

## npcs.yml — 副本 NPC

```yaml
guide:
  name: "&e向导·艾琳"                # 显示名
  type: VILLAGER                     # 实体类型；有 Adyeshach 时可写 PLAYER
  location: "0,80,-5,0,0"            # x,y,z,yaw,pitch
  look-at-player: true               # 注视附近玩家
  dialogs:                           # 右键时逐句播放的对话
    - "&e欢迎来到虚空试炼场！"
  dialog-interval: 40                # 对话间隔（tick）
  click-script:                      # 右键时执行的脚本
    - "quest_step slay_guard"
  once: false
```

> 装 Adyeshach 时 NPC 用其渲染（支持 PLAYER 皮肤型）；未装时退化为原版实体。

## quests.yml — 副本任务

副本任务采用「NPC 接取/条件提交」模型，与 Chemdah 等外部任务插件无关：

```yaml
slay_guard:
  name: "讨伐虚空怪物"
  description: "击杀 5 只副本怪物后回来找向导领取报酬"
  accept-text: "&e[艾琳] &f拜托了！击杀 5 只怪物后回来找我。"
  accept-script:
    - "message @trigger &a已接取任务"
  submit-text: "&e[艾琳] &f这是说好的报酬。"
  submit-conditions:
    - "%axsabyss_dungeon_kills% >= 5"   # PAPI 条件
  submit-script:
    - "grant_reward @trigger quest_pack"
```

配合脚本动作：`quest_step <任务>`（未接取→接取，已接取→提交，推荐 NPC `click-script` 用）、`accept_quest` / `submit_quest` / `quest_status`。

## rewards.yml — 奖励集与宝箱

### 命名奖励集

`grant_reward <集名>` 脚本动作调用：

```yaml
rewards:
  clear_pack:
    items:
      - "material:DIAMOND:3"         # material:<材质>:<数量>
      - "material:GOLDEN_APPLE:2"
    money: 100                       # 货币（走宿主 currencyManager）
    currency: "money"
    exp: 50
    commands: []                     # 控制台命令（%player% 占位）
```

物品写法 `material:<Material>:<数量>`；MythicMobs/NeigeItems 等外源物品经宿主 ItemSourceRegistry 生成（写法见 integration 页）。

随机奖励集：

```yaml
  random_pack:
    type: random
    picks: 1                         # 抽取次数
    pool:
      - reward: clear_pack           # 引用其他集
        weight: 80
      - reward: quest_pack
        weight: 20
```

### 宝箱奖励

`open_chest_ui @trigger <名>` 打开宝箱 UI（无 ArcartX 客户端时直接发放）：

```yaml
chest-rewards:
  trial_chest:
    title: "试炼宝箱"
    rows: 3                          # UI 行数
    options:                         # 权重抽取的物品槽
      - item: "material:IRON_INGOT:5"
        weight: 50
      - item: "material:DIAMOND:2"
        weight: 20
```

宝箱 UI 支持单个/全部领取；玩家未领取关闭时服务端自动全发兜底，不吞奖励。

## floors.yml + rooms.yml — 多层房间地牢

`config.yml` 设 `mode: floors` 后启用：地牢由若干**层（floor）**组成，每层是一条**房间链**，玩家逐房推进——进战斗房自动锁门刷怪，清完开门解锁出口，层末房清完进入下一层，最终层清完即通关（类元气骑士结构）。

### floors.yml

```yaml
defaults:
  lock-material: BARRIER     # 锁门填充材质
  border-pullback: true      # 战斗房锁门期间离开区域拉回（逃逸双保险）
  room-spacing: 200          # pool 模式相邻房锚点间距（格）
  paste-y: 64                # pool 模式 schematic 粘贴基准高度
  advance-timeout: 60        # portal 推进兜底秒数（0=不兜底）

floors:
  - id: f1
    name: "第 1 层"
    source: region              # region=固定区域 | pool=schematic 随机拼接
    spawn: "0,65,0,90,0"        # 层入口站位（region 绝对坐标）
    rooms: [corridor_a, corridor_b]   # region 模式：rooms.yml 引用链
    boss-room: boss_1           # 层末房（可选；不配则链尾房即层末）
    advance: portal             # portal=踩出口传送 | auto=清完自动传送
    on-enter: [...]             # 层开始脚本
    on-clear: [...]             # 层清完脚本
  - id: f2
    source: pool                # 随机拼接（world.template 建议 void + FAWE）
    pool: [combat_a, combat_b, shop_a, treasure_a]
    room-count: 3               # 池内随机抽取数（0=全用且打乱顺序）
    boss-room: boss_2
    direction: x                # 拼接排列轴 x|z
    advance: portal
```

| 字段 | 说明 |
|---|---|
| `source: region` | 房间已手工建在世界模板里，坐标写世界绝对值 |
| `source: pool` | 虚空世界 + 房间 `.schem` 随机抽取粘贴（需 WorldEdit/FAWE，进本时校验） |
| `advance: portal` | 层/房清完激活出口区，玩家踩 `exit` 传送；`advance-timeout` 超时自动推 |
| `advance: auto` | 清完 3 秒后自动传送下一目标 |

### rooms.yml

```yaml
rooms:
  corridor_a:
    type: combat                 # combat=锁门清怪 | safe/shop=不锁 | boss=战斗(语义标记)
    schematic: "rooms/a.schem"   # pool 模式必填（相对地牢目录）；region 忽略
    origin: "0,0,0"              # region 房间原点（默认 0,0,0 = 坐标写绝对值）
    region: ["0,60,0", "29,80,29"]  # 房间 box 两角（相对 origin）
    spawn: "1,64,15,90,0"        # 进房站位（相对 origin）
    exit: ["29,63,13", "31,67,17"]  # 出口传送区（可选）
    doors:                        # 物理门盒（锁=填 lock-material，开=还原原方块）
      - region: ["30,64,14", "30,66,16"]
        material: BARRIER
    groups:                       # 房内怪组（格式同 monsters.yml，坐标相对 origin）
      wave1:
        spawn-timing: AUTO_START  # 房内语义：AUTO_START=锁门即刷 / DELAYED=锁门后延迟 / TRIGGERED=组联动
        monsters:
          - mob-id: minecraft:zombie
            location: "15,64,15"
            amount: 4
    on-enter: [...]               # 玩家首次进房
    on-lock: [...]                # 锁门瞬间
    on-clear: [...]               # 房内组全清（无怪房进房即清）
```

### 运行规则

- 房间物化：进本时按层生成房间链；pool 房沿轴粘贴，一切坐标（region/spawn/doors/groups/exit）自动按锚点偏移为绝对值
- 怪组物化：房内组注册为 `f{层}_r{房序}_{模板id}:{组名}`；`trigger-after` 引用房内短名自动加前缀
- 事件：`axs.abyss.room_enter` / `room_clear` / `floor_enter` / `floor_clear`
- 脚本变量：`{floor}` `{floor_name}` `{floors_total}` `{room}` 写入实例变量
- 脚本动作：`floor_next`（强制推层）/ `room_lock <房>` / `room_unlock <房>` / `room_status <房> <变量>`
- 虚空防护：玩家掉出当前房底部 8 格以下自动拉回房中心
- 最终层链尾房清完自动 `complete_dungeon`；中途判负/超时/全员死亡走现有失败流程
