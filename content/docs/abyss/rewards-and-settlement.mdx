把领取奖励、打开结算面板和退出副本当作三个独立步骤。先确认奖励的触发入口，再测试正常通关、失败和玩家提前离场。

## 结算与退出

在模板 `config.yml` 的 `settlement.exit-mode` 选择退出方式。

| 模式 | 玩家体验 |
| --- | --- |
| `IMMEDIATE` | 结束后安排离场，结算面板可在传送完成后显示 |
| `COUNTDOWN` | 结束后留出 `exit-delay-seconds` 秒，可拾取战利品或提前用 `/abyss leave` 离场 |
| `MANUAL` | 由玩家主动离场。`manual-timeout-seconds` 为 `0` 时不强制倒计时退出 |

`settlement.failure` 可单独设置失败时的退出模式、倒计时和结算面板。若希望在离场后显示结算，查看 `show-stats-after-exit`。全部玩家离场后，副本最多等待 `script-timeout-seconds` 秒让结算与退出脚本收尾。

### 示例：通关留出拾取时间，失败尽快离场

| settlement 字段 | 通关默认值 | 失败默认值 | 用途 |
| --- | --- | --- | --- |
| `exit-mode` | `COUNTDOWN` | `COUNTDOWN` | 选择退出方式 |
| `exit-delay-seconds` | `60` | `10` | COUNTDOWN 的等待秒数，0 到 86400 |
| `show-stats` | `true` | `true` | 是否请求显示统计，仍需全局统计功能可用 |
| `show-stats-after-exit` | `false` | `false` | 希望退出后显示时开启 |
| `manual-timeout-seconds` | `0` | `0` | MANUAL 的最长等待秒数，0 为一直等主动离场 |
| `protect-players` | `true` | `true` | 结算期间保护玩家 |
| `revive-players` | `true` | `true` | 结算时处理本局死亡玩家 |
| `script-timeout-seconds` | `30` | `30` | 全部离场后等待结算与退出脚本的上限，0 到 600 秒 |

失败参数写在 `settlement.failure` 中。它使用自己的失败默认值，不能假定所有未填写项都继承上方通关参数。

将下方字段合并到模板的 `settlement` 中。

```yaml
settlement:
  exit-mode: COUNTDOWN
  exit-delay-seconds: 90
  show-stats: true
  show-stats-after-exit: false
  failure:
    exit-mode: COUNTDOWN
    exit-delay-seconds: 15
    show-stats: true
```

用两次独立试跑分别触发通关和失败。通关时关闭结算面板，确认能在倒计时内拾取物品并提前离场。失败时确认采用 15 秒的独立倒计时。测试队伍提前退出时，分别观察每位成员的结算与离场。

## 选择发放时机



- 副本委托完成时，通过委托的脚本调用奖励集。

- 玩家需要主动领取时，把奖励放进宝箱交互，或用委托的手动领取模式。

- 同一份奖励只绑定一个入口。用测试玩家走一遍重复点击与提前离场，核对实际到账。



## 命名奖励集

使用 `grant_reward <选择器> <集名>` 发放命名奖励。完成事件通常使用 `@all`，单个宝箱交互使用 `@trigger`。

```yaml
rewards:
  clear_pack:
    items:
      - "material:DIAMOND:3"         # material:<材质>:<数量>
      - "material:GOLDEN_APPLE:2"
    money: 100                       # 货币（走Suite currencyManager）
    currency: "money"
    exp: 50
    commands: []                     # 控制台命令（{player} 占位）
```

上例是原版物品写法。外部物品的来源 ID 必须对应已安装的物品库，调整奖励时先测试生成，再测试实际发放。各模块的物品生成结构见[物品来源](/docs/guide/item-sources)，不能直接把其他模块的外层字段复制到本文件。

随机奖励集：

```yaml
  random_pack:
    type: random
    picks: 1                         # 抽取次数
    pool:
      - reward: clear_pack           # 引用其他集
        weight: 80
      - reward: quest_pack
        weight: 20
```

## 宝箱奖励

`open_chest_ui @trigger <名>` 打开宝箱 UI（无 ArcartX 客户端时直接发放）：

```yaml
chest-rewards:
  trial_chest:
    title: "试炼宝箱"
    rows: 3                          # UI 行数
    options:                         # 权重抽取的物品槽
      - item: "material:IRON_INGOT:5"
        weight: 50
      - item: "material:DIAMOND:2"
        weight: 20
```

宝箱 UI 支持单个/全部领取；玩家未领取关闭时服务端自动全发兜底，不吞奖励。

## shops.yml — 副本商店

`open_shop_ui <选择器> <商店id>` 打开自定义商店 UI（替代台座购买）：商品行列表展示图标/名称/描述/价格，顶部实时余额，金币不足自动置灰。

```yaml
shops:
  caravan:                         # 商店 id
    title: "旅行商队"               # 面板标题
    currency-var: coins            # 结算变量（副本实例变量，击杀掉落攒的那种）
    goods:
      - id: heal
        name: "&a治疗药剂"
        icon: "material:SPLASH_POTION"   # material:<材质> 或物品描述
        desc: ["&7恢复 12 点生命", "&75 秒再生"]
        price: 8                   # 货币价格
        script:                    # 购买成功后执行（@trigger=买家）
          - "heal @trigger 12"
          - "apply_potion @trigger REGENERATION 5 2"
      - id: power
        name: "&c力量药剂"
        icon: "material:POTION"
        price: 12
        script:
          - "random shop_power_lvl 1 3"
          - "run_script shop_power_t1"   # 各档段首行 if_var 门控
          - "run_script shop_power_t2"
          - "run_script shop_power_t3"
```

- **NPC 入口**：`npcs.yml` 的 `click-script` 里写 `open_shop_ui @trigger caravan`；同店多台座/多入口并存不冲突
- **类型注意**：接商店的 NPC **不要用 `VILLAGER`/`WANDERING_TRADER`**——Adyeshach 缺席降级真实体时，右键会先弹原版交易 GUI 盖住交互；`WITCH` 无交易界面两条路径都安全
- 商品 `script` 是完整动作行列表，随机档位/条件分支照常用 `random`+`if_var`+`run_script` 模式
