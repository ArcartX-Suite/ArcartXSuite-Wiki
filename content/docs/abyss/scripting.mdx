# 脚本系统

Abyss 的副本流程由 `scripts.yml` 中的生命周期脚本驱动。每个脚本段是一串动作行，按顺序执行；`wait <秒>` 挂起当前脚本（不阻塞其他脚本），`{player}`/`{killer}` 等占位符在运行时展开。

## 生命周期段

| 段名 | 触发时机 |
|---|---|
| `init` | 世界加载完成后、玩家传送前（虚空世界在此搭场景） |
| `start` | 玩家已传送，副本正式开始 |
| `complete` | 通关（脚本 `complete_dungeon` 或怪物组条件触发） |
| `fail` | 失败（脚本 `fail_dungeon`、团灭、超时 FAIL） |
| `player-death` | 副本内玩家死亡（`{player}` = 死者，`@trigger` 指向该玩家） |
| `all-death` | 全员死亡（配合 `team-wipe-mode`） |
| `exit` | 玩家离开副本（`@trigger` = 离开者） |

```yaml
init:
  - "fillblocks -6,79,-6 6,79,6 END_STONE"
  - "message @all &7正在构建竞技场..."

start:
  - "bossbar @all 600 RED SOLID &c虚空试炼场"

complete:
  - "grant_reward @all clear_pack"
  - "wait 3"
  - "exit_dungeon @all"

fail:
  - "exit_dungeon @all"

player-death:
  - "wait 5"
  - "revive_player @trigger"

all-death:
  - "fail_dungeon"
```

## 选择器

动作行中 `选择器` 位置支持：

| 选择器 | 指向 |
|---|---|
| `@all` | 副本内全部玩家 |
| `@trigger` | 触发者（交互点触发者/死亡者/NPC 点击者等上下文玩家） |
| `@random` | 随机一名副本内玩家 |
| `@dead` | 当前死亡的玩家 |
| 玩家名 | 指定玩家 |

### 全服共享计数

跨副本/跨实例的**服务器级**计数器（持久化到数据库，重启不丢）。典型用途：全服收集进度（"重启密钥归档"）、全服完成率统计、全服事件的触发数据源。

| 动作 | 用法 |
|---|---|
| `global_add` | `global_add <键> [增量]` 累加（默认 +1），命中阈值自动发事件 |
| `global_set` | `global_set <键> <值>` 直接设定 |
| `global_get` | `global_get <键> <变量>` 把全服计数读进实例变量（配合 `check` 判断） |
| `global_reset` | `global_reset <键>` 归零并清阈值触发记录（一轮全服事件结束用） |

**阈值事件**：模块配置 `ArcartXAbyss.yml` 的 `global-thresholds` 节声明阈值表：

```yaml
global-thresholds:
  reboot_key_fragments: [50, 100]   # 到达 50 / 100 时各发一次 axs.abyss.global_threshold
```

计数每次变更发 `axs.abyss.global_change`（payload：`key`/`value`/`delta`/`dungeon`/`instance`/`player`）；首次跨越阈值额外发 `axs.abyss.global_threshold`（payload 加 `threshold`），同一阈值只触发一次，`global_reset` 后可重新触发。**事件本体（全服防守战/阵营混战等）由 eventpacket 规则或外部玩法模块订阅实现**——abyss 只出数据源。

### 副本内引导（路标/路径渲染）

调用 `api.util.NavigationTargetService`——HUD 目标行 + 客户端路标 + 路径标记链直达目标，到达发事件并可自动跑脚本段。

| 动作 | 用法 |
|---|---|
| `guide_point` | `guide_point <navId> <x,y,z> [到达半径] <标题...>` 全员登记导航目标（同 navId 覆盖） |
| `guide_clear` | `guide_clear <navId\|all>` 撤下目标 |

```yaml
start:
  - "guide_point pump_room 90,64,-55 3 &e前往泵房"

# 到达回调：scripts.yml 里定义 guide_<navId> 段自动运行
guide_pump_room:
  - "guide_clear pump_room"
  - "message @all &a已抵达泵房"
```

到达同时发 `axs.abyss.guide_arrive` 事件（payload：`nav`）。HUD 顶部常驻显示最新一条目标标题；玩家退出/副本结束自动清理；中途进本的玩家自动补推当前目标。ArcartX 路标桥不可用时动作静默跳过。

### 跨模块联动

以下动作调用其他 AXS 模块的 capability；目标模块未启用时**静默跳过**，不报错不阻塞。

| 动作 | 用法 | 依赖模块 |
|---|---|---|
| `signal` | `signal <选择器> <信号名>` 触发 EventPacket 规则引擎信号 | eventpacket |
| `announce_global` | `announce_global <文本> [forward]` Announcer 全服公告（`forward`/`true` 结尾=跨服） | announcer |
| `qq_group` | `qq_group [群号] <消息>` QQ 群推送（群号省略=全部已配置群） | qqbot |
| `subtitle` | `subtitle <选择器> <字幕组id>` 播放字幕组 | subtitle |
| `chat_card` | `chat_card <选择器> <卡片id> [k=v,k=v]` 发送聊天卡片 | chat |
| `combat_effect` | `combat_effect <选择器> <特效包id>` 触发战斗特效包 | combateffect |
| `bp_task` | `bp_task <选择器> <任务id> [增量]` 推进战令任务进度 | battlepass |
| `apply_attribute` | `apply_attribute <选择器> <属性id> <值> [percent\|flat]` 副本内属性修饰，出本自动清除 | 属性桥（Symphony 等） |
| `remove_attribute` | `remove_attribute <选择器>` 主动移除副本属性修饰 | 同上 |

> 注意 `announce`（本地 title/actionbar 展示）与 `announce_global`（announcer 模块全服公告）是两个动作，不要混淆。

## 内联脚本与占位符

- 动作行可用 `aria: <表达式>` / `js: <代码>` 前缀走 Aria/JavaScript 脚本（`js:` 需服务端有 Nashorn/GraalJS，否则跳过并警告）
- 条件字段支持 PAPI 占位符比较：`%axsabyss_dungeon_kills% >= 5`（完整占位符见 [命令与占位符](/docs/abyss/commands#placeholderapi-占位符)）
- `check` 动作可在脚本中途做条件判断，不满足即中止本段后续动作

## 实例变量

`setvar`/`delvar`/`addvar` 读写副本实例级变量（如 `setvar last_killer {killer}`），生命周期随实例结束销毁。占位符 `{变量名}` 在后续动作行中展开。

**预置变量**（进本/推进流程自动写入，无需 setvar）：

| 变量 | 内容 | 来源 |
|---|---|---|
| `{plan}` / `{plan_name}` | 作战方案 id / 显示名 | 地牢定义了 `plans` 时，进本选定的方案 |
| `{floor}` / `{floor_name}` / `{floors_total}` | 当前层序号 / 层名 / 总层数 | floors 模式推进时写入 |
| `{room}` | 当前房间 id | floors 模式进房时写入 |
| `{player}` / `{killer}` 等 | 触发者/击杀者 | 事件脚本上下文 |
