> **付费模块** — 本页详细说明 OnlineRewards 模块的全服签到目标/集体奖励系统，包括目标配置、达成触发逻辑、多渠道奖励发放（命令/邮件/物品/聊天卡片/字幕/标题/QQ广播）与 EventBus 事件订阅。

全服签到目标是 OnlineRewards 模块的社会化激励功能。每当有玩家签到时，系统统计今日全服签到人数，当签到人数达到某个目标的 `required` 阈值时，给所有在线玩家发放该目标的奖励。每个目标每天只触发一次，通过数据库记录防止重复触发。

## 功能概述

| 特性 | 说明 |
|---|---|
| 全服目标 | 配置多个签到人数目标，达到阈值时全服发放奖励 |
| 防重复触发 | 每个目标每天只触发一次（数据库记录） |
| 多渠道奖励 | 命令、邮件预设、物品、聊天卡片、字幕组、标题、QQ广播 |
| 全服广播 | 达成目标时全服广播消息 |
| EventBus 事件 | 发布 `axs.onlinerewards.server_goal_reached` 事件供其他模块订阅 |
| 占位符查询 | 提供当前签到人数与下一个目标所需人数的占位符 |

## 配置结构

全服签到目标配置在主配置文件 `config.yml` 的 `server-sign-in-goal` 节中。

### 顶层配置

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `server-sign-in-goal.enabled` | `boolean` | `true` | 是否启用全服签到目标 |
| `server-sign-in-goal.broadcast` | `boolean` | `true` | 达成目标时是否全服广播 |
| `server-sign-in-goal.targets` | `List<Map>` | 见下 | 目标列表 |

### 目标字段

每个目标支持以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | 目标唯一 ID（用于去重与触发记录） |
| `required` | `int` | 所需签到人数 |
| `name` | `String` | 目标名称（用于广播与 UI 展示） |
| `rewardText` | `String` | 奖励描述 |
| `commands` | `List<String>` | 达成后对每个在线玩家执行的命令（支持 `{player}`） |
| `mail.presets` | `List<String>` | 邮件预设 ID 列表 |
| `item-rewards` | `List<Map>` | 物品奖励列表（见 [物品来源](/docs/guide/item-sources)） |
| `chat-cards` | `List<String>` | 聊天卡片 ID 列表 |
| `subtitle-groups` | `List<String>` | 字幕组 ID 列表 |
| `title-ids` | `List<String>` | 标题 ID 列表 |
| `broadcast` | `String` | 达成时的广播文本（支持 `{player}`） |

## 触发流程

```
玩家签到成功
  │
  └→ checkServerSignInGoals(triggerPlayer)
       │
       ├→ 检查 server-sign-in-goal.enabled 是否为 true
       │    └→ 未启用 → 直接返回
       │
       ├→ 查询今日全服签到人数（repository.countSignInRecords）
       │    └→ 查询失败 → 记录日志并返回
       │
       └→ 遍历 targets 列表
            │
            ├→ signedCount < target.required → 跳过该目标
            │
            ├→ 检查该目标今日是否已触发（repository.isServerGoalTriggered）
            │    └→ 已触发 → 跳过该目标
            │
            ├→ 记录触发状态（repository.saveServerGoalTriggered）
            │
            ├→ 全服广播（broadcastServerGoal）
            │    ├→ Bukkit.broadcastMessage（若 broadcast 为 true）
            │    └→ QQBot.sendToAllGroups（若 QQBot 可用）
            │
            ├→ 遍历所有在线玩家（executeServerGoalCommands）
            │    ├→ 执行 commands（支持 {player} 变量）
            │    ├→ 发送 mail.presets 邮件预设
            │    ├→ 发放 item-rewards 物品奖励
            │    ├→ 发送 chat-cards 聊天卡片
            │    ├→ 播放 subtitle-groups 字幕组
            │    └→ 授予 title-ids 标题
            │
            └→ 发布 EventBus 事件（axs.onlinerewards.server_goal_reached）
```

### 防重复触发机制

模块通过数据库表 `online_rewards_server_goals` 记录每个目标的触发状态，防止同一目标同一天重复触发：

| 列名 | 类型 | 说明 |
|---|---|---|
| `goal_date` | `VARCHAR(32)` | 目标日期（ISO 格式） |
| `goal_id` | `VARCHAR(64)` | 目标 ID |
| `triggered` | `TINYINT` | 是否已触发（1=已触发） |
| `created_at` | `TIMESTAMP` | 创建时间 |

> 主键：`(goal_date, goal_id)`。跨天后日期变化，所有目标可重新触发。

## 多渠道奖励发放

全服签到目标达成时，系统对每个在线玩家执行以下奖励发放：

### 命令（commands）

对每个在线玩家以控制台身份执行命令，支持 `{player}` 变量替换：

```yaml
commands:
  - "say {player} 领取了全服签到目标奖励"
  - "give {player} diamond 1"
  - "eco give {player} 100"
```

> 玩家名称会经过 `CommandSanitizer.validatePlayerName` 安全校验，防止命令注入。

### 邮件预设（mail.presets）

通过 Mail 模块发送邮件预设，填写 Mail 模块 `mail/presets/*.yml` 中的 `preset.id`：

```yaml
mail:
  presets: ["server_goal_10_bonus", "server_goal_10_extra"]
```

### 物品奖励（item-rewards）

通过 ItemSourceRegistry 生成物品并统一发放（背包满转邮件兜底）：

```yaml
item-rewards:
  - source: "minecraft"
    id: "DIAMOND"
    amount: 3
  - source: "mythic"
    id: "legendary_chest"
    amount: 1
```

| source | 说明 | id 格式 |
|---|---|---|
| `minecraft` | 原版物品 | 材质名（如 `DIAMOND`） |
| `mythic` | MythicMobs | 物品 ID |
| `neige` | NeigeItems | 物品 ID |
| `overture` | Overture | 物品 ID |
| `mmoitems` | MMOItems | `类型ID;物品ID` |

> 物品发放统一行为：放入背包 → 背包满转邮件 → 无邮件则掉落。详见 [物品来源](/docs/guide/item-sources)。

### 聊天卡片（chat-cards）

通过 `ChatCardSendable.sendChatCard(player, cardId, variables)` 向在线玩家发送聊天卡片：

```yaml
chat-cards:
  - "server_goal_card_10"
  - "server_goal_card_50"
```

> 聊天卡片 ID 对应 ChatCard 模块中注册的卡片 ID。发送时附带 `{"goal": target.name()}` 变量。

### 字幕组（subtitle-groups）

通过 `SubtitlePlayable.playGroup(player, groupId)` 向在线玩家播放字幕组：

```yaml
subtitle-groups:
  - "server_goal_subtitle_10"
```

### 标题（title-ids）

通过 `TitleGrantable.giveTitle(uuid, titleId, "permanent", "OnlineRewards:ServerGoal")` 向在线玩家授予标题：

```yaml
title-ids:
  - "server_goal_title_10"
```

> 标题授予方式为永久（`"permanent"`），来源标记为 `"OnlineRewards:ServerGoal"`。

### QQ 群广播

当 QQBot 模块可用时，达成目标会通过 `QQBotBroadcastable.sendToAllGroups(message)` 向所有 QQ 群广播消息。

> 广播消息使用目标的 `broadcast` 字段内容，支持 `{player}` 变量替换为触发签到的玩家名。

## 占位符

| 占位符 | 返回值 | 说明 |
|---|---|---|
| `%axsonlinerewards_server_signin_count%` | `int` | 今日已签到人数 |
| `%axsonlinerewards_server_signin_next_goal%` | `int` | 下一个全服签到目标所需人数（0 表示无目标） |

### next_goal 计算逻辑

```
遍历所有 targets：
  ├→ signedCount >= target.required && 未触发 → 跳过（即将触发）
  ├→ signedCount < target.required → 记录为候选
  └→ 取所有候选中 required 最小的值作为 next_goal

如果所有目标都已触发或已达成 → 返回 0
```

> 该占位符可用于 UI 中展示"距离下一个全服奖励还需 X 人签到"的进度提示。

## EventBus 事件

全服签到目标达成时，模块通过 `EventBusCapability` 发布事件，其他模块可订阅对应 Topic 接收事件。

### axs.onlinerewards.server_goal_reached

| Payload 字段 | 类型 | 说明 |
|---|---|---|
| `goal_id` | `String` | 目标 ID |
| `goal_name` | `String` | 目标名称 |
| `required` | `String` | 所需签到人数 |
| `signed_count` | `String` | 实际签到人数 |

```java
// 订阅示例（其他模块中）
eventBus.subscribe("axs.onlinerewards.server_goal_reached", (player, payload) -> {
    String goalId = payload.get("goal_id");
    String goalName = payload.get("goal_name");
    int required = Integer.parseInt(payload.get("required"));
    int signedCount = Integer.parseInt(payload.get("signed_count"));
    // 处理全服签到目标达成事件
    // 例如：触发自定义成就、记录日志等
});
```

> `player` 参数为触发签到的玩家（即达到阈值时最后一个签到的玩家），非所有在线玩家。

## 数据库表结构

### online_rewards_server_goals

全服签到目标触发记录表，防止同一目标同一天重复触发。

| 列名 | SQLite 类型 | MySQL 类型 | 说明 |
|---|---|---|---|
| `goal_date` | `TEXT` | `VARCHAR(32)` | 目标日期 |
| `goal_id` | `TEXT` | `VARCHAR(64)` | 目标 ID |
| `triggered` | `INTEGER` | `TINYINT` | 是否已触发（1=已触发） |
| `created_at` | `TEXT` | `TIMESTAMP` | 创建时间 |

> 主键：`(goal_date, goal_id)`

## 跨服同步

全服签到目标的签到人数统计基于共享数据库（`online_rewards_sign_ins` 表），因此多服环境下签到人数是全服汇总的。

| 前提条件 | 说明 |
|---|---|
| `storage.shared: true` | 必须使用共享存储模式 |
| MySQL 共享数据库 | 各子服共享同一数据库 |
| `cross-server.enabled: true` | 启用跨服同步通知 |

> 跨服同步详见 [联动](/docs/onlinerewards/integration) 页面的跨服同步章节。

## 配置注意事项

1. **每日重置**：全服签到目标按自然日重置，跨天后所有目标可重新触发
2. **仅在线玩家**：奖励只发放给达成时在线的玩家，离线玩家不会补发
3. **防重复**：每个目标每天只触发一次，通过数据库记录保证
4. **签到触发**：目标检查在每次玩家签到成功后触发，补签也会触发检查
5. **广播控制**：`broadcast` 顶层配置控制是否全服广播，每个目标也可自定义广播文本
6. **QQ 广播**：QQ 群广播使用与全服广播相同的消息文本，需要 QQBot 模块可用
7. **标题永久**：通过全服签到目标授予的标题为永久标题，来源标记为 `OnlineRewards:ServerGoal`
8. **命令安全**：命令中的 `{player}` 变量会经过 `CommandSanitizer` 安全校验
