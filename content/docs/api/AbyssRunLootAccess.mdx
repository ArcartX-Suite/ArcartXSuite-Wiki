| 项目 | 说明 |
| --- | --- |
| 提供模块 | [abyss](/docs/abyss) |
| 完整类型 | `xuanmo.arcartxsuite.api.capability.AbyssRunLootAccess` |

## 获取接口

通过 `AxsCapabilities.get(AbyssRunLootAccess.class)` 获取。同时从 [AbyssAdmissionAccess](/docs/api/abyss-integration) 读取 `integrationInfo().features().get("runLoot")`。接口存在且该值为 `AVAILABLE` 时开放查询入口。

## 方法声明

```java
public interface AbyssRunLootAccess {
    CompletionStage<LootSnapshot> snapshot(UUID runId, UUID viewerId, String cursor, int limit);
}
```

## 参数与返回值

在 Bukkit 主线程调用。异步回调如需访问 Bukkit 对象，请切回主线程。首屏将 `cursor` 传为 `null`，每页查询 1～100 条。
接入插件应从当前玩家会话取得 `viewerId`。只有本局原始成员能查询。`PERSONAL` 条目仅向归属人返回，`SHARED` 条目对原始成员可见。
成员离场和实例结束后，原始成员仍可回看记录。

返回值包含 runId、revision、runState、entries、nextCursor、complete 和 code。
complete 表示本次分页已读完。每条记录包含稳定的 entryId、rewardId、displayName、
quantity、quality、source、ownerId、scope、state 和 updatedAt。
物品源未提供品质时 quality 为 null。

| code | 含义 |
| --- | --- |
| `OK` | 正常结果，entries 可为空 |
| `FORBIDDEN` | 查看者不是原始成员，不能显示为“暂无战利品” |
| `UNKNOWN_RUN` | 找不到此局的战利品记录 |
| `UNAVAILABLE` | 模块未运行 |
| `STALE_CURSOR` | 账本在翻页期间发生变化，从首屏重新读取 |

游标绑定 runId、viewerId 和修订。畸形游标、越界分页参数、数据库不可用会异常完成。
读取不会发奖、领取、修改分配或推进结算。适合面板打开、切页时读取，
不需要每帧轮询。

```java
AbyssRunLootAccess api = AxsCapabilities.get(AbyssRunLootAccess.class);
if (api == null) return;
api.snapshot(runId, authenticatedViewerId, null, 50)
    .whenComplete((page, error) -> {
        // error 保持“读取失败”；FORBIDDEN 保持“无权限”。
        // OK 时保存 revision、entries 和 nextCursor，切回主线程后更新 UI。
        // 下一次主线程切页调用使用 page.nextCursor()。
    });
```

## 调用注意事项

### 奖励来源与状态

查询结果包括配置的奖励集、标准宝箱，以及翻牌、转盘和三选一中已选中的奖励。

- `PENDING` 表示奖励正在等待交付确认。
- `HOST_ACCEPTED` 表示宿主已接收奖励，玩家可能仍在等待发放。
- `DELIVERED` 用于能够提供实际发放回执的来源。当前内置奖励以 `HOST_ACCEPTED` 记录宿主接收状态，实际到账以玩家的背包、仓库、邮件或货币余额为准。
- `UNKNOWN` 表示来源无法确认结果。

货币条目的 `quantity` 为实际金额。脚本命令奖励显示配置中的奖励描述。`quantity` 为该条命令奖励的数量。地面掉落和自行拾取的物品由玩家在副本内处理。

记录随实例世界销毁继续保留，在管理员显式清理模块数据库前可查询。
每局上限 10000 条，超限会拒绝登记新批次并使相应操作异常完成。
