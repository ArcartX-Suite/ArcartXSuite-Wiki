| 项目 | 内容 |
| --- | --- |
| 完整类型 | `xuanmo.arcartxsuite.api.capability.MaterialContainerAdapter` |
| 用途 | 由容器插件实现，配合仓库材料转移接口使用 |
| 获取方式 | 插件自行创建实现类，无全局能力查询或自动注册入口 |

## 接入方式

容器插件实现本接口，并在自己的填料流程中调用 [WarehouseMaterialAccess](/docs/api/WarehouseMaterialAccess)。仅实现适配器不会自动增加 VanillaUI 支持的容器类型，也不会注册新的界面。

## 方法声明

```java
public interface MaterialContainerAdapter {
    String id();
    boolean supports(InventoryView view);
    Delivery capture(Player player, InventoryView view,
        Map<Integer, ItemStack> storageChanges,
        Map<Integer, ItemStack> inputChanges);

    interface Delivery {
        WarehouseMaterialAccess.Target target();
        boolean unchanged();
        void apply();
    }
}
```

## 参数与返回值

| 方法 | 参数 | 返回值及用途 |
| --- | --- | --- |
| `id()` | 无 | 稳定的适配器标识，写入材料转移记录 |
| `supports(view)` | `view`：玩家当前容器窗口 | 是否支持该容器类型 |
| `capture(...)` | `player`：玩家；`view`：当前窗口；`storageChanges`：玩家储物栏的计划变更；`inputChanges`：容器输入槽的计划变更 | 返回本次交付对象，只记录计划，不修改库存 |
| `Delivery.target()` | 无 | 提供容器身份、存档方式与变更证据，传给 `prepareMaterials` |
| `Delivery.unchanged()` | 无 | 当前窗口及相关槽位是否仍与计划相符 |
| `Delivery.apply()` | 无 | 执行计划中的库存变更，不返回结果，异常由调用方处理 |

槽位映射的键使用各自库存的槽位编号，值为变更后的完整 `ItemStack`。适配器应保存变更前后的物品数据，以便校验和异常核对。全部方法在 Bukkit 主线程执行。

## 交付顺序与失败处理

1. 检查 `supports(view)`，生成合法的材料计划后调用 `capture`。
2. 将 `target()` 传给仓库的 `prepareMaterials`，准备失败时结束操作。
3. 准备成功后检查 `unchanged()`；计划失效时调用 `cancelPrepared` 取消。
4. 调用 `authorizeDelivery`，只有授权成功且再次检查 `unchanged()` 通过后，才调用一次 `apply()`。
5. 写入成功后调用 `completeDelivery` 记录结果；授权后校验失败或写入异常时调用 `recordUncertain`，保留记录供核对，不重复执行 `apply()`。

新的容器必须检查合法槽位、材料要求、玩家窗口与容器是否仍有效，并只修改计划涉及的槽位。容器坐标只能标识目标，不能证明物品已经写入存档；无法确认的交付不得自行重试或补发。

VanillaUI 提供工作台、熔炉、高炉、烟熏炉、切石机、锻造台、酿造台和村民交易适配。锻造台的目标装备由玩家先放入，材料计划只补齐模板与辅材；切石机填入石材后仍需选择原版切割配方，不应自行生成结果物品。
