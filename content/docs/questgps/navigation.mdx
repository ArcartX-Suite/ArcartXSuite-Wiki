# 导航系统

QuestGPS 的导航系统是模块的核心功能之一，将 Chemdah 任务的动态坐标或 overlay 静态坐标转化为玩家可感知的导航指引。导航系统由三层组成：路标导航（Waypoint）、导航标记（Marker）和指引 HUD（Guide）。

## 导航架构

```
                    ┌─────────────────────────────────┐
                    │      QuestGpsNavigationService   │
                    └──────────┬──────────┬───────────┘
                               │          │
              ┌────────────────┘          └────────────────┐
              ▼                                            ▼
    ┌──────────────────┐                        ┌────────────────────┐
    │  WaypointRuntime │                        │ QuestGpsMarkerService│
    │  (路标导航)       │                        │  (导航标记模型)      │
    └────────┬─────────┘                        └──────────┬─────────┘
             │                                             │
    ┌────────┴─────────┐                          ┌────────┴──────────┐
    │ WaypointBridgeAPI │                          │ AdyeshachNpcBridge  │
    │ (ArcartX 路标桥接) │                          │ API (私有实体渲染)  │
    └──────────────────┘                          └────────────────────┘
```

### 导航坐标来源

导航坐标来源由 `navigation.mode` 控制，全局三选一：

| 模式 | 说明 | 坐标来源 |
|---|---|---|
| `hybrid`（默认） | Chemdah tracker 动态坐标优先，overlay 配置坐标作回退 | Chemdah tracker → overlay YAML |
| `chemdah` | 仅使用 Chemdah tracker 动态坐标 | Chemdah tracker |
| `overlay` | 仅使用 `quests/*.yml` 配置的静态坐标 | overlay YAML |

> `hybrid` 模式下，若 Chemdah tracker 返回有效坐标则使用动态坐标，否则回退 overlay 配置坐标。Chemdah Tracker API 不可用时（如 Chemdah 版本过低），自动降级为 overlay 导航。

## 路标导航

路标导航通过 ArcartX 的 `WaypointBridgeAPI` 实现，在客户端显示方向指引箭头。

### 路标配置

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `navigation.enabled` | `boolean` | `true` | 是否启用导航功能 |
| `navigation.waypoint-style-id` | `String` | `"default"` | ArcartX waypoint 路标样式 ID |
| `navigation.quest-id-prefix` | `String` | `"AXS-questgps-"` | 路标 ID 前缀 |
| `navigation.remove-on-finish` | `boolean` | `true` | 任务完成后自动移除导航 |

### 路标 ID 生成规则

路标 ID 由前缀 + 任务 ID + 可选子任务 ID 拼接而成：

```
AXS-questgps-<questId>              # 任务级追踪
AXS-questgps-<questId>__<taskId>    # 子任务级追踪
```

> 任务 ID 和子任务 ID 中的非字母数字字符会被替换为 `_`（`sanitize`），确保路标 ID 合法。

### 路标样式解析

路标样式 ID 按以下优先级解析：

1. 子任务配置的 `tasks.<id>.navigation.style-id`
2. 任务配置的 `navigation.point.style-id`
3. 全局 `navigation.waypoint-style-id`
4. ArcartX waypoint 默认样式

> 样式 ID 须在 ArcartX waypoint 目录下有对应定义，详见 [/docs/guide/icons](/docs/guide/icons)。

### 任务级 vs 子任务级追踪

| 追踪级别 | 触发方式 | 坐标来源 |
|---|---|---|
| 任务级（`trackQuest`） | UI Packet `track_quest` 或 `QuestGpsNavigable.trackQuest` | 任务 `navigation.point` 或 Chemdah tracker |
| 子任务级（`trackTask`） | UI Packet `track_task` 或 `QuestGpsNavigable.trackTask` | 子任务 `tasks.<id>.navigation` 或 Chemdah tracker |

> 子任务级追踪会覆盖任务级追踪。同一时间每个玩家仅有一个活跃追踪。

## 导航标记

导航标记使用 Adyeshach 私有实体 + ArcartX 模型渲染客户端导航标记，仅在追踪状态变更时发包，客户端独立渲染，零服务端 tick 开销。

### 标记配置

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `navigation.marker.enabled` | `boolean` | `true` | 是否启用导航标记 |
| `navigation.marker.model-id` | `String` | `"nav_beacon"` | ArcartX 模型 ID |
| `navigation.marker.scale` | `double` | `1.0` | 模型缩放比例 |
| `navigation.marker.default-state` | `String` | `"idle"` | 模型默认状态名称 |
| `navigation.marker.animation` | `String` | `"rotate"` | 循环播放的动画名称 |
| `navigation.marker.y-offset` | `double` | `2.0` | 模型相对导航目标的 Y 轴偏移 |

> 导航标记依赖 Adyeshach 插件。Adyeshach 不存在时标记功能自动关闭，路标导航不受影响。

### 路径寻路参数

A* 寻路算法沿路径放置标记模型，支持以下参数：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `navigation.marker.path-interval` | `double` | `3.0` | 路径标记间距（方块数，沿路径每隔多少格放一个标记） |
| `navigation.marker.path-max-markers` | `int` | `20` | 路径标记最大数量（超出后截断远端标记） |
| `navigation.marker.path-update-ticks` | `int` | `10` | 路径更新间隔（tick，20=1秒，玩家移动后重新计算路径） |
| `navigation.marker.path-max-distance` | `double` | `64.0` | 路径最大渲染距离（方块数，超出此距离不显示路径标记） |
| `navigation.marker.path-max-iterations` | `int` | `2000` | A* 寻路最大迭代次数（100-50000，越大越精确但越耗时） |

> `path-max-iterations` 配置校验范围为 100-50000，超出范围会被 `ValidationRule` 拒绝。

### 标记服务委托

`QuestGpsMarkerService` 是模块的入口类，内部逻辑全部委托给本体的 `NavigationMarkerService`：

```
QuestGpsMarkerService
    └── NavigationMarkerService (本体)
        ├── AdyeshachNpcBridgeAPI (私有实体创建/销毁)
        └── A* 寻路引擎 (路径计算)
```

标记 ID 前缀固定为 `questgps_path_`，用于区分其他模块的导航标记。

## Chemdah 动态坐标

### Tracker Bridge

`ChemdahTrackerBridge` 桥接 Chemdah 原生任务追踪 API，供导航层消费动态坐标：

| 方法 | 说明 |
|---|---|
| `startQuestTracking(player)` | 启动 Chemdah 任务追踪会话 |
| `stopQuestTracking(player, questId)` | 停止指定任务追踪 |
| `stopAll(player)` | 停止玩家所有追踪 |
| `isTracking(player, questId)` | 检查是否正在追踪 |
| `resolveTrackingLocation(player, questId)` | 解析当前追踪坐标 |

> Chemdah Tracker API 不可用时（`probeAvailability` 返回 `false`），所有方法安全降级，导航回退 overlay 坐标。

### 坐标解析流程

```
resolveTrackingLocation(player, questId)
    │
    ├── getSession(player, questId)       # 优先按任务 ID 查找会话
    │   └── 失败 → getSession(player, QuestTrackingSession.SOURCE)  # 回退通用会话
    │
    └── session.getTargets()              # 遍历追踪目标
        └── target.getCenter().getLocation(player)  # 解析坐标
            └── 返回第一个有效的 Location
```

### 动态坐标刷新

`hybrid` 和 `chemdah` 模式下，导航服务启动一个定时任务（间隔为 `path-update-ticks`），周期性刷新所有在线玩家的 Chemdah 追踪坐标：

```
refreshChemdahTrackingPositions()
    │
    ├── 遍历所有在线玩家
    │   └── 检查追踪状态 (trackingStates)
    │       └── resolveChemdahPoint(player, questId, taskId, label)
    │           └── 坐标变化 > 0.5 格 → refreshWaypointPosition
    │           └── 坐标未变 → 跳过
    └── 坐标变化阈值: samePosition(current, next) → < 0.5 格视为未移动
```

> 坐标变化小于 0.5 格时不刷新路标，避免频繁发包导致客户端卡顿。

## 指引 HUD

追踪任务时，QuestGPS 会向客户端发送引导 HUD 数据包，在屏幕左上角常驻显示任务名、进度和导航坐标。

### HUD 数据包字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `packetId` | `String` | Packet 标识符 |
| `active` | `boolean` | HUD 是否激活显示 |
| `questName` | `String` | 当前追踪任务名称 |
| `completedCount` | `int` | 已完成目标数 |
| `totalCount` | `int` | 总目标数 |
| `progressText` | `String` | 进度文本（如 `"2/5"`） |
| `tasks` | `Map<String, Map>` | 目标字典，最多 3 个 |
| `taskCount` | `int` | 展示的目标数 |
| `hasNav` | `boolean` | 是否有可用导航点 |
| `navWorld` | `String` | 导航点所在世界名 |
| `navX` | `int` | 导航点 X 坐标 |
| `navY` | `int` | 导航点 Y 坐标 |
| `navZ` | `int` | 导航点 Z 坐标 |

> 引导 HUD 最多展示 3 个目标，由 `QuestGpsGuidePacketFactory.DISPLAY_TASK_LIMIT = 3` 控制。目标按 `sort-order` 排序，优先展示未完成的目标。

### HUD 生命周期

| 事件 | 行为 |
|---|---|
| 开始追踪（`trackQuest` / `trackTask`） | 发送 `init` 包，打开引导 UI |
| 追踪中刷新（`refreshViewer`） | 发送 `update` 包，更新 HUD 数据 |
| 清除追踪（`clearTrack`） | 关闭引导 UI |
| 玩家退出（`PlayerQuitEvent`） | 清除追踪状态，关闭引导 UI |

## AXMap 临时目标同步

追踪任务/子任务时，QuestGPS 通过 `MapNavigable` Capability 向 AXMap 同步临时目标标记：

| 操作 | 方法 | 说明 |
|---|---|---|
| 同步目标 | `upsertExternalTarget` | 更新/插入临时目标（source = `questgps`） |
| 清除目标 | `clearExternalTargets` | 清除 QuestGPS 来源的所有临时目标 |
| 打开地图 | UI Packet `open_map` | 调用 `MapNavigable.openMenuFor` 打开 AXMap 菜单 |

> AXMap 不存在时导航功能正常运行，仅跳过地图标记同步。`map-label` 字段配置同步到地图的标签文本。

## 导航状态管理

### TrackingState

每个玩家的追踪状态由 `TrackingState` record 表示：

| 字段 | 类型 | 说明 |
|---|---|---|
| `active` | `boolean` | 是否正在追踪 |
| `mode` | `TrackingMode` | 追踪模式：`NONE` / `QUEST` / `TASK` |
| `questId` | `String` | 任务 ID |
| `taskId` | `String` | 子任务 ID（任务级追踪时为空） |
| `waypointId` | `String` | 路径点标识符 |
| `label` | `String` | 追踪目标显示名称 |

### NavigationPoint

导航坐标点由 `NavigationPoint` record 表示：

| 字段 | 类型 | 说明 |
|---|---|---|
| `waypointId` | `String` | 路径点标识符 |
| `title` | `String` | 路径点标题 |
| `styleId` | `String` | 路径点样式 ID |
| `world` | `String` | 世界名称 |
| `x` | `double` | X 坐标 |
| `y` | `double` | Y 坐标 |
| `z` | `double` | Z 坐标 |
| `mapLabel` | `String` | 地图标记标签 |

## 导航完整配置示例

```yaml
navigation:
  enabled: true
  waypoint-style-id: "default"
  quest-id-prefix: "AXS-questgps-"
  remove-on-finish: true
  mode: hybrid
  marker:
    enabled: true
    model-id: "waypoint"
    scale: 1.0
    default-state: "idle"
    animation: "rotate"
    y-offset: 0.0
    path-interval: 3.0
    path-max-markers: 20
    path-update-ticks: 10
    path-max-distance: 64
    path-max-iterations: 2000
```

### 任务级导航配置

```yaml
example_mainline_quest:
  enabled: true
  navigation:
    enabled: true
    point:
      world: "world"
      x: 0
      y: 80
      z: 0
      title: "初入岛屿"
      style-id: "default"
      map-label: "主线目标"
```

### 子任务级导航配置

```yaml
example_mainline_quest:
  tasks:
    "0":
      sort-order: 10
      navigation:
        world: "world"
        x: 12
        y: 80
        z: -8
        title: "与长老对话"
        style-id: "default"
        map-label: "任务目标"
```

> 子任务导航点会覆盖任务级 `navigation.point`。`hybrid` 模式下 Chemdah tracker 坐标优先于 overlay 配置坐标。导航坐标的样式 ID 须在 ArcartX waypoint 目录下有对应定义，详见 [/docs/guide/icons](/docs/guide/icons)。

## 依赖关系

| 依赖 | 类型 | 不可用时的影响 |
|---|---|---|
| ArcartX Waypoint | 硬依赖 | 导航功能不可用（`navigationRuntimeReady` 返回 `false`） |
| Adyeshach | 软依赖 | 导航标记关闭，路标导航正常 |
| Chemdah Tracker API | 软依赖 | 回退 overlay 导航坐标 |
| AXMap | 软依赖 | 跳过地图标记同步，导航正常 |

> 导航运行时就绪状态可通过 `/axs questgps status` 查看 `导航就绪` 字段，或通过 UI Packet 的 `navigationReady` 字段获取。
