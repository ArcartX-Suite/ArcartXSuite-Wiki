## 概述

GACHA 模式实现原神风格的祈愿系统，核心规则包括：

- **硬保底**：5 星 / 4 星达到指定抽数必出
- **软保底**：5 星在起始抽数后概率逐抽递增
- **UP 机制**：大保底 / 小保底判定，UP 物品概率占比
- **命运点定轨**：武器池专属，定轨目标必出机制
- **共享保底组**：跨池共享保底计数

配置字段详见 [配置](/docs/lottery/configuration)，机制概览详见 [概览](/docs/lottery)。

## 保底参数

保底参数由奖池文件 `gacha` 节配置：

| 参数 | 配置字段 | 默认值 | 说明 |
|---|---|---|---|
| 5 星硬保底 | `pity-5star` | `90` | 达到该抽数必出 5 星 |
| 4 星硬保底 | `pity-4star` | `10` | 达到该抽数必出 4 星 |
| 软保底起始 | `soft-pity-start` | `73` | 之后每抽 5 星概率递增 |
| 软保底增量 | `soft-pity-increment` | `0.06` | 软保底区间每抽概率增量 |
| 5 星基础概率 | `base-5star-rate` | `0.006` | 软保底前的 5 星概率（0.6%） |
| 4 星基础概率 | `base-4star-rate` | `0.051` | 4 星基础概率（5.1%） |
| UP 概率 | `up-rate` | `0.5` | UP 物品在对应星级中的占比（50%） |
| 命运点上限 | `fate-point-cap` | `0` | 武器池定轨上限，0 不启用 |
| 共享保底组 | `shared-pity-group` | 无 | 同组卡池共享保底计数 |

## 抽卡规则

每抽按以下顺序判定：

1. **保底计数递增**：5 星与 4 星保底计数各 +1
2. **5 星概率**：保底计数达到 `pity-5star` 必出 5 星；否则按软保底概率判定
3. **5 星 UP 判定**：见下表
4. **4 星判定**：保底计数达到 `pity-4star` 必出 4 星；否则按 `base-4star-rate` 判定
5. **3 星**：未命中 5/4 星时出 3 星（`star3-items` 为必填项）
6. **同星级内加权随机**：同星级多件物品按 `weight` 加权随机选取

### 软保底概率

| 抽数区间 | 概率 | 示例（默认参数） |
|---|---|---|
| `1` ~ `73` 抽 | `base-5star-rate` | 0.6% |
| `74` 抽起 | `base + (抽数 - soft-pity-start) × increment` | 逐抽递增 6% |
| `90` 抽 | 硬保底触发 | 100%（必出） |

> 第 74 抽概率 = `0.006 + 1 × 0.06` = 6.6%；第 80 抽概率 = `0.006 + 7 × 0.06` = 42.6%。

### 5 星 UP 判定

| 条件 | 结果 | 后续状态 |
|---|---|---|
| 上次 5 星未命中 UP（大保底） | 必出 UP 5 星 | 大保底解除 |
| 常规 | 按 `up-rate` 概率出 UP 5 星 | 命中则保持常规 |
| 常规未命中 UP | 出常驻 5 星（"歪了"） | 下次 5 星必为 UP（大保底） |

出 5 星后，5 星与 4 星保底计数均重置为 0。

### 武器池命运点定轨

`pool-type: WEAPON` 且 `fate-point-cap > 0` 时启用：

| 事件 | 命运点变化 | 定轨状态 |
|---|---|---|
| 命中 UP 但非定轨目标 | `+1` | 保持定轨 |
| 命中定轨目标 | 清零 | 定轨完成并移除 |
| 未命中 5 星 UP | 不变 | 保持定轨 |
| 命运点达到上限 | 下次 5 星必出定轨目标 | 命中后清零移除 |

4 星 UP 判定与 5 星类似：按 `up-rate` 分流 UP 与常驻，某一侧列表为空时互相回退。

## 共享保底组

共享保底组允许同组 GACHA 池共享保底计数，通过两种方式配置：

### 奖池内显式声明

```yaml
gacha:
  shared-pity-group: "character_events"
```

### 顶层通配符匹配

主配置 `shared-pity-groups` 使用通配符匹配奖池 ID：

```yaml
shared-pity-groups:
  character_events: "character_event_*"
  weapon_events: "weapon_event_*"
```

### 解析优先级

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 奖池内 `shared-pity-group` | 显式声明，最高优先 |
| 2 | 顶层 `shared-pity-groups` 通配符 | `*` 匹配池 ID |
| 3 | 原始池 ID | 无共享，独立保底 |

> 共享组内任一卡池抽卡都会更新同一保底计数（以组名为准）。

## 概率计算示例

UI 详情页展示的综合基础概率：

| 奖池类型 | 概率公式 |
|---|---|
| GACHA 5 星 | `base-5star-rate × (item.weight / 同星级总权重)` |
| GACHA 4 星 | `base-4star-rate × (item.weight / 同星级总权重)` |
| GACHA 3 星 | `(1 - base-5star-rate - base-4star-rate) × (item.weight / 同星级总权重)` |
| CASE | `(rarity.base-weight / 稀有度总权重) × (item.weight / 同稀有度总权重)` |

> 展示的基础概率未含软保底递增与硬保底修正，实际概率随保底计数递增。

默认参数下，UP 5 星物品（同星级仅 1 件）的综合基础概率：

```
P(UP 5星) = 0.006 × 0.5 = 0.003 = 0.3%
```

常驻 5 星物品同样为 `0.006 × 0.5 = 0.3%`。

## 概率模拟

管理员可通过 `/axs lottery simulate <奖池ID> <次数>` 模拟抽奖统计（不扣费、不发奖、不保存状态）：

| 限制 | 说明 |
|---|---|
| 次数范围 | `1` ~ `100000` |
| GACHA 统计维度 | 星级（`3star` / `4star` / `5star`） |
| CASE 统计维度 | 稀有度名称（如 `COMMON` / `RARE`） |

模拟结果包含保底递增效果，统计更接近实际体验。
