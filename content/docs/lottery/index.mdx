| 主要调整内容 | pools/ 奖池、奖品权重、消耗与保底参数 |
| 重载 | `/axs reload lottery` |

## 开始前

确认 ArcartX 客户端可用，且 `/axs status` 显示本模块已加载。本模块还需要安装 `PlaceholderAPI`。可选插件只在使用对应功能时安装，具体要求见功能配置页。

## 第一次使用

1. 复制一个默认奖池。
2. 设置测试奖品与消耗。
3. 执行 `/lottery open <奖池ID>`。

## 检查是否配置成功

完成一次测试抽奖，核对消耗、奖品和记录。

功能未生效时，先检查模块状态、所用定义 ID、玩家权限及客户端安装情况，随后对照[日志与报错提示](/docs/guide/config-management)逐项检查。

## 可以配置的功能

| 特性 | 说明 |
|---|---|
| GACHA 祈愿 | 原神风格祈愿，5 星/4 星硬保底、软保底递增、UP 概率、大保底/小保底、武器池命运点定轨机制，支持单抽与十连 |
| 多资源消耗 | 单次抽奖可同时消耗货币（CURRENCY）、物品（ITEM，含物品匹配器）、积分（POINT）三类资源 |
| 积分系统 | 每次抽奖按稀有度/星级累积积分，积分可在兑换商店兑换奖品 |
| 积分兑换商店 | 支持积分/物品/货币兑换奖品，支持限购次数（limit） |
| 跨池共享保底 | 同组 Gacha 池共享保底计数（通配符匹配池 ID 或奖池内显式声明 `shared-pity-group`） |
| 奖品投递 | 支持直接发放（DIRECT）、命令执行（COMMAND）、邮件发放（MAIL）三种投递方式 |
| 物品库支持 | 奖品与图标支持原版 / MythicMobs / NeigeItems / Overture / MMOItems |
| 抽奖历史记录 | 记录玩家抽卡/开箱历史，UI 可查看最近 100 条抽卡 / 20 条开箱记录 |
| 待发放奖励领取 | 投递失败的奖励自动入队，玩家上线或执行 `/lottery claim` 领取 |
