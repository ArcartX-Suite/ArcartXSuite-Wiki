# 联动

## EventBus 事件

EntityTracker 模块通过宿主 EventBus 发布以下事件主题，供其他模块订阅：

| 主题 | 触发时机 | 说明 |
|---|---|---|
| `axs.entitytracker.boss_kill` | Boss 死亡结算完成 | 发布 Boss 击杀事件，包含 Boss ID、显示名、参与者、伤害数据、结算记录等 |

其他模块（如 BattlePass、QuestGPS 等）可通过 EventBus 订阅 `axs.entitytracker.boss_kill` 主题，将 Boss 击杀作为任务条件或战令任务触发源。

事件条件配置详见 [/docs/guide/conditions](/docs/guide/conditions)。

## Capability 注册

EntityTracker 在宿主 Capability 注册表中注册以下能力：

### BossTrackerQueryable（公开）

活跃 Boss 会话查询能力（`@PublicCapability`），外部插件经 `AxsCapabilities.get(BossTrackerQueryable.class)` 获取；EntityTracker 未启用时返回 `null`。

| 方法 | 说明 |
|---|---|
| `isTrackedBoss(entityUuid)` | 实体是否为被追踪的配置 Boss |
| `activeSessionCount()` | 当前活跃 Boss 会话数 |
| `activeViewerCount()` | 正在观看 Boss 面板的玩家总数 |
| `activeSessions(mobIdFilter)` | 活跃会话列表；`mobIdFilter` 为 MythicMob id 过滤，`null` 不过滤 |

`activeSessions` 返回 API 侧 `BossSessionInfo` record（`entityUuid`/`mythicMobId`/`displayName`/`health`/`maxHealth`/`participantCount`/`trackedPlayerCount`/`totalDamage`），不暴露模块内部类型。

### PlayerDataPurgeable

| 方法 | 说明 |
|---|---|
| `moduleId()` | 返回 `"entitytracker"` |
| `purgePlayerData(UUID)` | 删除指定玩家的所有数据（最高伤害记录、DKP、奖励记录等），返回删除条数 |
| `purgeAllPlayerData()` | 删除所有玩家数据，返回删除条数 |

> 当数据库不可用（`repository` 为 null）时，此 Capability 不会注册。

### DatabaseMigratable

| 方法 | 说明 |
|---|---|
| `moduleId()` | 返回 `"entitytracker"` |
| `migrateDatabase(StorageDescriptor, boolean)` | 将数据迁移至目标存储，`overwrite` 控制是否覆盖已有数据 |
| `currentDescriptor()` | 返回当前存储描述符 |

> 当数据库可用时，此 Capability 支持管理员在切换数据库（如 SQLite → MySQL）时无缝迁移 EntityTracker 数据。

### MailDispatchable（消费方）

EntityTracker 是 `MailDispatchable` Capability 的**消费方**，而非提供方。模块在以下场景使用邮件功能：

- **奖励发放**：物品奖励背包满时，通过 `MailDispatchable` 发送邮件
- **离线奖励**：排行榜定时奖励发放时，离线玩家通过邮件接收

若 Mail 模块不可用，物品奖励降级为掉落地面。

## 跨服同步

### 跨服 Boss 排行

当 `cross-server.enabled` 和 `new-features.cross-server-ranking.enabled` 均为 `true` 时，EntityTracker 启用跨服 Boss 排行功能。

**工作流程**：

```
Boss 死亡结算
  → BossTrackerService.onDeath()
  → 生成 BossDamageSettlementRecord
  → EntityTrackerCrossServerService.publishSettlement()
    → 遍历结算条目，写入本地 player_boss_best_damage 表
    → 若伤害为该玩家历史最高，通过 CrossServer Channel 广播
  → 其他服收到广播
    → EntityTrackerCrossServerService.handlePayload()
    → mergeBestDamage() 合并至本地数据库
    → 若更新了最高伤害，请求排行榜缓存刷新
```

**跨服通道**：

- 通道名称：`entitytracker`
- 通道配置：通过宿主 `config.yml` 的 `cross-server` 节配置（Redis / Proxy 双后端）
- 模块配置中的 `cross-server.enabled` 控制是否启用

**广播数据类型**：

| 类型 | 说明 |
|---|---|
| `best_damage` | 玩家 Boss 最高伤害记录 |
| `kill_record` | Boss 击杀记录 |

### 跨服击杀记录

Boss 击杀记录同样支持跨服同步。当 Boss 死亡时，`BossKillRecordingService` 记录击杀信息（包含参与者、掉落物、位置等），并通过 `EntityTrackerCrossServerService.publishKillRecord()` 广播至其他服。其他服通过 `mergeKillRecord()` 合并至本地记录。

## 数据库表结构

EntityTracker 使用以下数据库表（建表脚本位于 `sql/init_tables.sql`）：

### 核心业务表

| 表名 | 说明 |
|---|---|
| `boss_kill_records` | Boss 击杀记录（Boss ID、击杀时间、参与者、掉落物、总伤害、位置） |
| `boss_drop_statistics` | Boss 掉落统计（Boss ID、物品 ID、掉落次数、掉落率） |
| `player_boss_best_damage` | 玩家 Boss 最高伤害记录（玩家 UUID、Boss ID、最高伤害、服务器名） |
| `cross_server_boss_rankings` | 跨服 Boss 排行缓存（排行类型、Boss ID、排行数据 JSON） |

### DKP 系统表

| 表名 | 说明 |
|---|---|
| `player_dkp` | 玩家 DKP 积分（总积分、获得积分、消耗积分） |
| `dkp_transaction_records` | DKP 交易记录（交易类型、积分数、原因、关联击杀 ID） |

### 掉落分配表

| 表名 | 说明 |
|---|---|
| `drop_allocation_records` | 掉落分配记录（击杀 ID、物品 ID、分配类型、获胜者、消耗积分、ROLL 值） |
| `roll_participation_records` | ROLL 参与记录（分配记录 ID、玩家、ROLL 类型、ROLL 值） |

### 排行榜奖励表

| 表名 | 说明 |
|---|---|
| `ranking_reward_configs` | 排行榜奖励配置（奖励类型、排行类型、Boss ID、名次范围、奖励内容） |
| `ranking_reward_records` | 排行榜奖励发放记录（配置 ID、周期、玩家、名次、状态、失败原因、重试次数） |
| `ranking_periods` | 排行榜统计周期（周期类型、排行类型、起止时间、参与人数、发放统计） |

### 其他表

| 表名 | 说明 |
|---|---|
| `offline_reward_storage` | 离线奖励存储（玩家 UUID、奖励类型、奖励数据、领取状态） |
| `entitytracker_version` | 版本记录表（用于迁移管理） |

### 主要索引

| 索引名 | 表 | 说明 |
|---|---|---|
| `idx_boss_kill_records_boss_time` | `boss_kill_records` | 按 Boss ID + 击杀时间查询 |
| `idx_player_boss_best_damage_boss` | `player_boss_best_damage` | 按 Boss ID + 伤害降序查询 |
| `idx_player_boss_best_damage_player` | `player_boss_best_damage` | 按玩家 + 伤害降序查询 |
| `idx_cross_server_rankings_type` | `cross_server_boss_rankings` | 按排行类型查询 |
| `idx_ranking_reward_records_status` | `ranking_reward_records` | 按发放状态查询 |
| `idx_ranking_periods_range` | `ranking_periods` | 按周期时间范围查询 |

## 与其他模块联动

### MythicMobs / MythicBukkit（外部依赖）

- **Boss 追踪**：监听 `MythicMobSpawnEvent`、`MythicMobDeathEvent`、`MythicMobDespawnEvent`
- **Boss 识别**：通过 `MythicBukkit.inst().getMobManager().getActiveMobs()` 扫描已存在的 Boss
- **Mohist 兼容**：混合服务端启动时，MythicMobs 事件可能延迟触发，模块自动执行补扫（启动时 6 次 × 20tick 间隔，稳定后 100tick 间隔，连续 10 次无遗漏后降频至 500tick）

### 属性插件桥接

EntityTracker 通过宿主的 `AttributeBridgeRegistry` 支持以下属性插件的伤害事件：

| 属性插件 | 说明 |
|---|---|
| AttributePlus | 属性伤害事件监听 |
| Crane | 属性伤害事件监听 |
| MythicLib | 属性伤害事件监听 |
| Symphony | 属性伤害事件监听 |

当属性插件存在时，Boss 伤害排名同时记录属性插件的伤害数据，确保排名准确。

### TACZ 枪械模组

模块通过 `TaczGunDamageEvent` 支持 TACZ 枪械模组的伤害事件，枪械伤害同样计入 Boss 伤害排名。

### Mail 模块

- **物品奖励兜底**：背包满时通过 `MailDispatchable` 发送邮件
- **离线奖励**：排行榜定时奖励发放时，离线玩家通过邮件接收
- **邮件奖励动作**：奖励配置中 `type: mail` 的动作直接通过邮件系统发送

### ItemRewardDispatcher

所有物品奖励发放统一由宿主的 `ItemRewardDispatcher` 处理：

```
发放物品 → 尝试放入背包 → 背包满 → 尝试发送邮件 → 无邮件 → 掉落地面
```

物品来源支持 `minecraft` / `mythic` / `neige` / `overture` / `mmoitems`，详见 [/docs/guide/item-sources](/docs/guide/item-sources)。

### PlaceholderResolverAPI

奖励动作中的变量替换完成后，会再走一次 PlaceholderAPI 解析，支持在奖励命令和消息中使用其他插件的占位符（如 `%vault_eco_balance%` 等）。

### 存储共享

EntityTracker 支持两种存储模式：

| 模式 | 配置 | 说明 |
|---|---|---|
| 共享存储（推荐） | `storage.shared: true` | 复用宿主统一数据源，连接由本体管控 |
| 独立存储 | `storage.shared: false` | 自建独立 HikariCP 连接池，支持 SQLite 或 MySQL |

存储层配置与迁移详见宿主存储文档。
