# Boss 追踪机制

> **付费模块**（消费额度满 ¥150 获得授权）

Boss 追踪子系统是 EntityTracker 的核心功能，依赖 MythicMobs / MythicBukkit。它监听 MythicMob 的生成、死亡、消失事件，为每个被追踪的 Boss 推送 HUD 数据，并在 Boss 死亡时触发伤害结算。

## 会话生命周期

每个活跃的 MythicMob 实体对应一个追踪会话：

| 阶段 | 处理行为 |
|---|---|
| 生成 | 匹配 Boss 定义 → 纳入追踪 → 发送生成聊天卡片（若配置）→ 刷新 HUD |
| 伤害 | 记录伤害数据 → 刷新 HUD |
| 死亡 | 生成结算记录 → 发放即时奖励 → 跨服同步 → 发送死亡卡片 → 移除 |
| 消失 | 发送消失卡片 → 移除 |

> 只有在 `bosses/` 目录中配置了对应 MythicMob ID 且 `enabled: true` 的 Boss 才会被追踪。模块启动时会扫描已存在的 MythicMob，将启动前已生成的 Boss 纳入追踪；已死亡或无效的实体会自动清理。

## HUD 显示

模块按 `refresh-interval-ticks` 周期向在线玩家推送 Boss HUD。玩家能看到某个 Boss 的条件：

| 条件 | 说明 |
|---|---|
| 玩家在线 | 玩家在线且未死亡 |
| 同一世界 | 玩家与 Boss 在同一世界 |
| 距离范围内 | 距离 ≤ Boss 定义的 `viewerRange`（未配置时使用全局默认值） |

Boss 生成/死亡/消失、玩家攻击 Boss 时会即时刷新；每个玩家最多显示 `max-visible-bars` 个 Boss 条目，超出部分不显示但可通过总数获知。

## 排序模式

通过 `boss.settings.sort-mode` 配置 HUD 中多个 Boss 的排列方式：

| 模式 | 配置值 | 排序逻辑 | 适用场景 |
|---|---|---|---|
| 生成顺序 | `spawn-order` | 先生成的 Boss 排前面 | 默认模式 |
| 距离优先 | `distance` | 按玩家与 Boss 的距离升序 | 优先显示最近的 Boss |
| 血量百分比 | `health-percent` | 按血量百分比升序 | 残血优先，适合集火提示 |
| 配置优先级 | `priority` | 按 Boss 定义的 `priority` 降序 | 手动指定重要 Boss |
| 混合 | `hybrid` | 综合排序，同时启用 Mohist 补扫机制 | Mohist 混合端推荐 |

## Mohist 混合端兼容

当 `sort-mode` 设为 `hybrid` 且服务端为 Mohist 混合端时，模块启动补扫机制，解决 Mohist 上 MythicMobs 事件延迟触发导致的 Boss 遗漏问题（启动时高频补扫，稳定后自动降频）。

```yaml
boss:
  settings:
    sort-mode: "hybrid"
```

## 聊天卡片

Boss 在生成、死亡、消失时可发送 ArcartX 聊天卡片，通过 Boss 配置文件中的以下字段控制：

| 字段 | 触发时机 |
|---|---|
| `spawn-chat-card` | Boss 生成时 |
| `death-chat-card` | Boss 死亡时 |
| `despawn-chat-card` | Boss 消失时 |

### 卡片可用变量

| 变量 | 说明 |
|---|---|
| `title` / `subtitle` | 渲染后的标题和副标题 |
| `mob_id` / `display_name` | MythicMob ID 和显示名称 |
| `health` / `max_health` / `health_percent` | 血量信息 |
| `distance` / `distance_text` | 距离信息 |
| `spawn_order` / `priority` | 生成顺序和优先级 |
| `world` / `x` / `y` / `z` | 位置信息 |
| `alive_seconds` / `alive_time` | 存活时间 |
| `has_target` / `target_name` / `target_uuid` / `target_type` | 目标信息 |
| `ranking_enabled` / `damage_participant_count` / `total_damage` | 排名信息 |
| `top_N_name` / `top_N_damage` / `top_N_damage_percent` | 各名次数据（N = 1 ~ max-entries） |
| `state` | 事件状态（`spawn` / `death` / `despawn`） |

> 聊天卡片仅发送给能够看到该 Boss 的玩家（同世界 + 距离范围内）。留空的卡片配置不会发送。

## 伤害记录

以下伤害会被计入伤害排名：

| 伤害类型 | 说明 |
|---|---|
| 造成伤害 | 玩家对 Boss 造成的伤害（原版近战/投射物、属性插件伤害、TACZ 枪械伤害） |
| 承受伤害 | Boss 对玩家造成的伤害 |

> 属性插件伤害支持 AttributePlus / Crane / MythicLib / Symphony，对应插件安装时自动计入。

## HUD 可用字段

Boss HUD UI 以槽位方式提供数据，UI 文件中可直接绑定以下字段：

```yaml
bossCount: 2              # 当前显示的 Boss 数量
totalBossCount: 5         # 可见 Boss 总数（含未显示的）
maxVisibleBars: 5         # 最大显示血条数
maxDamageRankingEntries: 10  # 最大排名条目数
sortMode: "spawn-order"   # 当前排序模式

# 每个槽位字段（slot1_ ~ slotN_）
slot1_visible: true
slot1_title: "&cExampleBoss"
slot1_subtitle: "&7MythicMob: &fSkeletalKnight"
slot1_health: 500.0
slot1_maxHealth: 1000.0
slot1_healthText: "500"
slot1_maxHealthText: "1000"
slot1_healthPercent: 50.0
slot1_healthPercentText: "50"
slot1_progress: 0.5
slot1_distance: 32
slot1_distanceText: "32m"
slot1_mobId: "SkeletalKnight"
slot1_displayName: "骷髅骑士"
slot1_entityUuid: "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
slot1_hasTarget: true
slot1_targetDisplayName: "Steve"
slot1_spawnOrder: 1
slot1_priority: 100
slot1_world: "world"
slot1_x: 100
slot1_y: 64
slot1_z: 200
slot1_aliveSeconds: 120
slot1_aliveTime: "02:00"
slot1_rankingEnabled: true
slot1_damageParticipantCount: 5
slot1_damageTrackedPlayerCount: 3
slot1_totalDamage: 15000.0
slot1_viewerRank: 2
slot1_viewerRankText: "#2"
slot1_viewerQualified: true
slot1_viewerDamage: 5000.0
slot1_viewerDamagePercent: 33.3
slot1_viewerTakenDamage: 200.0
# 排名条目（top1 ~ topN）
slot1_top1Name: "Alex"
slot1_top1Damage: 8000.0
slot1_top1DamagePercent: 53.3
slot1_top1TakenDamage: 100.0
```

空槽位（超出实际 Boss 数量的部分）发送默认空值。

> MythicMobs 重载或暂时不可用时血量自动回退到实体属性，HUD 不中断。UI 图标配置详见 [图标指南](/docs/guide/icons)。
