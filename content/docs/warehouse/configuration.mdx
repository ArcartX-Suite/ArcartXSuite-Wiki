## 先改哪些内容

仓库容量、分类、共享成员权限与银行规则。先使用默认示例完成一次测试，再按本页逐项调整。

配置位置：`plugins/ArcartX-Suite/data/warehouse/config.yml`。定义文件与子目录均相对此模块目录。本文中的 YAML 片段用于修改对应小节，请保留文件中的其他设置。

修改后执行 `/axs reload warehouse`；涉及插件安装或全局设置的变更请重启后验证。

配置文件位于 `plugins/ArcartX-Suite/data/warehouse/config.yml`，修改后执行 `/axs reload warehouse` 生效。

当前配置版本（`config-version`）为 **6**。仓库存取操作即时持久化。

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enabled` | boolean | `false` | 是否启用共享仓库的跨服功能；使用前先完成各子服的部署配置 |

### 界面显示（ui）

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `register-ui-on-enable` | boolean | `true` | 启动时是否自动注册 UI |
| `overwrite-ui-files` | boolean | `false` | 是否强制覆盖用户已修改的 UI 文件 |
| `page-size` | int | `72` | 仓库网格每页显示的槽位数量（控件按此数量动态创建），最小 1 |

### 自动入库（pickup）

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enabled` | boolean | `true` | 服务器总开关：关闭后全服自动入库功能失效，玩家个人开关不生效，管理界面隐藏整个拾取开关组 |
| `auto-store-on-pickup` | boolean | `true` | 拾取时是否自动存入仓库（玩家个人设置的默认值） |
| `auto-store-mythic-loot` | boolean | `false` | 是否自动存入 MythicMobs 自定义掉落物（玩家个人设置的默认值） |
| `mythic-loot-enabled` | boolean | `true` | 服务器开关：是否允许 MythicMobs 自定义掉落物自动入库（关闭后管理界面隐藏"怪物战利品"开关） |
| `notify-on-auto-store` | boolean | `true` | 自动存入时是否通知玩家（玩家个人设置的默认值） |

玩家可在管理 UI 中分别开关普通物品入库、怪物战利品入库和入库聊天提示，设置保存后重新上线仍然生效，优先于全局默认值。

> `enabled` 与 `mythic-loot-enabled` 为**服务器级开关**，优先级高于玩家个人设置：关闭时对应功能全服失效，管理界面同时隐藏对应开关，玩家无法在 UI 中看到或切换它。

与 Pickup 联动时，按两种场景配置：

1. **正常靠近拾取并提示**：Pickup 使用 `settings.mode: notification`，Warehouse 按上述服务器和个人开关决定是否入库，Pickup 补充显示实际已存入的数量。
2. **按键选取附近掉落物**：Pickup 使用 `settings.mode: scanner`。开启 `scanner.warehouse-auto-deposit: true` 后，点击物品才尝试入库；Warehouse 的服务器和个人开关仍然有效。没有开启、入库失败或容量不足的部分会尝试放入背包，背包也放不下时留在地面。

普通拾取在支持拾取尝试事件的服务端也覆盖“背包完全装满”的情况。关闭工作台时，只把背包装不下的材料尝试自动入库；关闭对应个人开关后按原版退回、掉落。具体规则见[自动存入与材料恢复](/docs/warehouse/material-recovery)。

两个模块不会同时对扫描模式接管的同一次拾取重复入库。入库聊天提示与 Pickup 的 HUD 开关独立；关闭入库聊天提示不会关闭 HUD。

## 仓库分类配置

`warehouses` 节定义个人仓库类型。个人仓库采用**逐格解锁模型**：初始 `base-slots` 格，玩家按 `slot-price` 逐格付费购买至 `max-slots`（不再整级升级）。扩展背包（ExtraBackpack）与个人仓库共用同一存储——两个入口看到同样的格子。

```yaml
warehouses:
  personal:
    display-name: "&6个人仓库"    # 仓库显示名称
    default-owned: true           # 玩家首次使用时是否自动创建
      base-slots: 72                # 初始解锁槽位数
      max-slots: 720                # 槽位总数上限，包含初始格
    slot-price:
      currency: "points"          # 每格所需货币 ID
      amount: 100                 # 每格价格
    permission: ""                 # 拥有此仓库所需的权限（留空 = 无限制）
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `display-name` | string | 仓库显示名称，支持颜色码 |
| `default-owned` | boolean | 玩家首次使用时是否自动创建此仓库 |
| `base-slots` | long | 初始解锁槽位数（默认 72） |
| `max-slots` | long | 槽位**总数**上限，含初始格（默认 720）；已解锁 = `base-slots` + 已购格数，不得超过此值 |
| `slot-price.currency` | string | 每格所需货币 ID，留空表示不可购买 |
| `slot-price.amount` | decimal | 每格价格 |
| `permission` | string | 拥有此仓库所需的权限节点，留空表示无限制 |

> **已解锁格数 = `base-slots` + `extra_slots`（数据库字段）**。玩家每点一次购买消耗 `slot-price` 并 `extra_slots + 1`。共享仓库仍使用 `shared.levels` 等级制，不受本模型影响。


## 物品分类配置

`categories` 节定义物品分类规则，按**物品注册键**或 **NBT/PDC 路径**匹配物品归属，三组规则为"或"关系：

```yaml
categories:
  equipment:
    display-name: "装备"
    priority: 10                   # 分类排序优先级（数字越小越靠前）
    nbt:
      path: "pdc:arcartx:item_category"   # NBT 匹配路径
      values: ["equipment", "weapon", "armor"]  # 匹配值列表
  mod_items:
    display-name: "Mod物品"
    priority: 5
    material-prefixes: ["tacz:", "apotheosis:"]   # 按 mod 命名空间分类
  material:
    display-name: "材料"
    priority: 20
    nbt:
      path: "pdc:arcartx:item_category"
      values: ["material"]
  other:
    display-name: "其它"
    priority: 9999                 # 兜底分类，优先级最低
    default: true                  # 未匹配任何分类的物品归入此分类
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `display-name` | string | 分类显示名称 |
| `priority` | int | 排序优先级，数字越小越靠前；先命中者优先 |
| `material-ids` | list | 物品注册键精确匹配（`minecraft:diamond_sword`、`tacz:modern_kinetic_gun`） |
| `material-prefixes` | list | 物品注册键前缀匹配（`tacz:` 命中全部 TaCZ 物品，`apotheosis:` 命中全部 Apotheosis 物品） |
| `nbt.path` | string | NBT/PDC 匹配路径（支持 `pdc:` 前缀读取 PersistentDataContainer，也可用 `material`/`name`/`custom-model-data`） |
| `nbt.values` | list | 匹配值列表，物品 NBT 路径值在此列表中即归入此分类 |
| `default` | boolean | 是否为兜底分类（未匹配任何分类的物品归入此处） |

> `other` 分类为系统内置兜底分类，始终存在，优先级 9999。
>
> 物品注册键指 Bukkit `Material.getKey()` 的全名（`命名空间:ID`）：原版物品为 `minecraft:<id>`，混合服 mod 物品为 `<modid>:<id>`（如 `tacz:modern_kinetic_gun`）。若只需精确匹配原版物品也可写 `nbt.path: "material"` + `values`（材质枚举名）。
>
分类规则修改并重载后，首次读取对应仓库时会按新规则重新计算已有物品的分类，不需要先取出再存入。

### 共享仓库权限分层

`shared.permission-tiers` 定义不同权限组可享受的共享仓库上限：

```yaml
shared:
  enabled: true
  create-cost:
    currency: "points"
    amount: 1000
  default-level: 1
  levels:
    "1":
      capacity: 2000
      upgrade:
        currency: "points"
        amount: 800
    "2":
      capacity: 5000
      upgrade:
        currency: "points"
        amount: 1800
    "3":
      capacity: 10000
  role-names:
    owner: "所有者"
    member: "成员"
    viewer: "观众"
  permission-tiers:
    default:
      permission: ""                              # 默认权限组（无额外权限要求）
      priority: 0
      max-owned: 1                                # 可拥有的共享仓库上限
      max-members: 6                              # 每个仓库的成员上限
    vip:
      permission: "ArcartXSuite.warehouse.shared.vip"
      priority: 10
      max-owned: 3
      max-members: 12
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `enabled` | boolean | 是否启用共享仓库功能 |
| `create-cost.currency` | string | 创建共享仓库所需货币 ID |
| `create-cost.amount` | decimal | 创建费用，`<=0` 或留空表示免费 |
| `default-level` | int | 默认共享仓库等级 |
| `levels` | map | 共享仓库等级配置（格式同个人仓库） |
| `role-names.owner` | string | 所有者角色显示名 |
| `role-names.member` | string | 成员角色显示名 |
| `role-names.viewer` | string | 观众角色显示名 |
| `permission-tiers.<id>.permission` | string | 权限节点，留空表示默认组 |
| `permission-tiers.<id>.priority` | int | 优先级，数字越大优先级越高 |
| `permission-tiers.<id>.max-owned` | int | 可拥有的共享仓库上限 |
| `permission-tiers.<id>.max-members` | int | 每个仓库的成员上限 |

### 排序方案配置

`sort-profiles` 定义搜索结果的排序方案：

```yaml
sort-profiles:
  time:
    fields:
      - "updated:desc"    # 按更新时间降序
      - "name:asc"        # 再按名称升序
  name:
    fields:
      - "name:asc"
  amount:
    fields:
      - "amount:desc"
      - "updated:desc"
```

支持的排序字段：`name`、`amount`、`updated`、`created`、`material`、`category`、`warehouse`。每字段可附加 `:asc`（升序）或 `:desc`（降序）。

系统内置三个排序方案：`time`、`name`、`amount`，可在配置中覆盖。

## 更新已有界面文件

本版的存取按钮与界面数据需要配套使用新版 `ui/warehouse_storage.yml`，管理页与银行页也有显示和交互修正。

1. 备份模块目录下 `ui/` 中的三个界面文件。
2. 使用默认界面时，临时设置 `ui.overwrite-ui-files: true`，执行 `/axs reload warehouse` 导出新版界面。
3. 将该选项恢复为 `false`，再调整自己的外观。自定义界面应先对照新版模板更新操作回包，再验证存取、分页、锁定和预览。

Pickup 的两个扫描界面也需要同时更新，步骤见[扫描模式](/docs/pickup/scanner-mode#更新已有界面文件)。

## 黑名单配置

`blacklist` 节定义物品存入拦截规则，匹配任意一条规则的物品将无法存入仓库。配置格式参考 [物品匹配器](/docs/guide/conditions)。

仓库黑名单的各字段分别生效：名称命中时即可拦截，不要求 Lore 也命中；同样，材质、物品库 ID、Lore、正则或 NBT 条件任一命中就会拦截。`nbt-values` 是一个整体条件，配置多组键值时必须全部符合才命中该字段。该规则同时用于手动存入、自动入库和第三方接口写入。

```yaml
blacklist:
  material-ids: []              # 按原版 Material ID 拦截
  mythic-item-ids: []           # 按 MythicMobs 物品 ID 拦截
  neige-item-ids: []            # 按 NeigeItems 物品 ID 拦截
  overture-item-ids: []         # 按 Overture 物品 ID 拦截
  kinds: []                     # 按物品种类拦截
  name-contains:                # 物品显示名包含任意关键词即拦截
    - "绑定不可存"
  lore-contains:                # 物品 Lore 包含任意关键词即拦截
    - "不可存入仓库"
  name-regex: []                # 物品显示名匹配任意正则即拦截
  lore-regex: []                # 物品 Lore 匹配任意正则即拦截
  nbt-keys: []                  # PDC 或原始 NBT 中存在任意 key 即禁止存入
```
