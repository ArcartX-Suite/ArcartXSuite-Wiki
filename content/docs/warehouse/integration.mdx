# 联动

## EventBus 事件

Warehouse 模块通过 EventBus 发布事件，供其他模块订阅：

| 事件主题 | 触发时机 | Payload 字段 |
| --- | --- | --- |
| `axs.warehouse.item_deposited` | 物品成功存入玩家个人仓库（含自动入库） | `material`（材质 ID）、`amount`（存入数量） |

### 事件发布流程

当物品通过以下方式存入个人仓库时触发事件：

1. **UI 手动存入**：玩家在存取界面通过 `deposit_slot` / `deposit_all_backpack` 操作
2. **自动入库**：拾取物品时自动存入（需服务器开启 `pickup.enabled` 且玩家开启自动入库）
3. **外部模块调用**：通过 `WarehouseAutoDepositable` Capability 调用自动入库

事件通过 `EventBusCapability` 发布，payload 包含物品材质名称与存入数量。其他模块可通过 EventBus 订阅此事件实现联动（如任务系统统计入库量、成就系统触发解锁等）。

```java
// 示例：其他模块订阅 warehouse 入库事件
eventBus.subscribe("axs.warehouse.item_deposited", (player, payload) -> {
    String material = payload.get("material");
    long amount = Long.parseLong(payload.get("amount"));
    // 处理入库事件...
});
```

## Capability 注册

Warehouse 模块注册以下 Capability，供其他模块通过 `getCapability()` 获取：

### WarehouseAutoDepositable

提供自动入库接口，供 Pickup 等外部模块调用将物品存入玩家个人仓库。

```java
public interface WarehouseAutoDepositable {
    DepositResult depositToPersonalWarehouse(Player player, ItemStack itemStack);
}
```

| 方法参数 | 说明 |
| --- | --- |
| `player` | 目标玩家，必须在线 |
| `itemStack` | 待存入物品（会被 clone，不会修改原对象） |

| 返回值字段 | 说明 |
| --- | --- |
| `success` | 是否存入成功 |
| `storedAmount` | 已存入数量 |
| `remainingAmount` | 剩余未存入数量 |
| `message` | 提示消息 |

存入逻辑：先经服务器级开关校验（`pickup.enabled` 关闭时直接拒绝；MythicMobs 自定义物品还需 `mythic-loot-enabled` 开启），再经黑名单校验后存入玩家第一个个人仓库，相同物品自动堆叠。存入成功后发布 `axs.warehouse.item_deposited` 事件。

### 数据清理与迁移

- `/axs purge` 支持清除玩家的个人仓库、银行余额、定期存款与共享成员记录
- `/axs migrate` 支持跨数据库源迁移仓库数据

### WarehouseAccess（模块提供）

模块注册 `WarehouseAccess` Capability（`axs-api`），向其他模块暴露玩家个人仓库的直接读写：槽位快照/存取/覆写、已解锁容量、逐格购买与管理端发放/重置。ExtraBackpack 模块依赖此能力——扩容背包即个人仓库的第二入口。

| 方法 | 说明 |
| --- | --- |
| `slots(player)` | 个人仓库全部占用槽位（`SlotItem{slot, itemStack}`） |
| `snapshot(player)` | 聚合快照（used/unlocked/max/canPurchase/nextSlotPrice） |
| `deposit(player, stack)` | 存入：先合并同类堆叠再填首个空位 |
| `setSlot(player, slot, stack)` | 覆写/清空指定槽位 |
| `withdraw(player, slot, amount)` | 按槽位取出到玩家背包 |
| `purchaseSlot(player)` | 逐格购买（扣费 + `extra_slots+1` + 失败退款） |
| `grantSlots` / `resetSlots` | 管理端赠送/重置已购槽位 |

## 跨服同步

### 共享仓库编辑锁

当 `cross-server.enabled: true` 且共享仓库功能启用时，共享仓库的编辑锁跨服同步：玩家在任一子服打开共享仓库编辑模式后，其他子服上的玩家打开同一共享仓库时以只读模式进入；编辑者关闭界面或退出后锁自动释放。

**启用条件**：

**启用条件**：

- `cross-server.enabled: true`
- `shared.enabled: true`
- 宿主 `config.yml` 配置了跨服通道（Redis 或 Proxy 后端）
- MySQL 共享数据库（多子服共用同一数据库）

> 跨服编辑锁仅影响共享仓库的编辑模式。个人仓库不受跨服锁影响。

## 数据存储

Warehouse 模块将个人仓库物品、银行余额、定期存款、共享仓库与成员关系、玩家设置存储在数据库中（SQLite 或 MySQL）。

## 与其他模块联动

| 联动模块 | 说明 |
| --- | --- |
| Pickup | 拾取物品自动入库；入库后通过 Pickup 发送 HUD 通知 |
| ExtraBackpack | 扩容背包与个人仓库共用同一存储 |
| 核心二级密码 | 存取物品、银行操作、共享仓库管理等敏感操作前检查二级密码会话 |
| 货币桥接 | 银行系统、定期存款产品与仓库升级使用全局货币 |

### 与 Pickup 模块联动

当 Pickup 模块启用且玩家开启自动入库时，拾取物品直接存入玩家仓库并发送通知；存入失败时物品保留在地面或背包。

> MythicMobs 自定义掉落物走战利品通道：需服务器开启 `pickup.mythic-loot-enabled` 且玩家开启"怪物战利品"开关才会自动入库；普通物品只需玩家开启"自动入库"。服务器关闭 `pickup.enabled` 时所有自动入库失效。

### 与核心二级密码联动

Warehouse 的二级密码由核心统一管理，不再由模块自行存储密码。玩家通过 `/axs password set|unlock|clear` 管理密码。Warehouse 在存取物品、银行操作、共享仓库管理等敏感操作前检查二级密码会话状态。

会话有效期由宿主 `config.yml` 的 `security.secondary-password.unlock-timeout-seconds` 配置（默认 1800 秒 = 30 分钟），超时后需重新解锁。
