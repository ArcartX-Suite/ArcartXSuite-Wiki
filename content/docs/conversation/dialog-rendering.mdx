# 对话渲染流程

> **付费模块**

`ChemdahAxRenderer` 是 Conversation 模块的核心渲染器，负责将 Chemdah 会话的对话正文与回复列表渲染到 ArcartX 对话 UI。它维护每个玩家的 `DialogState` 生命周期，处理回复选择 / 确认 / 取消、按键导航、UI 打开与关闭等交互，并通过 `PacketBridgeAPI` 向对话 UI 同步 payload。

## 架构概览

`ChemdahAxRenderer` 由 `ConversationService` 持有，属于模块内部组件（包私有）：

| 组件 | 职责 |
| --- | --- |
| `DialogState` | 单个玩家的对话状态快照（会话、正文、回复列表、选中项） |
| `ReplyView` | 单条回复的展示视图（id、text、replyType） |
| `dialogStates` | `ConcurrentMap<UUID, DialogState>` 玩家对话状态表 |
| `displaySequences` | `ConcurrentMap<UUID, Long>` 显示序号（防止过期渲染） |
| `closedSessions` | `ConcurrentMap<UUID, Session>` 已关闭的会话 |
| `uiClosedSessions` | `ConcurrentMap<UUID, Session>` UI 端已关闭的会话 |
| `dialogOpenedPlayers` | `Set<UUID>` 对话 UI 已打开的玩家集合 |

### 渲染入口

渲染由 `ArcartXConversationTheme`（Chemdah 主题）回调驱动：

| 主题回调 | 渲染器方法 | 说明 |
| --- | --- | --- |
| `onBegin(Session)` | `display()` | 开始对话时渲染首屏 |
| `onDisplay(Session, lines, canReply)` | `display()` | 对话内容更新时重新渲染 |
| `onClose(Session)` | `close()` | 关闭对话 UI |

## 对话渲染流程

### display 流程

`display(session, lines, canReply)` 是渲染入口，完整流程：

```
display(session, lines, canReply)
  → 检查 session / player 有效
  → 检查是否已关闭的会话（closedSessions）
  → 检查会话可渲染（isSessionRenderable）
  → safeLines(lines) 清理文本行
  → nextDisplaySequence(playerId) 递增显示序号
  → checkRepliesSafely(session) 异步获取回复列表
  → replyFuture.thenAccept:
    → runSyncIfEnabled("deliver-dialog"):
      → deliverDialogState(player, session, lines, canReply, replies, displaySequence)
```

### deliverDialogState 流程

`deliverDialogState` 在主线程执行，构建 `DialogState` 并同步到 UI：

```
检查玩家在线
  → 检查 displaySequence 是否最新（防过期）
  → 检查会话未关闭且可渲染
  → 获取 previous DialogState（保持选中项）
  → 构建 repliesById / replyViews / replyIds
  → preserveSelection 保持或初始化选中项
  → 创建 DialogState 存入 dialogStates
  → closeSelectorForDialog() 关闭选择器
  → syncDialogView() 同步到 UI
```

### 会话可渲染检查

`isSessionRenderable(player, session, fallbackReason)` 检查会话状态：

| 检查项 | 方法 | 失败处理 |
| --- | --- | --- |
| session 为 null | — | 记录 `fallbackReason` 日志，返回 false |
| 会话已关闭 | `session.isClosed()` | 记录 `closed-session-display` 日志，返回 false |
| 会话无效 | `session.isValid()` | 记录 `invalid-session-display` 日志，返回 false |

> `isClosed` / `isValid` 通过 `readSessionBoolean` 安全调用，捕获 `Exception` / `LinkageError` 时返回 fallback 值。

## DialogState 生命周期

### DialogState 字段

| 字段 | 类型 | 可变 | 说明 |
| --- | --- | --- | --- |
| `session` | `Session` | 否 | Chemdah 会话 |
| `speakerName` | string | 否 | 说话人名称（NPC 名） |
| `messageLines` | `List<String>` | 否 | 对话正文文本行 |
| `canReply` | boolean | 否 | 是否允许玩家回复 |
| `repliesById` | `Map<String, PlayerReply>` | 否 | 回复 ID → PlayerReply 映射 |
| `replyViews` | `Map<String, ReplyView>` | 否 | 回复 ID → 展示视图映射 |
| `replyIds` | `List<String>` | 否 | 有序回复 ID 列表 |
| `generation` | long | 否 | 创建时的 generation |
| `selectedReplyId` | string | 是 | 当前选中的回复 ID |
| `selectedReplyIndex` | int | 是 | 当前选中的回复索引 |
| `lastReplyActionAt` | long | 是 | 最近回复操作时间戳（防抖） |

### 选中项管理

`selectReply(replyId)` 修改选中项：

| 条件 | 结果 |
| --- | --- |
| `canNavigateReplies()` 为 false | 返回 false（无可选回复） |
| `replyId` 为 null 或空白 | 返回 false |
| `replyIds.indexOf(replyId)` `<` 0 | 返回 false（ID 不存在） |
| 匹配成功 | 更新 `selectedReplyIndex` 和 `selectedReplyId`，返回 true |

> `canNavigateReplies()` = `canReply && !replyIds.isEmpty()`，即允许回复且存在回复列表。

### 选中项保持

`preserveSelection(orderedIds, preferredId)` 在重新渲染时保持选中项：

| 场景 | 处理 |
| --- | --- |
| `preferredId` 有效且在列表中 | 沿用该选中项 |
| `preferredId` 无效或为空 | 回退到列表首项 |
| 列表为空 | 返回 `SelectionState(-1, "")` |

> 首次渲染时 `preferredId` 来自 `findPlayerSelectedReplyId`（检查 `PlayerReply.isPlayerSelected`），后续渲染沿用 `previous.selectedReplyId`。

## 回复处理

### 回复类型语义

`ConversationReplySemanticsSupport` 解析 Chemdah `PlayerReply` 的类型：

| 类型 | 判定 | UI 行为 |
| --- | --- | --- |
| `talk` | `replyType == "talk"` | 选中后仅同步 UI，不立即触发（等待确认） |
| `close` | `replyType == "close"` | 关闭对话 |
| 其他 | 其他值 | 正常处理 |

> 回复类型来自 `PlayerReply.getRoot().get("type")`，为空时回退到 `PlayerReply.getFormat()`。

### 回复选择

`handleSelectReply(player, replyId)` 处理 UI 点击选中回复（不触发执行）：

```
获取 DialogState
  → state.selectReply(replyId)
  → 成功则 syncDialogView("select-reply")
```

### 回复确认

`handleConfirmReply(player, replyId)` 处理确认选择回复，触发 Chemdah 回复执行：

```
获取 DialogState
  → replyId 非空时先 selectReply
  → confirmReply(player, state, "confirm-reply")
```

`confirmReply` 完整流程：

```
检查 canNavigateReplies
  → 获取 selectedReply
  → 检查防抖（reply-debounce-ms）
  → 更新 lastReplyActionAt
  → suppressSelectorOpen() 抑制选择器重新打开
  → talk 类型? → syncDialogView（仅刷新 UI）
  → selectedReply.select(session) 触发 Chemdah 回复执行
```

### 防抖机制

| 机制 | 配置项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 回复确认防抖 | `interaction.reply-debounce-ms` | `250` | 两次回复确认的最小间隔 |
| 选择器抑制 | `interaction.suppress-reopen-ms` | `500` | 回复后抑制选择器重新打开的时长 |

> 防抖通过比较 `now - state.lastReplyActionAt` 与 `replyDebounceMs` 实现。在防抖间隔内的确认请求被静默丢弃。

### 回复取消

`handleCancelDialog(player)` 处理取消对话：

```
获取 DialogState
  → state.session().close(true) 关闭 Chemdah 会话
  → 触发主题 onClose → close() 关闭 UI
```

## UI 同步

### syncDialogView 流程

`syncDialogView(player, state, source)` 同步对话状态到 UI：

```
检查 player 在线且 state 有效
  → 对话 UI 未打开?
    → bridge.openUiAll() 打开 UI
    → 成功: dialogOpenedPlayers.add, scheduleDialogSync（延迟 1 tick 同步）
    → 失败: 移除状态, restoreSelectorAfterDialog
  → 对话 UI 已打开?
    → sendDialogSync() 直接发送 sync 包
```

> 首次打开 UI 时延迟 1 tick 同步（`scheduleDialogSync`），确保 UI 控件已初始化。延迟期间检查 state 是否仍为当前状态，避免竞态。

### 对话 UI sync 包

`buildDialogPayload(state)` 构建发送给对话 UI 的 sync 包：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `token` | string | 会话令牌（基于 generation） |
| `packetId` | string | 通信标识 |
| `speakerName` | string | 说话人名称（NPC 名） |
| `messageLines` | `List<String>` | 对话正文文本行列表 |
| `hintText` | string | 底部提示文字 |
| `canReply` | boolean | 是否允许玩家回复 |
| `selectedReplyId` | string | 当前选中的回复 ID |
| `selectedReplyIndex` | int | 当前选中的回复索引 |
| `replyCount` | int | 可选回复总数 |
| `replyScrollRatio` | double | 回复列表滚动比例（0.0 ~ 1.0） |
| `replyRows` | `Map<String, Map<String, Object>>` | 回复行数据字典 |

### hintText 逻辑

| 条件 | hintText |
| --- | --- |
| `canNavigateReplies()` 为 true | `"点击选项或按数字键 1-9 发送"` |
| `canNavigateReplies()` 为 false | `"当前没有可选回复"` |

### replyRows 单行字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 回复 ID |
| `text` | string | 回复显示文本 |
| `replyType` | string | 回复类型（`talk` / `close` / 其他） |
| `selected` | boolean | 是否当前选中 |
| `index` | int | 回复序号（0-based） |

> 行键使用 `Integer.toString(index)`（纯数字字符串），UI 引擎自动转为整数。滚动比例由 `computeScrollRatio` 计算，可见行数为 6 行（`DIALOG_VISIBLE_ROWS`）。

## 会话生命周期

### 会话关闭

`close(session)` 处理 Chemdah 主题 `onClose` 回调：

```
检查 session / player 有效
  → closedSessions.put(playerId, session) 标记已关闭
  → 获取 DialogState
  → state 不存在? → 记录 "no-active-dialog" 日志
  → state.session != session? → 记录 "session-mismatch" 日志
  → displaySequences.merge +1（使进行中的渲染过期）
  → 检查 uiClosedSessions（UI 端是否已关闭）
  → closeDialogView(player, state, closeUi, restoreSelector, "theme-close")
```

### UI 关闭回调

`handleUiClosed(player)` 处理客户端 UI 被关闭（ESC / 关闭按钮）：

```
dialogOpenedPlayers.remove(playerId)
  → 获取 DialogState
  → state 不存在? → 记录日志
  → uiClosedSessions.put(playerId, session) 标记 UI 端已关闭
  → state.session().close(true) 关闭 Chemdah 会话
```

> `uiClosedSessions` 标记用于避免 `close()` 时重复发送关闭 UI 包。当 UI 端先关闭时，`close()` 的 `closeUi` 参数为 false，不再重复关闭。

### 关闭视图

`closeDialogView(player, state, closeUi, restoreSelector, reason)` 关闭对话 UI 视图：

| 参数 | 说明 |
| --- | --- |
| `closeUi` | 是否发送关闭包并关闭 UI（UI 端已关闭时为 false） |
| `restoreSelector` | 是否在关闭后恢复选择器（主题关闭时为 true） |

## 显示序号防过期

`displaySequences` 防止异步渲染竞态：

| 机制 | 说明 |
| --- | --- |
| `nextDisplaySequence` | 每次 `display()` 递增序号 |
| `isLatestDisplaySequence` | `deliverDialogState` 中检查序号是否仍为最新 |
| `close()` 时 `merge +1` | 使进行中的异步渲染过期 |

> `checkRepliesSafely` 是异步操作（`CompletableFuture`），在回调执行前可能已有新的 `display()` 或 `close()` 调用。序号检查确保只有最新的渲染请求会实际同步到 UI。

## Token 校验

服务端维护一个 `generation` 计数器（`AtomicLong`），每次模块重载 / 重置时递增。发送给客户端的 sync 包携带 `token`（generation 的字符串形式），客户端回包必须携带相同的 `token` 才会被服务端接受。

| 场景 | generation 变化 |
| --- | --- |
| 模块启动 | 从 `System.currentTimeMillis()` 初始化 |
| 模块重载 / 重置 | `advanceGeneration()` 递增 |
| Chemdah 对话重载 | `resetRuntimeState()` 递增 |

> `DialogState` 创建时捕获当前 `generation`，构建 payload 时使用 `tokenFor(state.generation())`。这确保了过期包（如模块重载前的旧包）不会被误处理。

## 数据包扁平化

`ConversationPayloadSupport` 确保发送给 UI 的每行数据只包含基本类型：

| 方法 | 说明 |
| --- | --- |
| `rowKey(index)` | 生成行键 `Integer.toString(index)` |
| `flatRow(entries)` | 构建扁平 `LinkedHashMap`，拒绝嵌套 Map / Iterable / 数组 |
| `isFlatRowDictionary` | 校验字典是否完全扁平 |

> 嵌套 Map / Iterable / 数组会导致 UI 引擎反序列化异常，`flatRow` 在构建时即抛出 `IllegalArgumentException`，确保数据包结构正确。
