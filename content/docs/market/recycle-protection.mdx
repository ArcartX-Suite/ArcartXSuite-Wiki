description: "管理个人自动回收、材质排除与收藏同款，了解回收确认、收益入账和异常提示。"

回收保护由每名玩家自行设置，对单件回收、批量回收和拾取自动回收同时生效。服务器仍需先在回收表中配置物品及价格；添加保护不会改变回收表。

## 打开保护页面

执行 `/market recycle protect`，或在 `/market recycle` 页面点击“个人回收保护”。也可使用 `protection`、`settings` 作为 `protect` 的别名。

页面展示个人自动回收状态、规则总数与上限，并提供“全部”“材质排除”“收藏同款”三个清单分类。默认每人最多保存 200 条规则，两类规则合计计数。

## 添加排除或收藏

1. 点击“排除此材质”或“收藏同款物品”。
2. 在背包选择页选取主背包或快捷栏中的真实物品。选物只保存规则所需的模板，不取走物品。
3. 查看确认弹窗中的物品及保护范围，点击“确认变更”。
4. 等待保存结果，再在清单中查看规则。可通过分类和分页继续管理。

| 规则 | 保护范围 | 适用情况 |
|---|---|---|
| 材质排除 | 相同原版材质的全部物品，包含同材质的自定义变体 | 不希望任何钻石剑、铁锭等物品被回收 |
| 收藏同款 | 与模板相同的物品；忽略数量、耐久和修复惩罚，仍区分名称、附魔及其他物品数据 | 只保护某款装备或特定自定义物品 |

例如，排除 `IRON_SWORD` 会保护普通铁剑、命名铁剑及使用铁剑材质的自定义装备。收藏一把命名铁剑则保护与它同款的物品，使用后耐久变化仍受保护；名称、附魔或其他数据发生变化后，需要为新款式重新添加规则。

收藏保护按模板识别同款，不标记某个物品实例，也不修改物品 NBT 或堆叠方式。因此，同款物品后来获得的新一组也受保护。

## 移除规则

在清单中点击“移除保护”，查看物品与提示后确认。移除只删除本人的对应规则，不修改背包物品或服务器回收价格。

同一物品可能同时命中材质排除和收藏同款。移除一条后，只要另一条仍然匹配，物品就继续受保护。移除后是否可以回收，还取决于服务器回收表是否包含该物品。

## 开启个人自动回收

个人自动回收默认关闭。点击“开启个人自动回收”，确认后等待服务器保存；关闭时点击“关闭个人自动回收”并等待状态更新。

自动回收必须同时满足以下条件：

| 条件 | 设置位置 |
|---|---|
| 回收功能已启用 | `recycle.enabled: true` |
| 服务器允许自动回收 | `recycle.allow-auto-recycle: true` |
| 玩家拥有自动回收权限 | `axsmarket.autorecycle` |
| 个人开关已打开 | 个人回收保护页面 |
| 保护资料可用，物品未受保护 | 页面显示的资料状态及保护规则 |

个人开关已打开，并不一定代表自动回收正在生效。页面会说明服务器开关、权限或保护资料造成的限制，回收页面也显示当前是否生效。

拾取回收表内且未受保护的物品时，系统受理回收并建立收益入账任务。未受理的物品继续正常拾取。关闭个人自动回收不会关闭手动回收，保护规则仍对手动回收生效。

## 单件和批量回收

执行 `/market recycle` 查看预览。受保护的物品显示保留原因，不能点击回收；预估收益只统计当前允许回收的物品，多种货币分别展示，可滚动查看。

批量回收只扫描主背包和快捷栏，不包含装备栏与副手。`recycle.batch-recycle-enabled: false` 会同时关闭 UI 和命令批量回收，仍可逐件回收。

开启 `recycle.batch-confirm` 后，点击批量回收需要确认；执行 `/market recycle all` 会先打开回收页面。背包物品或保护规则在预览后发生变化时，旧确认失效，必须刷新后重新确认，避免改变实际回收范围。

“回收已受理，收益等待入账”表示物品已收取，并建立了收益任务。最终入账以处理流水为准；尚未到账时，可请管理员在[交易管理面板](/docs/market/trade-management)查看关联入账记录。

## 保存、刷新与异常提示

保存期间暂停回收；关闭页面不代表取消已经提交的保存操作，重新打开可查看实际结果。确认弹窗绑定打开时的规则版本，其他服务器修改了个人设置后，需要重新选择并确认。

| 提示或现象 | 处理方式 |
|---|---|
| 保护资料读取中、正在更新 | 等待状态回显，必要时点击“刷新保护清单” |
| 收藏模板无法完整读取，回收暂停 | 在“全部”或“收藏同款”中找到对应规则，移除后重新选物添加；无法保存模板时可改用材质排除 |
| 规则类型无法识别 | 在“全部”清单中查看并移除该规则，再添加当前版本支持的规则 |
| 清单达到上限 | 删除不再需要的规则，或请管理员调整 `max-rules` |
| 背包、槽位或保护已变化 | 刷新回收预览，重新选择或确认 |
| 物品仍然受保护 | 检查是否同时存在材质排除及收藏同款规则 |
| 回收处理中断或已受理但未到账 | 保留物品、时间和提示信息，请管理员核对关联流水 |

保护资料无法读取时，手动回收暂停，自动回收跳过并保留正常拾取流程。

## 管理员配置示例

在 `plugins/ArcartX-Suite/data/market/config.yml` 中修改对应小节，保留其他已有设置：

```yaml
recycle:
  enabled: true
  allow-auto-recycle: true
  batch-recycle-enabled: true
  batch-confirm: true
  protection:
    default-auto-recycle: false
    max-rules: 200

ui:
  recycle-protection-ui-id: "AXS:market_recycle_protection"
  admin-trades-ui-id: "AXS:market_admin_trades"
```

`default-auto-recycle` 只决定首次创建个人设置时的默认值，不覆盖已有玩家的开关。`max-rules` 范围为 1–1000；调整上限不会自动删除已有规则。

规则和个人开关按 UUID 保存；共享同一市场数据库的服务器使用同一份个人设置。保护清单通过游戏内页面管理，不需要在回收价格文件中填写个人规则。

两个 UI ID 必须与彼此及其他市场界面不同。导出的个人保护页面为模块目录 `ui/market_recycle_protection.yml`，主回收页面为 `ui/market_recycle.yml`。升级时若已有自定义 UI，应先备份，再合并新版页面的交互改动；只更新模块而保留旧回收页面，可能导致缺少入口或持续要求重新预览。相关覆盖设置见[功能配置](/docs/market/configuration)。

修改主配置后执行 `/axs reload market`。回收物品与价格的定义见[商店系统](/docs/market/shops)。
