title: "NPC 兑换与在线编辑"

---

通过 Adyeshach NPC 提供兑换。一条报价可包含多种物品和货币作为成本或奖励。

## 第一次使用

1. 安装并启用 Adyeshach。在 Market 配置设置 `exchange.enabled: true` 后执行 `/axs reload market`。
2. 管理员执行 `/axs market exchange edit example`，查看示例“旅人兑换所”：一个绿宝石兑换四个铁锭。
3. 选择附近的 Adyeshach NPC，保存兑换所设置，再编辑兑换成本和奖励。
4. 右键已绑定的 NPC 打开兑换。核对成本和奖励后再确认。

编辑权限为 `arcartxsuite.market.exchange.admin`。玩家使用 NPC 时，还需满足兑换所与条目各自设置的权限；权限留空则不限。

## 编辑兑换所与条目

左侧选择兑换所，中间选择条目，右侧填写设置。兑换所和条目可分别启停，保存后立即生效。其他管理员的旧版本不能覆盖新内容，需刷新后重新编辑；删除配置和放弃未保存修改均需确认。

成本和奖励各支持 1～8 项，可混合多种物品与货币。单项物品数量为 1～64；货币金额必须大于零，并符合该币种的小数精度。

### 物品来源

| 来源 | 填写方式 | 用途 |
| --- | --- | --- |
| 原版物品 | 材质 ID，例如 `IRON_INGOT` | 使用标准原版物品 |
| MythicMobs | 物品内部 ID | 按物品库生成奖励或识别成本 |
| NeigeItems | 物品 ID | 按物品库生成奖励或识别成本 |
| Overture | 模板 ID | 按物品库和玩家上下文生成奖励 |
| MMOItems | `类型ID;物品ID`，如 `SWORD;EXCALIBUR` | 指定类型与物品 ID |
| 完整物品快照 | 从真实背包选择 | 固定名称、附魔、耐久等完整物品数据 |

背包选物只读取物品，不消耗它。识别到物品库道具时优先填写来源与 ID；选择完整快照则保留当前数据。

成本按物品库 ID 配置时，可匹配同一库 ID 的不同实例；完整快照要求物品数据一致。物品库奖励按该库的生成规则创建，预览不代表随机属性必然相同。

### 多货币

货币来自 Suite 主配置的 `currencies`，与 Market、Warehouse 共用定义。可以同时收取多种货币，也可把货币作为奖励；对应插件或接口必须可用。

界面显示账户余额，不会把虚拟货币当成背包中的金锭或绿宝石扣除。设置方法见[货币配置](/docs/guide/currencies)。

## 绑定 Adyeshach NPC

点击「选择附近 NPC」，或填写 `ady:实体ID`。绑定多个 NPC 时用逗号分隔。同一个 NPC 对应一个兑换所，一个兑换所可绑定多个 NPC。

玩家可以右键已绑定的 NPC，或在它附近执行 `/axs market exchange open <兑换所ID>`。打开界面和确认兑换时均需满足绑定、距离和使用权限要求。

## 仓库与背包

开启 Warehouse 时，成本优先使用背包物品，再从可用个人仓库补足。数量按真实总库存计算，不受仓库分页、分类和搜索影响。仓库锁定或不可用时，仅使用背包材料。

奖励物品进入背包，货币进入对应账户。背包无法接收全部奖励时，兑换不会开始。没有 Warehouse 的服务器也可以使用 NPC 兑换、货币和物品库功能。

## 兑换中断与人工核对

市场的交易管理面板可按“NPC 兑换”查询流水。完整凭证和人工结案由兑换管理权限控制。

系统保存成本、奖励和相关资产变化。无法确认扣款或交付结果时保留凭证，不自动重复扣款或补发。管理员可在编辑器顶部打开“交易核对”：

1. 选中记录或输入凭证 UUID，导出完整凭证。
2. 核对背包、仓库和货币系统的实际记录，必要时另行处理补偿。
3. 核对后人工结案。**结案不发放或退回任何资产。**

导出目录为 `plugins/ArcartX-Suite/data/market/npc-trade-evidence/`。重启或重载后，已在游戏中应用的记录也可能转为待核对；不能只凭状态判定物品丢失。成功记录不会自动重放，处理中断的未结案记录可能阻止继续兑换。

备份兑换记录时，请一并保留 Market 配置与数据库。
