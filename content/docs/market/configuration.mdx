## 先改哪些内容

shops/ 商品、回收价格、交易货币与拍卖规则。先使用默认示例完成一次测试，再按本页逐项调整。

主配置文件为 `plugins/ArcartX-Suite/data/market/config.yml`。定义文件与子目录均相对此模块目录。本文中的 YAML 片段用于修改对应小节，请保留文件中的其他设置。

修改后执行 `/axs reload market`；涉及插件安装或全局设置的变更请重启后验证。

### 四类交易的界面与记录

四类功能分别使用 `auction.enabled`、`player-shop.enabled`、`shop.enabled`、`recycle.enabled` 控制。关闭功能后，其入口会提示未启用。`/market sellui` 的上架模式只允许使用已启用的拍卖行或玩家商店。

上架界面按对应模式的 `min-duration-seconds`、`max-duration-seconds` 和 `default-duration-seconds` 设置时长，预设天数超出范围时不可选择。默认值应配置在允许范围内。

`/market history` 合并四类交易记录，按时间分页展示。玩家商店已有历史也会显示；系统商店购买和回收从本次版本起记录，不补造此前未保存的历史。

`auction.tax-discount` 和 `player-shop.tax-discount` 的值均为**最终税率**，取匹配权限中的最低值；不是从基础税率中减去的数值。例如 `axsmarket.vip: 0.02` 表示最终收取 2%。

`recycle.batch-recycle-enabled: false` 同时关闭界面和命令的批量回收，仍可逐件回收。`batch-confirm: true` 在界面显示确认弹窗；命令 `/market recycle all` 会先打开回收界面。自动拾取回收还需同时满足 `allow-auto-recycle`、`axsmarket.autorecycle` 权限及个人开关；个人默认关闭。材质排除与收藏同款保护对三种回收方式同时生效，详见[玩家回收保护](/docs/market/recycle-protection)。

Redis 启用后缓存玩家各自的拍卖和玩家商店列表页，保存时间使用 `cache-ttl-seconds`。交易、下架及到期会使列表缓存失效；Redis 不可用时直接查库。跨服消息发送不依赖此缓存开关。

系统商店 `refresh-interval-ticks` 调度到期限购清理及周期补货。单个商品只有设置了大于 0 的 `restock-interval-seconds` 才会按周期补满 `global` 或 `per-player` 库存；默认 0 不自动补货。动态商品策略在 `shop.dynamic.strategies` 中配置，需启用 `shop.dynamic.enabled`；三个策略类型为 `random-refresh`、`price-float`、`scheduled-swap`。

| `auction.end-protection.window-seconds` | int | `120` | 延时触发窗口，1–3600 秒 |

### 竞价加价规则

新出价必须满足：

```
新出价 ≥ max(当前最高价 × (1 + min-bid-increment-ratio), 当前最高价 + min-bid-increment-absolute)
```

例如：当前最高价 100，ratio=0.05，absolute=10 → 新出价至少 110（取 max(105, 110)）。

### 物品黑名单 (auction.blacklist)

黑名单使用统一的 ItemMatcher 规则，满足任意一条即拦截。详见 [物品匹配器](/docs/guide/conditions)。

| 字段 | 类型 | 说明 |
|---|---|---|
| `material-ids` | list | 禁止的原版材质 ID（Bukkit Material 枚举名） |
| `mythic-item-ids` | list | 禁止的 MythicMobs 物品 ID |
| `neige-item-ids` | list | 禁止的 NeigeItems 物品 ID |
| `overture-item-ids` | list | 禁止的 Overture 物品 ID |
| `kinds` | list | 禁止的物品类别（`mythic`/`neige`/`vanilla`） |
| `name-contains` | list | 物品名称包含此字符串则禁止 |
| `lore-contains` | list | 物品 Lore 包含此字符串则禁止 |
| `name-regex` | list | 物品名称匹配正则则禁止 |
| `lore-regex` | list | 物品 Lore 匹配正则则禁止 |
| `nbt-keys` | list | 物品存在此 NBT/PDC 键则禁止 |
| `nbt-values` | map | NBT/PDC 键值匹配则禁止 |

### 拍卖行分类 (auction.categories)

分类用于拍卖行界面的筛选功能，通过检查物品的 NBT/PDC 数据判定归属。

| 字段 | 类型 | 说明 |
|---|---|---|
| `display-name` | string | 分类在 UI 中显示的名称 |
| `priority` | int | 排序优先级，数字越小越靠前 |
| `nbt.path` | string | 检查的 NBT/PDC 路径（格式 `pdc:namespace:key`） |
| `nbt.values` | list | 值匹配列表，任一匹配即归属此分类 |
| `default` | boolean | 是否为默认分类（未匹配其他分类时归入） |

### 动态商品策略 (shop.dynamic)

| 字段 | 类型 | 说明 |
|---|---|---|
| `shop.dynamic.enabled` | boolean | 是否启用动态商品策略 |
| `shop.dynamic.strategies` | section | 策略配置节，每个键为策略唯一键 |

每个策略支持三种类型：

| 类型 | 说明 |
|---|---|
| `random-refresh` | 随机刷新（神秘商人）：从候选池按权重随机抽选 N 个商品上架 |
| `price-float` | 价格浮动：按 random-walk 或 supply-demand 模式动态调价 |
| `scheduled-swap` | 定时换货：按多个商品集轮换上架 |

详见 [商店系统 - 动态价格策略](/docs/market/shops#动态价格策略)。

## 回收商店配置 (recycle)

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `recycle.enabled` | boolean | `true` | 是否启用回收商店 |
| `recycle.recycle-directory` | string | `recycle` | 回收表文件目录 |
| `recycle.default-currency` | string | `money` | 默认回收货币 |
| `recycle.allow-auto-recycle` | boolean | `true` | 是否允许拾取自动回收（还需权限及个人开关） |
| `recycle.protection.default-auto-recycle` | boolean | `false` | 首次创建个人设置时的自动回收默认值，不覆盖已有设置 |
| `recycle.protection.max-rules` | int | `200` | 每人材质排除与收藏同款规则总上限，范围 1–1000 |
| `recycle.batch-recycle-enabled` | boolean | `true` | 是否允许 UI 一键回收 |
| `recycle.batch-confirm` | boolean | `true` | 一键回收是否需二次确认 |
| `recycle.price-multiplier` | map | - | 回收价格倍率（权限节点 → 倍率） |

`default-auto-recycle` 只用于首次创建个人设置，不会覆盖已有玩家的开关。`max-rules` 是每人两类规则的合计上限，调低后不会自动删除已有规则；玩家仍可查看或移除原有规则。个人清单通过 `/market recycle protect` 管理，不在回收价格文件中配置。

## 商店与回收配置示例

以下为原配置中两个功能小节的修改片段。先在全局货币中配置 `money`，再准备对应的商品与回收定义：

```yaml
shop:
  enabled: true
  shops-directory: shops
  refresh-interval-ticks: 6000
  default-currency: money
recycle:
  enabled: true
  recycle-directory: recycle
  default-currency: money
  allow-auto-recycle: true
  protection:
    default-auto-recycle: false
    max-rules: 200
  batch-recycle-enabled: true
  batch-confirm: true
```

重载后执行 `/market shop`，用测试账号完成一次购买和回收，核对货币余额与物品数量。


### 回收保护与交易管理界面

```yaml
ui:
  recycle-protection-ui-id: "AXS:market_recycle_protection"
  admin-trades-ui-id: "AXS:market_admin_trades"
```

这两个 ID 必须与彼此及其他市场界面不同。个人设置按 UUID 保存，共享市场数据库的服务器共同使用同一份设置。修改主配置后执行 `/axs reload market`。

已有自定义回收 UI 时，应先备份，再合并新版页面的交互改动。`overwrite-ui-files` 会影响已导出的市场界面，不能只为更新单个页面而忽略其他自定义内容。

完整操作流程见[玩家回收保护](/docs/market/recycle-protection)和[交易管理与异常查询](/docs/market/trade-management)。
