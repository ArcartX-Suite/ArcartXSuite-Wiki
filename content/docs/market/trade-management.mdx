交易管理面板用于查询拍卖、玩家商店、系统商店和回收记录，帮助管理员定位未到账、未收到物品及交易纠纷。

## 打开面板

玩家管理员执行 `/axs market trades`，或在交易历史页点击“交易管理”。需要 `arcartxsuite.market.admin` 权限。

控制台不能打开界面，可使用 `/axs market ledger` 查询流水；命令参数见[命令与权限](/docs/market/commands)。

## 选择查询内容

| 入口 | 展示内容 | 如何理解 |
|---|---|---|
| 交易记录 | 四类交易的业务历史 | 记录业务结果，不代表钱物全部交付 |
| 处理流水 | 业务操作、扣款、收益入账、物品及指令发放等记录 | 同一笔交易可能有多个处理步骤 |
| 待发放不限日期 | 尚待处理的物品、货币与指令任务 | 包含已准备、待执行和执行中的任务，不包含单纯通知 |
| 失败与待核对 | 明确失败及结果需要核对的处理记录 | 结合说明和关联流水判断后续处理 |

默认打开业务历史，创建时间范围从服务器日期的七天前零点至今天结束。点击“待发放不限日期”或“失败与待核对”会清除日期限制，保留玩家、物品及交易类型条件，便于找出长期未处理的记录。

## 填写筛选条件

1. 选择“交易记录”或“处理流水”。
2. 填写玩家、物品和创建时间，选择业务类型及记录状态。
3. 点击“查询”，或在输入框中按回车提交。
4. 查看结果并翻页。面板每页 12 条，页码从 1 显示；控制台流水命令使用从 0 开始的页码，每页 10 条。

| 条件 | 填写方式 |
|---|---|
| 玩家名或 UUID | 查询该玩家作为记录玩家或另一参与者的记录；历史姓名无法确定或有歧义时使用 UUID |
| 物品名或材质 ID | 使用中文名称、自定义显示名或材质 ID，如 `铁锭`、`IRON_INGOT`、`minecraft:iron_ingot` |
| 创建起始日期/时刻 | 留空不限制起始时间；填写后从该时刻开始查询 |
| 创建截止日期/时刻（含） | 留空不限制截止时间；填写后包含所填日期、分钟或秒 |
| 业务类型 | 全部、拍卖、玩家店铺、系统商店、回收、其他；“其他”用于无法归入四类的记录 |
| 记录状态 | 选择具体处理状态，或使用“待发放”“失败与待核对”组合条件 |

时间采用页面顶部显示的服务器时区，支持以下格式：

```text
2026-11-01
2026-11-01 18:30
2026-11-01 18:30:15
```

例如，截止日期填 `2026-11-01` 会包含当天全部记录；填 `2026-11-01 18:30` 会包含该分钟；填秒则包含该整秒。时间筛选依据记录创建时间，状态更新时间在详情说明中展示。

输入新条件后，页面提示“筛选尚未提交”，需要点击查询才会生效；此时暂停翻页。刷新按钮在存在未提交条件时会提交这些条件，没有修改时刷新当前页。

## 查看详情与关联流水

点击结果行，右侧展示记录玩家及 UUID、另一参与者、物品快照、数量、材质、金额、创建时间、状态和处理说明。长名称、说明或编号可在对应区域滚动查看。

点击“查看关联流水”，查询同一交易下的业务历史及处理步骤。关联模式临时放开原筛选条件，以展示整笔交易；点击“返回原筛选”恢复先前的筛选和页码。

批量回收的总记录显示“批量回收”，单件历史与收益任务分别保留自己的物品信息。没有物品快照的记录会明确提示，不能把快照数量 0 理解为实际丢失数量。

旧历史可能没有关联编号、名称或材质。页面会说明信息缺失；此时按玩家 UUID、创建时间及已有物品名称扩大查询范围，不会补造无法确认的信息。

## 理解处理状态

| 状态 | 含义 | 查看重点 |
|---|---|---|
| `PREPARED` 已准备 | 已保存交付快照，尚未确认扣款、收取回收物品等前置条件 | 查看父交易及处理说明 |
| `READY` 待执行 | 任务等待交付 | 查看玩家是否在线、货币或发放能力是否可用 |
| `RUNNING` 处理中 | 业务步骤或外部调用正在执行 | 稍后刷新，结合状态更新时间判断进度 |
| `REVIEW` 需核对 | 处理曾中断或结果不确定 | 核实实际钱物情况，再决定如何关闭或继续任务 |
| `DONE` 本条已完成 | 当前记录对应的操作已完成 | 继续查看关联记录，判断整笔交易进度 |
| `FAILED` 明确失败 | 业务或接口返回失败 | 阅读失败说明，同时检查是否存在退款、返还等子记录 |
| `CANCELLED` 已取消 | 当前记录已取消 | 判断是否仍有待完成的返还任务 |
| `EXPIRED` 已到期 | 业务历史记录了挂单到期 | 检查物品返还记录 |

业务历史显示的“业务已记录”和处理流水的“本条已完成”含义不同。一次购买可能已经记录成交，同时物品或指令任务仍在排队；一次回收可能已经收取物品，同时收益仍在等待入账。

## 常见问题的查询顺序

### 回收已受理，但余额没有增加

1. 填写玩家 UUID，选择“回收”，查询对应时间的业务历史。
2. 打开记录并查看关联流水，找到货币入账任务。
3. 根据任务状态及说明判断是待执行、等待货币接口恢复，还是需要核对。
4. 若历史没有关联编号，切换“处理流水”，按同一玩家及时间继续查询。

### 已扣款，但没有收到商品

先查看关联扣款、物品或指令任务的状态。物品发放还可能通过邮件完成，应结合背包与邮件情况核对；指令商品本身可能没有可预览的物品快照。

### 出现失败或需核对记录

先查看同笔交易的扣款、退款、返还和交付步骤。单条失败不一定代表最终损失，也不能只凭成交历史认定奖励已发放。

面板只提供查询。实际结果核实后，管理员可使用 `/axs market resolve` 处理 `REVIEW` 记录；`retry-confirmed` 表示已确认交付义务成立且尚未执行，再放回待交付队列。完整参数与含义见[命令与权限](/docs/market/commands)。

### 结果为空、读取失败或超时

检查玩家 UUID、创建时间和物品关键词；旧记录缺少材质时，可先去掉物品条件。查长期待发放时使用“不限日期”入口。

列表和详情分别显示读取状态。可以停止当前查询后重新填写条件，详情失败时也可单独重新读取。取消查询只停止本次页面读取，不取消交易、入账或发放任务。

## 界面配置

```yaml
ui:
  admin-trades-ui-id: "AXS:market_admin_trades"
```

面板导出文件为模块目录 `ui/market_admin_trades.yml`。ID 必须与其他市场界面不同；配置与权限参考[功能配置](/docs/market/configuration)和[命令与权限](/docs/market/commands)。
