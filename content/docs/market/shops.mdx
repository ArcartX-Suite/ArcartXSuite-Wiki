Market 的商店系统包含 **系统商店** 和 **回收商店** 两个子系统。系统商店允许管理员通过 YAML 文件定义商品，玩家使用货币购买；回收商店允许玩家将物品出售给系统换取货币。

## 玩家独立店铺

玩家商店另提供独立店铺入口，与管理员预设的系统商店分开：

1. `/market pshop` 打开店铺目录，可切换所有店铺、收藏店铺，并按店名、店主名或简介搜索。
2. 点击店铺进入独立页面，查看店名、图标、简介、公告、在售商品、历史成交笔数和收藏人数。
3. 店内搜索只查询当前店铺；商品按整组固定价格出售，确认后由服务端核对归属和状态再交易。
4. 通过“我的店铺”进入自己的页面，可上架、下架和装修资料。商品卖完后，店铺和收藏仍会保留。

“全部商品”入口保留原来的玩家市场，便于跨店浏览；从市场进入店铺再返回，会保留原商品筛选与页码。从目录进入则返回原目录搜索、分页和收藏分类。

### 装修资料

执行 `/market pshop edit`，或在自己的店铺点击“装修店铺”：

| 字段 | 默认限制 | 说明 |
|---|---|---|
| 店名 | 32 字 | 必填，展示名称，不改变店铺身份或商品归属 |
| 简介 | 256 字，最多 8 行 | 介绍经营方向，可留空 |
| 公告 | 512 字，最多 12 行 | 展示补货、营业等说明，可留空 |
| 图标 | 背包中真实物品的单件副本 | 不取走物品；可选择默认图标或还原已保存图标 |

资料按纯文本展示，并沿用已有内容过滤能力。保存失败会保留草稿；离开或重新加载时若有未保存修改，会提示是否放弃。若同一资料已被其他会话修改，旧版本不能覆盖保存，需重新加载。

每名玩家拥有一个以 UUID 标识的店铺。店主姓名是身份提示，店名是可自定义的招牌；即使店名相同，也不会合并店铺。已有卖家的历史挂单会接入默认店铺资料，不会重写原有挂单、物品快照或交易历史。

### 收藏与分享

访客可收藏店铺，默认最多 100 家，在目录“收藏店铺”中继续访问。店铺收藏和拍卖商品关注独立保存。自己的店铺从“我的店铺”进入，不需收藏自己。

收藏和取消收藏按明确的目标状态保存，重复请求不会把状态来回切换。服务器确认后才更新收藏显示；在收藏目录取消收藏后，会重新分页，最后一页变空时自动回到有效页码。

购买或下架前，确认弹窗会重新向服务端核对商品所属店铺、是否仍在售、物品数据和购买余额；核对失败不能确认。弹窗中可手动“重新核对”，核对本身不扣款。实际购买提交时还会再次检查，已过期或已售出的商品不会被重复购买。

店铺资料保存过程中若迟迟没有明确结果，可点“核对保存状态”。该入口只读服务器状态，不会自动重发保存，不会替换当前草稿；返回资料版本后可选择重新加载核对。读取资料期间仍可返回店铺，未保存的修改保留放弃确认。

目录和店铺均提供手动刷新。搜索框中的新关键词在按回车或点击搜索前不会生效，页面会提示“关键词尚未应用”；后台刷新也不会覆盖正在输入的搜索草稿。查询失败时会保留上次成功的筛选和返回位置。

店铺地址为 `/market store <店主UUID>`，不受店名变化影响。访客可通过店铺页“店铺地址”查看分享命令；`/market store` 省略 UUID 时打开自己的店铺。在线提示仅表示店主是否在当前服务器，店主离线不影响现有挂单购买。

### 玩家店铺配置

```yaml
player-shop:
  profile:
    name-max-length: 32
    description-max-length: 256
    announcement-max-length: 512
    max-favorites: 100
```

允许范围分别为店名 1–64、简介 1–1024、公告 1–2048、收藏上限 1–1000。修改后使用 `/axs reload market`。限制约束新保存的资料，不会批量改写已有自定义内容。

三个新页面的默认 UI ID 为 `AXS:market_player_shops`（目录）、`AXS:market_player_store`（独立店铺）、`AXS:market_player_store_edit`（资料编辑）。自定义这些 ID 时，必须与彼此及其他市场界面保持不同。

## 游戏内编辑系统商店

### 库存管理和周期补货

在商品编辑表单右侧可查看实际库存，并操作：

- **补货**：在当前剩余数量上增加，最多补到配置上限。
- **清空**：将剩余库存设为 0。
- **补满**：恢复到配置的 `stock-amount`。
- **重置限购**：清除该商品的购买计数，不改变库存。

玩家独立库存可以填写目标玩家 UUID；留空表示所有玩家，清空和补满也会影响尚未建立库存记录的玩家。全服库存操作应留空 UUID。以上操作均需确认。

修改库存配置后，默认保留实际库存；勾选“保存配置后补满实际库存”才会在保存时补满，并再次提示确认。库存操作不会保存表单内其他尚未提交的修改。

```yaml
stock-mode: global
stock-amount: 100
restock-interval-seconds: 86400
limit-per-player: 10
limit-reset: daily
```

此例库存上限 100，每 24 小时补满，每人每日限购 10。`restock-interval-seconds: 0` 关闭周期补货。周期按时间间隔计算；实际处理发生在 `shop.refresh-interval-ticks` 调度时，库存补满与限购重置相互独立。多服共享数据库时同一轮补货只由一次数据库抢占负责执行。

### 数量选择与结算预览

点击商品卡购买后，在结算弹窗中增加、减少或输入数量，也可以点击“最大”。手动输入后按回车或点击“报价”，取得服务端重新计算的报价后才能确认。

报价显示原单价、折后单价、总价、库存、限购余额与背包可容纳数量；最大数量同时受余额、库存、限购、背包空间和单次购买上限 2304 限制。指令商品不受背包空间限制。

确认后仍会重新检查价格、余额、库存和限购。物品和奖励指令先保存为持久任务，扣款成功后激活交付；在线玩家通常在下一轮交付调度收到奖励，离线任务在上线后继续。物品发放沿用背包、邮件等现有交付能力。

1. 管理员执行 `/axs market edit [商店ID]`，或在系统商店顶栏点击编辑入口。
2. 左侧选择商店；新商店先填写 ID、显示名、权限和标签，再保存，随后才能添加商品。已有 ID 不可直接改名。
3. 打开商品后，在可滚动表单中填写物品或指令类型、价格、货币、库存、限购、条件和折扣。字段填错会提示错误并保留当前表单，不会自动把错误价格保存为免费商品。
4. 物品来源支持 `minecraft`、`mythic`、`neige`、`overture`、`mmoitems`；可以从背包选物，也可以手填来源、ID、NBT 后点击“按当前字段更新预览”。预览不会发放物品，背包选物也不会取走物品。
5. 图标可从背包选择或清除。奖励指令每行一条，由控制台运行，支持 `{player}`、`{uuid}`、`{amount}`；物品商品也可附带奖励指令。
6. 保存后会重新读取商店与商品信息。未修改条件表达式时保留原有条件结构及附加设置。

切换商店、返回或离开编辑器时，未保存的修改需要确认放弃。编辑器使用界面按钮返回，避免误按 Esc 丢失表单。删除商店或商品也需要确认。

编辑器填充表单时会暂时锁定操作，待字段和预览填充完毕再恢复。价格和折扣按原始精度回显；不修改这些字段直接保存，也不会被自动截成两位小数。

若另一位管理员或文件编辑操作已经修改同一商店，旧表单的保存、删除会被拒绝，并保留当前输入。点击顶栏“重新加载当前内容”，确认放弃旧草稿后，再基于最新内容修改。新建商品也会检查所属商店是否在编辑期间变化。

编辑器中的预留价格字段对应 `sell-price`，不自动将该商品加入回收表；物品回收价格仍由 `recycle/` 中的条目控制。

## 玩家购买和回收

系统商店商品卡显示当前玩家折扣后的单价，点击购买后选择数量并确认金额，再由服务端扣款，将奖励交给持久交付队列。失败会保留商店页面并恢复操作按钮。

确认期间若动态价格或权限折扣发生变化，购买会停止并刷新商品，需重新确认新金额。回收期间若背包或目标槽位内容变化，也会刷新预览，避免按旧列表回收新放入的物品。

回收页面可逐组回收，批量回收开启 `batch-confirm` 时需先确认；执行时以服务端背包中的实际物品为准。回收完成后刷新剩余物品与各货币收益，并写入统一历史。

### 先跑通一次购买和回收

以下例子用普通玩家购买并回收一个苹果。测试服需启用 `shop.enabled` 和 `recycle.enabled`，安装 PlaceholderAPI、Vault 和提供 Vault 经济服务的 EssentialsX。将本体的 `currencies.money` 按 [Vault 货币示例](/docs/guide/currencies#vault--vault-经济)配置。使用其他经济插件时，以该插件的查询命令读取实际余额。

将第一段保存为 `plugins/ArcartX-Suite/data/market/shops/trial_shop.yml`。示例商店 ID 为文件名 `trial_shop`，商品 ID 为 `apple`，购买单价为 10。

```yaml
display-name: "补给商店"
permission: ""
items:
  apple:
    type: item
    display-name: "苹果"
    item:
      source: minecraft
      id: APPLE
    buy-price: 10
    currency: money
    stock-mode: unlimited
```

将第二段保存为 `plugins/ArcartX-Suite/data/market/recycle/trial_recycle.yml`。测试服如已配置苹果回收，先确认同一种物品只命中这条规则。单价为 2，普通玩家以无回收加成的权限组测试。

```yaml
display-name: "补给回收"
entries:
  trial_apple:
    source: minecraft
    item-id: APPLE
    price: 2
    currency: money
```

1. 管理员执行 `/axs reload market`。用具有 `arcartxsuite.market.use` 的非 OP 测试玩家进服，确保主背包有空位且没有苹果。通过 `/market recycle protect` 关闭个人自动回收，并确认苹果未受保护。
2. 以玩家 `WikiTester` 为例，在游戏服控制台执行 `essentials:eco set WikiTester 100`，再用 `essentials:balance WikiTester` 确认余额为 100。替换为你的测试玩家名。
3. 让该玩家执行 `/market shop trial_shop`，选择苹果、数量 1，确认报价为 10 后购买。等交付完成，核对背包增加 1 个苹果，实际余额降到 90。
4. 执行 `/market recycle`，选中这一个苹果并确认单件回收。核对苹果减少 1 个，收益入账后实际余额升到 92。在 `/market history` 查看这次购买和回收。
5. 将另一个无折扣测试玩家的余额设为 5，尝试购买同一商品。应无法确认购买或提示余额不足，实际余额仍为 5，背包没有收到苹果。

若有成交历史但钱物尚未交付，按[交易管理与异常查询](/docs/market/trade-management#常见问题的查询顺序)核对扣款、发放和入账步骤。

`item` 负责实际发放，`icon` 只负责显示。改成物品库商品前先确认来源插件能生成该 ID。回收或换货使用匹配器识别现有物品，与生成商品的 `source + id` 分别配置。

### 商店文件结构

每个 `.yml` 文件定义一个独立的商店，文件名（不含扩展名）即为商店 ID。文件放置在 `<模块数据目录>/shops/` 目录下，模块启动时递归扫描加载。

首次启动时若 `shops` 目录为空，会自动导出示例文件 `example_shop.yml`。

### 商店基础字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `display-name` | string | 商店在 UI 中显示的名称（支持 `&` 颜色码） |
| `icon` | section | 商店图标定义，详见 [图标配置](/docs/guide/icons) |
| `permission` | string | 查看此商店所需的权限（空字符串表示无限制） |
| `tags` | list | 分类标签（用于 UI 筛选） |
| `items` | section | 商品列表，每个键为商品唯一标识 |

### 商品配置

每个商品在 `items` 节下以唯一键定义，支持以下字段：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `type` | string | `item` | 商品类型：`item`（物品商品）或 `command`（指令商品） |
| `item` | section | - | 物品定义（`item` 类型必填） |
| `item.source` | string | `minecraft` | 物品来源 |
| `item.id` | string | - | 物品 ID |
| `item.nbt` | string | - | 原版物品 NBT 数据（SNBT 格式） |
| `icon` | section | - | 商品图标（省略时用 `item` 生成的物品当图标），详见 [图标配置](/docs/guide/icons) |
| `display-name` | string | 物品 ID | 商店 UI 货架展示的名称 |
| `buy-price` | double | `0` | 玩家购买价格（0 = 不可购买） |
| `sell-price` | double | `0` | 商品编辑器中的预留字段。实际回收单价由 `recycle/*.yml` 的 `price` 指定 |
| `currency` | string | 商店默认货币 | 货币类型 |
| `stock-mode` | string | `unlimited` | 库存模式 |
| `stock-amount` | int | `0` | 库存数量（`unlimited` 模式下无效） |
| `limit-per-player` | int | `0` | 每个玩家的购买上限（0 = 无限制） |
| `limit-reset` | string | `never` | 限购重置周期 |
| `discount` | map | - | 折扣配置（权限节点 → 折扣比例） |
| `conditions` | section | - | 上架条件 |
| `reward-commands` | list | - | 奖励指令（`command` 类型必填） |

### 物品来源 (item.source)

| 来源 | item.id 格式 | 说明 |
|---|---|---|
| `minecraft` | Bukkit Material 名 | 原版 Minecraft 物品 |
| `mythic` | MythicMobs 内部名称 | MythicMobs 自定义物品 |
| `neige` | NeigeItems 物品 ID | NeigeItems 自定义物品 |
| `overture` | Overture 物品 ID | Overture 自定义物品 |
| `mmoitems` | `TYPE;ID` | MMOItems 物品（如 `ARMOR;STEEL_HELMET`） |

详见 [物品来源](/docs/guide/item-sources)。

### 库存模式 (stock-mode)

| 模式 | 说明 |
|---|---|
| `unlimited` | 无限库存，可无限购买 |
| `global` | 全服共享库存，所有玩家共用同一库存量 |
| `per-player` | 每个玩家独立库存，互不影响 |

### 限购重置周期 (limit-reset)

| 值 | 说明 |
|---|---|
| `daily` | 每日重置（服务器时间 00:00） |
| `weekly` | 每周重置（周一 00:00） |
| `monthly` | 每月重置（1 日 00:00） |
| `never` | 从不重置（终身限购） |

### 折扣系统

折扣按权限节点配置，拥有对应权限的玩家购买时享受折扣。若同时拥有多个折扣权限，取**最低折扣值**（即最大优惠）。

```yaml
discount:
  "axsmarket.vip": 0.9    # VIP 9 折
  "axsmarket.mvp": 0.8    # MVP 8 折
```

### 指令商品

指令商品不发放物品，只在扣款成功后由控制台执行奖励命令。支持以下占位符：

| 占位符 | 说明 |
|---|---|
| `{player}` | 玩家名（已做安全校验） |
| `{uuid}` | 玩家 UUID |
| `{amount}` | 购买数量 |

```yaml
command_reward:
  type: "command"
  icon:
    material: "NETHER_STAR"
    name: "&d指令奖励"
  display-name: "&d指令奖励"
  buy-price: 100
  currency: "money"
  reward-commands:
    - "give {player} diamond {amount}"
    - "say 恭喜 {player} 获得指令奖励"
```

### 购买流程

1. 打开商店，选择商品和数量，取得服务端报价。
2. 检查折后金额、库存、限购余额和可购买数量，再确认购买。
3. 服务端重新核对价格、余额及购买限制，保存奖励任务并处理扣款。条件变化时需要重新取得报价。
4. 扣款成功后激活交付任务；物品发放沿用背包、邮件等交付方式，指令商品执行对应奖励命令。
5. 在交易历史中查看业务记录。若已扣款但未收到奖励，请管理员通过[交易管理面板](/docs/market/trade-management)核对关联处理状态。

物品商品的报价上限包含当前背包容量，指令商品不受背包容量限制。交易受理与最终交付分别记录，不能仅凭成交历史判断奖励已经收到。

### 货币支持

商品未指定 `currency` 时，使用 `shop.default-currency` 作为 fallback。

## 动态价格策略

动态商品策略通过 `shop.dynamic` 配置节定义，支持三种策略类型。策略状态持久化到数据库，跨服同步，并通过 EventBus 发布事件。

### random-refresh（随机刷新 / 神秘商人）

从候选商品池中按权重随机抽选 N 个商品上架，可配置是否下架旧随机商品。

```yaml
shop:
  dynamic:
    enabled: true
    strategies:
      mystery_merchant:
        type: "random-refresh"
        shop-id: "example_shop"
        schedule:
          cron: "0 0 */6 * * ?"    # 每 6 小时触发
        probability: 0.5            # 触发概率（0-1）
        max-items: 5                # 每次刷新上架商品数
        remove-old: true            # 刷新时是否下架旧随机商品
        pool:                       # 候选商品池
          rare_sword:
            item:
              source: "mythic"
```

### price-float（价格浮动）

按 `random-walk` 或 `supply-demand` 模式动态调整商品价格乘数。

| 模式 | 说明 |
|---|---|
| `random-walk` | 每次触发在基准价上下随机波动（±volatility），乘数限制在 [min, max] 范围 |
| `supply-demand` | 根据成交量调价：买的人多则涨价、少则降价；无成交时向 1.0 回归 |

```yaml
shop:
  dynamic:
    enabled: true
    strategies:
      price_fluctuation:
        type: "price-float"
        shop-id: "example_shop"
        schedule:
          cron: "0 */30 * * * ?"   # 每 30 分钟触发
        float-mode: "supply-demand" # 或 "random-walk"
        volatility: 0.2             # 波动幅度（0.2 = ±20%）
        min-multiplier: 0.5          # 最低价格乘数
        max-multiplier: 2.0          # 最高价格乘数
```

### scheduled-swap（定时换货）

按多个商品集轮换上架，每次触发切换到下一个集。

```yaml
shop:

    enabled: true
    strategies:
      weekly_rotation:
        type: "scheduled-swap"
        shop-id: "example_shop"
        schedule:
          cron: "0 0 0 ? * MON"     # 每周一 0 点触发
        item-sets:
          set_a:                     # 商品集 A
            item1:
              item:
                source: "minecraft"
                id: "DIAMOND"
              display-name: "&b钻石"

              sell-price: 100

          set_b:                     # 商品集 B
            item1:
              item:
                source: "minecraft"
```

### 回收表文件结构

每个 `.yml` 文件定义一张独立的回收表，文件放置在 `<模块数据目录>/recycle/` 目录下。首次启动时若目录为空，会自动导出 `default_recycle.yml`。

### 回收条目字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `source` | string | 物品来源（同商店 `item.source`） |
| `item-id` | string | 物品标识（格式与商店配置一致） |
| `price` | double | 回收单价（每个物品获得的货币数量） |
| `currency` | string | 货币类型（覆盖默认货币） |

### 回收价格计算

```
最终回收价格 = 基础价格 × 玩家匹配的最高权限倍率
```

例如：圆石 `price=1`，VIP 倍率 1.2，MVP 倍率 1.5 → MVP 玩家每个圆石获得 1.5。

### 个人回收保护

执行 `/market recycle protect`，或在回收界面点击“个人回收保护”，管理个人自动回收开关、材质排除及收藏同款。保护规则对单件、批量和拾取自动回收共同生效。

材质排除保护相同材质的全部变体；收藏同款保留名称、附魔及其他物品特征的区分，忽略数量、耐久和修复惩罚。选物不取走物品，收藏也不改变物品 NBT。

### 自动回收

需要服务器启用回收并允许自动回收、玩家拥有 `axsmarket.autorecycle` 权限，以及个人开关已打开。个人开关默认关闭，保护资料不可用时自动回收跳过，物品继续正常拾取。

### 批量回收

`/market recycle all` 或界面批量按钮只处理主背包与快捷栏中的可回收物品，不包含装备栏及副手，受保护物品会保留。开启 `batch-confirm` 后需要确认；背包或保护规则变化时需要刷新后重新确认。

回收收益进入持久入账队列，“回收已受理”表示已建立收益任务。多种货币的预估收益分别显示，实际入账状态可由管理员查询关联流水。

完整的选物、确认、移除、自动开关、配置示例及异常处理见[玩家回收保护](/docs/market/recycle-protection)。收益查询见[交易管理与异常查询](/docs/market/trade-management)。
