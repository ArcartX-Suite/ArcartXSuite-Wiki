# 联动

Market 模块通过 EventBus、Capability、跨服通道等机制与其他模块和外部系统联动。

## EventBus 事件

Market 模块通过 `EventBusCapability` 发布事件，其他模块可通过 EventBus 监听这些事件实现联动。

### 发布的事件

| 事件 Topic | 触发时机 | Payload |
|---|---|---|
| `axs.market.listing_created` | 拍卖行上架成功 | `price`（起拍价）、`currency`（货币 ID） |
| `axs.market.auction_purchased` | 拍卖行竞价成交结算完成 | `listing_id`、`item`、`price`、`formatted_price`、`currency`、`tax`、`seller_uuid`、`buyer_uuid`、`buyer`（买家名） |
| `axs.market.shop_dynamic_triggered` | 动态商品策略触发 | `strategy_key`、`strategy_type`、`shop_id` |

> `auction_purchased` 在到期结算路径（`BID_WIN`）发布；此时买家通常已离线，`event.player()` 可能为 null，订阅方应以 payload 的 `buyer`/`buyer_uuid` 为准。

### 信号派发

Market 还派发以下信号，可供 QuestGPS、条件触发器等模块监听：

| 信号 | 触发时机 | 变量 |
|---|---|---|
| `market_listing_created` | 拍卖行上架成功 | `price`、`currency` |

## Capability 注册

Market 模块注册了以下 Capability，供其他模块调用：

### AxsMarketService（公开）

市场公开服务接口（`@PublicCapability`），面向外部 Bukkit 插件。经 `AxsCapabilities.get(AxsMarketService.class)` 获取，市场模块未启用时返回 `null`。所有方法请在 Bukkit 主线程调用。

| 方法 | 说明 |
|---|---|
| `openUi(player, MarketView)` | 打开指定市场视图：`AUCTION`/`AUCTION_SELL`/`SHOP_LIST`/`SHOP`/`RECYCLE`/`HISTORY`/`SELL`/`PLAYER_SHOP`/`MY_LISTINGS` |
| `createAuctionListing(player, item, startingBid, currency, durationSeconds)` | 替玩家创建拍卖挂单（`currency` 为 null 用默认货币）。返回 `CompletableFuture<Boolean>`——操作在调用线程同步完成（须主线程），`false` 表示校验失败；`item` 必须与玩家主手物品匹配（防复制），不支持上架未持有物品 |
| `cancelListing(player, listingId)` | 取消玩家的一条挂单。返回 `CompletableFuture<Boolean>`（同步完成，`false` 表示挂单不存在/不属于该玩家等） |
| `searchAuction(player, keyword)` | 打开拍卖 UI 并按关键字搜索。返回 `CompletableFuture<Boolean>`（`false` 表示市场服务不可用） |
| `auctionCount()` / `shopCount()` / `myListingCount(player)` | 活跃挂单数 / 商店条目数 / 玩家自己的挂单数 |
| `playerShopEnabled()` | 玩家商店功能是否启用 |

```java
AxsMarketService market = AxsCapabilities.get(AxsMarketService.class);
if (market != null) {
    market.openUi(player, AxsMarketService.MarketView.AUCTION);
}
```

### 数据清理与迁移

- `/axs purge` 支持清理玩家市场数据
- `/axs migrate` 支持跨源数据迁移

### Mail 邮件联动

当 `expired-return-method: mail` 时，到期未售物品和背包满时无法发放的物品通过邮件系统退回。若 Mail 模块未加载，则降级为待发放队列（玩家上线补发）。

## 跨服同步

开启跨服同步后，竞价更新、挂单变更、限购记录与动态商品状态等数据在子服间实时同步。

### 跨服配置

跨服同步需配合宿主 `config.yml` 的 `cross-server` 节：

```yaml
# 宿主 config.yml
cross-server:
  node-id: "default"
  redis:
    enabled: true
    host: "127.0.0.1"
    port: 6379
    channel: "AXS:CROSS"
  proxy:
    enabled: false
    messenger-channel: "AXS_CROSS"
```

```yaml
# 模块 ArcartXMarket.yml
cross-server:
  enabled: true
```

<Callout type="info">
跨服同步支持 Redis + BungeeCord/Velocity Forward 双后端。单服无需开启跨服和 Redis。
</Callout>

## 数据存储

Market 模块将拍卖挂单、竞价记录、交易历史、收藏、限购记录、库存、回收统计与待发放队列存储在数据库中（SQLite 或 MySQL）。表前缀默认为 `axs_market_`。

拍卖行搜索使用数据库全文索引，不可用时自动降级为模糊查询。搜索关键字最大长度 100 字符。

## 与其他模块联动

### Mail 模块

Market 消费 `MailDispatchable` Capability，用于：
- 拍卖行到期未售物品退回
- 竞价成交物品发放（背包满时转邮件）
- 玩家商店到期/下架物品退回
- 待发放队列补发（背包满时转邮件）

若 Mail 模块未加载，物品发放降级为：放入背包 → 背包满则掉落 → 掉落失败则入待发放队列。

### QuestGPS / 信号触发模块

Market 通过 `SignalDispatchable` 派发 `market_listing_created` 信号，可供任务系统监听"上架物品"事件。

### EventPacket 模块

Market 发布的 EventBus 事件可被 EventPacket 模块捕获，用于触发条件判定（如"玩家上架物品后触发某事件"）。

### CurrencyBridge（经济系统）

Market 通过 `CurrencyBridgeAPI` 统一管理货币，支持：
- Vault（`money`）
- PlayerPoints（`points`）
- Xconomy
- Rondo
- Command（自定义命令货币）
- Placeholder-Command（占位符货币）
- Custom（自定义货币）

货币定义在宿主 `config.yml` 的 `currencies` 节，模块配置只引用货币 ID。

### 物品来源

Market 可识别和生成多种物品来源的物品：MythicMobs、NeigeItems、Overture、MMOItems。配置见 [物品来源](/docs/guide/item-sources)。

### 物品发放降级链

物品发放按以下优先级执行：
1. 放入玩家背包
2. 背包满 → 转邮件（需 Mail 模块）
3. 邮件不可用 → 掉落在玩家脚下
4. 以上均失败 → 入待发放队列

### 内容审核

拍卖行/玩家商店的留言经过敏感词过滤。审核组件不可用时不过滤。

### LuckPerms（权限查询）

拍卖行税率减免支持离线玩家权限查询：
- 在线玩家：直接 `player.hasPermission`
- 离线玩家：通过 LuckPerms API 异步加载用户数据后查询权限
- LuckPerms 不可用时：回退到默认税率
