# 分类与物品匹配

> **福利模块**

ExtraBackpack 的核心机制是**多分类额外背包**：物品按照可配置的 NBT/PDC/Lore 匹配规则自动归入不同分类页，每页独立管理槽位与扩容。本页详细说明分类配置结构、匹配规则、优先级排序、兜底分类与自动归类流程。

## 分类配置结构

每个分类页在 `extra-backpack.categories` 下以键名作为分类 ID（自动 `trim().toLowerCase()` 归一化），包含以下字段：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `display-name` | string | 分类 ID | 分类显示名称，展示在 UI 标签上 |
| `priority` | int | 当前分类序号 | 排序优先级，数值越小越靠前匹配 |
| `default` | boolean | `false` | 是否为兜底分类 |
| `slots.max` | int | `999` | 该页网格显示上限（应 >= 仓库 `max-slots`） |
| `material-ids` | `list<string>` | `[]` | 物品注册键精确匹配（`minecraft:diamond_sword`、`tacz:modern_kinetic_gun`） |
| `material-prefixes` | `list<string>` | `[]` | 物品注册键前缀匹配（`tacz:` 命中全部 TaCZ 物品、`apotheosis:` 命中全部 Apotheosis 物品） |
| `match.nbt.path` | string | `""` | NBT 匹配路径 |
| `match.nbt.values` | `list<string>` | `[]` | 匹配值列表 |

> 向后兼容字段：`nbt.path` 等价于 `match.nbt.path`，`nbt.values` 等价于 `match.nbt.values`。
>
> **已移除字段**：`slots.initial`/`initial-slots`、`price.*`（存储与定价已统一走仓库槽位，`obsoletePath` 自动剪除）。

### 分类 ID 归一化

分类 ID 在加载时统一执行 `trim().toLowerCase(Locale.ROOT)` 归一化处理。例如配置键 `Equipment` 会被归一化为 `equipment`，后续所有匹配与存储操作均使用归一化后的 ID。

```yaml
extra-backpack:
  enabled: true
  categories:
    # 键名 "Equipment" → 归一化为 "equipment"
    Equipment:
      display-name: "装备"
      priority: 10
      match:
        nbt:
          path: "pdc:arcartx:item_category"
          values: ["equipment", "weapon", "armor"]
```

## 物品注册键匹配（mod 物品推荐）

`material-ids` 与 `material-prefixes` 直接匹配物品的 Bukkit 注册键（`Material.getKey()`，形如 `minecraft:diamond_sword` 或 mod 物品的 `tacz:modern_kinetic_gun`），**与 `match.nbt` 规则为"或"关系**——任一命中即归入该分类。这是给 mod 物品分类的首选方式：

```yaml
categories:
  weapon:
    display-name: "武器"
    priority: 5
    slots:
      max: 999
    material-prefixes: ["tacz:"]                    # 全部 TaCZ 枪械
  enchant:
    display-name: "附魔物品"
    priority: 6
    slots:
      max: 999
    material-prefixes: ["apotheosis:"]              # 全部 Apotheosis 物品
    material-ids: ["minecraft:enchanted_book"]      # 另加精确注册键
```

> 分类 ID 归一化：`material-ids`/`material-prefixes` 均做 `trim().toLowerCase()`。原版物品的注册键总是 `minecraft:` 前缀——`material-prefixes: ["minecraft:"]` 可命中全部原版物品。

## NBT 匹配路径类型

`match.nbt.path` 支持以下路径类型，服务端通过 `resolvePath()` 方法读取物品对应值：

| 路径格式 | 说明 | 匹配方式 |
| --- | --- | --- |
| `pdc:<namespace>:<key>` | 读取 PersistentDataContainer 字符串值 | 精确匹配 |
| `pdc:<key>` | 读取 PDC 值，namespace 默认为插件名 | 精确匹配 |
| `material` | 读取物品材质 ID（经 VanillaItemNameBridge 翻译） | 精确匹配 |
| `display-name` | 读取物品显示名称 | 精确匹配 |
| `name` | 等价于 `display-name` | 精确匹配 |
| `custom-model-data` | 读取 CustomModelData 整数值 | 精确匹配 |
| `lore` | 遍历物品 Lore 行 | 包含匹配（`contains`） |

### 路径解析细节

#### PDC 路径

`pdc:` 前缀的路径用于读取 Bukkit `PersistentDataContainer` 中的字符串值：

```yaml
# 带命名空间
match:
  nbt:
    path: "pdc:arcartx:item_category"
    values: ["equipment", "weapon", "armor"]

# 不带命名空间（默认使用插件名作为 namespace）
match:
  nbt:
    path: "pdc:category"
    values: ["rare", "epic"]
```

服务端解析逻辑：
1. 截取 `pdc:` 后的字符串作为 key 文本
2. 若 key 文本包含 `:`，按第一个 `:` 拆分为 namespace 与 key
3. 否则使用插件名作为 namespace
4. 通过 `PersistentDataType.STRING` 读取 PDC 值

#### material 路径

读取物品的材质 ID。若 `VanillaItemNameBridge` 可用，会将材质名翻译为中文名后再匹配：

```yaml
# 匹配原版药水与金苹果类物品
match:
  nbt:
    path: "material"
    values: ["potion", "golden_apple", "enchanted_golden_apple"]
```

> `VanillaItemNameBridge` 由核心提供，用于将 `Material.DIAMOND_SWORD` 等枚举名翻译为中文显示名。匹配值与读取值均做 `trim().toLowerCase()` 归一化。

#### display-name / name 路径

读取物品的显示名称（`ItemMeta.getDisplayName()`）。若物品无自定义名称，回退到 `VanillaItemNameBridge.resolveDisplayName()` 返回的名称：

```yaml
# 按物品显示名称分类
match:
  nbt:
    path: "display-name"
    values: ["传说之剑", "神话装备"]
```

#### custom-model-data 路径

读取物品的 `CustomModelData` 整数值（转为字符串）：

```yaml
match:
  nbt:
    path: "custom-model-data"
    values: ["10001", "10002"]
```

> 仅当 `ItemMeta.hasCustomModelData()` 为 `true` 时返回值，否则返回空字符串。

#### lore 路径

遍历物品的 Lore 行，逐行检查是否**包含**匹配值（使用 `contains` 而非精确匹配）：

```yaml
# 匹配 Lore 中包含"任务物品"或"不可丢弃"的物品
match:
  nbt:
    path: "lore"
    values: ["任务物品", "不可丢弃"]
```

> Lore 匹配对每一行和每一个匹配值都做 `trim().toLowerCase()` 归一化后执行 `contains` 检查。只要任意一行包含任意一个匹配值即匹配成功。

## 匹配流程

物品分类匹配由 `matchCategory()` 方法执行，流程如下：

```
matchCategory(itemStack)
  │
  ├─ 遍历所有分类（按 priority 升序排序）
  │   │
  │   ├─ 跳过兜底分类（default: true）
  │   ├─ 跳过无任何匹配规则的分类（material-* 与 nbt.path 全为空）
  │   │
  │   └─ 对每个有效分类执行 matches() 检查
  │       ├─ 注册键匹配：material-ids 精确 / material-prefixes 前缀 → 命中即返回 true
  │       └─ NBT 匹配：读取 nbt.path 对应值 → 归一化 → 在 values 列表中
  │           ├─ lore 路径：contains 匹配
  │           └─ 其他路径：精确匹配
  │
  ├─ 首个匹配成功的分类 → 返回该分类 ID
  └─ 无匹配 → 返回空字符串（不自动归类）
```

### 优先级排序

分类按 `priority` 字段升序排列（`Comparator.comparingInt`）。数值越小越优先匹配：

```yaml
categories:
  quest_item:
    priority: 5      # 最先匹配
    # ...
  equipment:
    priority: 10     # 其次匹配
    # ...
  material:
    priority: 20     # 再次匹配
    # ...
  other:
    priority: 9999   # 兜底分类，最后
    default: true
    # ...
```

> `priority` 未配置时默认值为当前分类在 `LinkedHashMap` 中的插入序号（从 0 开始），因此不配置 `priority` 时分类按配置文件中的声明顺序排列。

## 兜底分类

标记 `default: true` 的分类作为兜底页签。在共通存储模型下，页签是仓库内容的**过滤器**：

| 场景 | 行为 |
| --- | --- |
| 视图过滤 | 兜底页显示所有「不匹配任何分类规则」的仓库槽位 + 剩余空格 |
| 携物放入 | 无分类命中的物品只能放入兜底页签（严格校验），反之亦然 |
| 无兜底分类 | 配置中无 `default: true` 时，取 priority 最大的分类作为兜底；未命中任何规则的仓库物品在背包 UI 中不可见（仍在仓库中，可从仓库 UI 存取） |

### 兜底分类选择逻辑

`fallbackCategory()` 方法的选择逻辑：

1. 遍历所有分类，返回第一个 `default: true` 的分类
2. 若无分类标记为 `default`，返回排序后列表的最后一个分类（priority 最大）
3. 若无任何分类，返回 `null`

```yaml
# 兜底分类示例
other:
  display-name: "杂物"
  priority: 9999
  default: true
  slots:
    max: 999   # 该页网格显示上限，应 >= 仓库 max-slots
  # 兜底分类可不配置 match 规则
  # 也可配置 match 规则，但匹配流程会跳过它
```

> 兜底分类配置了 `match.nbt.path` 和 `match.nbt.values` 时，匹配流程仍会跳过它（因为 `default: true`）。兜底分类的匹配规则不会生效。

## 拾取存入

拾取自动存入由 **仓库模块**负责（`pickup.auto-store-on-pickup`）——ExtraBackpack 与仓库共用同一存储，拾取物品直接进仓库，背包 UI 按页签过滤即时可见。本模块不再监听拾取事件。

## 手动存入

除拾取自动归类外，玩家可通过 UI 手动存入物品：

### 快捷栏存入

点击 UI 底部快捷栏区域的物品，将快捷栏指定槽位（0-8）的物品存入额外背包：先匹配合适的分类页，然后先合并相同物品堆叠、再写入空闲槽位。

> 快捷栏存入不使用兜底分类回退逻辑。若目标分类页已满，剩余物品留在快捷栏并提示 `该分类页已满`。

### 原版标签页存入

在原版背包标签页右键物品，选择"存入"，物品按分类匹配后存入对应分类页。目标分类页放不下时尝试兜底分类页；兜底分类也放不下时提示 `无可用额外槽位`。

## 存入规则

物品存入分类页时按以下规则处理：

1. 优先合并到已有的相同物品堆叠（不超过最大堆叠数）
2. 剩余部分写入空闲槽位（按槽位顺序填充）
3. 放不下的部分按场景处理：快捷栏存入留在快捷栏；原版存入尝试兜底分类页

## 配置示例

### PDC 标签分类（推荐）

适用于通过其他插件或命令为物品写入 PDC 标签的场景：

```yaml
extra-backpack:
  enabled: true
  categories:
    equipment:
      display-name: "装备"
      priority: 10
      slots:
        max: 999
      match:
        nbt:
          path: "pdc:arcartx:item_category"
          values: ["equipment", "weapon", "armor"]
    material:
      display-name: "材料"
      priority: 20
      slots:
        max: 999
      match:
        nbt:
          path: "pdc:arcartx:item_category"
          values: ["material"]
    other:
      display-name: "杂物"
      priority: 9999
      default: true
      slots:
        max: 999
```

### 材质分类

按原版物品材质 ID 分类，无需额外 PDC 标签：

```yaml
extra-backpack:
  enabled: true
  categories:
    consumable:
      display-name: "消耗品"
      priority: 5
      slots:
        max: 999
      match:
        nbt:
          path: "material"
          values: ["potion", "splash_potion", "lingering_potion", "golden_apple", "enchanted_golden_apple"]
    tool:
      display-name: "工具"
      priority: 10
      slots:
        max: 999
      match:
        nbt:
          path: "material"
          values: ["diamond_pickaxe", "diamond_axe", "diamond_shovel", "netherite_pickaxe"]
    fallback:
      display-name: "其他"
      priority: 9999
      default: true
      slots:
        max: 999
```

### Lore 匹配分类

按物品 Lore 文本分类，适用于 RPG 服务器自定义物品：

```yaml
extra-backpack:
  enabled: true
  categories:
    quest_item:
      display-name: "任务物品"
      priority: 5
      slots:
        max: 999
      match:
        nbt:
          path: "lore"
          values: ["任务物品", "不可丢弃", "绑定"]
    rare_item:
      display-name: "稀有装备"
      priority: 10
      slots:
        max: 999
      match:
        nbt:
          path: "lore"
          values: ["稀有", "史诗", "传说"]
    fallback:
      display-name: "普通物品"
      priority: 9999
      default: true
      slots:
        max: 999
```

### 混合路径分类

不同分类使用不同路径类型：

```yaml
extra-backpack:
  enabled: true
  categories:
    custom_model:
      display-name: "自定义模型"
      priority: 5
      slots:
        max: 999
      match:
        nbt:
          path: "custom-model-data"
          values: ["10001", "10002", "10003"]
    named_item:
      display-name: "命名物品"
      priority: 10
      slots:
        max: 999
      match:
        nbt:
          path: "display-name"
          values: ["传说之剑", "神话护甲"]
    other:
      display-name: "杂物"
      priority: 9999
      default: true
      slots:
        max: 999
```

## 匹配规则注意事项

| 注意点 | 说明 |
| --- | --- |
| 大小写归一化 | 所有路径值与匹配值均执行 `trim().toLowerCase(Locale.ROOT)`，配置时无需关心大小写 |
| 空规则跳过 | `material-ids`/`material-prefixes` 与 `nbt.path` 全为空的分类不参与匹配，等同于"不自动归类" |
| 空值列表跳过 | `nbt.values` 为空列表时 NBT 匹配不生效，但 `material-*` 规则仍可独立生效 |
| 兜底分类跳过 | `default: true` 的分类在匹配流程中被跳过，不参与自动归类 |
| 首匹配优先 | 按 `priority` 升序遍历，首个匹配成功的分类即为结果，后续分类不再检查 |
| 无匹配不拦截 | 拾取时若物品不匹配任何分类，物品正常进入原版背包，额外背包不拦截 |
| lore 使用 contains | `lore` 路径使用 `contains` 匹配，其他路径使用精确匹配 |
| PDC 仅读 STRING | PDC 路径仅读取 `PersistentDataType.STRING` 类型的值，不支持其他 PDC 类型 |

> 关于条件系统与物品来源的通用知识，参考 [条件系统](/docs/guide/conditions) 与 [物品来源](/docs/guide/item-sources)。
