# 连击追踪与触发器

> **付费模块**

连击追踪、死亡缓冲、按键触发器与状态/控制器触发器是 CombatEffect 模块的高级战斗特效子系统。它们在基础击杀/攻击特效之上，提供了连击里程碑、死亡可视化缓冲、按键驱动特效和 Chronos 状态联动等能力。所有子系统可独立开关，互不依赖。

## 子系统概览

| 子系统 | 配置节 | 源码类 | 依赖 | 默认状态 |
|---|---|---|---|---|
| 连击追踪 | `combo-tracker` | `ComboTrackerService` / `ComboTrackerConfiguration` | Chronos（可选） | 禁用 |
| 死亡缓冲 | `death-buffer` | `DeathBufferService` / `DeathBufferConfiguration` | ArcartX（视觉）/ Chronos（可选） | 禁用 |
| 按键触发器 | `keybind-trigger` | `KeybindTriggerService` | ArcartX | 禁用 |
| 状态/控制器触发器 | `state-trigger` | `StateTriggerService` | Chronos | 禁用 |

> 四个子系统均默认禁用，需在 `config.yml` 中显式启用。启用时需确保对应依赖已安装，否则自动降级或保持禁用。

## 连击追踪

### 工作原理

连击追踪服务维护每个玩家的连击状态（`ComboState`），包含当前连击数、上次攻击时间和目标 ID。每次攻击或 Chronos 状态进入时累加连击，超时后自动重置。

```yaml
# 连击追踪核心流程
1. 攻击/状态进入 → incrementCombo(player, targetId)
2. 计算 ComboState
   ├─ 首次攻击或超时 → count=1
   ├─ per-target 模式且目标切换 → count=1
   └─ 正常累加 → count++
3. 调度超时重置任务（timeoutMs / 50 tick 后执行）
4. 同步连击数到客户端服务器变量
5. 遍历 trigger:combo 的包定义 → matchesCombo() 检查
6. 匹配则向接收者发送 UI 包
```

### 连击来源

连击来源通过 `combo-tracker.source` 配置，支持三种模式：

| 来源模式 | 配置值 | 说明 | 降级行为 |
|---|---|---|---|
| 自动检测 | `auto` | Chronos 可用时优先 Chronos，否则回退 Bukkit | Chronos 不可用 → Bukkit |
| 仅 Chronos | `chronos` | 仅使用 Chronos `PlayerEnterStateEvent` | Chronos 不可用 → 不启用 |
| 仅 Bukkit | `bukkit` | 仅使用 `EntityDamageByEntityEvent` | 无降级 |

```java
// ComboTrackerService.start() 中的来源选择逻辑
boolean useChronos = config.source() == ComboSource.CHRONOS || config.source() == ComboSource.AUTO;
boolean useBukkit = config.source() == ComboSource.BUKKIT || config.source() == ComboSource.AUTO;

if (useChronos) {
    chronosHooked = initChronos();  // 尝试初始化 Chronos
}
if (!chronosHooked && useBukkit) {
    // Chronos 不可用或 source=bukkit，注册 Bukkit 攻击事件监听
    Bukkit.getPluginManager().registerEvents(this, plugin);
}
```

### Chronos 连击集成

当来源为 `chronos` 或 `auto`（且 Chronos 可用）时，连击追踪通过 `ChronosHook.registerComboListener()` 监听 `PlayerEnterStateEvent`：

| 配置项 | 说明 |
|---|---|
| `chronos-groups` | 状态组过滤列表，仅这些组的状态进入才计为连击一击 |
| 默认值 | `["攻击", "连击"]` |

```java
// ChronosHook.registerComboListener() 的过滤逻辑
EventExecutor executor = (listener, event) -> {
    PlayerEnterStateEvent enterEvent = (PlayerEnterStateEvent) event;
    Player player = enterEvent.getPlayer();
    String group = chronosApi.getPlayerStateGroupId(player);
    if (group != null && groups.contains(group)) {
        onStateEnter.accept(player);  // 状态组匹配，累加连击
    }
};
```

> Chronos 集成通过 `ChronosHook` 隔离层实现，Chronos 未安装时 `ChronosHookFactory.tryCreate()` 返回 `null`，不触发 `NoClassDefFoundError`。参考 [联动文档](/docs/combateffect/integration#chronos-集成)。

### 超时重置

每次连击累加后，调度一个延迟任务在 `timeout` 毫秒后执行重置。如果在此期间有新的攻击，旧任务被取消并重新调度：

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `combo-tracker.timeout` | long | `2000` | 超时重置时间（毫秒），最小 200 |

```java
// 超时重置任务调度
private void scheduleReset(UUID playerId) {
    BukkitTask oldTask = resetTasks.remove(playerId);
    if (oldTask != null) oldTask.cancel();  // 取消旧任务
    long timeoutTicks = Math.max(1, config.timeoutMs() / 50);
    BukkitTask task = AxsScheduler.runTaskLater(plugin, () -> {
        comboStates.remove(playerId);
        resetTasks.remove(playerId);
        syncVariable(player, 0);  // 重置时同步变量为 0
    }, timeoutTicks);
    resetTasks.put(playerId, task);
}
```

> 超时后连击数重置为 0，同时同步客户端服务器变量为 0。UI 可通过 `{server.combo_count}` 引用实时连击数。

### 目标锁定模式

`per-target` 模式控制切换攻击目标时是否重置连击：

| `per-target` | 行为 | 适用场景 |
|---|---|---|
| `false`（默认） | 切换目标不重置，连续攻击任意目标均累加 | 群战、清怪 |
| `true` | 切换目标重置为 1，仅对同一目标的连续攻击累加 | Boss 战、单挑 |

```java
// per-target 模式的重置逻辑
if (config.perTarget() && targetId != null && existing.targetId != null
    && !targetId.equals(existing.targetId)) {
    return new ComboState(1, now, targetId);  // 目标切换，重置为 1
}
```

> `per-target` 仅在 Bukkit 来源模式下有效（有目标 ID）。Chronos 来源模式下 `targetId` 为 `null`，不触发目标锁定逻辑。

### 客户端变量同步

`sync-variable` 开启后，每次连击累加和超时重置都会同步连击数到 ArcartX 客户端服务器变量：

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `combo-tracker.sync-variable` | boolean | `false` | 是否同步连击数到客户端变量 |
| `combo-tracker.variable-name` | string | `combo_count` | 客户端变量名 |

```yaml
# UI 中引用连击数变量
连击数字:
  type: Text
  attribute:
    texts: "~&f{server.combo_count}"
    visible: "server.combo_count > 0 || var.combo_show"
```

> 推荐方式：开启 `sync-variable` 后直接用 `{server.combo_count}` 显示实时数字，`packetHandler` 仅用于里程碑动画（如 5 连击闪光、10 连击特效）。

### 连击包触发

每次连击累加后，`dispatchComboPackets()` 遍历所有 `trigger: combo` 的包定义，调用 `matchesCombo()` 检查是否满足条件：

```java
// PacketDefinition.matchesCombo() 的匹配逻辑
public boolean matchesCombo(int comboCount) {
    if (!triggers.contains(PacketTrigger.COMBO)) return false;
    if (comboCount < comboMin || comboCount > comboMax) return false;
    if (!comboRepeat && comboMin > 0) {
        return comboCount == comboMin;  // 非重复模式：仅达到 min 时触发一次
    }
    return true;  // 重复模式或 min=0：每击都触发
}
```

| `combo-repeat` | `combo-min` | 触发时机 |
|---|---|---|
| `false` | `5` | 仅当 `comboCount == 5` 时触发一次 |
| `false` | `0` | 每一击都触发（min=0 时 repeat 逻辑不生效） |
| `true` | `5`（`combo-max=10`） | 5~10 连击范围内每一击都触发 |

> 连击场景下 `attacker` 和 `target` 均为玩家自身（`recipientType.resolve(player, player)`），即连击特效仅发给攻击者自己。

## 死亡缓冲

### 工作原理

死亡缓冲在 `EntityDamageEvent` 的 `HIGHEST` 优先级拦截致死伤害，在真正死亡前给玩家一个可视化缓冲期。缓冲期间冻结玩家、应用视觉效果、发送 `trigger: death` 包，缓冲结束后执行真正死亡。

```yaml
# 死亡缓冲核心流程
1. EntityDamageEvent(HIGHEST) → 检测伤害是否致死（healthAfter <= 0）
2. 取消伤害事件 → event.setCancelled(true)
3. 进入缓冲状态
   ├─ 冻结玩家（无敌、移速归零、血量设为 0.001）
   ├─ 应用视觉效果（Shader / 第三人称 / 预设相机 / Chronos 状态）
   ├─ 发送 trigger:death 的包定义
   └─ 调度延迟任务（durationTicks 后执行 exitBuffer）
4. 缓冲结束 → exitBuffer()
   ├─ 清除视觉效果
   ├─ 恢复移动（移速恢复正常）
   └─ 执行真正死亡（setHealth(0)）
```

### 拦截机制

死亡缓冲监听 `EntityDamageEvent`（非仅 `EntityDamageByEntityEvent`），覆盖所有伤害来源：

| 监听事件 | 优先级 | 说明 |
|---|---|---|
| `EntityDamageEvent` | `HIGHEST` | 拦截所有伤害（含摔落、岩浆等非实体伤害） |
| `PlayerDeathEvent` | `HIGHEST` | 安全网兜底，防止其他插件绕过伤害拦截 |
| `PlayerRespawnEvent` | `HIGHEST` | 防御性监听，阻止自动复活 |
| `PlayerQuitEvent` | `MONITOR` | 玩家退出时清理缓冲状态 |

```java
// 致死伤害检测逻辑
double healthAfter = victim.getHealth() - event.getFinalDamage();
if (healthAfter > 0) return;  // 非致死伤害，不拦截

// 确定击杀者（仅 EntityDamageByEntityEvent 可解析）
Player killer = null;
if (event instanceof EntityDamageByEntityEvent entityEvent) {
    killer = CombatEventSupport.resolvePlayerAttacker(entityEvent);
}

// 取消伤害，进入缓冲
event.setCancelled(true);
enterBuffer(victim, killer);
```

> 已在缓冲中的玩家受到的一切伤害都会被取消（`event.setCancelled(true)`），确保缓冲期间玩家不会死亡。

### 视觉效果

缓冲期间可应用四种视觉效果，通过 ArcartX 客户端 API 实现：

| 效果 | 配置项 | 说明 |
|---|---|---|
| Shader | `visuals.shader` | ArcartX Shader 名称（灰度/模糊等），需在客户端 `shaders/` 目录存在 |
| 第三人称视角 | `visuals.third-person-camera` | 切换到第三人称视角，缓冲结束后恢复 |
| 预设相机 | `visuals.camera-preset` | ArcartX 预设相机 ID（电影级俯拍镜头） |
| Chronos 状态 | `visuals.chronos.enabled` + `visuals.chronos.state-id` | 强制玩家进入指定 Chronos 状态 |

```java
// applyVisuals() 的视觉效果应用
ArcartXPlayer axPlayer = getArcartXPlayer(player);
if (!config.shader().isBlank()) {
    axPlayer.enableShader(config.shader());        // 启用 Shader
}
if (config.thirdPersonCamera()) {
    axPlayer.setThirdPerson(true);                  // 第三人称
}
if (!config.cameraPreset().isBlank()) {
    axPlayer.setCameraFromPreset(config.cameraPreset()); // 预设相机
}
// Chronos 死亡状态
if (chronosAvailable && config.chronosEnabled()) {
    chronosHook.tryEnterControlledState(player, config.chronosStateId(), config.durationMs());
}
```

> ArcartX 视觉效果通过 `ArcartXAPI.getEntityManager()` 获取 `ArcartXPlayer` 实例。ArcartX 未安装时 `arcartxVisualAvailable=false`，视觉效果不应用但不影响缓冲流程。Chronos 状态通过 `ChronosHook.tryEnterControlledState()` 设置，持续时间与缓冲时长一致。

### 缓冲状态管理

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `death-buffer.duration` | long | `3000` | 缓冲持续时间（毫秒），最小 500 |
| `death-buffer.block-auto-respawn` | boolean | `true` | 缓冲期间阻止其他插件触发的自动复活 |
| `death-buffer.world-blacklist` | `List<String>` | `[]` | 不启用死亡缓冲的世界列表 |

```java
// durationMs → durationTicks 换算
public int durationTicks() {
    return (int) Math.max(10, durationMs / 50);  // 最小 10 tick（500ms）
}
```

> `world-blacklist` 中的世界不启用死亡缓冲，致死伤害正常触发原版死亡。`block-auto-respawn` 防止其他插件在缓冲期间自动复活玩家（正常流程不应到达 `PlayerRespawnEvent`，因伤害已被拦截）。

### 死亡包分发

缓冲期间发送 `trigger: death` 的包定义。在 DEATH 场景下，`attacker=killer`，`target=victim`：

```java
// dispatchDeathPackets() 的接收者解析
for (PacketRecipient recipientType : definition.recipients()) {
    // DEATH 场景: attacker=killer, target=victim
    Player recipient = recipientType.resolve(killer, victim);
    if (recipient == null || !recipient.isOnline()) continue;
    Object payload = context.renderPayload(definition.packTemplate(), recipientType, recipient);
    packetBridge.sendPacket(recipient, definition.uiId(), definition.packetHandler(), payload);
}
```

| 接收者 | 实际接收 | 说明 |
|---|---|---|
| `target` | 被击杀的玩家 | 显示全屏死亡界面 |
| `attacker` | 击杀者（可能为 `null`） | 复用击杀特效 HUD 显示击杀提示 |

> 环境死亡（摔落、岩浆等）时 `killer=null`，`attacker` 接收者解析为 `null` 自动跳过。仅 `target` 接收者会收到死亡缓冲包。

## 按键触发器

### 工作原理

按键触发器监听 ArcartX 客户端按键事件，匹配 `trigger: keybind` 的包定义并发送 UI 包。需要 ArcartX 插件安装且 `keybind-trigger.enabled=true`。

```java
// KeybindTriggerService 监听的按键事件
ClientKeyPressEvent         → handleKeybind(player, keyName, true,  "client")
ClientKeyReleaseEvent       → handleKeybind(player, keyName, false, "client")
ClientSimpleKeyPressEvent   → handleKeybind(player, keyName, true,  "simple")
ClientSimpleKeyReleaseEvent → handleKeybind(player, keyName, false, "simple")
ClientKeyGroupPressEvent    → handleKeybind(player, groupID, true,  "group")
```

### 按键类型

| 按键类型 | 配置值 | 监听事件 | 说明 |
|---|---|---|---|
| 客户端按键 | `client` | `ClientKeyPressEvent` / `ClientKeyReleaseEvent` | ArcartX 标准按键绑定 |
| 简易按键 | `simple` | `ClientSimpleKeyPressEvent` / `ClientSimpleKeyReleaseEvent` | 轻量按键 |
| 按键组 | `group` | `ClientKeyGroupPressEvent` | 按键组按下事件（无释放事件） |

> 按键组（`group`）仅有按下事件，无释放事件。`key-action: release` 对按键组类型无效。

### 按键匹配逻辑

```java
// PacketDefinition.matchesKeybind() 的匹配逻辑
public boolean matchesKeybind(String incomingKeyName, boolean isPress, String incomingKeyType) {
    if (!triggers.contains(PacketTrigger.KEYBIND) || keyName == null) return false;
    if (!wildcardMatch(keyName, incomingKeyName)) return false;  // 通配符匹配
    if (keyType != null && !keyType.equalsIgnoreCase(incomingKeyType)) return false;  // 类型匹配
    return matchesAction(keyAction, isPress);  // 动作匹配
}
```

| 匹配维度 | 条件字段 | 说明 |
|---|---|---|
| 按键名称 | `key-name` | 通配符匹配（`*` 匹配任意字符序列） |
| 按键类型 | `key-type` | 精确匹配（大小写不敏感） |
| 按键动作 | `key-action` | `press` / `release` / `both` |

### 按键触发示例

```yaml
# 按下 attack_* 按键时触发技能爆发特效
skill-burst:
  enabled: true
  trigger: keybind
  ui-id: "AXS:combat_kill_effect"
  packet-handler: "attack"
  recipients:
    - attacker
  conditions:
    key-name: "attack_*"    # 匹配 attack_1, attack_2, attack_combo 等
    key-action: "press"     # 仅按下时触发
    key-type: "client"      # 仅客户端按键
  cooldown: 1000            # 1 秒冷却
  pack:
    player: "{player}"
    key_name: "{key_name}"
```

> 按键触发器的接收者始终为触发的玩家自身（按键事件无攻击者/目标概念）。变量替换支持 `{player}` 和 `{key_name}`。

## 状态/控制器触发器

### 工作原理

状态/控制器触发器监听 Chronos 状态进入/离开与控制器切换事件，匹配 `trigger: state` 和 `trigger: controller` 的包定义。需要 Chronos 插件安装且 `state-trigger.enabled=true`。

### 状态触发

状态触发监听 `PlayerEnterStateEvent` 和 `PlayerLeaveStateEvent`：

| Chronos 事件 | 对应动作 | `state-action` 配置值 |
|---|---|---|
| `PlayerEnterStateEvent` | 进入状态 | `enter` |
| `PlayerLeaveStateEvent` | 离开状态 | `leave` |
| 两者均监听 | 进入或离开 | `both` |

```java
// StateTriggerService.handleState() 的匹配逻辑
private void handleState(Player player, String stateId, boolean isEnter, String currentController) {
    for (PacketDefinition definition : configuration.packetDefinitions()) {
        if (!definition.enabled() || !definition.matchesState(stateId, isEnter, currentController)) continue;
        // 冷却检查 → 发包
    }
}
```

`matchesState()` 的匹配维度：

| 维度 | 条件字段 | 说明 |
|---|---|---|
| 状态 ID | `state-id` | 通配符匹配（`*` 匹配任意字符序列） |
| 动作 | `state-action` | `enter` / `leave` / `both` |
| 控制器过滤 | `controller-id` | 可选，通配符匹配。为空时不做控制器过滤 |

> `controller-id` 为可选过滤条件。设置后仅当玩家当前控制器 ID 匹配时才触发。为空或未设置时不做控制器过滤，任意控制器下的状态变化均可触发。

### 控制器触发

控制器触发监听 `PlayerControllerChangeEvent`，当玩家切换 Chronos 控制器时触发：

```java
// StateTriggerService.handleController() 的匹配逻辑
private void handleController(Player player, String controllerId) {
    for (PacketDefinition definition : configuration.packetDefinitions()) {
        if (!definition.enabled() || !definition.matchesController(controllerId)) continue;
        // 冷却检查 → 发包
    }
}
```

`matchesController()` 的匹配逻辑：

| `controller-id` 配置 | 匹配行为 |
|---|---|
| 未设置或为空 | 匹配所有控制器切换 |
| 设置值（如 `弓箭手`） | 仅匹配指定控制器 |
| 通配符（如 `mode_*`） | 通配符匹配控制器 ID |

### 状态/控制器触发示例

```yaml
# 进入 "狂暴" 状态时触发特效
berserk-effect:
  enabled: true
  trigger: state
  ui-id: "AXS:combat_kill_effect"
  packet-handler: "attack"
  recipients:
    - attacker
  conditions:
    state-id: "狂暴"
    state-action: "enter"
  pack:
    player: "{player}"
    state_id: "{state_id}"

# 离开 "防御" 状态时触发
defense-end:
  enabled: true
  trigger: state
  ui-id: "AXS:combat_kill_effect"
  packet-handler: "attack"
  recipients:
    - attacker
  conditions:
    state-id: "防御"
    state-action: "leave"
  pack:
    player: "{player}"
    state_id: "{state_id}"

# 切换到 "弓箭手" 控制器时触发
archer-mode:
  enabled: true
  trigger: controller
  ui-id: "AXS:combat_kill_effect"
  packet-handler: "attack"
  recipients:
    - attacker
  conditions:
    controller-id: "弓箭手"
  pack:
    player: "{player}"
    controller_id: "{controller_id}"
```

> 状态触发器的接收者始终为触发的玩家自身。变量替换支持 `{player}`、`{state_id}` 和 `{controller_id}`。

## 冷却系统

连击追踪的包分发不使用冷却（由 `combo-min` / `combo-max` / `combo-repeat` 条件控制频率）。按键触发器和状态/控制器触发器均支持独立冷却：

| 触发器 | 冷却实现 | 冷却 key |
|---|---|---|
| 按键触发器 | `KeybindTriggerService.cooldownMap` | `packetId:playerUUID` |
| 状态/控制器触发器 | `StateTriggerService.cooldownMap` | `packetId:playerUUID` |

> 冷却逻辑与包定义系统的冷却一致：发包成功后设置冷却，冷却内跳过。参考 [包定义系统](/docs/combateffect/packet-definitions#冷却系统)。

## 内存状态管理

所有子系统的运行时状态均保存在内存 `ConcurrentHashMap` 中，玩家退出或模块卸载时自动清理：

| 子系统 | 状态存储 | 清理时机 |
|---|---|---|
| 连击追踪 | `ConcurrentHashMap<UUID, ComboState>` + `ConcurrentHashMap<UUID, BukkitTask>` | 超时重置 / 玩家退出 / 模块卸载 |
| 死亡缓冲 | `ConcurrentHashMap<UUID, BufferState>` | 缓冲结束 / 玩家退出 / 模块卸载 |
| 按键触发器冷却 | `ConcurrentHashMap<String, Long>` | 冷却过期 / 玩家退出 / 模块卸载 |
| 状态触发器冷却 | `ConcurrentHashMap<String, Long>` | 冷却过期 / 模块卸载 |

> 模块卸载时按反向顺序停止各子服务（state → keybind → combo → deathBuffer → display → packet），确保监听器正确注销、任务取消、状态清理。

## 模块启动顺序

```java
// CombatEffectModule.startService() 中的启动顺序
1. 注册 UI 面板（combat_kill_effect / combo_effect / death_buffer）
2. 导出 damage_display 资源
3. 启动 PacketService（事件监听 + 包分发）
4. 启动 DisplayService（伤害飘字，需 ClientBridge 可用）
5. 启动 DeathBufferService（需 enabled=true）
6. 启动 ComboTrackerService（需 enabled=true）
7. 启动 KeybindTriggerService（需 enabled=true，需 ArcartX）
8. 启动 StateTriggerService（需 enabled=true，需 Chronos）
9. 注册 CombatEffectTriggerable Capability
```

> 各子系统的启动条件独立检查。例如 DisplayService 仅在 `clientBridge != null && clientBridge.isAvailable()` 时启动，KeybindTriggerService 仅在 ArcartX 已安装时注册监听。
