# 绑定系统

> **付费模块**

Menu 模块的绑定系统是菜单触发的入口层。除了通过 `/menu open <菜单ID>` 命令手动打开菜单外，模块支持三种自动触发方式：命令绑定（输入命令打开菜单）、物品绑定（手持物品交互打开菜单）和 ESC 拦截（按 ESC 键替换原版暂停界面）。此外，菜单可配置自定义 UI 目标，将同一份菜单数据发送到不同的客户端 UI。

## 命令绑定

命令绑定将菜单注册为游戏命令，玩家输入匹配的命令时自动打开对应菜单。菜单重载时绑定自动重建。

### 精确命令绑定

通过菜单定义的 `commands` 字段注册精确命令别名。玩家输入 `/别名` 即可打开菜单。

```yaml
id: example
commands:
  - "examplemenu"
  - "emenu"
  - "功能菜单"
```

- 支持中文命令别名
- 可注册多个别名
- 命令匹配忽略大小写
- 支持带参数匹配：`/examplemenu arg1 arg2` 同样触发（匹配前缀 + 空格）

### 命令正则匹配

通过 `command-regex` 字段注册正则表达式，匹配更灵活的命令输入。

```yaml
id: example
command-regex:
  - "example(?:menu)?"
  - "menu_(?:main|home)"
```

| 特性 | 说明 |
|---|---|
| 匹配方式 | 正则全匹配，大小写不敏感 |
| 编译失败 | 记录警告日志，跳过该正则绑定 |
| 权限继承 | 使用菜单定义的 `permission` 字段 |

### 命令绑定匹配

玩家输入命令时依次匹配命令绑定：命中且权限通过时拦截命令并打开菜单；未命中或无权限时静默放行，不干预原命令执行。

### 精确匹配 vs 正则匹配

| 维度 | 精确匹配 (`commands`) | 正则匹配 (`command-regex`) |
|---|---|---|
| 匹配方式 | 忽略大小写相等 + 前缀匹配 | 正则全匹配 |
| 灵活性 | 固定别名 | 任意正则模式 |
| 参数支持 | 支持（`/别名 参数`） | 不支持（全匹配） |
| 适用场景 | 固定命令名 | 命令模式匹配（如 `menu_(?:main\|home)`） |

> 精确匹配支持带参数：`/examplemenu arg1` 会匹配 `examplemenu` 绑定。正则匹配为全匹配，不支持带参数。

## 物品绑定

物品绑定将菜单绑定到背包中的特定物品，玩家手持匹配物品执行指定交互动作时打开菜单。绑定可定义在菜单级（`item-binds`）或全局级（`settings.item-binds`）。

### 菜单级物品绑定

在菜单定义中配置 `item-binds`，仅对该菜单生效：

```yaml
id: example
item-binds:
  - material: COMPASS
    name-contains: "功能菜单"
    action: RIGHT_CLICK
```

### 全局物品绑定

在主配置 `settings.item-binds` 中配置，可绑定到任意菜单（通过 `menu` 字段指定目标菜单 ID）：

```yaml
settings:
  item-binds:
    - menu: example
      material: NETHER_STAR
      name-contains: "服务器菜单"
      action: RIGHT_CLICK
```

### 物品绑定字段

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `menu` | `String` | 菜单自身 ID | 目标菜单 ID（全局绑定时必填） |
| `material` | `String` | `""` | 物品材质名称（Minecraft 物品 ID），空表示不限制 |
| `name-contains` | `String` | `""` | 物品显示名称需包含的文本（模糊匹配，忽略大小写） |
| `name-regex` | `String` | `""` | 物品显示名称需匹配的正则表达式 |
| `lore-contains` | `String` | `""` | 物品 Lore 需包含的文本 |
| `custom-model-data` | `int` | `-1` | 自定义模型数据 ID，`-1` 表示不限制 |
| `action` | `String` | `RIGHT_CLICK` | 触发所需的点击类型 |
| `main-hand` | `boolean` | `true` | 是否允许主手触发 |
| `off-hand` | `boolean` | `true` | 是否允许副手触发 |
| `permission` | `String` | `""` | 触发所需的权限节点，空表示无限制 |

> 字段别名兼容：`name-contains` / `nameContains`、`name-regex` / `nameRegex`、`lore-contains` / `loreContains`、`custom-model-data` / `customModelData`、`action` / `click` 均可使用。

### 点击类型

| 配置值 | 对应 Bukkit Action | 说明 |
|---|---|---|
| `RIGHT_CLICK` | `RIGHT_CLICK_AIR` / `RIGHT_CLICK_BLOCK` | 右键点击 |
| `LEFT_CLICK` | `LEFT_CLICK_AIR` / `LEFT_CLICK_BLOCK` | 左键点击 |
| `PHYSICAL` | `PHYSICAL` | 物理交互（如踩压力板） |

> 未配置或无法识别的点击类型默认为 `RIGHT_CLICK`。

### 物品匹配规则

| 匹配项 | 匹配方式 | 说明 |
|---|---|---|
| `material` | 精确匹配 | 空值跳过材质检查 |
| `name-contains` | 去色后忽略大小写包含 | 支持 `&` 颜色代码 |
| `name-regex` | 去色后正则查找 | 大小写不敏感 |
| `lore-contains` | 逐行去色后忽略大小写包含 | 任一行匹配即通过 |
| `custom-model-data` | 精确比较 | `>= 0` 时启用检查 |

> 匹配前自动去除物品名称与 Lore 的颜色代码。物品绑定匹配按手位、点击类型、权限、物品条件依次检查，全部通过时拦截交互并打开菜单。

### 绑定加载顺序

1. 全局物品绑定（`settings.item-binds`）
2. 各菜单的 `commands`（精确命令）、`command-regex`（正则命令）、`item-binds`（菜单级物品）

## ESC 拦截

ESC 拦截将菜单绑定到玩家的 ESC 键，替代原版暂停界面。仅 `layout: esc` 的菜单可启用此功能。

### 配置方式

在菜单定义中设置 `match-esc: true`：

```yaml
id: esc_main
layout: esc
match-esc: true
```

### ESC 菜单查找

玩家按 ESC 键时按以下优先级查找菜单：

| 优先级 | 查找 |
|---|---|
| 1 | `client.esc-menu-id` 配置指定的菜单（默认 `esc_main`） |
| 2 | 第一个 `layout: esc` 或 `match-esc: true` 的菜单 |
| 兜底 | 无匹配菜单时不做任何操作 |

> `client.esc-menu-id` 是菜单定义 ID（非 UI ID），指向 `menus/` 目录中某个 `layout: esc` 的菜单。

### 底栏按钮 footer-buttons

ESC 布局专属功能，底部固定按钮始终显示在菜单底部，不受分页影响。常用于游戏选项、退出游戏等原生功能。

```yaml
footer-buttons:
  options:
    text: "&f游戏选项"
    order: 0
    client-action: "options"
  quit:
    text: "&f退出游戏"
    order: 1
    client-action: "quit"
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `text` | `String` | 按钮显示文字 |
| `order` | `int` | 排列顺序（越小越靠前） |
| `permission` | `String` | 按钮级权限，无权限的玩家看不到 |
| `use-conditions` | `List<String>` | 按钮可点击条件 |
| `deny-message` | `String` | 条件不满足时的提示 |
| `actions` | `List<String>` | 点击时执行的服务端动作 |
| `client-action` | `String` | 客户端原生动作标识 |
| `icon` | `Map` | 按钮图标配置 |

### client-action 客户端原生动作

`client-action` 字段指定由 ArcartX 客户端 UI 引擎直接处理的动作，不经过服务端：

| client-action | 说明 |
|---|---|
| `options` | 打开 Minecraft 原版设置界面 |
| `quit` | 退出游戏 |

> `client-action` 与 `actions` 可共存：`client-action` 由客户端 UI 直接处理，`actions` 由服务端执行。

## 自定义 UI 目标

默认情况下，菜单根据 `layout` 自动选择对应的 UI（`panel` → `menu_panel`，`esc` → `menu_esc`），使用内置的 `init` / `update` 生命周期 handler。菜单可通过 `ui-id` / `ui-targets` 配置自定义 UI 目标。

### 简写格式

单 UI 目标，指定 UI ID 和可选的 packet handler：

```yaml
id: my_menu
ui-id: "my_custom_panel"
packet-handler: "menu"
```

| 字段 | 说明 |
|---|---|
| `ui-id` | 自定义 UI 的注册 ID |
| `packet-handler` | 自定义 packet handler 名称，留空时使用 `init` / `update` |

### 多 UI 目标

同一份菜单 payload 同时发送给多个 UI，第一个 UI 用于 `open` / `close` 操作：

```yaml
id: my_menu
ui-targets:
  - ui-id: "my_custom_panel"
    packet-handler: "menu"
  - ui-id: "menu_hud"
    packet-handler: "overlay"
```

| 字段 | 说明 |
|---|---|
| `ui-id` | 目标 UI 的注册 ID（必填） |
| `packet-handler` | packet handler 名称，留空时使用 `init` / `update` |

> `ui-targets` 优先级高于 `ui-id + packet-handler`，两者不要同时配置。

### UI 注册

自定义 UI 文件需放置在 `ArcartXSuite/ui/` 目录下，文件名为 `<ui-id>.yml`。模块启动时自动注册所有 `ui-targets` 中声明的非内置 UI：文件不存在或注册失败时记录警告。

> 自定义 UI 的 `ui-id` 应使用不带命名空间前缀的 ID（如 `my_panel` 而非 `AXS:my_panel`）。

### Payload 分发

| 配置 | 分发方式 |
|---|---|
| 无 `ui-targets` | 发送到默认 UI，handler 为 `init`（首次）或 `update`（刷新） |
| 有 `ui-targets` | 遍历每个 target，handler 为 `packet-handler` 或 `init` / `update` |

### UI 数据包结构

| Payload 字段 | 类型 | 说明 |
|---|---|---|
| `packetId` | `String` | 数据包 ID（`ui.packet-id`） |
| `menuId` | `String` | 菜单 ID |
| `layout` | `String` | 布局类型（`panel` / `esc`） |
| `title` | `String` | 菜单标题（PAPI 解析后） |
| `pageId` | `String` | 当前页面 ID |
| `pageTitle` | `String` | 页面标题（PAPI 解析后） |
| `pageIndex` | `int` | 当前页索引 |
| `pageCount` | `int` | 总页数 |
| `columns` | `int` | 每行按钮列数 |
| `hasPrev` | `boolean` | 是否有上一页 |
| `hasNext` | `boolean` | 是否有下一页 |
| `buttonRows` | `Map<String, Object>` | 按钮行数据 |
| `buttonCount` | `int` | 当前页按钮数 |
| `footerRows` | `Map<String, Object>` | 底栏行数据 |
| `footerCount` | `int` | 底栏按钮数 |
| `maxButtonCount` | `int` | 每页按钮上限 |
| `maxFooterCount` | `int` | 底栏按钮总数 |

### 客户端数据包动作

客户端 UI 向服务端发送的动作（自定义菜单 UI 时参考）：

| 客户端动作 | 说明 |
|---|---|
| `refresh` | 刷新当前菜单数据 |
| `esc_open` | 打开默认 ESC 菜单 |
| `close` | 关闭当前菜单 |
| `page <token>` | 翻页（`prev` / `next` / 页面 ID） |
| `click <buttonId>` | 普通按钮点击 |
| `footer <buttonId>` | 底栏按钮点击 |

> 数据包 ID 需匹配 `ui.packet-id`（默认 `AXS_MENU`）。

## 按钮可见性与排序

### 可见性过滤

| 过滤层 | 字段 | 不满足时行为 |
|---|---|---|
| 权限过滤 | `permission` | 按钮完全不显示 |
| 查看条件 | `viewConditions` / `requirements` | 按钮完全不显示 |
| 使用条件 | `useConditions` | 按钮显示但灰色禁用（`enabled: false`） |

> 条件系统的完整说明详见 [条件系统](/docs/guide/conditions)。

### 排序规则

可见按钮按 `order` 升序排列，`order` 相同则按 `id` 字典序排列。

### 分页裁剪

按钮按 `buttons-per-page` 上限分页，取可见按钮列表的前 `buttons-per-page` 个作为当前页按钮。

> 自动分页仅裁剪首页按钮，多页按钮需在 YAML 中手动定义多个 `pages` 页面。页面索引越界时自动截断到首尾页。

## 图标系统

按钮图标支持原版材质、物品库、自定义贴图等多种来源。图标配置详见 [图标配置](/docs/guide/icons) 和 [物品库匹配](/docs/guide/item-sources)。

```yaml
buttons:
  my_button:
    text: "&f仓库系统"
    icon:
      material: CHEST
      name: "&f仓库"
      custom-model-data: 0
```

| 图标来源 | 配置方式 | 说明 |
|---|---|---|
| 原版物品 | `material` + `name` + `lore` + `custom-model-data` | Minecraft 物品 ID |
| 物品库 | `source` + `id` | NeigeItems / MythicMobs / Overture |
| MMOItems | `source: mmoitems` + `mmo-type` + `mmo-id` | 需类型与 ID 两段定位 |
| ArcartX 贴图 | `texture` / `texture-url` / `nbt` | 写入 NBT 渲染自定义贴图 |
| 直接 NBT | `json` | 直接提供物品 NBT JSON |

> 图标解析结果以 `itemJson` 字段发送给客户端 UI，`hasIcon` 标识是否包含有效图标。详见 [图标配置](/docs/guide/icons)。

## 会话管理

每个玩家同时持有一个菜单会话：

| 事件 | 行为 |
|---|---|
| 打开菜单 | 创建会话，记录当前菜单与页码 |
| 关闭菜单 | 移除会话，执行 `close-actions` |
| 玩家退出 | 移除会话（不执行 `close-actions`） |
| 翻页 | 更新页码并刷新界面 |

### 点击冷却

按钮点击受 `settings.click-cooldown-ms` 配置保护（默认 300ms），冷却期内的点击被忽略。设为 `0` 可禁用冷却。

## 完整绑定示例

### 命令 + 物品 + ESC 三重绑定

```yaml
id: main_menu
title: "&f&l主菜单"
layout: panel
columns: 4
buttons-per-page: 64

# 命令绑定
commands:
  - "menu"
  - "主菜单"
command-regex:
  - "menu(?:main)?"

# 物品绑定
item-binds:
  - material: COMPASS
    name-contains: "功能菜单"
    action: RIGHT_CLICK
  - material: CLOCK
    name-regex: ".*时钟.*"
    action: RIGHT_CLICK

pages:
  - id: main
    title: "&f功能"
    buttons:
      shop:
        text: "&f商城"
        order: 0
        actions:
          - "close"
          - "delay: 10"
          - "command: market shop"
```

### 全局物品绑定

```yaml
# ArcartXMenu.yml
settings:
  item-binds:
    - menu: main_menu
      material: NETHER_STAR
      name-contains: "服务器菜单"
      action: RIGHT_CLICK
      main-hand: true
      off-hand: false
      permission: "arcartxsuite.menu.use"
```

### ESC 菜单 + 底栏按钮

```yaml
id: esc_main
title: "&f&l菜单"
layout: esc
match-esc: true
columns: 2
buttons-per-page: 64

pages:
  - id: main
    title: "&f菜单"
    buttons:
      shop:
        text: "&f商城"
        order: 0
        actions:
          - "close"
          - "delay: 10"
          - "command: market shop"

footer-buttons:
  options:
    text: "&f游戏选项"
    order: 0
    client-action: "options"
  quit:
    text: "&f退出游戏"
    order: 1
    client-action: "quit"
```

### 自定义 UI 目标

```yaml
id: hud_menu
title: "&fHUD 菜单"
layout: panel

# 同时发送到面板 UI 和 HUD 覆盖层
ui-targets:
  - ui-id: "menu_panel"
    packet-handler: "init"
  - ui-id: "menu_hud"
    packet-handler: "overlay"

pages:
  - id: main
    title: "&fHUD"
    buttons:
      toggle:
        text: "&f切换显示"
        order: 0
        actions:
          - "signal: toggle_hud"
```
