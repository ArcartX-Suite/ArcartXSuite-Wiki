## 最常用的写法

在按钮的 `actions` 列表中逐行填写动作。下面的按钮先关闭菜单，等待 10 ticks，再执行玩家命令。

```yaml
actions:
  - "close"
  - "delay: 10"
  - "command: warehouse open"
```

`20 ticks = 1 秒`。动作中的命令不带开头的 `/`。

## 动作速查

| 动作 | 示例 | 效果 |
| --- | --- | --- |
| 玩家命令 | `command: spawn` | 按玩家已有权限执行命令 |
| 控制台命令 | `console: say %player_name% 打开了菜单` | 以控制台身份执行 |
| 发消息 | `message: &a欢迎来到服务器` | 向当前玩家发送消息 |
| 聊天 | `chat: 大家好` | 以玩家身份发送聊天 |
| 打开菜单 | `open: teleport` | 打开 ID 为 teleport 的菜单 |
| 翻页 | `page: page2` | 切换到当前菜单的 page2 页面 |
| 关闭 | `close` | 关闭当前菜单 |
| 延迟 | `delay: 10` | 等待后继续下一条动作 |
| 音效 | `sound: UI_BUTTON_CLICK` | 播放音效，名称以服务端支持为准 |
| 切服 | `connect: survival` | 切换到已配置的子服 |

## 给按钮添加动作

以下片段放在某一页的 `buttons` 中，`warehouse` 是按钮 ID。

```yaml
warehouse:
  text: "&f打开仓库"
  icon:
    material: CHEST
  actions:
    - "close"
    - "delay: 10"
    - "command: warehouse open"
```

需要启用 Warehouse，并确认玩家可执行对应命令。

## 菜单与页面有什么区别

`open` 的目标是菜单 `id`；`page` 的目标是当前菜单 `pages` 中的页面 `id`。页面 ID 相同也不会自动定位到另一个菜单。

## 打开与关闭时执行

菜单可使用 `open-actions` 与 `close-actions`，格式与按钮动作列表一致。先使用一条消息验证触发时机，再增加其他操作。

## 修改后检查

执行 `/axs reload menu`，用普通测试玩家打开菜单，检查命令权限、目标 ID 与跳转结果。
