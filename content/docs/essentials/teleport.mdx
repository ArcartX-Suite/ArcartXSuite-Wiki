## 服务概述

传送系统由 `TeleportService` 统一承担，实现 `Listener` 接口，负责家（home）、传送点（warp）、出生点（spawn）、TPA 请求、`/top`、`/back`、坐标传送（`/tppos`）以及带预热的延迟传送。位置数据通过 `EssentialsRepository` 持久化到数据库，运行时状态保存在两个并发映射中：

| 运行时状态 | 类型 | 说明 |
|------------|------|------|
| `pendingTpa` | `Map<UUID, TpaRequest>` | 待处理 TPA 请求（键为目标玩家 UUID） |
| `warmups` | `Map<UUID, Integer>` | 传送预热中的玩家（值为任务 ID） |

`start()` 阶段注册事件监听器，`shutdown()` 阶段注销监听器、取消全部预热任务并清空 TPA 请求。

## 家系统（Home）

家是玩家私有的传送点，每个玩家可设置多个家，数量受 `teleport.max-homes` 限制（默认 3）。

| 方法 | 功能 |
|------|------|
| `setHome(Player, name)` | 设置或更新家（超出上限时提示 `home-limit`） |
| `deleteHome(Player, name)` | 删除家（不存在时提示 `home-not-found`） |
| `teleportHome(Player, name)` | 延迟传送到家 |
| `getHomeNames(Player)` | 返回玩家全部家名称（用于 Tab 补全与 UI 列表） |

### 权限覆盖上限

`setHome` 在检查上限时支持权限覆盖：从大到小遍历 `axs.essentials.homes.<数字>` 权限节点，取玩家拥有的最高值作为实际上限：

```java
int max = config.teleport().maxHomes();
for (int i = 100; i > max; i--) {
    if (player.hasPermission("axs.essentials.homes." + i)) {
        max = i;
        break;
    }
}
```

> 例如配置 `max-homes: 3`，玩家拥有 `axs.essentials.homes.10` 权限时，上限提升为 10。仅对新增家生效，更新已有家不检查上限。

家名称在仓储层统一存储为小写（`name.toLowerCase()`），主键为 `(uuid, name)` 联合主键，同名家会被覆盖。

## 传送点（Warp）

传送点是全服共享的公共传送点，任何拥有 `axs.essentials.warp` 权限的玩家均可使用，设置与删除需要 `axs.essentials.setwarp` / `axs.essentials.delwarp` 权限。

| 方法 | 功能 |
|------|------|
| `setWarp(Player, name)` | 以玩家当前位置设置传送点 |
| `deleteWarp(Player, name)` | 删除传送点（不存在时提示 `warp-not-found`） |
| `teleportWarp(Player, name)` | 延迟传送到传送点 |
| `getWarpNames()` | 返回全部传送点名称（按名称排序） |

传送点名称同样存储为小写，主键为 `name`，同名传送点会被覆盖。

## 出生点（Spawn）

出生点是单行记录（`id=1`），未设置时 `teleportSpawn` 回退到世界默认出生点（`world.getSpawnLocation()`）：

| 方法 | 功能 |
|------|------|
| `setSpawn(Player)` | 以玩家当前位置设置服务器出生点 |
| `teleportSpawn(Player)` | 延迟传送到出生点（未设置则用世界默认） |

## TPA 请求

TPA 是玩家间的双向传送请求，分为两种模式：

| 命令 | 模式 | 传送方向 |
|------|------|----------|
| `/tpa <玩家>` | `here=false` | 请求者 → 目标 |
| `/tpahere <玩家>` | `here=true` | 目标 → 请求者 |

### 请求生命周期

`sendTpa(sender, target, here)` 创建请求并存入 `pendingTpa`（键为目标 UUID），同时调度一个延迟任务在 `tpa-timeout`（默认 60 秒，最小 10）后自动清除过期请求并通知发送者 `tpa-expired`。

```
发送请求 ──→ pendingTpa[target] = TpaRequest(sender, here, timestamp)
              │
              ├─ /tpaccept ──→ 移除请求，根据 here 决定传送方向，执行延迟传送
              ├─ /tpdeny    ──→ 移除请求，通知双方 tpa-denied
              └─ 超时       ──→ 自动移除请求，通知发送者 tpa-expired
```

`acceptTpa(player)` 接收请求后，根据 `here` 字段决定传送方向：`here=true` 时传送接收者到发送者位置，`here=false` 时传送发送者到接收者位置。请求者下线时 `onQuit` 监听器自动清理其待处理请求。

> 每个目标玩家同一时刻只保留一个待处理请求，新请求会覆盖旧请求。

## 延迟传送与预热

`delayedTeleport(Player, target, successMessage)` 是所有传送功能的统一入口，实现预热机制：

| 条件 | 行为 |
|------|------|
| `teleport-delay <= 0` | 即时传送 |
| 拥有 `axs.essentials.teleport.bypass-delay` | 即时传送（跳过预热） |
| 其他 | 进入预热，发送 `teleport-warmup` 提示，调度延迟任务 |

预热期间监听 `PlayerMoveEvent`（`ignoreCancelled = true`），当玩家移动到不同方块时取消传送任务并提示 `teleport-cancelled`：

```java
if (event.getTo() != null && !event.getFrom().getBlock().equals(event.getTo().getBlock())) {
    int taskId = warmups.remove(uuid);
    AxsScheduler.cancelTask(taskId);
    player.sendMessage(prefix() + config.messages().teleportCancelled());
}
```

> `cancel-on-move` 配置为 `false` 时禁用移动取消机制，预热期间移动不影响传送。

## 安全传送

`executeTeleport` 在实际传送前调用 `findSafeLocation` 寻找无碰撞位置（当 `teleport.safe-teleport` 为 `true` 时）：

- 若目标方块是固体方块，向上搜索最多 10 格，找到"脚部与头部均为非固体"的位置。
- 找到后返回该位置（中心点 `+0.5, 0, +0.5`，保留原朝向）。
- 找不到时返回原位置。

传送前会调用 `playerService.pushBackLocation(player)` 将当前位置压入 `/back` 栈，确保 `/back` 能返回传送前位置。

## 返回栈（/back）

`back(Player)` 弹出 `PlayerManagementService` 维护的返回栈中最新的位置并延迟传送过去。栈为空时提示 `back-none`。栈深度由 `teleport.back-stack-size`（默认 5）控制。

> 返回栈由 `PlayerManagementService` 维护，`TeleportService` 通过构造注入的 `playerService` 引用访问。每次 `executeTeleport` 都会压栈，因此连续传送可多级返回。

## 直接传送

| 方法 | 功能 |
|------|------|
| `teleportTop(Player)` | 传送到当前坐标最高非空气方块上方（`getHighestBlockYAt + 1`） |
| `/tp <玩家> [目标]` | 传送到玩家，或传送玩家到目标（命令层处理） |
| `/tppos <x> <y> <z>` | 传送到指定坐标（命令层解析坐标后调用 `delayedTeleport`） |

`/top` 与 `/tppos` 均通过 `delayedTeleport` 走预热流程，`/tp` 直接调用 `player.teleport`（不走预热）。

## 事件监听

| 事件 | 用途 |
|------|------|
| `PlayerMoveEvent` | 预热期间移动取消传送（`ignoreCancelled = true`） |
| `PlayerQuitEvent` | 玩家退出时清理待处理 TPA 请求与预热任务 |

## 配置项汇总

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `teleport.tpa-timeout` | `60` | TPA 请求过期时间（秒，最小 10） |
| `teleport.teleport-delay` | `3` | 传送预热延迟（秒，0=即时） |
| `teleport.cancel-on-move` | `true` | 预热期间移动是否取消 |
| `teleport.max-homes` | `3` | 每玩家家数量上限（可被权限覆盖） |
| `teleport.back-stack-size` | `5` | `/back` 返回栈最大深度 |
| `teleport.safe-teleport` | `true` | 是否启用安全传送 |

## UI 菜单集成

玩家工具菜单提供三个传送相关页面，由 `EssentialsMenuPacketHandler` 处理客户端回包：

| 页面 | 客户端 Action | 服务端处理 |
|------|---------------|------------|
| 家列表 | `teleport_home` / `delete_home` / `set_home` | 委托 `teleportService` 对应方法，操作后刷新 `homes` 页 |
| 传送点 | `teleport_warp` | 调用 `teleportWarp` |
| TPA | `send_tpa` / `accept_tpa` / `deny_tpa` | `send_tpa` 支持第三个参数 `here` 触发 tpahere |

服务端推送的家列表结构（`homes` 字段）为 `list<map>`，每项含 `name`、`world`、`coords`；传送点列表（`warps` 字段）为 `list<string>`；在线玩家列表（`onlinePlayers` 字段）排除自己，供 TPA 选择目标。

管理员面板的玩家列表页提供 `teleport_to` / `teleport_here` 操作，均通过 `delayedTeleport` 走预热流程；传送点页提供 `set_warp` / `del_warp`；世界页提供 `set_spawn`。
