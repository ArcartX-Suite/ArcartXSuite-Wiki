---
title: "多界面配置"
description: "按模块实际支持的界面字段配置多个 UI，区分 ID 列表、Tab 目标列表与自定义文件覆盖。"
---

部分模块支持将同一功能显示到多个界面，但并非所有 `ui-id` 都能由字符串改成列表。先确认目标模块读取的字段，再选择下表中的结构。

## 支持字符串或列表的字段

以下路径均在对应模块数据目录中，主配置文件使用实际文件名：

| 模块 | 文件 | 支持的字段 |
| --- | --- | --- |
| Announcer 公告 | `config.yml` | `ui.ui-id`、`ui.subtitle-ui-id` |
| Conversation 对话 | `config.yml` | `ui.dialog-ui-id`、`ui.selector-ui-id`、`ui.letterbox-ui-id` |
| EntityTracker 目标面板 | `config.yml` | `ui.boss-ui-id`、`ui.target-ui-id` |
| QuestGPS 任务导航 | `config.yml` | `ui.menu-ui-id`、`ui.guide-ui-id` |
| OnlineRewards 在线奖励 | `config.yml` | `ui.ui-id` |
| Announcer 字幕组 | `subtitle/groups/*.yml` | 每个字幕组自己的 `ui-id`，未指定时使用模块默认字幕界面 |

公告主配置示例：

```yaml
ui:
  ui-id:
    - "AXS:announcer_hud"
    - "AXS:announcer_hud_alt"
```

它表示同一份公告内容用于两个已有界面，不会为它们自动生成不同文案。添加第二个 ID 前，应先准备对应的界面配置和资源，并核对各自需要的数据。

## Tab 使用目标列表

Tab 的 `tabs/*.yml` 使用 `ui-targets`，每项包含一个界面 ID 与匹配的处理名称：

```yaml
ui-targets:
  - ui-id: "tab"
    packet-handler: "tab"
  - ui-id: "tab-arena"
    packet-handler: "arena"
```

这里每项的 `ui-id` 是字符串。不要把它写成 ID 列表，也不要省略 `packet-handler`，多个目标使用上述列表结构。

## 界面文件、自动注册与覆盖

界面 ID、界面文件和界面内容是不同概念。仅填写一个新 ID，不会自动设计布局、生成贴图或让旧界面理解新数据。

支持 `register-ui-on-enable` 的模块用它控制启动或重载时的界面注册；支持 `overwrite-ui-files` 的模块用它控制默认界面文件的覆盖。准确字段位置按模块配置页查看，不要将这些字段复制到所有模块。

自定义界面前备份已编辑的文件，再确定是否允许默认文件覆盖。更改后重载对应模块，先验证单界面，再测试多个界面共同显示与关闭，防止重复覆盖、数据不匹配或界面残留。

## 常见错误

| 现象 | 检查 |
| --- | --- |
| 改成列表后无效 | 该字段是否在支持列表的清单内，是否误用了 Tab 单目标字段 |
| 新界面没有出现 | ID、实际文件、注册日志与客户端资源是否齐全 |
| 同时显示两份内容 | 当前功能确实启用了多个界面；检查是否需要只保留一个 ID |
| 自定义布局重载后恢复默认 | 核对对应模块的覆盖开关与实际被注册的文件 |
| 界面打开但数据为空 | 目标界面需要的内容格式是否与该功能提供的数据匹配 |
