---
title: "货币系统"
description: "配置全局货币，连接经济插件，并在商品或奖励中引用货币 ID。"
---

Suite 内置统一货币桥接层，所有涉及经济的模块（Warehouse、Mail、Map、Market、OnlineRewards 等）共享同一组货币定义。你只需在 `config.yml` 顶部的 `currencies` 节配置一次，全局生效。

## 基本结构

```yaml
currencies:
  <货币ID>:
    enabled: true
    provider: "<提供者类型>"
    display-name: "显示名称"
    scale: 2
    rounding: "DOWN"
    # 以下三项仅 command / placeholder-command / custom 类型需要
    balance-placeholder: ""
    withdraw-command: ""
    deposit-command: ""
```

### 通用字段说明

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | boolean | `true` | 设为 false 则跳过该货币 |
| `provider` | string | `"vault"` | 提供者类型 |
| `display-name` | string | 货币 ID | 显示给玩家的名称 |
| `scale` | int | `2` | 小数精度位数。0 = 整数，2 = 保留两位小数 |
| `rounding` | string | `DOWN` | 舍入策略，支持 HALF_UP 等标准 RoundingMode 名称 |
| `balance-placeholder` | string | — | PAPI 占位符，返回纯数字余额（command 类型必填） |
| `withdraw-command` | string | — | 扣款时执行的控制台命令（command 类型必填） |
| `deposit-command` | string | — | 入账时执行的控制台命令（command 类型必填） |

## 支持的 Provider 类型

| Provider | 前置插件 | 适用场景 |
|----------|----------|----------|
| `vault` | Vault + 经济插件 | 最通用，适配 CMI / EssentialsX 等 Vault 经济 |
| `playerpoints` | PlayerPoints | 整数点券系统 |
| `xconomy` | XConomy | 直连 XConomy 原生 API |
| `rondo` | Rondo | ArcartX 生态多货币插件 |
| `command` | PlaceholderAPI | 通过控制台命令 + PAPI 占位符桥接任意经济 |
| `placeholder-command` | PlaceholderAPI | 同 command，别名 |
| `custom` | PlaceholderAPI | 同 command，别名 |

> `command`、`placeholder-command`、`custom` 三个名称完全等价，配置时任选其一。

### vault — Vault 经济

需要服务端安装 Vault 插件以及至少一个注册了 Vault Economy 服务的经济插件。

```yaml
currencies:
  money:
    enabled: true
    provider: "vault"
    display-name: "金币"
    scale: 2
    rounding: "DOWN"
```

Suite 的 `vault` 类型读取 Vault 当前选中的经济服务。需要多种独立余额时，可使用支持多货币的 Rondo，或分别配置能操作不同余额的命令。

### playerpoints — PlayerPoints 点券

适用于基于整数点数的经济系统。建议设置 `scale: 0`。

```yaml
currencies:
  points:
    enabled: true
    provider: "playerpoints"
    display-name: "点券"
    scale: 0
    rounding: "DOWN"
```

### xconomy — XConomy 原生经济

直连 XConomy，不经过 Vault。

```yaml
currencies:
  money:
    enabled: true
    provider: "xconomy"
    display-name: "金币"
    scale: 2
    rounding: "DOWN"
```

### rondo — Rondo 多货币

Rondo 原生支持多种货币 ID，需要在 Suite 与 Rondo 两边使用相同的货币 ID。

```yaml
currencies:
  money:
    enabled: true
    provider: "rondo"
    display-name: "金币"
    scale: 2
    rounding: "DOWN"
  points:
    enabled: true
    provider: "rondo"
    display-name: "点券"
    scale: 0
    rounding: "DOWN"
```

> Suite 中的货币 ID（即 `currencies:` 下的键名）会直接作为 Rondo 的 `currencyId` 参数传递，请确保两边 ID 完全一致。

### command — 命令桥接

命令式货币通过 PlaceholderAPI 读取余额，用控制台命令扣款或入账。Suite 根据命令的返回值判断操作结果。若目标插件接收了命令，却因余额限制或其他规则拒绝变更，Suite 仍可能报告成功。验收时直接查询经济插件里的余额。

下例使用 Vault 和 EssentialsX。先在测试服安装 PlaceholderAPI，按 [PlaceholderAPI 命令文档](https://wiki.placeholderapi.com/users/commands/)安装 Vault 扩展并重载。用已进服的测试玩家确认 `/papi parse me %vault_eco_balance%` 返回数值。

```yaml
currencies:
  money_command_test:
    enabled: true
    provider: "command"
    display-name: "命令测试金币"
    scale: 2
    rounding: "DOWN"
    balance-placeholder: "%vault_eco_balance%"
    withdraw-command: "essentials:eco take {player} {amount}"
    deposit-command: "essentials:eco give {player} {amount}"
```

`balance-placeholder`、`withdraw-command`、`deposit-command` 三项必须全部填写，否则该货币桥接将标记为不可用。

#### 命令模板变量

| 变量 | 替换为 | 示例 |
|------|--------|------|
| `{player}` | 玩家名 | `Steve` |
| `{uuid}` | 玩家 UUID | `069a79f4-...` |
| `{amount}` | 操作金额（经过精度处理） | `100`、`99.5` |

命令不需要加 `/` 前缀（加了也会自动去除），以控制台身份执行。

#### 验证命令桥接

1. 测试玩家进服后，用 `essentials:eco set WikiTester 100` 在控制台设置余额。用实际测试玩家名替换 `WikiTester`。
2. 在控制台执行 `essentials:eco take WikiTester 5` 和 `essentials:eco give WikiTester 5`。每条命令后运行 `essentials:balance WikiTester`，应依次读到 95、100。PAPI 的查询值也应一致。
3. 将上面的定义合并到本体 `config.yml` 后执行 `/axs reload all`。将[商店与回收示例](/docs/market/shops#先跑通一次购买和回收)中两个文件的 `currency` 都设为 `money_command_test`，用同一玩家实际买、回收一个苹果。读回余额应依次为 90、92。
4. 使用余额只有 5 的测试玩家尝试购买。确认余额和苹果数量都没有变化。若界面、流水和实际余额不一致，以经济插件的读回结果排查命令、账户和余额限制。

此示例和 `vault` 类型读取同一个 Vault 余额。用于正常交易时可直接使用 `vault`。 [EssentialsX 命令定义](https://github.com/EssentialsX/Essentials/blob/2.x/Essentials/src/main/resources/plugin.yml)

## 完整配置示例

```yaml
currencies:
  # 主货币 — Vault
  money:
    enabled: true
    provider: "vault"
    display-name: "金币"
    scale: 2
    rounding: "DOWN"
  # 点券 — PlayerPoints
  points:
    enabled: true
    provider: "playerpoints"
    display-name: "点券"
    scale: 0
    rounding: "DOWN"
```

## 模块局部货币

部分模块（如 Warehouse、Map、Market）在自身配置中也支持 `currencies` 节。模块中定义的货币会合并到全局池中，但不覆盖已有的同名货币。全局 `config.yml` 中的货币定义优先。

## 货币变动事件

Suite 在货币提供者报告操作成功时发布对应事件。

| 事件主题 | 触发时机 |
|---------|---------|
| `axs.currency.spent` | 提供者报告扣款成功时 |
| `axs.currency.earned` | 提供者报告入账成功时 |

Payload 字段：

| 字段 | 说明 |
|------|------|
| `currency_id` | 货币 ID |
| `amount` | 此次请求的金额 |
| `action` | `"withdraw"` 或 `"deposit"` |
| `balance_after` | 调用结束后尝试读取的余额，读取异常时可能返回 `0` |

模块可通过 `event-topic` 订阅这些事件。`command` 类型的事件只表明命令报告成功，统计实际消费或人工核账时应另查余额。

## 状态检查

使用 `/axs status` 命令可以查看当前已注册的货币数量：

```
ArcartXSuite 状态:
 - 货币桥接: 已注册 2 种货币
```

此处显示注册数量。各货币是否能实际扣款和入账，要用对应经济插件查询余额并进行小额交易。

## 故障排除

| 现象 | 排查方向 |
| --- | --- |
| 货币不可用，提示"桥接不可用" | 确认前置插件已安装、provider 拼写正确 |
| Vault 提示未注册 | 安装一个 Vault 经济插件（如 CMI、EssentialsX） |
| PlayerPoints 余额始终为 0 | 将 `scale` 设为 `0`（整数点数） |
| command 类型提示成功但余额无变化 | 用同一测试玩家在控制台执行实际命令，检查经济插件的响应及前后余额 |
| `balance-placeholder` 返回非数字 | 确保占位符返回纯数字，不含货币符号 |
