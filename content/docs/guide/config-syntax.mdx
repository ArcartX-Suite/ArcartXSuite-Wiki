第一次编辑配置，不必先学会所有 YAML 语法。先认清文件位置、字段层级和值的类型，再从一个可以验证的小改动开始。

## 先看示例写在哪个位置

配置页中的“字段路径”用点号描述层级。例如 `scanner.keybind.name` 应写成：

```yaml
scanner:
  keybind:
    name: AXS_PICKUP_PICK
```

不是在文件末尾新增一行 `scanner.keybind.name: ...`。一般每层缩进两个空格，同级字段保持对齐，不使用 Tab。同名小节已经存在时，在原小节修改，不要再写第二份 `scanner:`。

**只有标明完整文件的示例才可作为整份文件使用。** 标注“在已有条目中增加”“字段片段”的例子，应放回指定条目，不能覆盖整份配置。模块自己的主配置也不能写进本体 `config.yml`。

## 看懂字段类型

| 类型 | 写法示例 | 注意 |
| --- | --- | --- |
| 开关 | `enabled: true` | 使用 `true` 或 `false`，不是中文“开”“关” |
| 整数 | `amount: 8` | 不写单位；需要整数时不要写 `8个` |
| 小数 | `exp-multiplier: 1.1` | 使用英文小数点，不写成 `1,1` |
| 文本 | `name: "欢迎礼包"` | 含冒号、颜色符号等内容时加引号 |
| 文本列表 | 下方的 `material-ids` 示例 | 每项前加短横线 |
| 键值映射 | 下方的 `nbt-values` 示例 | 每项是“名称: 值”，前面不加短横线 |

### 列表与映射不要混用

```yaml
match:
  # 列表：这里允许两种材质，任选一种
  material-ids:
    - fishing_rod
    - stick
  # 映射：标签 rod_id 必须具有这个值
  nbt-values:
    "rod_id": "jade_rod"
```

这里先要求物品材质是鱼竿或木棍，再要求它带有指定标签值；不是四个名称任选一个。完整匹配规则见[物品匹配与消耗](/docs/guide/item-matching)。

列表也可写成 `[fishing_rod, stick]`。不熟悉时优先使用多行写法，便于增加和删除条目。

## 引号、注释和空值

- `#` 后通常是注释，不参与配置。文本中要显示 `#`、`&` 等字符时用引号包住。
- `[]` 是空列表，`{}` 是空映射，`""` 是空文本，含义不同，按字段要求选择。
- 仅写 `enabled:` 不等于明确关闭；需要关闭就填写 `false`。
- `# - welcome_demo` 是被注释掉的示例，不会参与派发；要启用需去掉该行前的 `#`，并保持缩进。

多行正文可以写成：

```yaml
body: |-
  欢迎来到服务器。
  请打开邮件领取附件。
```

这是需要文本字段支持的 YAML 多行写法，不要在表格单元格中照抄整个正文。

## ID、显示名称和占位符不同

| 你看到的内容 | 应怎样填写 |
| --- | --- |
| 预设 ID `welcome_demo` | 填引用该预设的实际 ID，不填它的显示名称“欢迎礼包” |
| `<模块ID>`、`<玩家名>` | 命令模板说明，需要换成实际值，不保留尖括号 |
| `%axsfishing_level%` | PAPI 变量，两侧 `%` 是写法的一部分，支持 PAPI 的位置才会解析 |
| `{player}`、`{uuid}`、`{amount}` | Suite 命令变量，保留花括号。可用变量请查对应字段说明 |
| `"myitems:rod_id"` | 示例标签名，必须先确认真实物品存在该数据再使用 |

提示和路标标题也可能提供花括号变量，例如道具名 `{item}`、剩余秒数 `{remaining_seconds}`。消息中的 `{0}` 表示第一个传入值。以对应字段的说明为准。

创建定义时用简短、稳定且不重复的 ID。引用时按定义原值填写；文件名、文件内 ID 与中文名称是否必须相同，由具体模块决定，不能一概而论。

## 单位与大小写必须按字段

`Duration: 30` 在 Prop 中表示 30 秒，字段名的大写 `D` 要保留；`refresh-interval-ticks: 60` 表示 60 tick，正常 20 TPS 下约 3 秒；`5000` 毫秒为 5 秒。

只有接受时长字符串的字段才可填 `5m`、`7d` 等值，数字字段不能擅自加单位。ID 或字段名也不要因为看起来相似就改大小写或连字符，例如 `default-key` 与 `defaultKey` 属于不同配置位置。

## 正则与标签从哪里开始

只想检查一段固定文字，用 `name-contains` 或 `lore-contains` 即可。需要“完整名称相同”“数字模式”等规则时，再读[正则写法](/docs/guide/item-matching#正则表达式怎样写)。

NBT/PDC 需要先取得物品真实键名和值，再写[标签匹配](/docs/guide/item-matching#nbtpdc-标签从哪里获取)。不要把示例数据误认为 Suite 会自动给所有物品添加的字段。

## 修改后怎样检查

1. 先备份目标文件，只改一个字段或一组相关设置。
2. 保存为 UTF-8，检查缩进与引号。
3. 按模块文档重载；本体设置参考[生效方式](/docs/guide/first-run#保存后怎样生效)。
4. 查看是否有读取失败、未知字段相关诊断或无效表达式提示。
5. 用一个应当成功、一个应当失败的例子分别测试。没有报错不代表字段一定被识别。

读取错误时先恢复备份，按[日志与报错提示](/docs/guide/config-management)定位文件和字段，不要通过删除玩家数据来修复语法问题。
