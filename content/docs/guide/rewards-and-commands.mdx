奖励的字段和触发条件见各模块的功能配置。本页用于处理已经触发奖励、玩家却没有看到到账结果的情况。

## 先确认奖励发到了哪里

| 现象 | 检查方法 |
| --- | --- |
| 背包有空间，仍未获得物品 | 核对奖励条件、物品来源、ID 和数量，再看对应模块日志 |
| 背包满了 | 对使用统一物品发放的功能，检查仓库、邮箱、待补发提示和玩家附近的掉落物，具体去向取决于该功能和可用模块 |
| 邮件到了，附件领不了 | Mail 会检查背包是否能容纳整封邮件的物品附件。腾出空间后重新领取 |
| 玩家离线时触发奖励 | 查看对应模块的结算或待交付记录，确认确实已暂存，再检查玩家上线后的结果 |
| 命令已触发，实际奖励未到账 | 检查变量展开、执行身份，以及目标插件返回的结果 |

重试前先核对已经交付的数量。邮件发送、领取附件和命令发放应分别验证，避免重复补奖。

## 命令里的玩家名

在支持玩家名替换的命令字段中写 `{player}`。它在奖励命令中指奖励接收者，在邮件领取命令中指领取人，在事件动作中默认指触发者，在公告点击命令中指点击者。

```text
tell {player} 你的奖励已发放
```

EventPacket 若给规则显式传入了名为 `player` 的上下文变量，会优先使用该值。需要明确引用事件主体时，可以继续用 `{player_name}`。

如果游戏里收到的命令仍含变量原文，先核对该字段支持的变量。手动验证时，把 `{player}` 换成测试玩家名，再以配置指定的身份执行。三类写法见[配置写法](/docs/guide/config-syntax#id显示名称和占位符不同)。

命令配置和执行身份分别见[在线奖励](/docs/onlinerewards)、[邮件预设](/docs/mail/presets)及[事件动作](/docs/eventpacket/actions)。
