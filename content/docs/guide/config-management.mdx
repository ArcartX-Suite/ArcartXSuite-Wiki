遇到问题时，先在服务端控制台或 `logs/latest.log` 中找到出问题时间附近的 AXS 提示。本页列出常见日志中的关键文字；模块名、文件路径和错误详情会随实际情况变化，不必逐字匹配整行。

主配置各字段的功能与生效方式见[本体安装与配置](/docs/guide/first-run)。本页用于判断日志所说明的问题，再决定应该修改什么或补充什么信息。

## 先看哪一条日志

1. 找到首次发生异常的时间，保留错误前后相关日志。
2. 从最早的错误开始读，不要只看最后一行“失败模块”。后续报错可能由前面的依赖或连接失败引起。
3. Java 异常若包含 `Caused by:`，继续看后面的具体原因；只有异常名称或堆栈末尾几行通常不够定位。
4. 用 `/axs status` 对照当前状态，区分整个 Suite 未启动、某个模块未加载，以及单项功能不可用。

| 级别或文字 | 怎样理解 |
| --- | --- |
| `INFO` | 状态与操作结果，不等于报错；但内容也可能是诊断摘要，需要继续阅读 |
| `WARN` / `WARNING` | 某项能力不可用、设置被跳过或外部服务异常，不一定影响全部模块 |
| `ERROR` / `SEVERE` | 初始化、加载或操作失败，结合紧随其后的具体原因处理 |
| “已跳过”“未启用” | 该功能没有运行；如果是主动关闭，可能符合预期 |
| “保留现有”“已回滚旧版本” | 本次操作未完成，日志说明保留或恢复了旧状态，仍需检查实际功能 |

## Suite 启动与模块加载

### ArcartX 桥接初始化失败，已禁用插件

**含义：** Suite 所需的 ArcartX 连接未正常建立，本次 Suite 启动已终止。

**处理：** 先查看这条提示之前的 ArcartX 错误，确认服务端已安装并成功启用匹配版本的 ArcartX，再核对 Suite、服务端和客户端的版本组合。调整依赖后完整重启，不要仅重载某个 Suite 模块。

### 检测到模块……但未启用

**含义：** 找到了模块，但主配置的启用开关未打开。这本身不代表模块文件损坏。

**处理：** 如果有意关闭则无需处理；需要使用时检查 `config.yml` 的 `modules.<模块ID>.enabled`，修改后重启，并用 `/axs status` 核对。实际数据目录以服务器生成的 `plugins/ArcartX-Suite/` 为准。

### 模块需要……插件，已跳过加载

**含义：** 该模块缺少必要的前置插件。

**处理：** 按日志中的插件名称安装对应前置，核对兼容版本后重启。安装了同类插件，不代表能替代日志指定的前置。

### 依赖的外部插件……已安装但未启用

**含义：** 前置插件文件存在，但它自身启动失败或处于禁用状态。

**处理：** 向前查找该插件自己的启动错误。先修复前置，再检查 Suite；重复加载 Suite 不能让失败的前置自动恢复。

### 模块依赖……未就绪，已跳过加载

**含义：** 需要的另一个 Suite 模块尚未正常启用。

**处理：** 检查日志所指模块的装备状态、开关、前置和启动错误，先解决依赖模块的问题，再重启检查。

### 模块未加载或未启用，无法重载

**含义：** 对一个没有正常运行的模块执行了重载命令。

**处理：** 用 `/axs status` 检查 ID 和状态，再查看启动或同步时的日志。重载现有模块不能代替首次装备、启用和成功加载。

### 模块 id 冲突

**含义：** 同一模块 ID 出现重复来源，插件无法按预期区分。

**处理：** 核对近期手动放入的模块文件和旧版本，备份后移走已确认重复的文件。不要同时保留多个版本试图解决兼容问题；无法判断来源时保留日志并联系维护者。

### 失败模块：……

**含义：** 启动结果的汇总，不是具体失败原因。

**处理：** 在此前日志中搜索对应模块名称，定位第一条失败提示及异常详情。不要只凭这一行重新安装全部插件。

## 云端绑定与模块同步

### 未配置 cloud.qq / cloud.apiKey，无法绑定服务器

**含义：** 缺少云端账号信息，无法完成首次绑定。

**处理：** 按[主配置说明](/docs/guide/first-run#云端账号与服务器绑定)填写注册账号 QQ 与后台验证密匙，确认保存的是当前服务器使用的 `config.yml`，然后重启检查。

### 服务器尚未绑定，无法同步

**含义：** 当前还没有成功完成服务器绑定。

**处理：** 向前查看绑定失败的原因，核对账号信息和服务器访问云端的网络。不要随意填写或复制其他服务器的 `server-code`。

### 服务器绑定暂时失败 / 下载……暂时不可达

**含义：** 本次连接暂时没有成功，可能是网络或云端服务状态问题；具体以同一行的状态码和文字为准。

**处理：** 检查服务端机器的网络和云端运行状态，恢复后再执行 `/axs sync`。不要因为一次暂时失败就清空服务器码或删除已有模块和玩家数据。

### 服务器绑定失败 / 下载……被拒绝

**含义：** 云端未接受本次请求。不能只凭“失败”二字认定原因。

**处理：** 阅读后面的状态码和返回说明，核对账号、验证密匙以及当前服务器的模块装备状态。持续出现时提供完整返回提示和时间，交由维护者确认。

### 未能绑定服务器（暂时故障），保留现有云模块

或“刷新模块令牌暂时失败，保留现有云模块”。

**含义：** 这次同步没有完成，日志说明现有模块被保留；它不表示已经更新成功。

**处理：** 先用 `/axs status` 和实际操作确认当前功能，待连接恢复后同步。无需为了清除此警告而删除现有文件。

### 模块……不在云端授权列表中，无法通过云端更新

**含义：** 当前服务器没有获得该模块的云端更新资格。

**处理：** 检查登录的云端账号、选中的服务器与装备列表，再同步。只修改本地模块开关不能解决此提示。

### 模块……加载失败：可能缺少依赖或该模块已在 config.yml 中关闭

**含义：** 模块同步后没有成功启用；提示列出的是待检查方向，不是已经确定的唯一原因。

**处理：** 同时检查本地开关、前置插件及这条汇总之前的模块加载错误。

### 模块……更新失败，已回滚旧版本

**含义：** 新版本没有正常运行，已尝试恢复旧版本。

**处理：** 用 `/axs status` 和实际功能检查旧版本是否恢复，保留新版本加载失败的完整日志。如果出现“更新失败且旧版本回滚失败”，应停止反复更新，先恢复可用的配套版本或联系维护者。

## 配置读取与诊断

### 配置诊断：……ERROR / ……WARN / ……INFO

**含义：** 这是配置检查的统计，不是所有问题的详细列表。诊断中的严重级别与该行日志自身的 `INFO` 级别不是一回事。

**处理：** 执行 `/axs config diagnose` 查看详细报告，关注文件、字段路径、当前值和具体问题。先理解报告，再决定是否修改；不要看到有提示就直接应用全部建议。

### InvalidConfigurationException / YAML 解析错误

**含义：** YAML 语法无法读取。这类异常可能由服务端配置读取过程输出，文字与行列号会有所不同。

**处理：** 找到异常指向的文件和位置，检查空格缩进、引号、冒号、列表写法与重复小节。错误实际原因也可能在提示行的上一行。恢复最近一次备份后再逐项修改，比反复覆盖整个配置更容易定位。

### 写入诊断……失败

例如“写入诊断 markdown 失败”或“写入诊断 summary 失败”。

**含义：** 诊断报告没有成功保存，不一定代表模块本身无法运行。

**处理：** 检查日志给出的目标路径、磁盘剩余空间，以及服务器进程是否能写入该目录。修复后重新生成报告。

## 数据库与数据目录

### 统一数据源初始化失败 / AXS 全局 MySQL 连接池初始化失败

**含义：** 主配置指定的数据库未能正常连接，依赖数据存储的功能可能无法使用。

**处理：** 阅读随后的原始异常，核对数据库地址、端口、库名、账号与密码，并从服务端机器检查数据库是否可达。修改存储连接后重启。已有数据时不要为消除错误直接切换数据库或新建空库代替原库。

### MySQL 配置缺失……host 为空 / database 为空

**含义：** 已选择 MySQL，但连接字段缺失。

**处理：** 按错误指出的位置检查全局或模块已有的存储配置，填写实际地址和库名。不要以为全局填写了连接信息，独立的模块存储配置就一定正确。

### AXS 全局 MySQL 数据源不可用

**含义：** 当前无法取得可用数据库连接，往往是前面连接初始化失败的后续表现。

**处理：** 先修复最早的数据库错误。暂停依赖该数据的交易或奖励验收，恢复后读回已有记录，再确认业务正常。

### 无法创建 SQLite 数据目录 / SQLite 数据源初始化失败

**含义：** 本地目录创建或数据库打开失败。

**处理：** 检查具体路径、磁盘空间、写入权限以及文件是否被其他服务端实例占用。保留原数据库，不能用删除数据库作为通用修复方式。

## 按键、占位符与功能依赖

| 日志关键文字 | 含义 | 处理方法 |
| --- | --- | --- |
| `[Keybind] 跳过无效按键配置` | 按键缺少名称或默认键位 | 检查对应 `keybinds` 条目的 `name` 和 `default-key`，保存后重载主配置 |
| `[Keybind] 注册客户端按键失败` | 按键没有成功注册 | 检查 ArcartX 状态、按键名称与版本兼容性，重新连接客户端验证 |
| `PlaceholderAPI 扩展注册失败` | 对应变量没有成功提供 | 确认 PAPI 与模块正常启用，检查重复扩展或版本问题，再用 `/papi parse` 测试 |
| `[MythicLib] 桥接初始化失败` 等属性插件提示 | Suite 无法使用该属性来源 | 先确认该插件自身启动成功，再核对版本与主配置属性开关 |
| `初始化 MMOItems 物品桥接失败` 等物品插件提示 | 对应来源的物品无法正常获取 | 核对物品插件状态、版本及后续异常；使用其他来源的功能不一定受影响 |
| `[CrossServer] Redis 初始化失败` | 跨服连接未建立 | 检查地址、端口、密码及服务状态；先确认单服功能正常 |
| `[CrossServer] Redis 订阅中断，3 秒后重试` | 已建立的跨服连接中断，插件正在重试 | 观察是否恢复，持续出现时检查网络与 Redis，不要把反复重试当作正常互通 |
| `拉取云端敏感词库失败` | 远程词库本次未更新 | 检查地址、返回格式与网络；本地过滤和其他云端功能需分别判断 |
| `moderation.blocked-patterns 正则非法，已跳过` | 某条过滤表达式无效，已被跳过 | 修正对应表达式后重载，再测试正常文本与命中结果 |

可选依赖未安装时，不一定需要安装全部插件。先判断自己是否使用对应属性或物品来源，再决定处理范围。

## 界面与展示模块日志

下面覆盖文档中的 30 个业务模块。列出的都是日志关键片段，省略会变化的文件名、玩家名和具体异常；它们不是该模块全部可能出现的日志。通用的依赖、数据库、YAML 错误仍按前文处理。

### 渐变文本（rgb）

- **“未加载任何 RGB 条目”**：条目目录为空或不存在，没有可渲染的内容。按[渐变配置](/docs/rgb/configuration)检查实际目录和启用条目，再重载。
- **“gradient-colors 含有无效颜色”“检测到递归 PAPI 引用”**：检查颜色格式，以及条目是否通过占位符再次引用自身。消除循环引用后，用 `/papi parse` 单独测试。

### 拾取提示（pickup）

- **“待推送拾取队列超过……丢弃最旧条目”**：待显示通知积压，日志指向客户端未正常显示或连接残留的可能性。检查玩家连接、ArcartX 与拾取界面，重新进入服务器后用少量掉落物验证。该日志描述通知队列，不应直接据此判断物品已丢失；核对实际物品栏。
- 对照[拾取提示配置](/docs/pickup/configuration)，区分自动通知与主动扫描模式，避免用错误入口测试。

### 公告与字幕（announcer）

- **“entries 目录为空或不存在，未加载任何公告条目”**：没有加载到轮播内容。检查条目目录、YAML 文件及条目启用状态，重载后查看活跃公告数。
- **“字幕组目录不存在”“加载字幕组失败”**：字幕文件路径或格式有问题。先用字幕组列表确认目标 ID，再按[公告与字幕](/docs/announcer)检查对应文件。

### 登录界面（loginview）

- **“宿主认证运行时未就绪”**。核对宿主 `authentication.yml` 的后端与入口，以及节点和中心是否可达。修改认证配置后重启宿主。[认证与界面配置](/docs/loginview/configuration)
- **“认证存储初始化失败”**。核对宿主存储配置及数据库可用性。中心模式下核对中心进程、节点密钥和连接地址，再用测试账号复核准入。[独立认证中心](/docs/loginview/center)

### 物品提示（tooltip）

- **“Tooltip 模块已启动，等待客户端 mod 发送 tooltip 数据”**是正常启动信息，不是报错。客户端没有安装扩展，或尚未产生可采集内容时，不会凭空出现提示数据。
- 界面不可用时先查[客户端安装要求](/docs/tooltip/client-mod)，再用[模块命令](/docs/tooltip/commands)检查缓存与显示模式。不要仅凭服务端模块启动成功认定客户端扩展也正常。

### 功能菜单（menu）

- **“Menu 配置解析失败”“Menu 定义无效”**：按文件名和文档序号找到出错定义，检查 YAML 与必需字段。一个文件可能包含多个菜单定义。
- **“Menu ID 重复，后者覆盖前者”“引用的自定义 UI 文件不存在”**：分别检查重复 ID 和自定义界面路径。若修改后仍显示旧菜单，先排除另一份同名定义覆盖。详见[菜单配置](/docs/menu/configuration)。

### 在线列表（tab）

- **“未加载任何 Tab 定义”“加载 Tab 定义文件失败”**：检查列表定义目录、文件格式与启用状态。
- **“ui-targets……不是字典”“sort-keys……不是字典”**：列表元素的结构不正确，相关项被跳过。按[在线列表配置](/docs/tab/configuration)恢复为键值结构，重载后检查显示和排序。

### 原版界面替换（vanilla）

- **“无法解析物品材料 id……按 AIR 处理”**：当前服务端无法识别该物品材料，显示结果可能为空。核对材质名和版本；模组物品还需对应服务端环境，不能直接把显示名称当材料 ID。详见[原版界面配置](/docs/vanilla/configuration)。

## 成长与奖励模块日志

### 在线奖励与签到（onlinerewards）

- **“时刻奖励调度失败”**：某个定时奖励没有正常安排，按奖励 ID 检查时间配置和后续异常。
- **“物品奖励生成失败”“物品奖励发放异常”**：先核对物品来源插件、物品 ID 与数量，再核对实际到账。重新触发奖励前确认是否已有部分发放。详见[在线奖励配置](/docs/onlinerewards/configuration)。

### 挂机奖励（afkreward）

- **“加载区域文件失败”“未配置 world，已跳过”**：区域文件未成功读取或缺少世界名，玩家进入该位置也不会使用这条区域定义。
- **“区域名称重复”**：检查多个区域文件中的名称和 ID，避免命令或显示对应到非预期区域。按[挂机区域](/docs/afkreward/afk-areas)修正，重新进入区域验证计时与奖励。

### 称号（title）

- **“引用了不存在的分组”“引用了不存在的品质”**：该称号已被跳过，先补齐或修正分组、品质 ID，再测试发放和装备。
- **“套装……没有有效的 required-titles”“引用了不存在的称号”**：套装条件引用无效。检查实际加载的称号 ID，不能用中文显示名称替代。详见[称号配置](/docs/title/configuration)。

### 抽奖与开箱（lottery）

- **“加载奖池文件失败”“奖池 ID 重复，已覆盖”**：检查日志指定文件和重复 ID，确认正在测试的是预期奖池。
- **“CASE 稀有度……没有奖品，已从抽取表移除”**：该档位没有有效奖品，实际抽取范围已变化。按[抽奖配置](/docs/lottery/configuration)补齐奖品，验证概率与保底后再开放抽取。

### 战令（battlepass）

- **“event_payload 条件无效”“regex 编译失败”“数值配置非法”**：某个任务的事件条件无法使用。按任务 ID 检查字段类型、比较值和表达式。
- 修复后按[战令任务](/docs/battlepass/tasks)实际触发一次对应事件，检查进度变化；只看到任务出现在界面中，不代表计数条件有效。

## 玩法与交互模块日志

### 战斗特效（combateffect）

- **“ChronosHook 初始化失败”“ChronosHook 延迟加载失败”**：与 Chronos 相关的联动未建立。先判断是否使用此联动，再核对 Chronos 自身状态与兼容版本；不能据此认定所有伤害显示都不可用。
- **“ChronosHook combo 事件处理失败”**：连击联动操作异常，保留同一时间的具体异常，用[战斗特效配置](/docs/combateffect/configuration)中的简单场景复测。

### 事件与动作（eventpacket）

- **“加载规则文件失败”“规则动作缺少 type，已跳过”**：规则或动作没有加载。检查文件名、规则 ID 与动作列表中的 `type`。
- **“规则动作类型未知，已跳过”“Chemdah 桥接初始化失败”**：分别核对[动作类型](/docs/eventpacket/actions)拼写和 Chemdah 状态。没有错误日志也不代表动作一定执行：缺少目标模块、玩家不在线或参数为空时，相关动作也可能不生效。

### 快捷道具（prop）

- **“未填写 coolDownGroup，已回退为 默认冷却组”**：道具仍可能可用，但会使用默认冷却分组。按预期冷却关系填写，避免多个道具共用冷却。
- **“自动触发条件格式无效”“MythicLib 属性未注册”“未知效果类型”**：条件或效果被跳过。核对[道具配置](/docs/prop/configuration)写法、属性名称与提供插件。

### NPC 对话（conversation）

- **“查找 NPC 失败”**：核对目标 NPC ID、NPC 插件状态和是否位于对应场景。
- **“选择回复失败”“[Cinematic] 执行动作失败”“恢复玩家状态失败”**：分别检查回复条件与动作、过场动作参数，以及结束后的玩家状态。按[对话配置](/docs/conversation/configuration)缩小到单步复测，过场异常后应实际确认视角和移动状态已恢复。

### 任务导航（questgps）

- **“展示设置无效，使用原生内容”**：检查日志中的任务或目标 ID，对应 `addon.axs-view` 的字段、类型或坐标有问题，修正后重载 Chemdah。
- **“原生展示刷新失败，保留上一次完整结果”**：此次刷新没有完成；先检查同一时间的 Chemdah 加载错误，再重载并核对列表。
- **“展示组件 ID 已被其他插件注册”**：注册冲突，模块不会覆盖其他组件；检查是否有重复版本或使用相同组件名的附属插件。
- **“Chemdah Tracker API 不可用”**：原生动态目标不可用；明确配置的展示目的地仍可单独使用。按[任务导航配置](/docs/questgps/configuration)核对依赖和位置。

### 地图与传送锚点（map）

- **“锚点 id……重复定义”**：多个世界或文件使用同一锚点 ID，需改为明确且不冲突的 ID，并检查引用。
- **“配置了 unlock.on-permission 但未设置 permission”“顶点不足 3 个，跳过该区域”**：分别补齐权限字段或有效边界点。按[地图配置](/docs/map/configuration)重载后，以普通账号测试解锁和导航。

### 钓鱼（fishing）

- **“加载鱼种文件失败”“加载饵料文件失败”“加载钓竿文件失败”**：按路径检查对应定义，不要只重载主配置而忽略子目录。
- 选区时提示**“没有已闭合的选区”**不是服务器崩溃：先完成至少三个点并闭合，再保存水域。参阅[区域选择](/docs/guide/region-selection)与[钓鱼配置](/docs/fishing/configuration)，保存边界后仍需配置鱼池内容。

### 地牢副本（abyss）

- **“玩家数据加载失败，进本保持关闭”**：该玩家数据未正常读入，不能以反复进入副本来解决。先处理对应数据库或数据读取错误，再核对玩家记录。
- **“buff 池不存在”“体力保存失败”“通关记录保存失败”**：分别检查配置引用与数据写入。保存失败期间不要直接将界面结果视为持久化成功；恢复后重新查询。详见[副本配置](/docs/abyss/configuration)。

### Boss 与目标面板（entitytracker）

- **“写入 Boss 最高伤害失败”“合并跨服 Boss 数据失败”**：统计或跨服数据没有正常保存或合并。检查同一时间的数据库与跨服异常，恢复后核对排名，不能仅凭战斗面板认定结算记录已保存。
- **“手动发放……奖励失败”“打开发放历史界面失败”**：保留奖励类型、玩家及异常，核对发放历史与实际到账后再决定是否重试。配置与奖励规则见[Boss 追踪配置](/docs/entitytracker/configuration)。

## 管理与社交模块日志

### 基础工具（essentials）

- **“Essentials.setSpawn 写入 Multiverse 失败”“调用 Multiverse API 失败”**：出生点与 Multiverse 联动异常。检查 Multiverse 是否启用、世界是否存在及版本是否兼容。
- 保存出生点后重新查询并实际传送验证。不要只凭设置命令的执行就认定位置已保存。详见[基础工具配置](/docs/essentials/configuration)。

### 区域规则（regions）

- **“世界规则持久化失败”**：本次世界规则未正常保存，重启后可能不保留修改。检查数据存储错误，修复后重新读取验证。
- **“注册 Paper AsyncChatEvent 失败”**：区域相关聊天事件的兼容异常，结合服务端版本检查实际聊天规则；不表示所有建造规则均失效。详见[区域规则配置](/docs/regions/configuration)。

### QQ 群互联（qqbot）

- **“忽略无效 group-id”**：某条群配置未被使用，检查群号的数字格式和字段位置。
- **“Node.js 版本不满足要求”“进程意外退出”“端口……被占用”**：属于启用内置机器人运行环境时的提示。核对运行环境、退出前日志与端口占用者，不要任意结束不相关进程。详见[QQ 群互联配置](/docs/qqbot/configuration)。

### 聊天频道（chat）

- **“未加载到任何频道定义”“自定义组件……正则非法”**：频道缺失或组件被跳过，检查目录与表达式。
- **“注册 Paper AsyncChatEvent 监听失败，已回退到 Bukkit 旧聊天事件”**：当前使用备用聊天事件；需实际测试与其他聊天插件的兼容，不能只凭回退提示判断聊天完全不可用。详见[聊天配置](/docs/chat/configuration)。

## 经济与物品模块日志

### 邮箱（mail）

- **“dispatchPreset 发送失败”“sendMail 发送失败”**：预设派发或邮件发送未成功。核对[邮件派发](/docs/guide/mail-delivery)中的预设 ID、接收者及数据库状态。
- **“物品序列化失败”**：附件内容未能保存为邮件数据。保留物品来源和异常，先用原版物品小批量测试；重发前核对收件箱与已领取记录，避免重复发奖。

### 仓库与银行（warehouse）

- **“打开仓库失败”“外部自动入库失败”**：仓库读取或入库操作异常。先看存储错误，再核对玩家物品和仓库内容，不能直接重复存入。
- **“定期产品……没有有效利率阶梯”“排序方案……包含无效字段”**：相应定义被跳过，不代表整座仓库不可用。按[仓库配置](/docs/warehouse/configuration)检查产品与排序字段。

### 商店与拍卖（market）

- **“[Auction] 在线入账失败，转入待发放队列”**：本次直接入账未完成，需检查货币服务和后续补发，不能立即人工再入账。
- **“物品反序列化失败”“待发放物品反序列化失败，已丢弃”**：需要保留订单或记录 ID，核对物品来源与版本，联系维护者恢复；不要假定所有失败内容都还在队列中。详见[市场配置](/docs/market/configuration)。

### 额外背包（extrabackpack）

- **“扩展背包功能未启用……或分类为空”**：模块可能已加载，但具体背包功能未开启或没有分类。
- **“仓库访问能力不可用”“读取额外背包快照失败”“额外背包存入失败”**：检查仓库模块是否就绪以及存储异常，先核对实际物品数量再重试。详见[额外背包配置](/docs/vanilla/backpack)。

## 奖励异常与反馈信息

出现“待发放奖励多次补发失败，继续保留并重试”时，表示该奖励尚未确认补发成功。先检查同一时间的数据库、物品和邮件相关异常，保留日志中的记录 ID；不要同时手动重复发奖并反复执行结算，以免难以核对实际到账情况。

需要反馈时，提供以下信息：

- Suite、ArcartX、服务端及相关前置插件版本。
- 发生问题的时间、模块、操作步骤，以及是否每次都能复现。
- 第一条相关错误前后的日志，包含完整 `Caused by:` 部分。
- `/axs status` 结果，以及出错字段附近的配置片段。

配置片段中隐去账号密匙、数据库密码和玩家个人信息；保留字段名称、错误码与必要上下文。若多次尝试，分别记录每次修改及结果，方便判断问题是否变化。
