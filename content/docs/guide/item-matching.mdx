[物品来源](/docs/guide/item-sources)解决“生成什么物品”，本页解决“现有物品是否满足规则”。`source + id` 不能直接替代 `match` 或 `matcher`，匹配器本身也不会生成、赠送或扣除物品。

## 哪些模块使用这些规则

| 模块 | 配置入口 | 用途 |
| --- | --- | --- |
| Fishing | 鱼竿、鱼饵定义中的 `match` | 识别玩家手持鱼竿或使用的鱼饵 |
| Lottery | 物品费用的 `matcher`、箱子物品的 `case-item.matcher` | 识别支付物品或打开箱子的物品 |
| Map | 锚点解锁、传送物品费用中每项的 `match` | 判断背包里哪些物品可用于支付 |
| Market | `auction.blacklist`、`player-shop.blacklist` 等支持的规则 | 判断物品是否允许上架；具体回收规则另按回收配置 |
| Pickup | `filter` 内材质、名称、Lore、NBT 黑白名单小节 | 过滤扫描拾取对象；还需结合 `filter.mode` 与数量限制 |
| Warehouse | 主配置 `blacklist` | 判断物品是否允许入库 |

随身背包的仓库区使用 [Warehouse 分类规则](/docs/warehouse/categories)。Mail 附件检查使用 [邮箱配置](/docs/mail/configuration) 中的独立规则。

## 支持的匹配字段

以下字段写在目标模块要求的匹配小节内：

| 字段 | 判断内容 |
| --- | --- |
| `material-ids` | 原版材质 ID 列表 |
| `mythic-item-ids` | MythicMobs 物品 ID 列表 |
| `neige-item-ids` | NeigeItems 物品 ID 列表 |
| `overture-item-ids` | Overture 物品 ID 列表 |
| `kinds` | 物品种类标记 |
| `name-contains` / `lore-contains` | 名称或某行描述包含指定文字 |
| `name-regex` / `lore-regex` | 名称或描述符合正则表达式 |
| `nbt-keys` | 存在所列标签之一 |
| `nbt-values` | 所列标签与预期值对应，多个键值均需满足 |

名称、描述会按匹配规则去颜色并忽略大小写。不要自行添加并不存在的 `mmo-item-ids` 字段；需要识别 MMOItems 等物品时，先核对目标模块支持的标签或其他识别条件。

第一次填写这些字段，先看[配置写法入门](/docs/guide/config-syntax)。下面分别给出文字、正则和标签的写法；示例中的标签名称是假定数据，不会由配置自动写入物品。

## 名称与描述：先用包含匹配

只想识别固定文字时，不需要写正则：

```yaml
match:
  name-contains:
    - "青玉钓竿"
  lore-contains:
    - "限定水域专用"
```

表示名称包含“青玉钓竿”，并且至少一行描述包含“限定水域专用”。普通文字按原样填写，列表每项一行。这里的 `name-contains` 是子串匹配，所以“高级青玉钓竿”也会命中；必须完全相同的名称可使用下一节的正则。

## 正则表达式怎样写

`name-regex` 检查名称，`lore-regex` 分别检查每一行 Lore。每个字段的值是**字符串列表**，不是一个字典，也不需要在表达式两边加 `/`。

```yaml
match:
  name-regex:
    - '^青玉钓竿$'
  lore-regex:
    - '^钓鱼等级：[0-9]+$'
```

上例要求名称恰好为“青玉钓竿”，且某行描述形如“钓鱼等级：20”。示例中的中文冒号 `：` 是要匹配的文字，不能换成英文冒号后仍期待匹配同一行。

### 常用写法速查

| 想匹配什么 | 表达式 | 命中示例 |
| --- | --- | --- |
| 任意位置含“钓竿” | `钓竿` | 青玉钓竿、钓竿礼包 |
| 名称完全相同 | `^青玉钓竿$` | 青玉钓竿，不含前后其他文字 |
| 以某段文字开头 | `^活动` | 活动钓竿 |
| 以某段文字结束 | `钓竿$` | 青玉钓竿 |
| 一位或多位数字 | `[0-9]+` | 1、20、300 |
| 两种固定名称之一 | `^(青玉钓竿\|赤金钓竿)$` | 青玉钓竿、赤金钓竿 |
| 任意长度的内容 | `.*` | 可包含零个或多个字符，通常配合其他固定文字 |

`^` 表示开头，`$` 表示结尾，`+` 表示前面的模式出现一次或多次。物品名称或单行 Lore 中只要找到符合表达式的部分就会命中，所以需要完整匹配时不要漏掉 `^` 和 `$`。

### 方括号、点号和反斜线

正则中的 `[ ]`、`( )`、`.`、`+` 等有特殊含义。要匹配名称里真正的 `[活动]`，可以使用反斜线并用 YAML 单引号包住：

```yaml
match:
  name-regex:
    - '^\[活动\].*$'
```

它能匹配“[活动]青玉钓竿”。推荐先用单引号保存正则，反斜线不用再经过 YAML 双引号转义。同一表达式若用双引号，反斜线要写两次：

```yaml
match:
  name-regex:
    - "^\\[活动\\].*$"
```

不要写成 `/青玉钓竿/i`，也不要把“正则”理解成默认包含匹配：`.` 不是普通点号，`*` 也不是单独的“任意名称”写法。只需查一段固定文字时优先使用 `name-contains` / `lore-contains`。

## NBT/PDC 标签从哪里获取

NBT/PDC 是物品携带的附加数据。**键**是数据名称，**值**是这项数据的内容；它们不一定显示在物品名称或 Lore 中。

1. 从实际发给玩家的那件物品开始核对，不要只看商品图标。
2. 查物品提供插件的定义文件、物品编辑器或已经安装的物品数据查看工具，取得真实键名和值。不同插件保存 ID 的方式不同，不能靠物品显示名称猜测。
3. 区分普通 NBT 键和带命名空间的 PDC 名称。例如 `myitems:rod_id` 中，`myitems` 是命名空间，`rod_id` 是键名。
4. 找不到标签时，先使用已知的材质、物品库 ID 或名称匹配，不要先填写示例标签并期待物品自动获得该数据。

本页的 `myitems:rod_id`、`rod_quality`、`rod_level` 都是假定已经存在的示例。换成自己的实际数据后再使用。`nbt-keys` 与 `nbt-values` 都是**读取与判断**，不会为物品新增标签。

## 只检查标签存在：nbt-keys

若实际物品带有 `myitems:rod_id`，但不关心它的值：

```yaml
match:
  nbt-keys:
    - "myitems:rod_id"
```

`nbt-keys` 是列表。列出多个键时，存在其中任意一个即可命中；不是要求全部键都存在。存在一个名为 `bound` 的标签也不代表它的值为“已绑定”，值为零时该键仍可能存在。

当前键比较也会按冒号后的名称匹配。即使填写完整名称，也不要据此认定其他命名空间的同名键必定被排除；有同名标签时，应结合物品库 ID、材质等条件缩小范围。

这里填写键名，不是整段 NBT 文本，也不是任意点分路径。例如不能未经核对就把物品数据的显示层级拼成 `tag.display.Name`。嵌套数据应确认实际要判断的键及其值。

## 检查具体值：nbt-values

若已查看到物品数据包含以下三项：`myitems:rod_id` 为 `jade_rod`、`rod_quality` 为 `rare`、`rod_level` 为数字 `3`，可写：

```yaml
match:
  nbt-values:
    "myitems:rod_id": "jade_rod"
    "rod_quality": "rare"
    "rod_level": "3"
```

`nbt-values` 是**键值映射**，每项前面不加 `-`。上例的三项都满足才命中；它不是三个条件任选其一，也不是只检查键是否存在。

| 实际值与配置 | 当前比较结果 |
| --- | --- |
| 实际文本 `RARE`，配置 `"rare"` | 文本忽略大小写，可匹配 |
| 实际数字 `3`，配置 `"3.0"` | 数值相等，可匹配 |
| 实际数字标签显示 `1b`，配置 `"1"` | 按支持的数值格式比较，可匹配 |
| 实际为表示真假的数字 `1`，配置 `"true"` | 不应视为同一个值，按实际数据填写 |
| 配置 `">=3"` 或 `"rare.*"` | 这里不是范围表达式或正则，不会按该含义判断 |

优先使用简单文本或数字标签，不要默认整段复合标签、数组或任意自定义数据类型都能按预期转换。只要求存在用 `nbt-keys`；要求具体值用 `nbt-values`，两者不必为了“写全”而重复配置。

## 多个条件怎样组合

**不同字段之间同时满足；一个列表内通常命中任意一项即可。** 例如同时配置材质和名称，必须既是指定材质又满足名称，不是二者任选其一。

```yaml
match:
  material-ids:
    - paper
  name-contains:
    - "传送券"
    - "旅行券"
```

该例匹配名称含“传送券”或“旅行券”的纸。它适用于外层字段为 `match` 的位置；要求 `matcher` 或 `blacklist` 的位置，应替换外层名称。空匹配器不会自动匹配全部物品，各模块还可能直接跳过空定义。

## 物品费用示例

Map 支持在锚点的费用物品列表中使用数量与匹配条件，例如在锚点 `unlock` 中配置：

```yaml
items:
  - amount: 3
    match:
      material-ids: [diamond]
```

表示手动解锁时使用符合条件的三颗钻石。自动解锁和手动解锁条件不同，不能用费用配置推断所有解锁路径都会扣物品；完整位置见[传送锚点](/docs/map/anchors)。

Lottery 的物品费用使用 `matcher`，且物品费用不能同时用 `id` 代替匹配条件。不要把上例直接改一个模块名就投入使用，具体结构见[抽奖功能配置](/docs/lottery/configuration)。

## 验证方法

用满足条件、仅满足一部分条件和完全不满足条件的物品分别测试。费用还要验证数量不足、刚好足够与多组可匹配物品；过滤规则还要检查黑名单和白名单方向。无效正则会被跳过，应同时检查重载日志，避免误以为限制已经生效。

## 完整示例：按标签识别鱼竿

假设真实鱼竿是原版 `FISHING_ROD`，且已存在值为 `jade_rod` 的 `rod_id` 标签，在 `plugins/ArcartX-Suite/data/fishing/rods/jade_rod.yml` 中可写：

```yaml
id: jade_rod
match:
  material-ids:
    - fishing_rod
  nbt-values:
    "rod_id": "jade_rod"
green-bar-height-bonus: 8
exp-multiplier: 1.1
min-player-level: 0
max-player-level: 0
```

保存后执行 `/axs reload fishing`，分别用带正确标签、带其他值和不带标签的鱼竿测试。这个文件只识别并赋予钓鱼加成，不会生成鱼竿、写入标签或自动给玩家发物品。鱼竿其余字段见[鱼竿配置](/docs/fishing/rods)。

## 常见写法错误

| 错误 | 正确处理 |
| --- | --- |
| 把 `nbt-keys` 写成 `rod_id: jade_rod` | 只查存在时用列表；查值时放入 `nbt-values` 映射 |
| 把 `nbt-values` 写成 `- rod_id` | 必须写真实键和值，不是键名列表 |
| 只改 `icon` 后期待识别物品 | `icon` 是显示，物品识别仍要配置实际匹配规则 |
| 把示例的 `myitems:rod_id` 原样复制 | 先确认自己的物品是否真的存在该键和值 |
| 同时填两个来源 ID，期待任选一个 | 不同字段需要同时满足；不要把“另一种方案”也一并启用 |
| 正则修改后有警告但仍继续使用 | 修正无效表达式并重新测试；被跳过的限制不能视为有效 |
