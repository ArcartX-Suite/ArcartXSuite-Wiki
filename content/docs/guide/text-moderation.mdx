主配置 `moderation` 提供统一词库，但各模块对过滤结果的使用方式不同。不能把“统一词库”理解为全服务器任意文本都会自动被替换。

## 已接入的文本场景

| 模块 | 实际检查内容 | 命中后的行为 |
| --- | --- | --- |
| Chat | 频道消息与私聊处理中的文本 | 取消型结果会阻止发送；替换型结果使用替换后的文字继续 |
| Market | 玩家上架、修改等操作中的留言 | 取消型结果会阻止该留言提交；否则使用处理后的留言 |
| Mail | 玩家写信的主题与正文检查 | 当前检查是否需要阻止发送，不将替换后的文本写回主题、正文；不能保证 `cancel-on-match: false` 会重写邮件内容 |

Mail 另有附件材质、名称、Lore 等限制；Market 的物品黑名单也不是文字词库。其他插件、控制台输出、公告预设或自定义界面文字，不会仅因打开本体开关就全部经过此流程。

## 配置词库

```yaml
moderation:
  enabled: true
  cancel-on-match: true
  replacement: "*"
  blocked-words:
    - "测试屏蔽词"
  blocked-patterns: []
  whitelist: []
  cloud:
    enabled: false
```

本例在对应场景使用本地词库，命中后返回取消结果。`replacement` 供替换模式使用；将 `cancel-on-match` 改为 `false` 后，应分别测试聊天、市场与邮件，不能假定三者表现一致。

`ignored-punctuations` 是文字匹配规则的一部分，按自己的文字政策调整即可。白名单会放行对应文本，添加后要测试正常句子和包含测试词的句子，避免放行范围与预期不同。

## 远程词库与本地词库

`moderation.cloud.enabled` 控制远程词库，和云端模块账号没有关系。`urls` 填词库地址，`ignored` 排除远程库中的指定词，`refresh-minutes` 为刷新间隔。

远程词库可使用每行一个词的文本、字符串 JSON 数组，或含 `words`、`data`、`list` 数组的对象。远程下载失败时应检查当前词库和实际过滤结果，不要用“没有继续刷错误”判断过滤已经恢复。

修改后执行 `/axs reload all`。分别在频道、私聊、市场留言、邮件主题与正文中使用测试词，并检查正常文本能否通过。

## 提示文字与内容过滤不同

玩家看到的操作提示通常来自模块 `messages.yml`，但并非每个模块都使用同一文件名：Prop 的部分提示在 `language.yml`，界面文字也可能位于 UI 或业务定义中。

编辑提示只改变显示，不会改变费用、权限、奖励或实际判断。`{0}`、`{item}` 等变量按当前提示字段的说明填写。修改后重载对应模块，分别测试成功、失败和无权限等提示。
