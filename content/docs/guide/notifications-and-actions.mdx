通知有不同的接收范围和触发方式。公告不是字幕组，聊天卡片不是普通文字，发送一个事件信号也不等于自动发奖；需要接收方功能和配置都已准备好。

## 各类通知怎样选择

| 类型 | 提供或处理模块 | 适用场景 |
| --- | --- | --- |
| 公告轮播、立即或排队广播 | Announcer | 本服或按配置跨服发送公告 |
| 字幕组 | Announcer | 对指定玩家播放已配置字幕序列 |
| 聊天卡片 | Chat 或明确支持该卡片的功能 | 显示任务、物品或通知的结构化内容 |
| QQ 群消息 | QQBot | 向指定群或已配置群发送消息 |
| 自定义信号与动作 | EventPacket | 收到指定信号后执行任务、称号、命令、邮件等动作 |
| 地图与任务导航 | Map、QuestGPS | 打开、推送或追踪实际存在的目标 |

没有启用接收方模块或没有对应 ID 时，可能没有效果。应先独立验证一条字幕、卡片、预设或任务，再组合联动。

## 各模块的联动入口

| 调用场景 | 实际用法与边界 |
| --- | --- |
| AfkReward | 进入、离开、开始、结束和发奖可发送信号；`manual.subtitle-on-reward`、`manual.subtitle-on-end` 指定字幕组，邮件结束配置另见邮件派发 |
| EventPacket | 规则 `actions` 可调用任务、字幕、卡片、称号、邮件、QQ 广播等；动作的参数与接收者各不相同 |
| Menu | 按钮 `SIGNAL` 动作可发送信号，其他按钮动作有自己的配置格式；不是直接粘贴 EventPacket 的 `actions` 列表 |
| Abyss | 副本脚本有公告、字幕、聊天卡片、QQ 通知、战斗效果、任务等动作，使用副本动作语法与目标选择器 |
| Mail | 收件提示可使用配置的通知卡片；邮件存在和通知显示应分别验证，卡片未显示不代表没有收到邮件 |
| Fishing | 存在称号和邮件等里程碑联动，例如首次传奇捕获邮件；不是所有里程碑都能通过任意同名字段改写 |

AfkReward 当前区域发奖使用固定信号 `afk_reward`。不要因为主配置中存在 `signal-on-reward` 就假定修改它能重命名当前实现发出的所有奖励信号；应以实际触发场景测试结果为准。

## 示例：信号触发字幕与邮件

先创建有效字幕组 `welcome_demo` 和邮件预设 `welcome_demo`，再在 EventPacket 规则文件中配置：

```yaml
welcome_notice:
  enabled: true
  trigger: command-signal
  signal: welcome_demo
  repeatable: true
  actions:
    - type: subtitle.play
      group-id: welcome_demo
    - type: mail.send
      preset-id: welcome_demo
```

此规则接收名为 `welcome_demo` 的信号，按顺序为触发玩家播放字幕并发送邮件。信号名、字幕组 ID 和邮件预设 ID 虽可相同，仍是三个独立配置，不会自动互相创建。

用[EventPacket 命令](/docs/eventpacket/commands)中的 `fire` 流程单独测试，再接入菜单或其他调用方。完整动作字段见[动作详解](/docs/eventpacket/actions)。

## 定时与声音等其他公共需求

定时命令、PAPI 条件监听、实体清理等由[EventPacket 定时服务](/docs/eventpacket/services)提供，需要启用该模块，不是本体中对所有模块自动生效的一组字段。

原版声音、ArcartX 资源声音、NPC 与镜头表现也有不同入口。例如[过场演出](/docs/conversation/cinematic)的 `sound` 与 `arcartx_sound` 不能互换资源名；菜单、地图或副本中的声音仍按各自字段填写。没有一个可复制到所有模块的全局 `sound` 或 `notify` 片段。
