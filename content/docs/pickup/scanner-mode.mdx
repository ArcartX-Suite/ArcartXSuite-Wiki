扫描模式使用常驻清单展示附近可收取的物品，不占用鼠标。**拾取键直接收取当前类**，不需要先打开菜单；大量物品重叠时，使用上一项／下一项切换。详细面板是可选入口。

## 先完成一次收取

1. 在 `plugins/ArcartX-Suite/data/pickup/config.yml` 中设置下方配置。
2. 在宿主 `plugins/ArcartX-Suite/config.yml` 中确认本页列出的按键注册存在，重启宿主使新增按键注册生效。只调整模块设置时执行 `/axs reload pickup`。
3. 执行 `/pickup on`，丢出铁锭和金锭两种物品，等待默认约 2 秒的拾取冷却结束；默认过滤不会屏蔽这两种材料。
4. 按拾取键收取当前类，再用切换键选择另一类；核对背包、仓库和 HUD 汇总数量。

```yaml
settings:
  mode: scanner
scanner:
  scan-radius: 5.0
  scan-interval-ticks: 5
  display-rows: 5
  max-candidates: 512
  disable-auto-pickup: true
  warehouse-auto-deposit: false
  pickup-delay-ticks: 40
  merge-same-items: true
  keybind:
    name: AXS_PICKUP_PICK
    previous: AXS_PICKUP_PREVIOUS
    next: AXS_PICKUP_NEXT
    collect-all: AXS_PICKUP_ALL
    details: AXS_PICKUP_DETAILS
  batch:
    enabled: true
    mode: all
    matcher:
      material-ids: []
    entities-per-tick: 8
    time-budget-ms: 4
    chat-summary: false
```

## 玩家操作

默认键位可在客户端按键设置中修改，HUD 显示客户端当前绑定的按键名称。

| 默认键位 | 操作 | 命令替代 |
| --- | --- | --- |
| F | 收取当前选中的整类物品 | `/pickup collect` |
| 左方向键 | 选择上一类，到顶后循环 | `/pickup previous` |
| 右方向键 | 选择下一类，到底后循环 | `/pickup next` |
| J | 收取符合批量规则的全部物品 | `/pickup all` |
| K | 打开或关闭详细面板 | `/pickup details` |
| Esc | 关闭详细面板，返回常驻清单 | 在详细面板内使用 |

常驻清单不监听滚轮，平时仍可正常切换快捷栏。打开详细面板后，滚轮切换条目，鼠标点击收取指定类；面板提供翻页、批量收取和可滚动的物品说明。鼠标位于说明区域时，滚轮用于阅读说明。

### 在宿主注册按键

把以下条目放在宿主配置的 `keybinds` 下；已有 `pickup-pick` 时修改原条目，不要重复定义同名键。这里的 `name` 必须与模块 `scanner.keybind` 对应；`default-key` 使用 GLFW 键名。

```yaml
keybinds:
  pickup-pick:
    name: AXS_PICKUP_PICK
    default-key: F
    category: ArcartXSuite
    module: pickup
  pickup-previous:
    name: AXS_PICKUP_PREVIOUS
    default-key: LEFT
    category: ArcartXSuite
    module: pickup
  pickup-next:
    name: AXS_PICKUP_NEXT
    default-key: RIGHT
    category: ArcartXSuite
    module: pickup
  pickup-all:
    name: AXS_PICKUP_ALL
    default-key: J
    category: ArcartXSuite
    module: pickup
  pickup-details:
    name: AXS_PICKUP_DETAILS
    default-key: K
    category: ArcartXSuite
    module: pickup
```

## 清单如何组织

- 完整物品信息一致时合并数量；同名但附魔、耐久、Lore 或 NBT 不同的物品分别列出。
- 已有条目保持顺序，新增类别追加到末尾。移动位置不会持续打乱清单，所选类别有其他实体留下时仍保持选择。
- `display-rows` 只决定 HUD 一页显示几行，不限制清单总长度。切换选择时自动翻页，并显示“第几类／共几类”。
- `max-candidates` 限制一次扫描纳入的可收取实体数。达到上限时会提示物品较多，收取后继续扫描；此时类别总数只代表已纳入的候选。

实体生成至少 `pickup-delay-ticks` tick 后才纳入清单，同时要求自身拾取冷却结束、物品归属允许且玩家可拾取。点击或按键后会再次核对距离、归属、物品信息及其他插件的拾取取消结果。

## 收取与批量规则

一次操作固定当时确认的实体和数量。执行过程中新增的掉落物、合入同一实体的新增数量不会被本次请求持续吸走；再次按键即可收取。连续按键不会把同一批任务重复加入队列。

当前类收取与批量收取都分批执行。全模块每 tick 最多处理 `entities-per-tick` 个实体，并轮流处理不同玩家的请求；达到 `time-budget-ms` 软预算后，剩余请求留到下一 tick。单次仓库调用无法中途打断，数据库较慢时应减少每 tick 数量。

| 设置 | 作用 | 使用场景 |
| --- | --- | --- |
| `batch.enabled: false` | 关闭全部收取，仍允许当前类收取 | 希望玩家逐类选择装备 |
| `batch.mode: all` | 收取所有通过清单过滤的候选 | 清理战斗后的物品堆 |
| `batch.mode: matching` | 只批量收取 `batch.matcher` 命中的物品，空规则不收取任何物品 | 材料批量收取，装备手动挑选 |
| `batch.chat-summary: false` | 完成后只在 HUD 汇总一次 | 避免大量掉落刷聊天栏 |

例如只批量收取矿物材料，同时保留装备在清单中供手动选择：

```yaml
scanner:
  batch:
    enabled: true
    mode: matching
    matcher:
      material-ids:
        - IRON_INGOT
        - GOLD_INGOT
        - DIAMOND
        - EMERALD
```

匹配规则的各已填维度需要同时满足，同一列表内任一项命中即可，详见[物品匹配条件](/docs/guide/conditions)。限制批量收取的规则不会影响“收取当前类”。

## Warehouse 联动与未收取物品

开启 `scanner.warehouse-auto-deposit: true` 后，顺序为：尝试 Warehouse 入库，再把剩余部分放入背包，放不下的保留在地面。Warehouse 的服务器总开关、战利品开关及玩家保存的个人开关仍然生效。

| 场景 | 结果 |
| --- | --- |
| 入库失败、仓库已满或个人关闭自动入库 | 继续尝试背包，不因为入库失败删除物品 |
| 背包和仓库都放不下 | 未能收取的部分留在地面，继续处理其他候选 |
| 物品已消失、归属变化或被其他插件阻止 | 跳过，不会用其他物品替换该目标 |
| 玩家离线、切换世界、关闭 Pickup 或模块停止 | 停止未完成的请求，已经完成的收取保留 |

HUD 汇总仓库、背包及“未收取”数量；未收取包含空间不足、物品失效和被跳过的快照数量，不保证这些物品仍在原地。默认不逐个发送聊天提示。开启聊天汇总后，Warehouse 的个人入库通知关闭时不在聊天中报告仓库存入数量，HUD 汇总仍可查看。

## 五维过滤

按固定顺序依次检查每个掉落物的五个维度，任一维度不通过则不显示：

| 顺序 | 维度 | 配置路径 | 判定规则 |
| --- | --- | --- | --- |
| 1 | 最小数量 | `filter.min-amount` | 堆叠数低于此值则过滤 |
| 2 | 材质过滤 | `filter.material-blacklist` / `filter.material-whitelist` | `blacklist` 模式：命中黑名单则过滤；`whitelist` 模式：白名单非空时未命中则过滤 |
| 3 | 名称正则 | `filter.name-blacklist.name-regex` | 命中任一正则则过滤 |
| 4 | Lore 正则 | `filter.lore-blacklist.lore-regex` / `filter.lore-whitelist.lore-regex` | 黑名单命中则过滤；白名单非空时未命中则过滤 |
| 5 | NBT 键 | `filter.nbt-blacklist.nbt-keys` / `filter.nbt-whitelist.nbt-keys` | 黑名单命中则过滤；白名单非空时未命中则过滤 |

### 材质过滤模式

材质过滤由 `filter.mode` 控制：

| 模式 | 配置值 | 行为 |
| --- | --- | --- |
| 黑名单 | `blacklist` | 命中 `material-blacklist` 的物品不显示，其余全部显示 |
| 白名单 | `whitelist` | 仅显示命中 `material-whitelist` 的物品；白名单为空时全部显示 |

```yaml
filter:
  mode: blacklist
  material-blacklist:
    material-ids:
      - DIRT
      - COBBLESTONE
      - GRAVEL
      - SAND
      - NETHERRACK
      - COBBLED_DEEPSLATE
  material-whitelist:
    material-ids: []
```

> 白名单模式下设为空列表（`[]`）等同于不启用白名单——所有物品均显示。

### 名称与 Lore 正则过滤

名称黑名单与 Lore 黑名单均使用正则表达式匹配。Lore 过滤检查物品 Lore 的**任意一行**，只要有一行匹配正则即视为命中。

```yaml
filter:
  name-blacklist:
    name-regex:
      - ".*垃圾.*"
  lore-blacklist:
    lore-regex:
      - ".*已绑定.*"
  lore-whitelist:
    lore-regex:
      - ".*稀有.*"
```

Lore 白名单为可选维度：配置为空时不启用；配置后物品 Lore 中必须至少有一行匹配白名单正则才显示。

### NBT 键过滤

NBT 键过滤支持嵌套路径（如 `custom.trash`），检查物品 NBT 中是否包含指定键。

```yaml
filter:
  nbt-blacklist:
    nbt-keys:
      - "custom.trash"
  nbt-whitelist:
    nbt-keys: []
```

> 过滤配置基于物品匹配体系，材质匹配使用 `material-ids`，名称/Lore 使用正则表达式，NBT 使用键路径匹配。详见 [物品匹配条件](/docs/guide/conditions) 与 [物品来源](/docs/guide/item-sources)。


## 更新已有界面文件

扫描模式的 `ui/loot_panel.yml` 与 `ui/loot_interact.yml` 需与模块版本配套。使用默认界面时，可临时设置 `ui.overwrite-ui-files: true`，执行 `/axs reload pickup` 后关闭该选项。自定义界面请对照配套模板调整数据字段和操作回包。
