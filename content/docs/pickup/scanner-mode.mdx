# 扫描模式

> **付费模块**

扫描模式（`settings.mode: scanner`）是 Pickup 模块的核心交互模式。该模式禁用原版自动拾取，周期性扫描玩家附近掉落物，经五维过滤筛选后推送到客户端 HUD 面板，玩家通过按键打开透明交互菜单，使用鼠标点击或滚轮切换选中并拾取目标物品。

## 扫描配置

```yaml
scanner:
  scan-radius: 5.0
  scan-interval-ticks: 5
  max-display: 8
  pickup-delay-ticks: 40
```

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `scan-radius` | `5.0` | 扫描半径（格） |
| `scan-interval-ticks` | `5` | 扫描间隔（tick，5 = 250ms） |
| `max-display` | `8` | 面板最多展示的条目数 |
| `pickup-delay-ticks` | `40` | 落地延迟（tick，40 = 2 秒）；刚扔出的物品延迟该时长后才显示 |
| `merge-same-items` | `true` | 相同材质+名称的条目合并数量 |
| `disable-auto-pickup` | `true` | 禁用玩家自动拾取 |
| `warehouse-auto-deposit` | `false` | 拾取后自动存入 Warehouse 仓库 |

> 面板列表仅在内容变化时推送更新，无变化时无额外开销。

## 五维过滤

按固定顺序依次检查每个掉落物的五个维度，任一维度不通过则不显示：

| 顺序 | 维度 | 配置路径 | 判定规则 |
| --- | --- | --- | --- |
| 1 | 最小数量 | `filter.min-amount` | 堆叠数低于此值则过滤 |
| 2 | 材质过滤 | `filter.material-blacklist` / `filter.material-whitelist` | `blacklist` 模式：命中黑名单则过滤；`whitelist` 模式：白名单非空时未命中则过滤 |
| 3 | 名称正则 | `filter.name-blacklist.name-regex` | 命中任一正则则过滤 |
| 4 | Lore 正则 | `filter.lore-blacklist.lore-regex` / `filter.lore-whitelist.lore-regex` | 黑名单命中则过滤；白名单非空时未命中则过滤 |
| 5 | NBT 键 | `filter.nbt-blacklist.nbt-keys` / `filter.nbt-whitelist.nbt-keys` | 黑名单命中则过滤；白名单非空时未命中则过滤 |

### 材质过滤模式

材质过滤由 `filter.mode` 控制：

| 模式 | 配置值 | 行为 |
| --- | --- | --- |
| 黑名单 | `blacklist` | 命中 `material-blacklist` 的物品不显示，其余全部显示 |
| 白名单 | `whitelist` | 仅显示命中 `material-whitelist` 的物品；白名单为空时全部显示 |

```yaml
filter:
  mode: blacklist
  material-blacklist:
    material-ids:
      - DIRT
      - COBBLESTONE
      - GRAVEL
      - SAND
      - NETHERRACK
      - COBBLED_DEEPSLATE
  material-whitelist:
    material-ids: []
```

> 白名单模式下设为空列表（`[]`）等同于不启用白名单——所有物品均显示。

### 名称与 Lore 正则过滤

名称黑名单与 Lore 黑名单均使用正则表达式匹配。Lore 过滤检查物品 Lore 的**任意一行**，只要有一行匹配正则即视为命中。

```yaml
filter:
  name-blacklist:
    name-regex:
      - ".*垃圾.*"
  lore-blacklist:
    lore-regex:
      - ".*已绑定.*"
  lore-whitelist:
    lore-regex:
      - ".*稀有.*"
```

Lore 白名单为可选维度：配置为空时不启用；配置后物品 Lore 中必须至少有一行匹配白名单正则才显示。

### NBT 键过滤

NBT 键过滤支持嵌套路径（如 `custom.trash`），检查物品 NBT 中是否包含指定键。

```yaml
filter:
  nbt-blacklist:
    nbt-keys:
      - "custom.trash"
  nbt-whitelist:
    nbt-keys: []
```

> 过滤配置基于物品匹配体系，材质匹配使用 `material-ids`，名称/Lore 使用正则表达式，NBT 使用键路径匹配。详见 [物品匹配条件](/docs/guide/conditions) 与 [物品来源](/docs/guide/item-sources)。

## 物品合并

`merge-same-items` 启用时，相同材质 + 相同显示名的物品合并为一条，数量累加。合并仅影响显示；拾取时实际取走其中一个掉落物实体。

## 玩家操作流程

1. 玩家按交互键（`scanner.keybind.name` 配置的按键）打开透明交互菜单
2. 滚轮切换选中项（到顶/底循环环绕），或鼠标点击指定条目
3. 确认拾取后物品进入背包
4. 周围无掉落物时菜单自动关闭；按 ESC 手动关闭

## 拾取行为

| 场景 | 处理方式 |
| --- | --- |
| `warehouse-auto-deposit` 启用 | 优先存入仓库，剩余部分放入背包 |
| 仓库存入全部 | 移除掉落物，提示 `hints.warehouse-stored` |
| 仓库存入部分 | 剩余放入背包，提示 `hints.warehouse-stored` |
| 仓库不可用 | 全部放入背包 |
| 背包满 | 物品保留在地面，提示 `hints.inventory-full` |
| `disable-auto-pickup: false` | 不拦截，玩家正常自动拾取 |
| 玩家手动关闭拾取功能（`/pickup off`） | 不拦截自动拾取，HUD 与菜单关闭 |

## HUD 生命周期

| 事件 | 行为 |
| --- | --- |
| 玩家登录且客户端就绪 | 自动打开常驻 HUD |
| 玩家退出 | 清理玩家状态 |
| 手动关闭（`/pickup off`） | 关闭 HUD 与菜单 |
| 手动开启（`/pickup on`） | 重新打开 HUD |
| 模块重载 | 重新打开所有玩家 HUD |
